## Overview

The SMS editor is intentionally minimal — a single text body and a live phone 
preview. SMS is a plain-text channel with no formatting, images, or buttons. 
What you write is exactly what the recipient receives.

## Getting Started

To add SMS to a template, open the template in edit mode, click **+** in the 
channel tab row, select **SMS**, and click **Add Channels**. SuprSend creates 
a `default` variant and opens the SMS editor.

To send SMS, you need an SMS vendor configured in your workspace. 
See [SMS Vendor Integration](/docs/sms-vendor-integration).

<Warning>
  **DLT Compliance (India):** If you are sending SMS in India, you are 
  responsible for registering your sender header and getting your SMS templates 
  approved on the DLT portal before using them in SuprSend. SuprSend does not 
  manage the DLT approval process. Sending unapproved templates will result in 
  delivery failure. See [DLT Guidelines](/docs/dlt-guidelines) for details.
</Warning>

## Fields

### Body *(required)*

The full text content of the SMS message. This is the only field in the SMS 
editor.

There is no subject line, header, or formatting — the body is the entire 
message as the recipient sees it.

Supports Handlebars variables and emoji. The content auto-saves as you type 
(shown by the **Saved** indicator in the top-right of the editor).

<Tip>
  SMS messages over 160 characters are split into multiple segments and billed 
  per segment by most carriers. Keep messages concise. If you need to include 
  a URL, use a URL shortener or pass a pre-shortened link as a variable — 
  e.g. `{{short_url}}`.
</Tip>

## Live Preview

The right panel shows a live mobile preview of the SMS in an iPhone Messages 
UI. The preview updates in real time as you type, with variables substituted 
using values from the Variables panel.

To preview with a specific user's data, search for a user in the **Recipient** 
section of the Variables panel.

---

## Variables

The Body field supports full Handlebars syntax. Define variables in the 
**Variables `{}`** panel before using them to get autocomplete and live preview.

| Source | Example | Description |
| --- | --- | --- |
| Trigger payload | `{{order_id}}` | Data sent when the workflow triggers |
| Recipient profile | `{{$recipient.first_name}}` | Properties from the user's SuprSend profile |
| Tenant | `{{$brand.brand_name}}` | Tenant branding properties |

For conditionals and helpers, see [Handlebars Helpers](/docs/handlebars-helpers).

<Warning>
  Unlike email, SMS has no fallback rendering. If a variable is missing at send 
  time, **the SMS notification is not sent** — but other channels in the same 
  workflow (e.g. email, push) are unaffected and will still be delivered. Always 
  ensure all variables have values in your trigger payload or user profile before 
  going live.
</Warning>

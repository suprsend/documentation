## Fields

### Body

**Required** · Supports variables

The full text of the SMS — everything the recipient sees.

**What to write here:** Put the most important detail first (order number, OTP, deadline). Aim for one GSM-7 segment (160 characters) — each extra segment is billed separately. Include one clear call to action when needed. Avoid generic URL shorteners; use a branded domain if you include a link. Supports Handlebars variables and emoji.

| Encoding | Chars per segment | When it applies |
|---|---|---|
| GSM-7 | 160 (single), 153 (multi-part) | Standard Latin characters, digits, basic punctuation |
| UCS-2 | 70 (single), 67 (multi-part) | Emojis, non-Latin scripts (Hindi, Arabic, Chinese, etc.) |

A single emoji or non-Latin character forces the **entire** message into UCS-2, cutting capacity from 160 to 70. Avoid emojis in transactional SMS to keep costs down.

Supports Handlebars: `{{variable_name}}`. For URLs with `&`, `?`, or `=`, use triple braces `{{{tracking_url}}}` so values are not HTML-escaped.

> Example: `Your verification code is {{otp_code}}. It expires in {{expiry_minutes}} minutes. Do not share this code with anyone.` (keep OTP copy under one segment — no URL required.)

> Example: `Hi {{$recipient.name}}, your order #{{order_id}} has been shipped! Track it here: {{{tracking_url}}}`

> Example: `Reminder: Your appointment with {{provider_name}} is on {{appointment_date}} at {{appointment_time}}. Reply CONFIRM to confirm or CANCEL to cancel.` — pair with a [delay node](/docs/delay) or [time window](/docs/time-window) in your workflow to send at the right time.

> Example: `Flash sale! Get {{discount}}% off on all items. Shop now: {{{shop_url}}}. Valid till {{expiry_date}}. Reply STOP to opt out.` — include opt-out language on promotional messages.

## Personalise with variables

You can add variables in the template to personalise it per recipient. SuprSend replaces variables with actual data at send time. Pass values via your workflow trigger payload or use recipient/tenant properties.

<Steps>
  <Step title="Add variables in the Variables panel">
    Add sample data in the **Variables panel** (Input Payload section) on the left side of the editor. This powers auto-suggestions and the live preview. For the full guide on setting up variables, see [Adding dynamic content](/docs/templates#the-variables-panel).
  </Step>

  <Step title="Use variables in the template">
    Type `{{` in the body field — matching variables appear as auto-suggestions. You can also type variable names manually following [Handlebars syntax](https://handlebarsjs.com/guide/#what-is-handlebars).

    **Examples using this sample data:**

    <CodeGroup>
      ```json json
      {
        "event": {
          "location": {
            "city": "Bangalore",
            "state": "KA"
          },
          "order_id": "11200123",
          "first_name": "Nikita"
        },
        "tracking_url": "https://yourapp.com/track/11200123"
      }
      ```
    </CodeGroup>

    - **Nested variable:** `{{event.location.city}}` → renders as `Bangalore`
    - **Variable with space in name:** `{{event.[first name]}}`
    - **URL (avoid escaping):** use triple braces `{{{tracking_url}}}` for URLs with `&`, `?`, `=`

    The preview section shows sample values rendered in real-time. If a variable isn't rendering, check:
    1. The variable is defined in the Variables panel.
    2. The variable name matches the Handlebars syntax exactly.
  </Step>
</Steps>

For conditionals and helpers, see [Handlebars Helpers](/docs/handlebars-helpers).

<Warning>
  If a variable cannot be rendered at send time (missing or mismatched data), SuprSend skips that notification for the affected user. Other channels in the same template group are still sent.
</Warning>

## Preview and test

Preview and test before you rely on this template in production.

The right panel shows a live phone preview, updated in real time as you type. Variables render using data from the **Variables panel**.

Click **Test** in the top-right corner to send a real SMS to a real phone number. This uses the **live version** — commit your changes before testing. See [Testing a Template](/docs/templates#test) for the full guide.

## Publish

Click **Commit** in the top bar to publish the current draft as a new live version. Add an optional description for versioning. The template goes live immediately and is used for all subsequent workflow triggers (unless [carrier approval](#sending-sms-in-india) applies — see below).

## Sending SMS in India

> India's telecom regulator (TRAI) requires all SMS templates to be registered and approved through your carrier before sending. This applies to all three message types: Transactional, Promotional, and Engagement. Once you enable approval in Settings, the editor shows additional fields. SuprSend handles submission to your carrier automatically — you design the template, commit it, and the approval request goes out on your behalf.

### Require template approval before sending

<Steps>
  <Step title="Go to Settings">
    Navigate to **Settings** on the SuprSend dashboard.
  </Step>
  <Step title="Enable SMS template approval">
    Toggle on **SMS Template Approval Required**. The SMS editor shows three fields instead of one (Message Type, Header, and Body).

    <Frame caption="Enable SMS Template Approval Required in Workspace Settings">
      <img src="/images/docs/templates-sms-dlt-settings-toggle.png" />
    </Frame>
  </Step>
</Steps>

### Message Type

**Required when carrier approval is enabled**

Select **Transactional** (triggered by a user action — delivery updates, OTPs), **Promotional** (marketing messages without explicit consent), or **Engagement** (re-engagement messages to existing users — feature promotions, discount offers).

### Header

**Required when carrier approval is enabled**

The sender ID (6 alphanumeric characters) registered with your carrier. Separate headers exist for each message type.

### Body (carrier-matched)

**Required when carrier approval is enabled**

The SMS content must **exactly** match the template registered in your carrier's registration portal, including punctuation. Variables must align with the approval placeholder format your carrier expects.

### Carrier approval flow

<Steps>
  <Step title="Design and commit">
    Author the template content and click **Commit**. The version enters **Approval Pending** state (it does not go live).
  </Step>
  <Step title="Approval at vendor portal">
    SuprSend submits the template to your SMS vendor for carrier approval. You'll be notified when approved or rejected.
  </Step>
  <Step title="Live or revise">
    On approval, the version goes **Live**. On rejection, it returns to **Draft** for revision.
  </Step>
</Steps>

Templates pending approval are visible in the **Approvals** tab on the [template listing page](/docs/templates#managing-templates). For content guidelines, see [India SMS Compliance Guide](/docs/dlt-guidelines).

<Warning>
  Approved templates **cannot be tested in draft**. You can only test after the template has been committed and approved. The Test button sends using the live (approved) version.
</Warning>

## Other ways to build this template

### Character count before you open the editor

Before touching the editor, write your SMS in the Notes app, iMessage draft, or any plain text editor and count characters (on Mac: paste into TextEdit → Format → Make Plain Text, then check word count; on any OS: paste into [charactercounttool.com](https://charactercounttool.com)). Knowing you're at 143 characters before you add variable values means you can plan your variable length budget. A name like "Priyanka Subramaniam" eats 20 characters — know this before you design around it.

### Build a message character budget spreadsheet

For high-volume transactional SMS (OTPs, order updates, delivery alerts), build a simple spreadsheet: message template in column A, character count formula in column B (`=LEN(A1)`), max possible variable length in column C, total worst-case length in column D. This lets you audit your entire SMS library before sending a single message. Teams that do this avoid mid-campaign surprises where a long user name pushes a message into 2 segments, doubling cost.

### Test encoding before committing

A single invisible Unicode character pasted from a word processor — a "smart quote" (`"` instead of `"`), an em-dash (`—` instead of `-`), or a non-breaking space — shifts your entire message from GSM-7 (160 chars) to UCS-2 (70 chars) without any warning. Before committing your template, paste the body text into [twilio.com/en-us/blog/sms-character-limit](https://www.twilio.com/en-us/blog/sms-character-limit) or any GSM-7 checker tool to verify encoding. The SuprSend editor's character counter tells you segment count — if a 90-character message shows as 2 segments, you have a UCS-2 character hiding in there.

### Localise at the template level with variants

If you send SMS to users in multiple countries or languages, use [template variants](/docs/template-variants) to create one variant per locale instead of maintaining separate templates. Set `$locale` on each user profile. SuprSend automatically routes to the matching variant at send time, with the default acting as the fallback. This means you manage one template with N locale variants instead of N separate templates with N separate workflows.

### Pre-validate your India templates against your carrier's format

India's carrier portals (Airtel, Jio, BSNL, Vi) each have their own dry-run validation. Before committing in SuprSend, log into your carrier's sender registration portal and submit the template body manually to check for format errors. Common issues: variable placeholders must match the exact format your carrier expects (usually `{#var#}` or `{0}`), punctuation must be identical to the registered version, and message type must match the sender header. Catching rejections at the carrier portal level before they surface in SuprSend saves a full approval cycle.

### Use conditional Handlebars to handle name edge cases

Some users have no first name, or their first name is a company name in all-caps, or it's very long. Instead of `Hi {{first_name}},` which can produce `Hi ,` or `Hi ACME CORPORATION,`, write: `{{#if first_name}}Hi {{first_name}},{{else}}Hi there,{{/if}}`. This one Handlebars pattern alone prevents a class of embarrassing message renders for users with incomplete profiles. See [Handlebars Helpers](/docs/handlebars-helpers) for the full conditional syntax.

## Best practices

- **Stay under 160 characters when you can** — Every segment beyond the first is billed separately — plan copy so transactional alerts stay in one segment unless you intentionally accept multi-part cost.
- **Emojis cost effective character budget** — A single emoji shifts the entire message to UCS-2 (70-character segments). Use emojis only when the trade-off is worth it.
- **Open with your brand name** — Recipients don't always recognise your sender number — identify your brand or use a registered sender ID they already know.
- **One link, branded domain** — Generic URL shorteners are often flagged as spam by carriers — use your own domain for links.
- **Always include opt-out language on promotional messages** — Legal requirement in most markets — include it in the body where applicable.
- **Avoid smart quotes and em-dashes** — They're invisible UCS-2 triggers when pasted from word processors — stick to plain ASCII punctuation for predictable GSM-7 encoding.

## FAQ

<AccordionGroup>
  <Accordion title="What is carrier approval and when do I need it?">
    In India, all SMS templates must be registered and approved through your carrier before sending. You need an approved header (sender ID) and carrier approval for each template. If you're sending SMS outside India, carrier approval in SuprSend does not apply — templates go live on commit as usual (unless your organisation enables approval for other reasons).
  </Accordion>

  <Accordion title="Why was my template rejected during approval?">
    Common reasons: the template body doesn't exactly match the content registered with your carrier (even minor punctuation differences count), the header is not registered for the selected message type, or the variable placeholders don't match the registration.
  </Accordion>

  <Accordion title="What's the difference between Transactional, Promotional, and Engagement?">
    **Transactional** — triggered by a user action (delivery updates, OTPs). **Promotional** — marketing messages without explicit consent. **Engagement** — re-engagement to existing users (feature promotions, discount offers). Pick the type that matches how you use the template; mismatches can cause rejection.
  </Accordion>

  <Accordion title="Why is my SMS being sent as multiple segments?">
    SMS has a per-segment character limit. Each extra segment is billed separately by your vendor.

    | Encoding | Chars per segment | When it applies |
    |---|---|---|
    | GSM-7 | 160 (single), 153 (multi-part) | Standard Latin characters, digits, basic punctuation |
    | UCS-2 | 70 (single), 67 (multi-part) | Emojis, non-Latin scripts (Hindi, Arabic, Chinese, etc.) |

    A single emoji or non-Latin character forces the **entire** message into UCS-2, cutting capacity from 160 to 70. Avoid emojis in transactional SMS to keep costs down.
  </Accordion>

  <Accordion title="How do I add URLs in SMS without them breaking?">
    Use triple curly braces `{{{url}}}` instead of double. Double braces HTML-escape characters like `&`, `?`, `=` — which breaks URLs. Triple braces output the raw value.
  </Accordion>

  <Accordion title="Can I send SMS in different languages?">
    Yes — use [template variants](/docs/template-variants). Create a variant for each language with a locale condition. Set the user's preferred language via `$locale` on their profile — SuprSend auto-selects the matching variant. The default variant acts as the English fallback.
  </Accordion>

  <Accordion title="Can I test a template before carrier approval?">
    No. When carrier approval is required, you can only test after the template is committed and approved. The Test button uses the live (approved) version. Templates without the approval workflow can be tested immediately after committing.
  </Accordion>

  <Accordion title="What happens if a variable is missing or has the wrong value at send time?">
    SuprSend skips that notification for the affected user. Other channels in the same template group (email, push, etc.) are still sent if they render successfully.
  </Accordion>

  <Accordion title="Can I use this channel alongside other channels in the same workflow?">
    Yes. Add SMS as one channel in a template group with email, push, WhatsApp, and others. Each channel renders independently; if SMS fails variable rendering, only SMS is skipped for that user.
  </Accordion>

  <Accordion title="How do I pass variable values when triggering the workflow?">
    Include properties in your workflow trigger payload or event properties so they match the Handlebars paths in your template. Use the **Variables panel** in the editor for sample data and auto-complete. See [Adding dynamic content](/docs/templates#the-variables-panel) and your SDK docs for the exact payload shape.
  </Accordion>
</AccordionGroup>

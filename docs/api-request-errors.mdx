This page covers all types of errors that can occur while validating and processing API/SDK requests, including common What does this means and how to fix them. If you encounter an error not listed here, please contact support with the error message and request details.

### What Request Logs are
Request Logs capture every API/SDK request SuprSend receives, including the full request payload and API response. They help you debug request validation issues, missing required fields, authentication failures, invalid resource identifiers, and any error that prevents workflow execution from starting.

### workflow not found / workflow with slug `<slug>` not found
<br/>
**What does this mean:** The workflow does not exist in the workspace, or exists but is not in an active state.

**How to fix it:** 
- Check if the `workflow_slug` is correct. You can check the slug from workflow settings on the workflow details page in the dashboard. Slugs are case-sensitive.
- Check if the workflow is in `draft` state, you need to click on `Commit` to start using it. See [Design Workflow](/docs/design-workflow).

### workflow with slug `<slug>` is disabled
<br/>
**What does this mean:** 
The workflow exists but is in **disabled** state.

**How to fix it:** 
Got the workflow details page and enable it by clicking on the 3 dots menu at the top right corner. See [Design Workflow](/docs/design-workflow).

### [workflow: `<slug>`] tenant_override: jq-expression `<expression>` evaluated to empty value. Value is either missing OR it is not of expected type: [string]
<br/>
**What does this mean:** 
You have event based trigger and in your trigger -> override settings, you have passed a jq expression for tenant override that is returning empty, null or non-string value.

**How to fix it:** 
- Verify the key your expression references exists in `data` and the variable referred in your expression matches exactly with payload. The expression must return a non-empty string.
- If you are new to jq, we recommend testing your expression at [jqplay.org](https://jqplay.org) with sample payload before using it in your trigger.
- If you have mistakenly overriden tenant in your trigger, you can remove it by clicking on trigger node in graph and opening the override settings. See [Trigger Workflow](/docs/trigger-workflow).

###  [workflow:  `<slug>`] recipients_override: jq-expression `<expression>` evaluated to empty value. Value is either missing OR it is not of expected type: [string / list(string)]
<br/>

**What does this mean:** You have event based trigger and in your trigger -> override settings, you have passed a jq expression for recipients override that is returning empty, null, non-string or non-array value.

**How to fix it:** 
- The expression must resolve to a `distinct_id` string or an array`distinct_id`s.
- Verify all key names and function names are correct. Test your expression at [jqplay.org](https://jqplay.org) with the same payload you are sending to SuprSend.
- If you have mistakenly overriden recipients in your trigger, you can remove it by clicking on trigger node in graph and opening the override settings. See [Trigger Workflow](/docs/trigger-workflow).

### no valid recipients found / user [distinct_id: `<distinct_id>`] not found / User not found with distinct_id: `<distinct_id>`

**What does this mean:**
`distinct_id` passed in event trigger or `recipient` passed in API trigger does not exist in the workspace.

**How to fix it:**
- Search with the `distinct_id` on the user page in the dashboard to confirm if the user exists. If not, create the user via API/SDK or dashboard. See [Create User](/docs/users#creating-user-profile-on-suprsend).
- You can also create the user inline in case of API based trigger by passing channel info inline in the recipient object like this - `{"distinct_id": "user-123", "$email": ["["user@example.com"]}`. 
- For event based triggers, users need to be pre-created; but if that user is part of your payload instead of the direct `distinct_id` field, you can use override settings in trigger node to override the recipient with the value from your payload. See [Trigger Workflow](/docs/trigger-workflow).

---

### channel details missing for transient user

**What does this mean:** 
A transient (anonymous) user was specified with `"is_transient": true` in workflow trigger but no channel identities were provided.

**How to fix it:** 
When you pass `is_transient: true` in the workflow trigger, SuprSend doesn't create or look for that user in db. Since, it's used for anonymous sending, you need to pass channel details inline in the recipient object like this - `{"is_transient": true, "$email": ["joe@example.com"]}`. See [Sending to Anonymous Users](/docs/node-trigger-workflow-from-api#sending-notification-to-anonymous-user) for more details.

---

### one of [distinct_id, object_type/id] must be present

**What does this mean:** 
In your API based trigger, recipient object is missing its identifier — neither `distinct_id` nor the `object_type`/`id` pair was included.

**How to fix it:** 
Every recipient object must have either a `distinct_id` (for users) or `is_transient: true` with channel details (for anonymous users),
or both `object_type` and `id` (for objects). See if you're missing it or the key name is wrong. See [Trigger Workflow](/docs/trigger-workflow).

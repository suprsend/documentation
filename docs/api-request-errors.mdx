Errors that occur **before** a workflow runs are recorded in **Request Logs**. Use the [idempotency key](/docs/logging) from the failed request to trace the call. A **`200`** response means the request was **accepted** only — not that a workflow ran. For failures after acceptance, see [Workflow Execution Errors](/docs/error-guides) or Message Logs.

<Note>
  API request errors are **not** retried automatically. For validation or auth errors, correct the request and retry with a new or corrected idempotency key. For transient errors, retry with the **same** idempotency key.
</Note>

## Errors

<span id="error-1"></span>
<span id="error-8"></span>

### `workflow not found` / `workflow with slug '<slug>' not found`

**Cause:** The workflow does not exist in the workspace, or exists but is not in an active state.

**Fix:** Check that the `workflow` field in your payload matches the slug of a live workflow exactly — slugs are case-sensitive and cannot be changed after creation. Open the workflow on the [Workflows page](https://app.suprsend.com/en/production/workflows) and copy the slug from the URL or the workflow header. If it doesn't exist yet, create and commit it. See [Create Workflow](/docs/workflows#create-workflow).

---

<span id="error-34"></span>

### `workflow with slug '<slug>' is disabled`

**Cause:** The workflow exists but is in draft or disabled state.

**Fix:** Open the workflow in the dashboard, finalize your edits, and click **Commit** to make it live. Workflows must be committed before they can receive API triggers. See [Design Workflow](/docs/design-workflow).

---

<span id="error-82"></span>

### `workflow missing`

**Cause:** The `workflow` key is absent from the request body.

**Fix:** Include the `workflow` field with a valid slug string in every trigger request. See [Trigger Workflow](/docs/trigger-workflow).

---

<span id="error-118"></span>

### `workflow version not found`

**Cause:** The specified workflow version does not exist.

**Fix:** Ensure the workflow has at least one committed version — open it in the dashboard and click **Commit** if needed. Retry without specifying a version, or use a valid version identifier.

---

<span id="error-45"></span>

### `[workflow: <slug>] tenant_override: jq-expression '<expression>' evaluated to empty value. Value is either missing OR it is not of expected type: [string]`

**Cause:** The `tenant_override` jq expression returned empty, `null`, or a non-string. The most common cause is a key name mismatch — e.g. the expression uses `.tenantId` but the payload key is `"tenant_id"`.

**Fix:** Verify the key your expression references exists in `data` and the path matches exactly. The expression must return a non-empty string.

### `[workflow: <slug>] recipients_override: jq-expression '<expression>' evaluated to empty value. Value is either missing OR it is not of expected type: [string / list(string)]`

**Cause:** The `recipients_override` expression returned empty, `null`, or a type that is neither a string nor a list of strings. Common causes: a typo in the path, a key missing from `data`, or an incorrect function name.

**Fix:** The expression must resolve to a `distinct_id` string or a list of `distinct_id` strings. Verify all key names and function names are correct. Test your expression at [jqplay.org](https://jqplay.org). See [Trigger Workflow](/docs/trigger-workflow).

<span id="error-106"></span>

### `[workflow: <slug>] actor_override: jq-expression '.<field>' evaluated to empty value. Value is either missing OR it is not of expected type: [string]`

**Cause:** The `actor_override` expression returned empty or a non-string. The path referenced (e.g. `.distinct_id`, `.targetUserId`) does not exist in the `data` object.

**Fix:** Verify the field your expression references is present in `data` and the key name matches exactly.

### `no valid recipients found`

**Cause:** SuprSend could not resolve any recipient — no `recipients` were passed, all referenced `distinct_id` values don't exist in the workspace, or users have no channel information.

**Fix:** There are two approaches. **Option 1 — inline channel info:** Pass channel data directly in the recipient object so SuprSend creates the user automatically: `{"distinct_id": "user-123", "$email": ["user@example.com"]}`. **Option 2 — pre-created user:** Pass just the `distinct_id` if the user already exists with channels on their profile. See [Create User](/docs/users#creating-user-profile-on-suprsend) and [Trigger Workflow](/docs/trigger-workflow).

---

<span id="error-4"></span>
<span id="error-95"></span>

### `user [distinct_id: '<distinct_id>'] not found` / `User not found with distinct_id: <distinct_id>`

**Cause:** The `distinct_id` does not match any user profile in the workspace.

**Fix:** Either [create the user first](/docs/users#creating-user-profile-on-suprsend), or pass channel info inline in the recipient object: `{"distinct_id": "user-123", "$email": ["user@example.com"]}`.

---

<span id="error-5"></span>

### `channel details missing for transient user`

**Cause:** A transient (anonymous) user was specified with `"is_transient": true` but no channel identities were provided.

**Fix:** Include at least one channel identity in the recipient object, e.g. `"$email": ["user@example.com"]`. Transient users are not stored in SuprSend, so all channel info must be supplied at trigger time. See [Anonymous Users](/docs/python-trigger-workflow-from-api#sending-notification-to-anonymous-user).

<span id="error-6"></span>
<span id="error-98"></span>

### `one of [distinct_id, object_type/id] must be present` / `in case recipient is a map, one of [distinct_id, object_type/id] must be present`

**Cause:** A recipient object is missing its identifier — neither `distinct_id` nor the `object_type`/`id` pair was included.

**Fix:** Every recipient object must have either a `distinct_id` (for users) or both `object_type` and `id` (for objects). See [Trigger Workflow](/docs/trigger-workflow).

---

<span id="error-24"></span>

### `error: must pass value for either event or distinct_id/anonymous_id`

**Cause:** The request is missing both an `event` name and a user identifier (`distinct_id` or `anonymous_id`).

**Fix:** Include either `event` (for event-based triggers) or `distinct_id`/`anonymous_id` in your payload.

<span id="error-42"></span>

### `{"distinct_ids":"must contain at least 1 item"}`

**Cause:** The `distinct_ids` array was included but is empty.

**Fix:** Include at least one valid `distinct_id` — an empty array `[]` is not accepted.

---

<span id="error-83"></span>

### `{"recipients":"must contain at least 1 item"}`

**Cause:** The `recipients` array was included but is empty.

**Fix:** Include at least one valid recipient.

---

<span id="error-72"></span>

### `{"distinct_ids":"must contain at maximum 100 items"}`

**Cause:** More than 100 `distinct_ids` were passed in a single request.

**Fix:** Split into batches of at most 100. For large user lists, use [Lists](/docs/lists) and [Broadcast](/docs/broadcast) instead.

---

<span id="error-56"></span>

### `error: must pass value for distinct_id`

**Cause:** `distinct_id` is required but was not provided.

**Fix:** Add `distinct_id` to the recipient object.

---

<span id="error-64"></span>

### `user's distinct_id must be present if it's not transient`

**Cause:** A non-transient user recipient is missing `distinct_id`.

**Fix:** Add `distinct_id`, or use `"is_transient": true` with channel details if sending to an anonymous user.

---

<span id="error-65"></span>

### `actor: value must be either of type string or map`

**Cause:** The `actor` field was passed as an incorrect type — e.g. a number or boolean.

**Fix:** Pass `actor` as a plain `distinct_id` string, or as a map object with user details. See [Trigger Workflow](/docs/trigger-workflow).

---

<span id="error-66"></span>

### `recipients: no valid value passed`

**Cause:** The `recipients` field contains no valid values.

**Fix:** Include at least one valid recipient — a `distinct_id` string or a recipient map object. See [Trigger Workflow](/docs/trigger-workflow).

---

<span id="error-74"></span>

### `invalid value for recipients. each element must be of type string or map`

**Cause:** The `recipients` array contains elements that are neither strings nor map objects.

**Fix:** Each element must be a plain `distinct_id` string or a recipient map. See [Trigger Workflow](/docs/trigger-workflow).

**Fix:** Create the user via API/SDK before referencing them in `from_user_id`, or pass their channel info inline. See [Create User](/docs/users#creating-user-profile-on-suprsend).

<span id="error-15"></span>

### `error while parsing number to E164 format`

**Cause:** The phone number is not in valid E.164 format — missing the `+` prefix, a leading `0` after the country code, spaces, dashes, or no country code at all.

**Fix:** Use `+` followed by the country code and number with no spaces or dashes. Examples: `+15555555555` (US), `+447911123456` (UK), `+919876543210` (India).

---

<span id="error-51"></span>

### `invalid value for channel 'sms': <value>. error: error while parsing number to E164 format`

**Cause:** The SMS number is not in valid E.164 format.

**Fix:** Use `+[country code][number]` with no spaces or dashes, e.g. `+15555555555`.

**Fix:** Use a valid IANA timezone string. Examples: `America/New_York`, `Asia/Kolkata`, `Europe/London`, `Australia/Sydney`. See the full list at [IANA Time Zone Database](https://www.iana.org/time-zones).

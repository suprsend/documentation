description: "Export your notification logs to Amazon S3 for analytics, debugging, and compliance."
---
 
Export your SuprSend notification data to your S3 bucket every 5 minutes in Parquet format. You maintain complete data ownership in your infrastructure for compliance audits, custom analytics dashboards, and detailed debugging workflows.

**Key features:**
- **5-minute sync frequency** - You export logs every 5 minutes, with initial sync taking up to 10 minutes for new or empty buckets
- **Complete data ownership** - All notification logs stored in your infrastructure
- **Encrypted** - TLS 1.2+ in transit, S3 server-side encryption at rest
- **Automatic backfilling** - Historical data automatically synced when you resume sync

---

## Data points

You export three data points individually or together. Choose based on your needs.

![Data Points Parameter on SuprSend Platform](/images/s3v2-types.png)

<Tabs>
<Tab title="Messages">

Delivery status and engagement metrics for each message sent to users.

**Key information:** Status (`triggered`, `delivered`, `seen`, `clicked`, `dismissed`, `failed`), timestamps, vendor information, failure reasons (execution and delivery level).

**Use cases:**
- Monitor delivery rates and identify failures
- Track user engagement (opens, clicks)
- Compare vendor performance
- Maintain compliance audit trail

</Tab>

<Tab title="Workflow Executions">

Step-by-step execution logs showing exactly how each workflow ran. Each workflow step becomes a separate row.

**Key information:** Execution stages, node details, status (`info`, `warning`, `error`), performance timing, execution data (template rendering results, webhook responses, preference computations).

**Use cases:**
- Debug workflow failures
- Identify performance bottlenecks
- Analyze template rendering
- Understand preference computation

</Tab>

<Tab title="Requests">

Complete API request logs for every request sent to SuprSend, including request payloads, responses, and triggered workflows.

**Key information:** API type, payload, response, status (`completed`, `failure`, `partial_failure`), errors, metadata (SDK version, machine details, location).

**Use cases:**
- Track API calls and success rates
- Identify error patterns
- Debug SDK integrations
- Maintain API audit trail

</Tab>
</Tabs>

## Quick start

You complete setup in 4 steps (~15 minutes):
 
### Prerequisites
 
- **AWS account** with admin access (permissions to create S3 buckets and IAM roles/users)
- SuprSend workspace

---
 
### Step 1: Create S3 bucket
 
1. Open [AWS S3 Console](https://s3.console.aws.amazon.com/) → **Create bucket**

   ![](/images/docs/c37cc40-image.png)

2. Configure these settings:
   - **Bucket name**: Unique name (e.g., `supersend-staging-s3-connector`) - **Save this name, you'll need it in Step 2**
   - **Region**: Your preferred region
   - **Bucket type**: General purpose
   - **Object Ownership**: ACLs disabled (recommended)
   - **Block all public access**: Enabled
   - **Bucket versioning**: Disabled
   - **Default encryption**: Server-side encryption with Amazon S3 managed keys (SSE-S3). For compliance-heavy use cases requiring audit trails and key management, use SSE-KMS instead.
   - **Bucket Key**: Enabled

3. Click **Create bucket**

   ![](/images/docs/4a07acb-Screenshot_2023-08-09_at_9.29.19_PM.png)


---
 
### Step 2: Create IAM policy
 
1. Open [IAM Console](https://console.aws.amazon.com/iam/) → **Policies** → **Create Policy** → **JSON** tab
2. Paste this policy (replace `YOUR_BUCKET_NAME` with the exact bucket name from Step 1):
 
```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllObjectActions",
      "Effect": "Allow",
      "Action": [
        "s3:PutObject",     // Upload notification data files
        "s3:ListBucket",    // Check existing files (prevents duplicates)
        "s3:GetObject"      // Read existing files for backfill operations
      ],
      "Resource": [
        "arn:aws:s3:::YOUR_BUCKET_NAME/*",
        "arn:aws:s3:::YOUR_BUCKET_NAME"
      ]
    }
  ]
}
```
 
Replace both instances of `YOUR_BUCKET_NAME` with your exact bucket name from Step 1. Keep the `/*` suffix on the first Resource ARN and ensure there are no extra spaces in the ARN.

3. Name it (e.g., `suprsend_s3_policy`) → **Create Policy**

---
 
### Step 3: Set up authentication
 
**Which should you choose?**

| Auth Scheme | When to Use | Pros | Cons |
|-------------|-------------|------|------|
| **IAM Role** | Enterprises, multi-account setups, production | Most secure, automates trust, no key rotation needed | Requires trust relationship setup |
| **IAM User** | Quick tests, small projects, development | Simple setup, fewer steps | Less secure, needs key rotation every 90 days |
 
<Tabs>
<Tab title="IAM Role">

#### Step 3.1: Create role

1. IAM Console → **Roles** → **Create Role**
2. Select **Trusted Entity Type** as **AWS Account**
3. Select **Another AWS Account**
4. Enter SuprSend account ID: `924219879248`
5. Attach the policy from Step 2
6. Name role (e.g., `suprsend_trust_role`) → **Create role**

#### Step 3.2: Verify trust relationship

1. Generate an External ID using a [UUID Generator](https://www.uuidgenerator.net/) (recommended best practice to prevent "confused deputy" attacks). Save it securely—you'll need the same value in both AWS and SuprSend (case-sensitive).

2. Select the role created above from IAM Console → **Roles** tab

3. In **Trust Relationships** tab, verify this trust policy:
 
```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "AWS": "arn:aws:iam::924219879248:root"
      },
      "Action": "sts:AssumeRole",
      "Condition": {
        "StringEquals": {
          "sts:ExternalId": "YOUR_EXTERNAL_ID_HERE"
        }
      }
    }
  ]
}
```

5. Replace `YOUR_EXTERNAL_ID_HERE` with the External ID you generated above

6. Click **Update policy**

#### Step 3.3: Save credentials

- **Role ARN** (from Summary tab - copy exactly, no extra spaces)
- **External ID** (the value you generated above - case-sensitive)
- **Maximum session duration**

</Tab>

<Tab title="IAM User">

#### Step 3.1: Create user

1. IAM Console → **Users** → **Add users**
2. Enter username (e.g., `s3-bucket-suprsend`)
3. Select **Provide access to AWS services and resources**
4. Attach policy from Step 2
5. Click **Next** → **Create user**

#### Step 3.2: Get credentials

1. Open user → **Security credentials** → **Create access key**
2. Choose **Third party service**
3. **Save immediately:** Access Key ID and Secret Access Key (AWS won't show secret again)

#### Step 3.3: Save credentials

- **Access Key ID** (copy exactly, no extra spaces)
- **Secret Access Key** (copy exactly, no extra spaces)

</Tab>
</Tabs>

1. SuprSend → **Settings** → **Connectors** → **Amazon S3 v2.0** → **Add Connector**

| Form Field | Description |
|------------|-------------|
| **Connector name*** | Descriptive name to identify the connector (for your reference) |
| **Authentication Scheme*** | Select IAM Role or IAM User for authentication |
| **AWS Region*** | AWS region where your S3 bucket is hosted (e.g., `us-east-1`, `ap-south-1`, `eu-west-2`). Must match Step 1 exactly. |
| **Export Bucket*** | Name of the S3 bucket where Parquet files will be exported. Must match Step 1 exactly. |
| **Data Points to export*** | Select which data points to sync: Messages, Workflow Executions, Requests, or all |
| **Role ARN*** | (IAM Role only) The Amazon Resource Name (ARN) of the IAM Role that grants access to the S3 bucket. Copy exactly from AWS (no extra spaces). |
| **External ID*** | (IAM Role only) The unique External ID you configured in the IAM Role's trust policy. Must match exactly (case-sensitive). |
| **Duration Seconds** | (IAM Role only) How long credentials remain valid. Default: 3600 (1 hour), range: 900-43200 |
| **Access Key ID*** | (IAM User only) The access key ID linked to the IAM user. Copy exactly from AWS (no extra spaces). |
| **Secret Access Key*** | (IAM User only) The secret access key linked to the IAM user. Copy exactly from AWS (no extra spaces). |

2. Click **Save** → Toggle **Enable sync**

Initial files appear within 5-10 minutes after enabling sync.

## Troubleshooting
 
<AccordionGroup>
<Accordion title="Files not appearing or connection test failed" defaultOpen={false}>

**Check these in order:**

1. **Wait time:** Initial sync takes 10+ minutes. Wait at least 10 minutes before troubleshooting.

2. **Bucket name mismatch:** Double-check your bucket name—even one wrong character will break the connection.
   - AWS Console: Copy exact bucket name (case-sensitive)
   - SuprSend: Paste exact same name (no extra spaces)

3. **Region mismatch:** AWS region must match exactly between Step 1 and Step 4.

4. **IAM permissions (IAM Role):**
   - Role ARN copied exactly (no extra spaces)
   - External ID matches exactly (case-sensitive)
   - Trust policy has correct Principal (`924219879248`)

5. **IAM permissions (IAM User):**
   - Access Key ID and Secret Access Key are correct
   - Keys haven't been rotated/deleted

6. **Policy configuration:**
   - Policy includes `s3:PutObject`, `s3:ListBucket`, `s3:GetObject`
   - Resource ARN has `/*` suffix on first entry
   - Both Resource ARNs use exact bucket name

7. **SuprSend configuration:**
   - Sync is enabled (toggle is ON)
   - At least one data point is selected
   - Connector status shows "Active"
 
</Accordion>
 
<Accordion title="Missing data" defaultOpen={false}>

**Common causes:**

- **Data point not selected:** Verify the data point is selected in "Data Points to export"
- **New data points:** New selections only export going forward, not retroactively
- **No notifications sent:** Check that notifications were actually sent during that time period
- **Sync was paused:** If sync was paused, data backfills automatically when resumed (may take time)
 
</Accordion>
 
<Accordion title="Backfill behavior" defaultOpen={false}>

**How backfilling works:**

- When you re-enable sync after pausing, all data from the pause period is automatically exported
- You can add or remove data points anytime; new selections only export going forward
- Backfill may take time depending on data volume
 
</Accordion>
</AccordionGroup>

## Best practices

<AccordionGroup>
<Accordion title="Security" defaultOpen={false}>

- **Use IAM Role for production** - More secure than IAM User, no key rotation needed
- **Rotate IAM User access keys every 90 days** - Required by AWS security standards
- **Never share IAM credentials** - Don't commit credentials to code repositories
- **Enable S3 bucket encryption** - Use SSE-S3 or SSE-KMS for compliance
- **Keep bucket private** - Block all public access

</Accordion>

<Accordion title="IAM management" defaultOpen={false}>

- **Assign policies to groups, not individual users** - Simplifies permission management
- **Use External ID for IAM Roles** - Prevents "confused deputy" attacks
- **Plan for key rotation** - Avoid service interruption by rotating IAM User keys proactively

</Accordion>

<Accordion title="Data management" defaultOpen={false}>

- **Start with Messages data point** - Verify setup before adding other data points
- **Monitor sync status** - Check connector status in SuprSend dashboard
- **Understand backfill behavior** - When you re-enable sync, historical data is automatically exported

</Accordion>
</AccordionGroup>

Categories organize your notifications and let users control what they receive. For detailed concepts, see [Notification Categories](/docs/notification-category).

---

## Creating sections and sub-categories

Go to [Developers → Notification categories](https://app.suprsend.com/en/staging/developers/preference-categories) and select a top-level category (System, Transactional, or Promotional).

### Creating a section

Sections are optional and help organize sub-categories on the preference page. To create a section:

1. Click `+Section`
2. Add name and description for the section
3. Click `Save Changes`

You'll see the updated section inside the category and can edit it later by clicking on the Edit button against that section.

![](/images/docs/7c1bb84-small-edit_section.png)

### Adding sub-categories

To add a sub-category:

1. Click `+Sub-Category`
2. Fill in:
   - **Name**: What users see (slug auto-generated)
   - **Section**: Select the section (optional)
   - **Description**: Optional. Description is rendered on the preference UI to help users understand what notifications they'll receive in this category.

![](/images/sub-category-optin.png)

<Warning>
  Don't change the sub-category name after using it in workflows—it updates the slug and breaks existing workflows.
</Warning>

## Configuring default preferences

Select a sub-category and choose a default preference: **On**, **Off**, or **Can't Unsubscribe**. This determines the default behavior for users who haven't set their own preference.

### Preference modes

- **On**: Users receive notifications by default (they can opt out)
- **Off**: Users don't receive notifications by default (they can opt in)
- **Can't Unsubscribe**: Users cannot fully opt out of these notifications (typically for critical system messages). Users can still opt out of specific channels, but at least one mandatory channel must remain active.

For detailed information on each preference mode and recommended defaults by category type, see [Default Preferences](/docs/user-preferences#default-preferences).

## Adding tags

Tags help filter and organize categories on the preference page. They can be added to sections and sub-categories.

1. Select a section or sub-category
2. Add tags (e.g., `billing`, `security`, `marketing`)
3. Section-level tags apply to all sub-categories in that section

<Frame caption="Tags within preference categories">
  ![](/images/preference-tag-changelog.png)
</Frame>

For details on how tags work and how to filter categories, see [Tags](/docs/notification-category#tags).

## Previewing and publishing

Before making your categories live, preview how they'll appear to users, then publish your changes.

<Steps>
  <Step title="Preview">
    Click **Preview** to see how categories will appear to users on the preference page.
  </Step>
  <Step title="Publish">
    Click **`Publish Changes`** to make categories live. Categories are only available in workflows after publishing and will not appear in workflow dropdowns until published.
  </Step>
  <Step title="Clone to production (optional)">
    Use **`Clone`** to copy changes from staging to production workspace.
  </Step>
</Steps>

<Warning>
  **Categories must be published to appear in dropdowns:**
  
  Categories will only appear in workflow dropdowns after they are published. If you don't see your category in the dropdown, make sure you've published your changes.
</Warning>

## Using categories in workflows

To use a category in your workflow, add the sub-category slug to the `notification_category` field.

**To find the slug:** Click the sub-category name in the categories page to copy it.

![](/images/docs/5d5cebe-image.png)

<Tabs>
  <Tab title="Via Dashboard">
    In workflow editor, select any delivery node and choose your sub-category from the **Notification Category** dropdown.
  </Tab>
  <Tab title="Via API">
    Add the sub-category slug to the `notification_category` field in your workflow trigger.
    
    **Example:**
    ```python
    from suprsend import Suprsend, WorkflowTriggerRequest
    
    supr_client = Suprsend("_workspace_key_", "_workspace_secret_")
    
    w1 = WorkflowTriggerRequest(
      body={
        "workflow": "welcome-email",
        "recipients": [{"distinct_id": "user-123"}],
        "notification_category": "newsletter"  # sub-category slug
      }
    )
    
    response = supr_client.workflows.trigger(w1)
    ```
    
    See [Trigger Workflow from API](/docs/trigger-workflow) for complete examples.
  </Tab>
  <Tab title="Via CLI">
    Manage categories in version control using CLI commands.
    
    Use `suprsend category pull` to download categories, edit locally, then `suprsend category push` to upload changes. Use `suprsend category commit` to publish.
    
    See [CLI Category Commands](/reference/cli-category-overview) for complete CLI reference.
  </Tab>
</Tabs>

<Note>
  **Important:** Use the **sub-category slug** (e.g., `marketing`, `newsletter`), not the top-level category name (e.g., `promotional`). Preferences only work when you use sub-categories. If you use a top-level category alone, user preferences will not be respected.
</Note>

## Managing category translations

<Note>
  This feature is only available for Enterprise plan customers.
</Note>

Upload and manage translations for category and section names and descriptions. For details on who needs it and what it does, see [Category translations](/docs/notification-category#category-translations).

### Via Dashboard

Manage translations directly from the Preference categories page:

<Steps>
  <Step title="Click translation icon">
    On the Preference categories page, click the translation icon (stylized 'A' with accent) in the top right corner to open the "Add / View Translation files" modal.
    
    ![](/images/tr-pref.png)
  </Step>
  <Step title="Add translation file">
    Click **"+ Add Translation"** to open the "Add Translation" modal. Select a locale from the dropdown and upload the translated JSON file (e.g., `es.json`, `fr.json`), then click **"Save & Add"**.
    
    ![](/images/tr-add.png)
    
    **Translation file structure:**
    
    Translation files follow this JSON structure with `sections` and `categories` objects. Each section and category is identified by its slug, and you provide translated `name` and `description` values:
    
    ```json
    {
      "sections": {
        "section-slug": {
          "name": "Translated section name",
          "description": "Translated section description" // or null
        }
      },
      "categories": {
        "category-slug": {
          "name": "Translated category name",
          "description": "Translated category description" // or null
        }
      }
    }
    ```
    
    **Example:**
    ```json
    {
      "sections": {
        "billing": {
          "name": "Facturation",
          "description": "Notifications liées à la facturation"
        }
      },
      "categories": {
        "invoice-ready": {
          "name": "Facture prête",
          "description": "Vous recevrez une notification lorsque votre facture est prête"
        },
        "payment-reminder": {
          "name": "Rappel de paiement",
          "description": null
        }
      }
    }
    ```
    
    **Note:** The `en.json` file is automatically generated from your preference settings. Download it to use as a template for translations.
  </Step>
  <Step title="Preview translations">
    Click the **Preview** button (next to the translations button) on the Preference categories page to see how categories appear in different languages. Select a locale from the language dropdown to preview translations.
    
    **Embeddable preference page:**
    
    ![](/images/tr-embed.png)
    
    **Hosted preference page:**
    
    ![](/images/tr-hosted.png)
  </Step>
</Steps>

<Note>
  English (`en.json`) is automatically created and cannot be overridden. It serves as the base language for all translations.
</Note>

## Frequently Asked Questions

<AccordionGroup>
  <Accordion title="When should I create sections?">
    Create sections when:
    - **Organizing by department**: Group related notifications like "Billing", "Sales", "Marketing"
    - **Large number of categories**: If you have 10+ sub-categories, sections help users navigate the preference page
    - **Product lines or features**: Group categories by product or feature area
  </Accordion>

  <Accordion title="When can I skip sections?">
    You can skip sections when:
    - **Small number of categories**: If you have fewer than 5-6 sub-categories, sections aren't necessary
    - **Simple structure**: If all categories are similar (e.g., all promotional), you can skip sections
  </Accordion>

  <Accordion title="What are some example use cases?">
    **Marketing emails**: Use Promotional category → Create "Marketing" section → Add "Newsletter" and "Product Updates" sub-categories
    
    **Critical alerts**: Use System category → Skip section → Add "Security Alerts" sub-category with "Can't Unsubscribe"
    
    **Billing notifications**: Use Transactional category → Create "Billing" section → Add "Invoice Ready" and "Payment Reminder" sub-categories
  </Accordion>

  <Accordion title="How many categories should I create?">
    Don't add too many categories as it can drive users to use channel level opt-outs. Keep your category structure simple and focused on the most important notification types.
  </Accordion>

  <Accordion title="Why aren't user preferences working for my notifications?">
    User preferences only work with **sub-categories** you create, not with top-level categories (System, Transactional, Promotional) alone.
    
    If you're sending notifications using only a top-level category (e.g., `notification_category: "promotional"`), preferences won't apply. You must:
    
    1. Create a sub-category (e.g., "Marketing", "Newsletter") under the top-level category
    2. Use the sub-category slug in your workflows (e.g., `notification_category: "marketing"`)
    
    Once you use a sub-category, user preferences will be respected and unsubscribed users won't receive notifications.
  </Accordion>
</AccordionGroup>

## Overview

Tenants define branding, preferences, and vendor routing for each customer. They enable truly multi-tenant notification rendering: you maintain one workflow and one template, and SuprSend dynamically applies the correct tenant's branding, vendors, and preferences at runtime.

<Note>
  One template works for all tenants. SuprSend replaces `$tenant.*` variables with tenant-specific values based on the `tenant_id` you pass.
</Note>

## Mental Model

Think of tenants as customer profiles. Each tenant represents a customer organization with its own settings stored in SuprSend.

**The Flow:**
1. Configure each customer's branding, preferences, and vendor settings in the [dashboard](https://app.suprsend.com/tenants)
2. Reference `$tenant.*` variables in [templates](https://app.suprsend.com/templates)
3. Pass `tenant_id` when sending notifications
4. SuprSend applies the correct tenant properties at runtime

## When Not to Use Tenants

- **Localization (Translations)** — Use template variables or separate templates
- **User-level overrides** — Tenants represent organizations, not individual users
- **A/B tests** — Use workflow variants or separate templates
- **Event-level styling** — Handle in templates or workflow data
- **Temporary campaigns** — Tenants are for persistent relationships

## Key Concepts

<CardGroup cols="2">
  <Card title="Tenant ID" icon="hashtag" iconType="solid">
    Unique identifier (max 64 chars). **Immutable** once created. **Map to your internal customer ID**. If omitted, default tenant is used.
  </Card>
  <Card title="Tenant Properties" icon="list" iconType="solid">
    Settings for notification appearance and behavior: logo, name, colors, social links, custom JSON, vendor settings, and preferences.
  </Card>
  <Card title="Tenant Variables" icon="code" iconType="solid">
    Template placeholders like `$tenant.tenant_name` replaced with tenant-specific values at runtime. [Learn how to use tenant variables →](/docs/tenant-templates)
  </Card>
  <Card title="Default Tenant" icon="star" iconType="solid">
    Fallback tenant (`tenant_id="default"`) used when no `tenant_id` is provided. Represents organization's base settings.
  </Card>
</CardGroup>

## Runtime Behavior

When a notification is sent with a `tenant_id`:

<Steps>
  <Step title="Fetch properties">
    SuprSend fetches the tenant's properties
  </Step>
  <Step title="Replace variables">
    Replaces `$tenant.*` variables in templates with tenant-specific values
  </Step>
  <Step title="Apply settings">
    Applies tenant-level preferences and vendor routing
  </Step>
  <Step title="Deliver">
    Renders and delivers the notification
  </Step>
</Steps>

<Note>
  **Fallback behavior:** If `tenant_id` is not provided, the default tenant is used. If a custom tenant is missing a property, SuprSend falls back to the default tenant's value for that property.
</Note>

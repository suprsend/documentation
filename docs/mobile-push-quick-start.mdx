Mobile Push is the only backend-trigger channel that **also** requires SDK work in your mobile app — to register the device token with FCM (Android) or APNs (iOS) and attach it to the user's SuprSend profile.

Setup is four steps:

1. **Configure the push vendor** (FCM for Android, APNs for iOS).
2. **Install the SuprSend mobile SDK** in your app.
3. **Call `identify()`** on login so the device token is attached to the user.
4. **Add a Push delivery node** to your workflow with a Push template.

## 3. Identify the user (and reset on logout)

Call `identify()` after the user logs in. The SDK automatically registers the device push token and attaches it to the user's `distinct_id`. **Always call `reset()` on logout** — otherwise multiple users will accumulate on the same device.

<CodeGroup>

```kotlin Kotlin (Android)
ssApi.identify("user_123")
// on logout:
ssApi.reset()
```

```swift Swift (iOS)
SuprSend.shared.identify(identity: "user_123")
// on logout:
SuprSend.shared.reset(unsubscribeNotification: true)
```

```javascript React Native
suprsend.identify("user_123")
// on logout:
suprsend.reset()
```

```dart Flutter
suprsend.identify("user_123");
// on logout:
suprsend.reset();
```

</CodeGroup>

## 4. Push template

Use the [Android Push template editor](/docs/android-push-template) and [iOS Push template editor](/docs/ios-push-template). Each platform has its own payload structure — title, body, image, action buttons, deeplinks. **Publish** before saving the workflow.

## Recipient identity at trigger time

You don't need to pass any channel identity in the trigger — the device token was attached during `identify()`. Just pass `distinct_id`:

```json
"recipients": [
  { "distinct_id": "user_123" }
]
```

## Mobile Push gotchas

- **Forgetting `reset()`** is the #1 source of "wrong user got the push" bugs.
- **Background vs foreground:** iOS requires extra entitlements for background notifications — see [iOS APNs setup](/docs/ios-apns-push).
- **Token rotation:** push tokens can change. The SuprSend SDK handles re-registration automatically as long as `identify()` is called on every app launch after login.
- **Common Android errors:** [Android push errors guide](/docs/androidpush-errors).
- **Permissions:** request notification permissions explicitly on iOS 14+ and Android 13+.

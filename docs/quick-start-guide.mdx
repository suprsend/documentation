This quick start takes you from a new account to a delivered notification, then to production. You can do every step in three ways: ask an AI agent, write code, or use the dashboard. All three work on the same workflows, templates and users, so you can switch at any step.

## Pick how you want to work

| Way | Best for | Start with |
|---|---|---|
| **AI agent** | Claude Code, the Claude app, ChatGPT, Codex, Cursor, VS Code, Gemini CLI and other AI clients that support MCP | Install the SuprSend plugin, or connect the MCP server (below) |
| **Code** | Backends in Node.js, Python, Java or Go, or any language through the REST API | [Integrate SuprSend](/docs/integrate-suprsend) |
| **Dashboard** | Product and marketing teams | [Send a broadcast](/docs/send-a-broadcast) |

To work with an agent, install the [SuprSend plugin](/reference/agent-plugin). One install connects your AI client to the hosted [MCP server](/reference/mcp-overview) (beta) and adds a skill that tells the agent which tools to use. In Claude Code, run:

```text
/plugin marketplace add suprsend/claude-plugin
/plugin install suprsend@suprsend
```

Then run `/mcp`, select **suprsend** and choose **Authenticate** to sign in with your SuprSend account. The agent can't do more than your role allows. Check it worked by asking: "List my SuprSend workspaces." For VS Code, GitHub Copilot CLI, Codex, Kiro and Cursor (Teams and Enterprise plans), see [plugins](/reference/agent-plugin). For other clients, see [how to connect](/reference/mcp-overview#how-to-connect).

The server already gives the agent SuprSend's workflow, template and docs skills, so you don't need to install them. Add the CLI skill only if your agent will run the SuprSend CLI:

```bash
npx skills add https://github.com/suprsend/skills --skill suprsend-cli
```

## What's already set up in Sandbox

Every account starts with a **Sandbox** [workspace](/docs/workspaces) for trying SuprSend:

- Email, SMS, WhatsApp and Inbox providers are already connected.
- A sample workflow and a sample user, created from your registered email, are ready to use.
- Email, SMS and WhatsApp only deliver to [verified channels](https://app.suprsend.com/en/sandbox/developers/verified-channels), up to 5 per channel type. Slack, Teams, Inbox and push have no such limit.
- Sandbox is a trial workspace. It expires 30 days after you sign up.

When you work with an agent, name the `sandbox` workspace in your prompt so the agent works there.

## Step by step

<Steps>
  <Step title="Learn the three building blocks">
    A **template** holds the content, a **user** holds the addresses to send to, and a **workflow** decides what to send and when. Read [core concepts](/docs/core-concepts) for the details.

    **With your agent:** "Using the SuprSend docs, explain how templates, users and workflows fit together."
  </Step>
  <Step title="Send your first notification">
    Build an email template and a workflow, add yourself as a user, trigger the workflow, and check the logs. [Integrate SuprSend](/docs/integrate-suprsend) shows each step in code and in the dashboard.

    **With your agent:** "In my SuprSend sandbox workspace, create an email template and an API-triggered workflow called order-shipped that sends it with an order_id. Publish both, send it to me at my verified email address, and then show me the delivery log."

    Ask for the delivery log every time. Starting a workflow only means SuprSend accepted the request, and the log shows whether the message actually went out.
  </Step>
  <Step title="Add more channels">
    Each channel needs an address on the user, and some need a provider or an SDK first:

    | Channel | What you need | Guide |
    |---|---|---|
    | Email, SMS, WhatsApp | The user's email address or phone number. Sandbox already has providers. | [Email, SMS and WhatsApp](/docs/add-a-channel#email-sms-and-whatsapp) |
    | In-App Inbox, web push | The JavaScript or React SDK in your frontend | [In-app inbox and web push](/docs/add-a-channel#in-app-inbox-and-web-push) |
    | Mobile push | A Firebase or APNs account, and a mobile SDK in your app | [Mobile push](/docs/add-a-channel#mobile-push) |
    | Slack, Microsoft Teams | A bot token, conversation ID or incoming webhook URL | [Slack and Microsoft Teams](/docs/add-a-channel#slack-and-microsoft-teams) |

    **With your agent:** "Add an in-app inbox version to my order-shipped template in sandbox and publish it."
  </Step>
  <Step title="Send a broadcast">
    Send one message to a whole list of users, now or on a schedule. [Send a broadcast](/docs/send-a-broadcast) walks through it in the dashboard, with no code.

    **With your agent:** "In my SuprSend sandbox workspace, create a list with only me in it, then send it a broadcast using the order-shipped template."
  </Step>
  <Step title="Go live">
    Build and test in **Staging**, then move your workflows and templates to **Production** with your own providers. Work through the [go-live checklist](/docs/go-live-checklist) before you launch.

    **With your agent:** "Copy my order-shipped workflow and its template from staging to production as drafts, and tell me what to review before I publish." Copies made through the MCP server land as drafts. To promote everything at once, use [`suprsend sync`](/reference/cli-sync) from the CLI instead. It commits every asset, so the changes go live immediately.
  </Step>
</Steps>

## Try the API without code

Run every API call from the [Postman collection](/docs/developer/postman-collection) before you write any code.

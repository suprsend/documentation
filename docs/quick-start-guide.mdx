This quick start takes you from a new account to a delivered notification, then to production. You can do every step in three ways: with an AI agent, in code, or in the dashboard. All three work on the same workflows, templates and users, so you can switch at any step.

## Before you start

[Create your SuprSend account](https://auth.suprsend.com/sign-up). Every account starts with a **Sandbox** [workspace](/docs/workspaces) for trying SuprSend, and this quick start runs there:

- Email, SMS, WhatsApp and Inbox providers are already connected.
- Push, Slack and Microsoft Teams aren't set up, because they send through your own apps: a Firebase or APNs account for push, and a Slack app or Teams bot for those channels. [Add a channel](/docs/add-a-channel) covers each one.
- A sample workflow and a sample user, created from your registered email, are ready to use.
- Email, SMS and WhatsApp only deliver to [verified channels](https://app.suprsend.com/en/sandbox/developers/verified-channels), up to 5 per channel type. Your registered email is a good first recipient. Slack, Teams, Inbox and push have no such limit.
- Sandbox is a trial workspace. It expires 30 days after you sign up.

Your account also has **Staging** and **Production** workspaces. That's where you build your real notifications, with your own providers (SuprSend calls them [vendors](/docs/vendors)). Add them in Staging to test before you go live.

## Set up how you'll work

<Tabs>
  <Tab title="AI agent">
    Add the hosted [MCP server](/reference/mcp-overview) (beta) at `https://mcp.suprsend.com/mcp` to your AI client. There's nothing to install. In Claude Code, run:

    ```bash
    claude mcp add --transport http suprsend https://mcp.suprsend.com/mcp
    ```

    For ChatGPT, Codex, Cursor, VS Code, Gemini CLI and others, see [how to connect](/reference/mcp-overview#how-to-connect). On first use, your client opens a browser window so you can sign in with your SuprSend account.

    The server already gives the agent SuprSend's workflow, template and docs skills, so you don't need to install [Agent Skills](/reference/agent-skills). Add the CLI skill only if your agent will run the SuprSend CLI:

    ```bash
    npx skills add https://github.com/suprsend/skills --skill suprsend-cli
    ```

    Admins get every tool, and members get read-only tools. Check it worked by asking: "List my SuprSend workspaces."

    Name the `sandbox` workspace in your prompts so the agent works there.
  </Tab>
  <Tab title="Code">
    Copy your **Workspace Key** and **Workspace Secret** from [Developers → API Keys](https://app.suprsend.com/en/sandbox/developers/api-keys) in Sandbox, and store them as environment variables:

    ```bash .env
    SUPRSEND_WORKSPACE_KEY=your_workspace_key
    SUPRSEND_WORKSPACE_SECRET=your_workspace_secret
    ```

    Install the SDK for your backend and create the client once:

    <CodeGroup>
    ```javascript Node.js
    // npm install @suprsend/node-sdk
    const { Suprsend } = require("@suprsend/node-sdk");

    const supr_client = new Suprsend(
      process.env.SUPRSEND_WORKSPACE_KEY,
      process.env.SUPRSEND_WORKSPACE_SECRET
    );
    ```

    ```python Python
    # pip install suprsend-py-sdk
    import os
    from suprsend import Suprsend

    supr_client = Suprsend(
        os.environ["SUPRSEND_WORKSPACE_KEY"],
        os.environ["SUPRSEND_WORKSPACE_SECRET"],
    )
    ```
    </CodeGroup>

    Java, Go and the REST API are covered in [Integrate SuprSend](/docs/integrate-suprsend#get-your-credentials).
  </Tab>
  <Tab title="Dashboard">
    Nothing to set up. Open [app.suprsend.com](https://app.suprsend.com) and switch to **Sandbox** from the top navigation bar. You can also ask the SuprSend Agent in the dashboard to do any step for you: press `Cmd+/` (`Ctrl+/` on Windows) to jump to its chat bar at the bottom of the page.
  </Tab>
</Tabs>

## Step by step

A **[template](/docs/templates)** holds the content, a **[user](/docs/users)** holds the addresses to send to, and a **[workflow](/docs/workflows)** decides what to send and when. A **[list](/docs/lists)** groups users so you can send one message to all of them, or send users down a workflow as they enter or exit the list. See [core concepts](/docs/core-concepts) for more.

<Steps>
  <Step title="Build your first notification">
    Create an email template, `order-shipped`, with one variable, `order_id`, and a workflow, `order-shipped-notification`, that sends it.

    <Tabs>
      <Tab title="AI agent">
        "In my SuprSend sandbox workspace, create an email template called order-shipped with the subject 'Your order has shipped' and the body 'Order #\{\{order_id\}\} is on its way.' Then create an API-triggered workflow called order-shipped-notification that sends it. Publish both."
      </Tab>
      <Tab title="Code">
        Build the template and workflow with an agent or in the dashboard (see the other tabs). Your code triggers the workflow in the next step. To manage templates and workflows as code instead, use the [CLI](/reference/cli-intro).
      </Tab>
      <Tab title="Dashboard">
        1. Go to **Templates → + New Template**, name it `Order Shipped` and pick **Email**.
        2. Set the subject to `Your order has shipped` and the body to `Order #{{order_id}} is on its way.` Then click **Commit**.
        3. Go to **Workflows → + New Workflow**, name it `Order Shipped Notification` and pick the `Transactional` category.
        4. Add a **Single Channel** delivery node, choose **Email** and the `order-shipped` template, and click **Commit**.

        [Integrate SuprSend](/docs/integrate-suprsend#build-the-notification) walks through each screen.
      </Tab>
    </Tabs>
  </Step>
  <Step title="Send it">
    Send the notification to yourself, at an email address that's verified in Sandbox.

    <Tabs>
      <Tab title="AI agent">
        "Trigger order-shipped-notification in my SuprSend sandbox workspace for me at my verified email address, with order_id ORD-1234."
      </Tab>
      <Tab title="Code">
        Identify the user once, then trigger the workflow when the event happens:

        <CodeGroup>
        ```javascript Node.js
        const { WorkflowTriggerRequest } = require("@suprsend/node-sdk");

        const user = supr_client.user.get_instance("user_1a2b3c");
        user.add_email("you@example.com"); // a verified email in Sandbox
        await user.save();

        const w1 = new WorkflowTriggerRequest({
          workflow: "order-shipped-notification",
          recipients: [{ distinct_id: "user_1a2b3c" }],
          data: { order_id: "ORD-1234" },
        });
        const res = await supr_client.workflows.trigger(w1);
        console.log(res);
        ```

        ```python Python
        from suprsend import WorkflowTriggerRequest

        user = supr_client.user.get_instance("user_1a2b3c")
        user.add_email("you@example.com")  # a verified email in Sandbox
        user.save()

        w1 = WorkflowTriggerRequest(body={
            "workflow": "order-shipped-notification",
            "recipients": [{"distinct_id": "user_1a2b3c"}],
            "data": {"order_id": "ORD-1234"},
        })
        res = supr_client.workflows.trigger(w1)
        print(res)
        ```
        </CodeGroup>

        `distinct_id` is your own ID for the user. The keys in `data` fill the template's variables.
      </Tab>
      <Tab title="Dashboard">
        Press `Cmd+/` (`Ctrl+/` on Windows) to jump to the SuprSend Agent chat bar and ask: "Trigger order-shipped-notification for me with order_id ORD-1234." To check the content alone, [send a test](/docs/templates#test) from the template editor.
      </Tab>
    </Tabs>
  </Step>
  <Step title="Check the delivery log">
    Starting a workflow only means SuprSend accepted the request. The log shows whether the message actually went out, and why if it didn't.

    <Tabs>
      <Tab title="AI agent">
        "Show me the delivery log for that run."
      </Tab>
      <Tab title="Code">
        Open [Logs](https://app.suprsend.com/en/sandbox/logs) in the dashboard. Under **Requests**, open the `workflow` request to follow it node by node.
      </Tab>
      <Tab title="Dashboard">
        Open [Logs](https://app.suprsend.com/en/sandbox/logs). Under **Requests**, open the `workflow` request to follow it node by node and see the email delivered.
      </Tab>
    </Tabs>

    Then check your inbox. See [logs](/docs/logging) for what each status means.
  </Step>
  <Step title="Add more channels">
    Each channel needs an address on the user, and some need a provider or an SDK first:

    | Channel | What you need | Guide |
    |---|---|---|
    | Email, SMS, WhatsApp | The user's email address or phone number. Sandbox already has providers. | [Email, SMS and WhatsApp](/docs/add-a-channel#email-sms-and-whatsapp) |
    | In-App Inbox, web push | The JavaScript or React SDK in your frontend | [In-app inbox and web push](/docs/add-a-channel#in-app-inbox-and-web-push) |
    | Mobile push | A Firebase or APNs account, and a mobile SDK in your app | [Mobile push](/docs/add-a-channel#mobile-push) |
    | Slack, Microsoft Teams | A bot token, conversation ID or incoming webhook URL | [Slack and Microsoft Teams](/docs/add-a-channel#slack-and-microsoft-teams) |

    **With your agent:** "Add an in-app inbox version to my order-shipped template in sandbox and publish it."
  </Step>
  <Step title="Send a broadcast to a list">
    Send one message to everyone on a [list](/docs/lists), now or on a schedule. If you don't have a list yet, [create one](/docs/lists#creating-lists) first. [Send a broadcast](/docs/send-a-broadcast) shows each step in the dashboard and with the SuprSend Agent.

    **With your agent:** "In my SuprSend sandbox workspace, create a list with only me in it, then send it a broadcast using the order-shipped template."
  </Step>
  <Step title="Move to Staging, then Production">
    Sandbox is for trying SuprSend. To build for real:

    1. In **Staging**, connect your own [providers](/docs/vendors) and turn on [Test Mode](/docs/developer/test-mode) so only your testers get messages.
    2. Build and test your notifications there.
    3. Sync your workflows and templates to **Production** and connect its providers.
    4. Work through the [go-live checklist](/docs/go-live-checklist) before you launch.

    **With your agent:** "Copy my order-shipped workflow and its template from staging to production as drafts, and tell me what to review before I publish." Copies made through the MCP server land as drafts. To promote everything at once, use [`suprsend sync`](/reference/cli-sync) from the CLI instead. It commits every asset, so the changes go live immediately.
  </Step>
</Steps>

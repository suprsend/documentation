Web Push is a backend-trigger channel that requires JS SDK work in your website to subscribe the browser and attach the resulting token to the user's profile.

Setup is four steps:

1. **Configure the Web Push vendor** in SuprSend (built-in, no third party needed).
2. **Install the SuprSend JS SDK** in your site.
3. **Call `identify()`** on login to attach the browser subscription.
4. **Add a Web Push delivery node** to your workflow.

---

## 1. Configure the vendor

Web Push uses SuprSend's built-in push vendor — no SendGrid/Twilio-style external account needed. Set it up on the [vendor page](https://app.suprsend.com/en/sandbox/vendors). Full guide: [JS Web Push setup](/docs/js-webpush).

---

## 2. Install the SuprSend JS SDK

See [Integrate JavaScript SDK](/docs/integrate-javascript-sdk). After install, register the service worker for push subscriptions per [Web Push integration](/docs/js-webpush).

---

## 3. Identify the user (and reset on logout)

Call `identify()` after login. The SDK subscribes the browser and attaches the resulting endpoint to the user's `distinct_id`. **Always call `reset()` on logout** — otherwise multiple users will accumulate on the same browser.

```javascript
suprsend.identify("user_123");

// on logout:
suprsend.reset();
```

---

## 4. Web Push template

Use the [Web Push template editor](/docs/web-push-template). Title, body, icon, image, action buttons, click URL. **Publish** before saving the workflow.

---

## Recipient identity at trigger time

You don't need to pass any channel identity at trigger time — the browser subscription was attached during `identify()`. Just pass `distinct_id`:

```json
"recipients": [
  { "distinct_id": "user_123" }
]
```

---

## Web Push gotchas

- **Forgetting `reset()`** is the #1 cause of "wrong user got the push" bugs.
- **HTTPS required:** browsers only allow Push on HTTPS origins (localhost is the exception for dev).
- **Permission UX:** request notification permission only after the user has done a meaningful action — browsers penalize sites that prompt on first load.
- **Service worker scope:** the SuprSend SW must be served from your origin root (or a sub-path that covers all pages where you want push to work).
- **Safari quirks:** Safari (and iOS web) requires PWA install + explicit Add to Home Screen for some flows.

Compose structured WhatsApp messages with headers, media, and buttons. Content is personalised with [Handlebars](/docs/handlebars-helpers) variables (`{{variable_name}}`).

<Note>
  You need a WhatsApp vendor connected, and every template must be approved by Meta before it can be sent. [Set up a WhatsApp vendor →](/docs/karix-whatsapp)
</Note>

The WhatsApp editor is a structured form (header, body, footer, buttons) with a live WhatsApp conversation preview on the right.

## Fields

### Template Category

**Required**

Every WhatsApp template must be categorised. See [Choosing the right category](#choosing-the-right-category) for rules and examples.

**What to write here:** Pick the category that matches the message purpose before you write copy — category mismatch is the most common rejection reason.

### Type

**Required**

`Text` or `Media`. Determines the header format.

**What to write here:** Use **Text** for a simple headline above the body. Use **Media** when a header image, video, or document carries the message.

### Header (Text)

**Required when Type is Text**

Bold text shown above the body. Max 60 characters. Emojis are not supported.

**What to write here:** Short, scannable headline — order status, campaign name, or reminder title.

Supports Handlebars variables.

> Example: `Order Shipped` for a utility order update.

### Header (Media)

**Required when Type is Media**

Choose a media format:

- **Image** — `.jpg`, `.png`; recommended 800×418 px, max 5 MB
- **Video** — `.mp4`, max 16 MB, under 30s
- **Document** — `.pdf`, max 100 MB; set a descriptive filename

Provide a public URL. Dynamic URLs with variables like `{{media_url}}` are supported. Fully dynamic media URLs are treated as one variable.

**What to write here:** Use HTTPS URLs that return quickly and match Meta's format requirements. For Marketing flash sales, a hero image plus body copy works well.

> Example image header: public URL for an 800×418 promotional banner.

### Body

**Required**

Main message content. Max 1024 characters. Multi-line. Supports Handlebars variables and [WhatsApp formatting](#formatting-whatsapp-messages) (`*bold*`, `_italic_`, `~strikethrough~`). HTML and Markdown do not work.

**What to write here:** Write like a chat message — short paragraphs, one main idea. Use realistic example values in the Variables panel; Meta reviews them during approval.

> Example: `Hi {{customer_name}}, your order #{{order_id}} has been shipped! Expected delivery: {{delivery_date}}.`

> Example: `Hi {{$recipient.name}}, our biggest sale starts now! Up to 50% off on all products.`

> Example (Authentication): `Your verification code is {{otp_code}}. It expires in 10 minutes.`

> Example: `Reminder: Your appointment with {{provider_name}} is on {{appointment_date}} at {{appointment_time}}.` — pair Quick Reply buttons `Confirm` / `Reschedule` for responses.

### Footer

**Optional**

Short text below the body in lighter font. Max 60 characters. Variables are not supported.

**What to write here:** Brand name, legal line, or opt-out for Marketing templates — e.g. `Reply STOP to opt out` improves approval rates.

> Example: `SuprSend Logistics` on a shipping update. `Reply STOP to opt out` on Marketing.

### Buttons

**Optional** — choose Call to Action, Quick Reply, or None.

**Call to Action** — up to 2 buttons. **Visit Website** opens a URL (Static or Dynamic — one variable at the **end** only, e.g. `https://yourapp.com/product/{{id}}`). **Call Phone Number** starts a call.

**Quick Reply** — up to 3 tap-to-reply buttons. Variables and emojis are not allowed in button text.

**What to write here:** Use verbs on buttons (`Track order`, `Shop now`). For dynamic URLs, only one variable at the end of the URL path/query.

## Personalise with variables

You can add variables in the template to personalise it per recipient. SuprSend replaces variables with actual data at send time.

<Steps>
  <Step title="Add variables in the Variables panel">
    Add sample data in the **Variables panel** (Input Payload section) on the left side of the editor. This powers auto-suggestions and the live preview. For the full guide, see [Adding dynamic content](/docs/templates#the-variables-panel).
  </Step>

  <Step title="Use variables in the template">
    Type `{{` in any field — matching variables appear as auto-suggestions. You can also type variable names manually following [Handlebars syntax](https://handlebarsjs.com/guide/#what-is-handlebars).

    **Examples using this sample data:**

    <CodeGroup>
      ```json json
      {
        "event": {
          "location": {
            "city": "San Francisco",
            "state": "California"
          },
          "order_id": "11200123",
          "first_name": "Joe"
        },
        "tracking_url": "https://yourapp.com/track/11200123"
      }
      ```
    </CodeGroup>

    - **Nested variable:** `{{event.location.city}}` → renders as `San Francisco`
    - **Variable with space in name:** `{{event.[first name]}}`

    The preview section shows sample values rendered in real-time. If a variable isn't rendering, check:
    1. The variable is defined in the Variables panel.
    2. The variable name matches the Handlebars syntax exactly.
  </Step>
</Steps>

<Info>
  When SuprSend submits your template to Meta for approval, named Handlebars variables like `{{order_id}}` are automatically converted to Meta's positional format (`{{1}}`, `{{2}}`). You always write named variables — SuprSend handles the conversion.
</Info>

<Warning>
  If a variable cannot be rendered at send time (missing or mismatched data), SuprSend skips that notification for the affected user. Other channels in the same template group are still sent.
</Warning>

## Preview and test

Preview and test before you rely on this template in production.

The right panel shows a live WhatsApp conversation preview, updated in real time as you fill in fields. Variables render using data from the **Variables panel**.

Click **Test** in the top-right corner to send a real WhatsApp message. This uses the **live version** — commit and get approval before testing. See [Testing a Template](/docs/templates#test) for the full guide.

## Publish

Click **Commit** in the top bar to publish the current draft. The template enters **Approval Pending** state — SuprSend submits it to Meta automatically. You'll be notified when approved or rejected. Once approved, the version goes **Live** and is used for all subsequent workflow triggers.

<Warning>
  WhatsApp templates **cannot be tested until approved**. The Test button uses the live (approved) version. If the template is still pending approval, testing is not available.
</Warning>

## Approval flow

Every WhatsApp template must be approved by Meta before it can be sent. This applies globally, not just in specific regions.

<Steps>
  <Step title="Design and commit">
    Author the template content and click **Commit**. The version enters **Approval Pending** state.
  </Step>
  <Step title="Meta reviews the template">
    SuprSend submits the template to Meta automatically. Most templates are approved within minutes to hours (up to 24 hours in some cases).
  </Step>
  <Step title="Live or revise">
    On approval, the version goes **Live**. On rejection, it returns to **Draft** for revision.
  </Step>
</Steps>

Templates pending approval are visible in the **Approvals** tab on the [template listing page](/docs/templates#managing-templates). For content guidelines to avoid rejection, see [WhatsApp Template Guidelines](/docs/whatsapp-template-guidelines).

## Choosing the right category

WhatsApp enforces different rules and pricing for each category. Choosing the wrong category is the most common reason for rejection.

| Category | Use when | Examples |
|---|---|---|
| **Utility** | Responding to a user action. Transactional or service updates. | Order confirmation, shipping update, payment receipt, appointment reminder |
| **Marketing** | Proactively reaching out with promotions or re-engagement. Requires opt-in. | Flash sale, product recommendation, abandoned cart nudge |
| **Authentication** | Sending OTPs or verification codes. Specialised template structure. | Login OTP, two-factor auth, phone verification |

<Warning>
  WhatsApp may **reclassify** your template if the content doesn't match the selected category. A "Utility" template with promotional language may be reclassified as "Marketing" — with different pricing and opt-in requirements.
</Warning>

## Other ways to build this template

### Design in WhatsApp Business App first, then recreate in SuprSend

The fastest way to know if your template will look good is to mock it in the actual WhatsApp Business App. Create a broadcast to yourself (or a test number in your team), write the message manually with the same structure (header, body, footer, buttons), and send it. You see exactly how it renders on a real device — truncation, font weight, button layout, image crop — before spending time in the SuprSend editor. Once you're happy with the visual, recreate it in SuprSend using the same structure, adding Handlebars variables where static text was.

### Use Loom or screen recording to test conversation flow

WhatsApp template messages start a conversation. Before finalising your template, think through what happens after the user taps your button. Record a quick Loom of the intended flow: user receives message → taps "Track Order" → lands on tracking page → sees status. Share it with your PM or designer as a no-code prototype before you build. This catches interaction design problems (wrong deep link, wrong landing state, missing context) before your template is submitted for approval.

### Build a template library by category before you need it

Meta's approval process takes minutes to hours. If you wait until you need a template to request approval, you'll be blocked. Build a library of approved utility and marketing templates in advance: a generic "order update" template, a generic "appointment reminder", a generic "promotional offer". When a campaign comes up, you pull from the approved library and fill in variables — you don't wait for a new approval cycle. Teams that maintain 10–15 approved templates have near-zero latency for new campaigns.

### Use Meta's Graph API to check template status programmatically

Meta exposes a WhatsApp Business Account API that lets you list all your templates and their approval status, quality scores, and category. Use `GET /v17.0/{whatsapp-business-account-id}/message_templates` with your Business API token. Pipe the response into a Slack alert or a simple dashboard so your team sees immediately when a template is approved, rejected, or paused — without logging into Meta Business Manager. This is especially useful if you manage templates across multiple WhatsApp numbers or business accounts.

### Pre-warm image URLs for media headers

WhatsApp downloads media headers from your URL at delivery time. If your server is slow or the URL returns a 404, the message is delivered without the header image — and you'll never know unless you test. Before using a media URL in a template, verify it: open it in an incognito tab (to rule out auth cookies), check that it returns `Content-Type: image/jpeg` or `image/png` with a 200 status, and confirm the file is under 5 MB. For high-volume sends, host your header images on a CDN (Cloudflare, Fastly, CloudFront) with aggressive cache headers rather than your origin server.

### Map your WhatsApp templates to your CRM segments

WhatsApp Marketing templates require opt-in. Before building templates, export your CRM segments (from HubSpot, Salesforce, Braze, or wherever you manage consent) and understand which users have opted in. Build your SuprSend user profiles with a `whatsapp_opt_in: true` property and set up a workflow filter node that checks this before sending Marketing category messages. This is not just a compliance requirement — it directly impacts your quality score, and low quality scores lead to template pausing.

## Best practices

- **Choose category before writing body** — The most common rejection cause is category mismatch — pick Utility, Marketing, or Authentication first, then write copy that fits.
- **Write the body conversationally** — WhatsApp is a messaging channel, not an email blast — short sentences and natural phrasing approve faster.
- **Use the footer for opt-out on Marketing templates** — Improves approval odds and sets clear expectations for recipients.
- **Use realistic variable examples** — Meta reviews example values in the Variables panel — placeholder text like `aaa` can hurt approval.
- **Never use URL shorteners in the body** — Common rejection trigger — use full branded URLs.
- **Monitor quality score in your vendor portal** — Paused templates stop sending — watch block and report rates in Meta / your vendor dashboard.

## FAQ

<AccordionGroup>
  <Accordion title="Why was my WhatsApp template rejected?">
    Common reasons: content doesn't match the selected category, too many variables without clear context, URL shorteners in the body, or example values that don't make sense. Review the [WhatsApp Template Guidelines](/docs/whatsapp-template-guidelines) and resubmit.
  </Accordion>

  <Accordion title="How long does approval take?">
    Most templates are approved within minutes to hours. In some cases, up to 24 hours. SuprSend handles submission automatically — you'll be notified when the status changes.
  </Accordion>

  <Accordion title="Can I edit a template after Meta has approved it?">
    No. To make changes, edit in draft mode and commit again. The new version goes through approval separately.
  </Accordion>

  <Accordion title="What does it mean when a template is &quot;paused&quot;?">
    WhatsApp may pause templates with low quality scores (high block/report rates). The template stops being sent until the quality score recovers. Fix the content and monitor in your vendor portal (e.g., WhatsApp Business Manager).
  </Accordion>

  <Accordion title="How do dynamic button URLs work?">
    One variable allowed at the **end** only — e.g., `https://yourapp.com/product/{{id}}`. The static prefix must be a valid URL on its own.
  </Accordion>

  <Accordion title="Can I send WhatsApp in multiple languages?">
    Yes — use [template variants](/docs/template-variants). Each language variant goes through approval separately. The default variant acts as the fallback.
  </Accordion>

  <Accordion title="Can I test a template before approval?">
    No. WhatsApp templates can only be tested after they are committed and approved by Meta. The Test button uses the live (approved) version.
  </Accordion>

  <Accordion title="What happens if a variable is missing or has the wrong value at send time?">
    SuprSend skips that notification for the affected user. Other channels in the same template group are still sent.
  </Accordion>

  <Accordion title="Can I use this channel alongside other channels in the same workflow?">
    Yes. Add WhatsApp with email, SMS, push, and other channels in the same template group. Each channel renders independently.
  </Accordion>

  <Accordion title="How do I pass variable values when triggering the workflow?">
    Include properties in your workflow trigger payload or event so they match the Handlebars paths in your template. Use the **Variables panel** for sample data. See [Adding dynamic content](/docs/templates#the-variables-panel) and your SDK documentation.
  </Accordion>
</AccordionGroup>

## Overview

WhatsApp Business messaging is regulated by Meta. Every message sent outside 
a 24-hour customer-initiated window must use a **pre-approved message template**. 
The WhatsApp editor in SuprSend is designed around this structure — helping you 
build compliant templates with the right category, message type, and component 
layout.

The editor renders a live WhatsApp conversation preview on the right as you 
compose.

## Getting Started

To add WhatsApp to a template, open the template in edit mode, click **+** in 
the channel tab row, select **WhatsApp**, and click **Add Channels**.

To send WhatsApp messages, you need a WhatsApp Business vendor configured in 
your workspace. See [WhatsApp Vendor Integration](/docs/whatsapp-vendor-integration).

---

## Template Approval

Every WhatsApp template must be approved by Meta before it can be used to send 
messages. SuprSend handles the submission process for you — once you publish a 
template version, SuprSend submits it to Meta automatically. The version enters 
a `Pending Approval` state, and SuprSend will email you as soon as Meta approves 
or rejects it. Once approved, the version moves to `Live` and can be used in 
workflows.

Follow the [WhatsApp Template Guidelines](/docs/whatsapp-template-guidelines) 
when designing your template to avoid rejection.

## Fields

### Template Category *(required)*

Meta requires every WhatsApp Business template to be categorised. Select the 
category that best describes your message:

| Category | Description |
| --- | --- |
| **Utility** | Transactional messages tied to a user action — order confirmations, receipts, alerts, OTPs. |
| **Marketing** | Promotional or engagement messages — offers, announcements, re-engagement. |
| **Authentication** | One-time passwords and verification codes. |

<Warning>
  Choose the category carefully. Meta reviews templates against their category 
  definition. A mismatched category is a common reason for template rejection. 
  Utility templates generally have higher deliverability and lower cost than 
  Marketing.
</Warning>

### Type *(required)*

The media type of the message — determines what appears in the header:

| Type | Description |
| --- | --- |
| **Text** | Plain text header. |
| **Image** | Image displayed at the top of the message (.jpg, .png). |
| **Video** | Video displayed at the top of the message (.mp4). |
| **Document** | A downloadable document at the top (.pdf). |

### Header

The topmost component of the message, displayed above the body.

- When **Type** is `Text`: a short text line used as a title or context (e.g. 
  `Order Update`). Maximum **60 characters**. Emojis are not supported in 
  the header.
- When **Type** is `Image`, `Video`, or `Document`: accepts a public media URL. 
  Supports Handlebars variables in the URL — e.g. 
  `https://s3.amazonaws.com/{{url_params}}`.
- For **Document** type only: an optional **Document Name** field sets the 
  filename visible to the recipient. Displays as "Untitled" if left blank. 
  Supports variables — e.g. `{{file_name}}`.

Supports Handlebars variables (Text header).

### Body *(required)*

The main content of the message.

- Maximum **1024 characters** — a live character counter is shown below the 
  field.
- Supports Handlebars variables and emoji.
- Supports WhatsApp native text formatting:

| Format | Syntax | 
| --- | --- |
| Bold | `*text*` |
| Italic | `_text_` |
| Strikethrough | `~text~` |
| Monospace | ` ```text``` ` |

<Warning>
  HTML tags and Markdown do not work in WhatsApp messages. Use only the native 
  WhatsApp formatting syntax above.
</Warning>

### Footer

An optional short line displayed below the body in lighter text. Used for 
disclaimers or opt-out instructions — e.g. `Reply STOP to unsubscribe`.

- Maximum **60 characters** — a live character counter is shown.
- Variables and rich formatting are not supported in the footer.

### Button Type

Optional interactive buttons. Select the type:

| Button Type | Description |
| --- | --- |
| **Quick Reply** | Tap-to-reply buttons — the recipient taps and a pre-defined reply is sent back. Use for confirmations or simple choices. |
| **Call to Action** | Buttons that open a URL or dial a phone number. |
| **None** | No buttons. |

---

## Button Configuration

### Quick Reply Buttons

Add up to **3 quick reply buttons**. Each button requires a label — the text 
displayed on the button.

- Variables and emojis are **not** allowed in quick reply button text.

### Call to Action Buttons

Call to Action supports two button subtypes, which can be combined:

#### Visit Website

Redirects the user to a URL on tap.

| Field | Description |
| --- | --- |
| **Button Text** | The label on the button. |
| **URL Type** | `Static` — a fixed URL. `Dynamic` — a URL with a variable appended at the end. |
| **Website URL** | The destination URL. For Dynamic type, one variable is allowed at the end of the URL — e.g. `https://www.suprsend.com/{{page}}`. |

#### Call Phone Number

Initiates a phone call on tap.

| Field | Description |
| --- | --- |
| **Button Text** | The label on the button. |
| **Phone Number** | The phone number to dial, including country code — e.g. `+1234567890`. |

## Live Preview

The right panel shows a live WhatsApp conversation preview — rendered exactly 
as it appears on the recipient's device, with the SuprSend sender identity and 
green chat bubbles. Updates in real time as you fill in fields.

To preview with a specific user's data, search for a user in the **Recipient** 
section of the Variables panel.

## Variables

Header (Text type) and Body support Handlebars syntax. Footer does not support 
variables.

| Source | Example | Description |
| --- | --- | --- |
| Trigger payload | `{{order_id}}` | Data sent when the workflow triggers |
| Recipient profile | `{{$recipient.first_name}}` | Properties from the user's SuprSend profile |
| Tenant | `{{$brand.brand_name}}` | Tenant branding properties |

<Info>
  When SuprSend submits your template to Meta for approval, named Handlebars 
  variables like `{{order_id}}` are automatically converted to Meta's positional 
  format (`{{1}}`, `{{2}}`). You always write named variables — SuprSend handles 
  the conversion.
</Info>

For conditionals and helpers, see [Handlebars Helpers](/docs/handlebars-helpers).

<Warning>
  If a variable is missing at send time, **the WhatsApp notification is not 
  sent** — but other channels in the same workflow (e.g. email, SMS) are 
  unaffected and will still be delivered. Always ensure all variables have 
  values in your trigger payload or user profile before going live.
</Warning>

This section is a step-by-step guide on how to design and publish WhatsApp notification template.

You can design the template with a simple form editor tool. You can add variables with `Handlebarsjs` language. You can see how the message will look in the preview section on the right side.

Once designed, commit the WhatsApp template by clicking **Commit**. This will create a version in **Approval Pending** state.

WhatsApp requires a template approval process, where every template has to be submitted to WhatsApp for approval, where WhatsApp reviews and either Approves or Rejects the message.

SuprSend handles the WhatsApp approval process for you. All you have to do is create a template on SuprSend while following [WhatsApp template guidelines](/docs/whatsapp-template-guidelines), and we'll send an email to you as soon as WhatsApp approves / rejects the template.

Based on the approval status, the published template version's state will move to `Live` or `Rejected`. Once the version goes `Live`, you can use the template to send messages to your users.

## Choosing the right category

WhatsApp enforces different rules and pricing for each category. Choosing the wrong category is the most common reason for template rejection.

| Category | Use when | Examples |
|---|---|---|
| **Utility** | Responding to a user action or request. Transactional, account-related, or service updates. | Order confirmation, shipping update, payment receipt, appointment reminder, account alert |
| **Marketing** | Proactively reaching out with promotions, offers, or re-engagement. Requires opt-in. | Flash sale announcement, product recommendation, abandoned cart nudge, loyalty reward |
| **Authentication** | Sending OTPs or verification codes. Has a specialised template structure with auto-fill support. | Login OTP, two-factor authentication, phone number verification |

<Warning>
  WhatsApp may **reclassify** your template if the content doesn't match the selected category. For example, a "Utility" template that includes promotional language may be reclassified as "Marketing" — which has different pricing and opt-in requirements.
</Warning>

## WhatsApp fields description

| Field | Description |
|---|---|
| **Template Category** | Category of the template as defined by WhatsApp. Choose the category which is most relevant for your message content. e.g. — if you are sending a message informing the user about his/her doctor appointment, select the category as *Appointment Update*. In case you are not able to find the relevant category for your message, select *Alert Update*. |
| **Type** | Type of the message template — `MEDIA/TEXT`. You can select one of the options. |
| **Header** *(Type - TEXT)* | Header of the message shown in bold in your WhatsApp message. Small message text box. You can add up to 60 characters in this field. *Emojis are not supported in header.* |
| **Header → Media Type** *(Type - MEDIA)* | Media type of the header — Document (.pdf) / Image (.jpg, .png) / Video (.mp4). You can select one of the media types based on the type of content that you want to add in the message. |
| **Header → Media File URL** *(Type - MEDIA)* | Add the Public URL of the document that you want to send. You can add dynamic URL by adding variables in the URL link, like `http://s3.amazonaws.com/{{url_params}}` or `{{url_link}}`. |
| **Header → Document Name** *(Type - MEDIA)* | *Valid only for media type — Document (.pdf).* This is the name of the document that will be visible to your user. Will be shown as "Untitled" if not added. You can add variable in media file as `{{file_name}}`. |
| **Body** | Large message text box. Can add multi-line texts. Use Handlebars to add variables. |
| **Footer** | Small message text box. You can add up to 60 characters in this field. *Variables are not supported in footer.* |
| **Buttons** | Button type to be added — Call to Action / Quick Reply. Select **"None"** if you don't require buttons. |
| **Action Buttons** | There are 2 types of action buttons: (1) **Call Phone Number Button** — to initiate a call action. (2) **Visit Website Button** — to redirect users to a website. Only one variable is allowed in "Website URL" at the end of the URL link, like `www.suprsend.com/{{page}}`. |
| **Quick Reply Buttons** | You can add up to 3 quick reply buttons to take user input. *Variables or emojis are not allowed in quick reply buttons.* |

### Call to Action buttons

You can add up to two action buttons:

- **Visit Website** — redirect users to a URL. Set the URL type as **Static** (fixed URL) or **Dynamic** (URL with a variable suffix, e.g. `https://yourapp.com/product/{{id}}`).
- **Call Phone Number** — initiate a phone call with a pre-filled number.

You can add up to 3 quick reply buttons for user input. Variables and emojis are not allowed in quick reply button text.

## Formatting WhatsApp messages

WhatsApp allows you to format text inside your messages. Use below options to format the text. **Other formatting like HTML tags or markdown will not work** for formatting the content.

| Text Format | Method | Description |
|---|---|---|
| **Italic** | `_text_` | To _italicize_ your message, place an underscore on both sides of the text |
| **Bold** | `*text*` | To **bold** your message, place an asterisk on both sides of the text |
| **Strikethrough** | `~text~` | To ~~strikethrough~~ your message, place a tilde on both sides of the text |
| **Monospace** | `` ```text``` `` | To `monospace` your message, place three backticks on both sides of the text |

## Approval flow

WhatsApp templates go through a vendor approval process:

1. Design and commit the template — it enters **Approval Pending** state.
2. SuprSend handles submission to WhatsApp. You'll be notified on approval or rejection.
3. On approval, the version goes **Live**. On rejection, it returns to **Draft** for revision.

Templates pending approval are visible in the **Approvals** tab on the [template listing page](/docs/templates#view-and-filter-your-template-list). For content guidelines, see [WhatsApp Template Guidelines](/docs/whatsapp-template-guidelines).

|---|---|

| Footer | 60 characters |

| Quick Reply buttons | Max 3 |
| Call to Action buttons | Max 2 (1 URL + 1 phone, or 2 URLs) |

## Variants

Create different template variants for multi-lingual messaging, tenant-specific content, or A/B testing. Add conditions based on tenant, recipient language, or any data from your workflow trigger. The first variant in order matching all its conditions is sent at runtime. The **default** variant acts as a fallback when no specific variant conditions are met.

For details on creating, managing, and selecting variants, see [Template Variants](/docs/template-variants).

## Adding dynamic content in the template

There will always be the case where you would require to add dynamic content to a template, so as to personalise it for your users. To achieve this, you can add variables in the template, which will be replaced with the dynamic content at the time of sending the message. You'll need to pass these while triggering the communication from one of our frontend or backend SDKs. Here is a step-by-step guide on how to add dynamic content:

<Steps>
  <Step title="Add variables in the Variables panel">
    Add sample data in the **Variables panel** (Input Payload section) on the left side of the editor. If you have declared the variables and added sample data, they will come as auto-suggestions when you type a curly bracket `{`. This removes the chances of errors like variable mismatch at the time of template rendering. To see how to declare variables before using them in designing templates, refer to [this section in the Templates documentation](/docs/templates#adding-variable-content).
  </Step>

  <Step title="Use variables in the template">
    Once the variables are declared, you can use them while designing the WhatsApp template. We support `handlebarsjs` to add variables in the template. As a general rule, all the variables have to be entered within double curly brackets: `{{variable_name}}`

    Note that you will be able to enter a variable name even when you have not declared it in the Variables panel. To manually enter the variable name, follow the [handlebarsjs guide here](https://handlebarsjs.com/guide/#what-is-handlebars).

    Below is an example of how to enter variables in the template design:

    <CodeGroup>
      ```json json
      {
        "array": [
          {
            "product_name": "Aldo Sling Bag",
            "product_price": "$50"
          },
          {
            "product_name": "Clarles & Keith Women Slipper, Biege, 38UK",
            "product_price": "$39"
          },
          {
            "product_name": "RayBan Sunglasses",
            "product_price": "$120"
          }
        ],
        "event": {
          "location": {
            "city": "San Francisco",
            "state": "California"
          },
          "order_id": "11200123",
          "first_name": "Joe"
        },
        "product_page": "https://www.suprsend.com"
      }
      ```
    </CodeGroup>

    - To enter a nested variable, enter in the format `{{var1.var2.var3}}`. E.g. to refer to city in the example above, you need to enter `{{event.location.city}}`
    - To refer to an array element, enter in format `{{var1.[index].var2}}`. E.g. to refer to `product_name` of the first element of the array `array`, enter `{{array.[0].product_name}}`
    - If you have any space in the variable name, enclose it in square bracket `{{event.[first name]}}`

    You will be able to see the sample values in the Preview section. If you cannot see your variable being rendered with the sample value, check:
    1. Make sure you have entered the variable name and the sample value in the Variables panel.
    2. Make sure you have entered the correct variable name in the template, as per the `handlebarsjs` guideline.
  </Step>
</Steps>

<Warning>
  At the time of sending communication, if there is a variable present in the template whose value is not rendered due to mismatch or missing, SuprSend will simply discard the template and not send that particular notification to your user.

  Please note that the rest of the templates will be sent. E.g. if there is an error in rendering Android Push template, but WhatsApp template is successfully rendered, Android Push notification will not be triggered, but WhatsApp notification will be triggered by SuprSend.
</Warning>

## Common scenarios

<AccordionGroup>
  <Accordion title="Utility — order shipped">
    | Field | Value |
    |---|---|
    | Category | Utility |
    | Header | `Order Shipped` |
    | Body | `Hi {{customer_name}}, your order #{{order_id}} has been shipped! Expected delivery: {{delivery_date}}.` |
    | Footer | `SuprSend Logistics` |
    | Button | Track Order → `https://yourapp.com/track/{{order_id}}` |

    Keep utility messages factual and action-oriented. Always include a tracking or reference link.
  </Accordion>

  <Accordion title="Marketing — flash sale">
    | Field | Value |
    |---|---|
    | Category | Marketing |
    | Header | `Flash Sale` |
    | Body | `Hi {{$recipient.name}}, our biggest sale of the year starts now! Get up to 50% off on all products. Shop before midnight to grab the best deals.` |
    | Footer | `Reply STOP to opt out` |
    | Button | Shop Now → `https://yourapp.com/sale` |

    Always include opt-out language in the footer for marketing templates. This improves approval rates and reduces user reports.
  </Accordion>

  <Accordion title="Authentication — OTP">
    | Field | Value |
    |---|---|
    | Category | Authentication |
    | Body | `Your verification code is {{otp_code}}. It expires in 10 minutes.` |

    Authentication templates have a specialised structure. Keep them minimal — just the code and expiry.
  </Accordion>

  <Accordion title="Utility — appointment reminder with buttons">
    | Field | Value |
    |---|---|
    | Category | Utility |
    | Body | `Reminder: Your appointment with {{provider_name}} is on {{appointment_date}} at {{appointment_time}}.` |
    | Button 1 (Quick Reply) | `Confirm` |
    | Button 2 (Quick Reply) | `Reschedule` |

    Use Quick Reply buttons for simple user responses. Pair with a [wait-until node](/docs/wait-until) in your workflow to handle the reply.
  </Accordion>
</AccordionGroup>

## Best practices

<AccordionGroup>
  <Accordion title="Avoid rejection">
    WhatsApp rejects templates that mix categories (e.g., a "Utility" template with a promotional offer), contain placeholder-heavy text with no clear purpose, or use URL shorteners in the body text.
  </Accordion>
  <Accordion title="Variable placement">
    WhatsApp converts Handlebars variables to positional placeholders (`{{1}}`, `{{2}}`). Ensure each variable in your template has a clear example value in the Variables panel; WhatsApp uses these examples during the approval review.
  </Accordion>
  <Accordion title="Footer for opt-out">
    Marketing templates should include opt-out language in the footer (e.g., "Reply STOP to opt out"). This improves approval rates and reduces user reports.
  </Accordion>
  <Accordion title="Button URLs">
    Dynamic URLs only allow one variable at the **end** of the URL (e.g., `https://yourapp.com/product/{{id}}`). The static prefix must be a valid URL on its own.
  </Accordion>
  <Accordion title="Template pausing">
    WhatsApp may pause templates with low quality scores (high block/report rates). Monitor your template quality in the vendor portal and adjust content if paused.
  </Accordion>
  <Accordion title="Media headers">
    When using a Media header type:

    - **Image** — recommended size: 800x418 px (roughly 2:1). Max 5 MB. Formats: JPEG, PNG.
    - **Video** — max 16 MB. Format: MP4. Keep under 30 seconds for best engagement.
    - **Document** — max 100 MB. Format: PDF. Set a descriptive filename so users know what they're opening.
    - **Dynamic media URLs** — if the URL is fully dynamic (e.g., `{{document_url}}`), the entire URL is treated as one variable. WhatsApp does not support partially dynamic media URLs.
  </Accordion>
</AccordionGroup>

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Why was my WhatsApp template rejected?">
    Common reasons: the content doesn't match the selected category (e.g., promotional language in a Utility template), the template has too many variables without clear context, URL shorteners are used in the body, or the example values provided don't make sense. Review the [WhatsApp Template Guidelines](/docs/whatsapp-template-guidelines) and resubmit.
  </Accordion>

  <Accordion title="How long does WhatsApp approval take?">
    Most templates are approved within a few minutes to a few hours. In some cases, it can take up to 24 hours. SuprSend handles submission automatically — you'll be notified via email when the status changes.
  </Accordion>

  <Accordion title="Can I edit a WhatsApp template after it's approved?">
    No. Approved WhatsApp templates cannot be edited. To make changes, create a new version by editing in draft mode and committing again. The new version goes through the approval process separately.
  </Accordion>

  <Accordion title="What happens if WhatsApp pauses my template?">
    WhatsApp pauses templates with low quality scores (high block/report rates from recipients). The template stops being sent until you fix the content and the quality score recovers. Monitor template quality in your vendor portal (e.g., WhatsApp Business Manager).
  </Accordion>

  <Accordion title="How do dynamic URLs work in buttons?">
    Dynamic URLs allow one variable at the **end** of the URL only. For example, `https://yourapp.com/product/{{id}}` is valid, but `https://{{domain}}/product/123` is not. The static prefix must be a valid URL on its own.
  </Accordion>

  <Accordion title="Can I send WhatsApp messages in multiple languages?">
    Yes — use [template variants](/docs/template-variants). Create a variant for each language with a `$recipient.language` condition. Each language variant goes through the WhatsApp approval process separately. The default variant acts as the fallback.
  </Accordion>

  <Accordion title="What's the difference between Text and Media header types?">
    **Text** headers show bold text at the top of the message (up to 60 characters, no emojis). **Media** headers show an image, video, or document above the message body. You can only choose one type per template — they cannot be combined.
  </Accordion>

  <Accordion title="What happens if a variable is missing at send time?">
    SuprSend discards the WhatsApp notification for that user. Other channels in the same template group (email, push, etc.) are still sent if they render successfully. Always ensure your workflow trigger includes all variables used in the template.
  </Accordion>
</AccordionGroup>

---
title: "Designing Notification Preferences"
description: "Design and implement notification preferences: channel and category controls, digest, threshold, tenant and tag filtering, and mandatory channels."
---

Your users want control over *which* notifications they get and *how*—by email, push, or SMS; by topic (billing, product updates); on a schedule (e.g. a daily digest); or filtered by their team or organization. SuprSend gives you **channel-level** and **category-level** preferences, **digest** and **threshold** (stored on the user profile), **tenant** and **tag** filtering, and **mandatory channels** for must-see messages.

This guide walks you through each scenario: what your users see, what you set up in the SuprSend dashboard, and how to build the preference UI in your app using the linked APIs and docs.

***

## Implementing each scenario

Below, each scenario is broken into: **what your users get**, **what you set up in SuprSend**, and **what you build in your app**. Use the links for detailed APIs and docs.

***

### 1. Channel level

**What your users get:** A global choice per channel (e.g. "All" vs "Only important"—you define the options in SuprSend) and, for each topic, the ability to pick which channel (Email, Push, SMS) receives that type of notification.

<Frame caption="Channel level — global options per channel and per-topic channel">
  ![](/images/channel.png)
</Frame>

**Set up in SuprSend**
- Go to **Developers → [Notification categories](/docs/managing-notification-categories)**.
- Create sections and sub-categories, turn on channels (Email, Push, SMS, etc.) for each, and define the channel-level options (e.g. All, Only important) you want to offer.
- Click **Publish Changes**.

**Build in your app**
1. Load preferences with your SDK or [Get user full preference](/reference/get-user-full-preference). You get global channel settings and per-topic channel data — see [User Preferences](/docs/user-preferences) for the response shape.
2. **Block 1 — Global:** For each channel, show the options you configured. When the user changes one, call [Update user channel preference](/reference/update-user-channel-preference) to save the global preference.
3. **Block 2 — Per topic:** List each topic and its current channel. Let the user change it; on change, call [Update user channel preference](/reference/update-user-channel-preference) for that category.

📘 [User Preferences →](/docs/user-preferences) | [Manage Categories →](/docs/managing-notification-categories) | [Update user channel preference →](/reference/update-user-channel-preference)

### 2. Category level

**What your users get:** The ability to turn each notification type On or Off and to choose which channel (Email, Push, etc.) receives that type.

<Frame caption="Category level — sections, sub-categories, and channel options">
  ![](/images/categories.png)
</Frame>

**Set up in SuprSend**
- Go to **Developers → [Notification categories](/docs/managing-notification-categories)**. Create sections and sub-categories, add channels to each, then click **Publish.**

**Build in your app**
1. Load preferences with your SDK or [Get user full preference](/reference/get-user-full-preference). You get sections and sub-categories with current On/Off and channel data — see [User Preferences](/docs/user-preferences) for the response shape.
2. Show each section as a heading; under it, each topic as a row with an On/Off toggle and channel options (Email, Push, etc.).
3. When the user toggles On/Off, call [Update user category preference](/reference/update-user-category-preference).
4. When the user changes the channel for a topic, call [Update user channel preference](/reference/update-user-channel-preference) for that category.

📘 [User Preferences →](/docs/user-preferences) | [Manage Categories →](/docs/managing-notification-categories) | [Update user category preference →](/reference/update-user-category-preference)

### 3. Digest

**What your users get:** Control over how often they receive a summary (daily, weekly, or off) and at what time—so they get one digest instead of a flood of separate notifications.

**Set up in SuprSend**
- Add a **Digest** node in your workflow. Set the schedule to **Dynamic** and map it to user profile fields (e.g. `digest_frequency`, `digest_time`). See [Digest](/docs/digest) and [Dynamic schedule](/docs/digest#dynamic-schedule-send-digest-based-on-user-preference).

**Build in your app**
1. Add "How often?" (Daily / Weekly / Off) and "What time?" (e.g. 9:00 AM) controls.
2. When the user saves, write those values to the **user profile** (e.g. via your SDK's user update). The Digest node reads them from the profile when it runs. See [Users](/docs/users) for profile fields.

📘 [Digest →](/docs/digest) | [Dynamic schedule →](/docs/digest#dynamic-schedule-send-digest-based-on-user-preference)

### 4. Tenant restriction

**What your users get:** Each brand (tenant) sees only the notification categories you allow for that brand. You decide what’s visible in the dashboard; your app just passes the tenant when loading preferences.

<Frame caption="Tenant categories — control which categories a tenant sees">
  ![](/images/tenant%20categories.png)
</Frame>

**Set up in SuprSend**
- Go to **Tenants → [your tenant] → [Tenant Preference](/docs/tenant-preference)**. Turn off any categories that tenant’s users should not see.

**Build in your app**
1. When loading preferences, pass the **tenant ID** (e.g. from the logged-in user) with your SDK or [Get user full preference](/reference/get-user-full-preference) using `tenantId`. You only get back categories you enabled for that tenant — see [User Preferences](/docs/user-preferences).
2. Show the list and handle toggles/updates the same way as in Category level ([Update user category preference](/reference/update-user-category-preference), [Update user channel preference](/reference/update-user-channel-preference)).

📘 [Tenant Preference →](/docs/tenant-preference) | [User Preferences →](/docs/user-preferences)

### 5. Filter by team

**What your users get:** They pick their team (e.g. Engineering, Sales) and only see notification categories for that team—no clutter from other departments.

<Frame caption="Filter by team — categories shown for the selected team">
  ![](/images/department.png)
</Frame>

**Set up in SuprSend**
- In **Developers → [Notification categories](/docs/managing-notification-categories)**, add **tags** to sections or sub-categories (e.g. `engineering`, `sales`). Click **Publish.** See [Lists](/docs/lists) for tag-based lists.

**Build in your app**
1. Add a team selector (tabs, dropdown, or pills). When the user picks a team, load preferences with that **tag** (e.g. `tags: ['engineering']`) via your SDK or [Get user full preference](/reference/get-user-full-preference). You only get categories for that tag — see [User Preferences](/docs/user-preferences).
2. Show the list with On/Off toggles (and channel options if needed). Use [Update user category preference](/reference/update-user-category-preference) and [Update user channel preference](/reference/update-user-channel-preference) as in Category level.

📘 [User Preferences →](/docs/user-preferences) | [Lists →](/docs/lists)

***

### 6. Filter by team and brand

**What your users get:** Same as Filter by team, but scoped to the current brand. They pick their team and only see categories that are both allowed for that brand and relevant to that team.

<Frame caption="Filter by team and brand — team selector with brand-scoped categories">
  ![](/images/dept.png)
</Frame>

**Set up in SuprSend**
- Add tags to categories (as in Filter by team above). In **Tenants → [tenant] → [Tenant Preference](/docs/tenant-preference)**, turn off categories that tenant’s users shouldn’t see. Click **Publish.**

**Build in your app**
1. When loading preferences, pass both **tenant ID** and **tags** (the selected department) via your SDK or [Get user full preference](/reference/get-user-full-preference). You only get categories allowed for that tenant and tag — see [User Preferences](/docs/user-preferences).
2. Show the list and update the same way as in Category level and Tenant ([Update user category preference](/reference/update-user-category-preference), [Update user channel preference](/reference/update-user-channel-preference)).

📘 [Tenant Preference →](/docs/tenant-preference) | [User Preferences →](/docs/user-preferences)

### 7. Filter by project

**What your users get:** They pick a project (e.g. Project Alpha, Project Beta) and only see and manage preferences for that project’s notification categories—so each project stays focused.

<Frame caption="Filter by project — project selector and its categories">
  ![](/images/project/module.png)
</Frame>

**Set up in SuprSend**
- In **Developers → [Notification categories](/docs/managing-notification-categories)**, tag sections or sub-categories per project (e.g. `project-alpha`). Click **Publish.**

**Build in your app**
1. Add a project selector. When the user picks a project, load preferences with that **tag** (e.g. `tags: ['project-alpha']`) via your SDK or [Get user full preference](/reference/get-user-full-preference). See [User Preferences](/docs/user-preferences).
2. Show the list and update the same way as in Category level ([Update user category preference](/reference/update-user-category-preference), [Update user channel preference](/reference/update-user-channel-preference)).

📘 [User Preferences →](/docs/user-preferences) | [Lists →](/docs/lists)

### 8. Threshold

**What your users get:** They choose at what percentage they want to be alerted (e.g. 80% or 90%). Your workflow reads that value from their profile and sends the alert when the metric hits it—so they’re notified when it matters to them.

<Frame caption="Threshold — user selects alert percentage (e.g. 80%, 90%)">
  ![](/images/threshold.png)
</Frame>

**Set up in SuprSend**
- In your workflow, add a **condition** that reads the user’s chosen percentage from their profile (e.g. `threshold_percent`). See [Workflows](/docs/workflows).

**Build in your app**
1. Add a screen with a short explanation and options (e.g. 80% “Earlier warning”, 90% “Closer to limit”).
2. When the user saves, write the chosen value to the **user profile** (e.g. `threshold_percent`) via your SDK. The workflow condition reads it when evaluating. See [Users](/docs/users) for profile fields.

📘 [Workflows →](/docs/workflows) | [Users →](/docs/users)

Notification preferences give users control over what they hear from your app, on which channel, and how often. Get them right and users stay engaged. Skip them and users will unsubscribe from everything.

This guide covers common preference patterns from real-world usecases, from simple channel opt-in/ out-outs to complex multi-tenant setups. Each section covers what it is, how to set it up in SuprSend, and the code for your application you can refer to.

> **New to preferences in SuprSend?** Read the [User Preferences overview](/docs/user-preferences) first — it covers how categories, channels, and the preference API response are structured. For multi-tenant setups, see [Tenant Preferences](/docs/tenant-preference).

## 1. Channel-level preferences

Users choose All or Only important alerts per channel (Email, Push, SMS, Slack etc) and separately pick which channel gets each type of notification.

<Frame caption="Channel-level preferences">
  <img src="/images/channel.png" alt="Channel-level preferences" width="280" />
</Frame>

**Configure in SuprSend**

1. Go to **Developers → [Notification categories](/docs/managing-notification-categories)**
2. Create sections and sub-categories; turn on the channels you need per category
3. Define the global options to offer (e.g. **All**, **Only important**)
4. Click **Publish Changes**

**Build in your app**

Call `getPreferences()` on page load. The response gives you two things: `channel_preferences` for the global per-channel controls, and `sections[].subcategories[].channels` for the per-topic channel picker. Only show channels you have labels for — filter out anything not in `channelLabels`.

```javascript
const { data, updateOverallChannelPreference, updateChannelPreferenceInCategory } = usePreferences();

// Block 1 — Global: All vs Only important per channel
data?.channel_preferences?.map((ch) => (
  <button onClick={() => updateOverallChannelPreference(ch.channel, 'all')}>All</button>
  <button onClick={() => updateOverallChannelPreference(ch.channel, 'required')}>Only important</button>
));

// Block 2 — Per-category: which channel for each notification type
data?.sections?.flatMap((s) => s.subcategories || []).map((sub) =>
  sub.channels?.map((ch) => (
    <button onClick={() => updateChannelPreferenceInCategory(ch.channel, ch.preference === 'opt_in' ? 'opt_out' : 'opt_in', sub.category)}>
      {ch.channel}
    </button>
  ))
);
```

**When to use:** Your app sends on multiple channels (Email, SMS, Push, Slack) and users want to control what they receive on each channel. Examples: "Email me everything, but send push only for critical alerts", "Turn off SMS entirely." Common in consumer apps, marketplaces, and collaboration tools.

**Related docs:** [User Preferences](/docs/user-preferences) | [Manage Categories](/docs/managing-notification-categories) | [JS SDK preferences](/docs/js-preferences)

## 2. Category-level preferences

Allow users to turn each notification type on or off (e.g. Product updates, Billing) and optionally choose which channel receives each type.

<Frame caption="Category-level preferences">
  <img src="/images/category.png" alt="Category-level preferences" width="280" />
</Frame>

**Configure in SuprSend**

1. Go to **Developers → [Notification categories](/docs/managing-notification-categories)**
2. Create sections (e.g. Product, Billing, Sales) and sub-categories under each
3. Add channels to each sub-category
4. Click **Publish**

**Build in your app**

Call `getPreferences()`. Render sections as headings and sub-categories as rows with a toggle and channel pills.

One thing to handle: each sub-category has an `is_editable` field. If it is `false`, disable the toggle. That category is mandatory and users cannot opt out of it.

```javascript
const { data, updateCategoryPreference, updateChannelPreferenceInCategory } = usePreferences();

data?.sections?.map((section) => (
  <div key={section.name}>
    <h3>{section.name}</h3>
    {section.subcategories?.map((sub) => (
      <div key={sub.category}>
        <span>{sub.name}</span>
        <button onClick={() => updateCategoryPreference(sub.category, sub.preference === 'opt_in' ? 'opt_out' : 'opt_in')}>
          On/Off
        </button>
        {sub.channels?.map((ch) => (
          <button key={ch.channel} onClick={() => updateChannelPreferenceInCategory(ch.channel, ch.preference === 'opt_in' ? 'opt_out' : 'opt_in', sub.category)}>
            {ch.channel}
          </button>
        ))}
      </div>
    ))}
  </div>
));
```

**When to use:** The default for most apps — the standard notification settings page. Examples: e-commerce (order updates on, promotions off), SaaS (product updates via email, billing via email + SMS), social apps (comments on, likes off).

**Related docs:** [User Preferences](/docs/user-preferences) | [Manage Categories](/docs/managing-notification-categories) | [Update category preference](/reference/update-user-category-preference)

## 3. Digest

Instead of individual notifications, users choose a **summary frequency** — Instant, Daily, Weekly, or Off. Your workflow checks the user's chosen frequency and routes to the appropriate digest node (or sends immediately for Instant).

This works through a user profile field `digest_frequency`. The workflow reads it at runtime via a **condition node** on the user property, then branches into the matching digest schedule (daily or weekly) or sends instantly.

<Frame caption="Digest preferences">
  <img src="/images/digest_guide.png" alt="Digest preferences" width="280" />
</Frame>

**Configure in SuprSend**

1. In **Developers → [Notification categories](/docs/managing-notification-categories)**, create sub-categories for each frequency option: **Instant**, **Daily**, **Weekly**, **Off**
2. Store the user's chosen frequency as a user property called `digest_frequency` (e.g. via your app's settings page using the [Users API](/docs/users))
3. In your workflow, add a **condition node** that reads `digest_frequency` from the user's profile
4. Branch the workflow: if `daily` → Digest node with daily schedule; if `weekly` → Digest node with weekly schedule; if `instant` → send immediately (no digest); if `off` → exit. See [Dynamic schedule](/docs/digest#dynamic-schedule-send-digest-based-on-user-preference)

{/* TODO: Add workflow screenshot showing condition on digest_frequency with daily/weekly digest branches */}

**Build in your app**

Show radio buttons or option cards for frequency (Instant / Daily / Weekly / Off) and optionally a time picker for daily/weekly. On save, write to the user profile using `client.user.set`. This is not a preferences API call; it is a profile update.

```javascript
const client = useSuprSendClient();
const [frequency, setFrequency] = useState('daily');
const [time, setTime] = useState('09:00');

const save = async () => {
  await client.user.set({
    digest_frequency: frequency,  // 'instant' | 'daily' | 'weekly' | 'off'
    digest_time: time,            // e.g. '09:00' (relevant for daily/weekly)
  });
};
```

**When to use:** Users get too many individual notifications and want a summary instead. Examples: daily activity digest ("Here's what happened today"), weekly analytics reports, aggregated comment or mention notifications, team standup summaries.

**Related docs:** [Digest](/docs/digest) | [Dynamic schedule](/docs/digest#dynamic-schedule-send-digest-based-on-user-preference) | [Users API](/docs/users)

## 4. Tenant restriction

Each brand or tenant sees only the categories you allow for them. Per tenant, you decide which categories (and channels) are visible to that tenant's users — hidden ones do not appear in `getPreferences()` and are not sent.

- **Admin:** Restrict what this tenant's users see.
- **User:** Same preference UI, list filtered by tenant.

<Frame caption="Tenant-restricted categories">
  <img src="/images/tenant-rest.png" alt="Tenant-restricted categories" width="280" />
</Frame>

**Configure in SuprSend**

1. Go to **Tenants**, select the tenant you want to configure, and open **Tenant Preference**
2. Disable any categories or channels that should be hidden from this tenant's users and excluded from notifications
3. Repeat for each tenant. Only the categories you leave enabled will be visible to that tenant's users and eligible for notifications

Most teams prefer the **API** for this — especially when managing many tenants programmatically:

```bash
curl -X PATCH "https://hub.suprsend.com/v1/tenant/{tenant_id}/category/{category_slug}/" \
  -H "Authorization: Bearer {secret_key}" \
  -H "Content-Type: application/json" \
  -d '{"preference": "opt_out", "visible_to_subscriber": false}'
```

Set `visible_to_subscriber: false` to hide the category entirely from the tenant's users. See [Tenant Preference API](/docs/tenant-preference).

**Build in your app**

Call `getPreferences({ tenantId })`. SuprSend filters the response to only return what is enabled for that tenant. Render the list and use `updateCategoryPreference` as usual — users only see categories you did not restrict.

```javascript
const TENANT_ID = 'default';
const { data, updateCategoryPreference } = usePreferences({ tenantId: TENANT_ID });

data?.sections?.flatMap((s) => s.subcategories || []).map((cat) => (
  <div key={cat.category}>
    <span>{cat.name}</span>
    <button onClick={() => updateCategoryPreference(cat.category, cat.preference === 'opt_in' ? 'opt_out' : 'opt_in')}>On/Off</button>
  </div>
));
```

**When to use:** Multi-tenant SaaS applications where each customer org sees a different set of notifications. Examples: free-plan tenants see only limited features, paid tenants see all the features they are subscribed to.

**Related docs:** [Tenant Preference](/docs/tenant-preference) | [User Preferences](/docs/user-preferences) | [Preference Evaluation](/docs/preference-evaluation)

## 5. Department

Different teams within your organization need different notifications. Instead of showing every category to every user and relying on them to configure, you can automatically filter categories based on the user's department.

This is done using **tags** in SuprSend. A tag is a label you assign to notification categories (e.g. `sales`, `finance`, `engineering`). When fetching preferences, you pass the relevant tag and SuprSend returns only the categories that match. The user never sees a department picker — your app determines their department from their profile or session and passes the corresponding tag automatically.

<Frame caption="A sales user sees only sales-related notification categories">
  <img src="/images/dept-sales.png" alt="Sales department preferences" width="280" />
</Frame>

<Frame caption="A finance user sees only finance-related notification categories">
  <img src="/images/dept-finance.png" alt="Finance department preferences" width="280" />
</Frame>

**Configure in SuprSend**

1. In **Developers → [Notification categories](/docs/managing-notification-categories)**, create categories and add tags to sections or sub-categories (e.g. `engineering`, `sales`, `finance`)
2. Click **Publish**

**Build in your app**

Determine the user's department from their profile or session context, then call `getPreferences({ tags })` with the corresponding tag. No filter UI is needed — the tag is set programmatically and the user only sees categories relevant to them.

```javascript
const TAG = user?.department || 'engineering';
const { data, updateCategoryPreference } = usePreferences({ tags: TAG });
```

**When to use:** Users in different teams should automatically see only relevant notifications — no picker needed. Examples: sales reps see deal and pipeline alerts; engineers see deploy and incident alerts; finance sees billing and expense alerts. The department is determined from the user's profile or session.

**Related docs:** [User Preferences](/docs/user-preferences) | [Manage Categories](/docs/managing-notification-categories)

## 6. Preferences Customization by Tenant Admins

Allow tenant admins to determine which notifications are relevant for their organization. Instead of the SuprSend dashboard admin configuring every tenant, the tenant's own admin can enable or disable categories, set default preferences, and control channel availability for their users — via the Dashboard or the API.

<Frame caption="Tenant admin customizing notification preferences for their organization">
  <img src="/images/tenant_pref.png" alt="Tenant admin preferences" width="280" />
</Frame>

**Configure in SuprSend**

1. Provide tenant admins access to manage their tenant's preferences via the [Tenant Preference API](/docs/tenant-preference).
2. Tenant admins can enable or disable categories, set default On/Off per category, and control which channels are available — all scoped to their tenant
3. **Publish**

**Build in your app**

Build an admin settings page that calls the Tenant Preference API. The admin selects categories to enable or disable and sets defaults. For end users, call `getPreferences({ tenantId })` — they only see what their tenant admin has left enabled.

```javascript
const TENANT_ID = 'acme-corp';
const { data, updateCategoryPreference } = usePreferences({ tenantId: TENANT_ID });
```

**When to use:** Multi-tenant apps where each organization's admin needs the ability to customize which notifications their users receive. Examples: a B2B platform where one customer org enables billing + product + security alerts while another only enables billing alerts, or a white-label product where each customer admin tailors the notification experience for their end users.

**Related docs:** [Tenant Preference](/docs/tenant-preference) | [User Preferences](/docs/user-preferences)

## 7. Categories by module

User sees modules on the UI (e.g. Source alerts, Destination alerts) and can switch between them. Uses tags — `getPreferences({ tags: selectedTag })`.

<Frame caption="Filter by module">
  <img src="/images/Categories%20by%20Module.png" alt="Filter by module" width="280" />
</Frame>

**Configure in SuprSend**

In **Developers → [Notification categories](/docs/managing-notification-categories)**, tag your sections or sub-categories per project. Two ways to structure this:

- **Option A:** Create one section per project (e.g. "Project Alpha", "Project Beta"). For each section, add the tag (e.g. section "Project Alpha" → tag `project-alpha`). Create sub-categories under each section. Publish.
- **Option B:** Create a single section (e.g. "Projects") and add sub-categories under it. Give each sub-category its own tag (e.g. one sub-category tag `project-alpha`, another tag `project-beta`). When you filter by tag, the API returns that section with only the sub-categories that match the tag. Publish.

**Build in your app**

Show a project/module selector (e.g. pills "Project Alpha" / "Project Beta"). Call `getPreferences({ tags: 'project-alpha' })` based on selection. Render sections and sub-categories with toggles and use `updateCategoryPreference`.

```javascript
const [selectedTag, setSelectedTag] = useState('project-alpha');
const { data, updateCategoryPreference } = usePreferences({ tags: selectedTag });

// Project selector: Project Alpha | Project Beta
data?.sections?.map((section) => (
  <div key={section.name}>
    <h3>{section.name}</h3>
    {(section.subcategories || []).map((cat) => (
      <div key={cat.category}>
        <span>{cat.name}</span>
        <button onClick={() => updateCategoryPreference(cat.category, cat.preference === 'opt_in' ? 'opt_out' : 'opt_in')}>On/Off</button>
      </div>
    ))}
  </div>
));
```

**When to use:** Your product has distinct modules or sections, and users manage notifications per module. Examples: a data pipeline tool with "Source alerts" and "Destination alerts" tabs, a project management tool where users switch between "Design" and "Engineering" modules to manage alerts separately.

**Related docs:** [User Preferences](/docs/user-preferences) | [Manage Categories](/docs/managing-notification-categories)

## 8. Threshold

Users pick **at what level they want to be alerted** (e.g. 80% or 90% of a usage limit). The threshold value is stored as a user profile property. Your workflow reads it and fires when the metric crosses that value.

Preferences are still involved — the notification category controls whether the alert is on or off, and which channels it is delivered on. The threshold just determines *when* the workflow triggers. You need both: the threshold (stored as a user property) decides when to fire the alert, and the category preference lets the user toggle the alert on or off and choose which channels receive it.

<Frame caption="Threshold alerts">
  <img src="/images/thresholdimg.png" alt="Threshold alerts" width="280" />
</Frame>

**Configure in SuprSend**

1. In **Developers → [Notification categories](/docs/managing-notification-categories)**, create a category for the threshold alert (e.g. "Usage alerts"). Add the channels you want to support. **Publish**
2. In your workflow, add a **condition node** that reads `threshold_percent` from the user's profile and compares it to the incoming metric (e.g. trigger when `usage >= user.threshold_percent`). See [Workflows](/docs/workflows)

**Build in your app**

The preference page has two parts: the **threshold picker** (stored as a user property) and the **category/channel preferences** (collected via the preference API as usual).

```javascript
const client = useSuprSendClient();
const [threshold, setThreshold] = useState(80);
const { data, updateCategoryPreference, updateChannelPreferenceInCategory } = usePreferences();

// 1. Threshold picker — saved to user profile
const saveThreshold = async () => {
  await client.user.set({
    threshold_percent: threshold,  // 80 or 90
  });
};

// 2. Category on/off and channel selection — via preference API
// Render the "Usage alerts" category with a toggle + channel pills
// (same pattern as Category-level preferences)
```

**When to use:** Users set their own trigger point for usage or quota alerts. Examples: cloud storage ("alert me at 80% full"), API rate limits ("notify at 90% of my quota"), budget tracking ("warn me when spend hits 75%"). The user picks *when* they want to know, not just *whether*.

**Related docs:** [Workflows](/docs/workflows) | [Users API](/docs/users) | [User Preferences](/docs/user-preferences)

## 9. Project level

Each project gets its own full set of preference settings — tags do not work for this pattern. Instead, each project is represented as a **tenant**. Preferences are saved at the tenant level. User selects a project → `getPreferences({ tenantId: projectId })`.

<Frame caption="Project-level preferences — each project = tenant">
  <img src="/images/Project%20Level.png" alt="Project-level preferences" width="280" />
</Frame>

**Configure in SuprSend**

1. Create **one tenant per project** in SuprSend
2. Configure **[Tenant Preference](/docs/tenant-preference)** per tenant (enable/disable categories, set defaults)
3. **Publish**

**Build in your app**

Show a project selector (using tenant IDs). Call `getPreferences({ tenantId: selectedTenantId })`. Render the full preference UI: Channels (All / Important only + per-topic) and Categories (toggles + channel pills). Use `updateCategoryPreference`, `updateChannelPreferenceInCategory`, and `updateOverallChannelPreference`. All updates are saved at the tenant level for that project.

```javascript
const [selectedTenantId, setSelectedTenantId] = useState('project-alpha');
const { data, updateCategoryPreference, updateChannelPreferenceInCategory, updateOverallChannelPreference } = usePreferences({ tenantId: selectedTenantId });

// Full UI: Channels + Categories, same as Channel/Category pages but scoped to selectedTenantId
```

**When to use:** Each project or sub-account needs its own complete set of notification preferences — not just filtered categories, but separate channel settings, category toggles, everything. Examples: an ad platform where a business has multiple ad accounts and wants separate notification settings per account (one account gets email + SMS for budget alerts, another only gets email), or a cloud hosting provider where each sub-account (production, staging, dev) has independent alert preferences.

**Related docs:** [Tenant Preference](/docs/tenant-preference) | [User Preferences](/docs/user-preferences)

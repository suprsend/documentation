You can design template with a simple form editor tool. You can add variables with `Handlebarsjs` language. You can check how the message will look in the preview section on the right side. Once designed, commit the push notification template by clicking **Commit**.

## iOS Push notification fields description

| Field | Description |
|---|---|
| Title | Small message text box. Note that this field will be displayed in single line only, and very long content can get curtailed. Use Handlebars to add variables. |
| Body | Large message text box. Use Handlebars to add variables. |
| Image URL | *Optional.* Public URL for a rich notification image. Formats: PNG, JPG, JPEG. |
| Action URL | *Optional.* URL opened when the user taps the notification. Supports deep links and Handlebars variables. |

## Rich notifications (images)

To display images in iOS push notifications, your app must include a **Notification Service Extension**. Without it, the `Image URL` field is ignored and only the title and body are shown.

<Note>
  The SuprSend iOS SDK includes the service extension setup. If you're using the SDK, rich notifications work out of the box. See [iOS SDK integration](/docs/ios-integration) for setup details.
</Note>

Supported image formats: JPEG, PNG, GIF. Max size: 10 MB. Images are displayed in the expanded notification view (long-press or swipe down on the notification).

## Deep linking

The **Action URL** supports both web URLs and custom URL schemes:

| URL type | Format | Behaviour |
|---|---|---|
| Web URL | `https://yourapp.com/orders/123` | Opens in Safari (or your app if [Universal Links](https://developer.apple.com/ios/universal-links/) are configured) |
| Custom scheme | `yourapp://orders/123` | Opens the matching view controller in your app |
| Universal Link | `https://yourapp.com/orders/123` (with Associated Domains) | Opens your app directly |

## Variants

Create different template variants for multi-lingual messaging, tenant-specific content, or A/B testing. Add conditions based on tenant, recipient language, or any data from your workflow trigger. The first variant in order matching all its conditions is sent at runtime. The **default** variant acts as a fallback when no specific variant conditions are met.

For details on creating, managing, and selecting variants, see [Template Variants](/docs/template-variants).

## Adding dynamic content in iOS Push

There will always be the case where you would require to add dynamic content to a template, so as to personalise it for your users. To achieve this, you can add variables in the template, which will be replaced with the dynamic content at the time of sending the message. You'll need to pass these while triggering the communication from one of our frontend or backend SDKs.

<Steps>
  <Step title="Add variables in the Variables panel">
    Add sample data in the **Variables panel** (Input Payload section) on the left side of the editor. If you have declared the variables, they will come as auto-suggestions when you type a curly bracket `{`. To see how to declare variables, refer to [this section in the Templates documentation](/docs/templates#adding-dynamic-content).
  </Step>

  <Step title="Use variables in the template">
    We support `handlebarsjs` to add variables in the template. As a general rule, all the variables have to be entered within double curly brackets: `{{variable_name}}`

    Note that you will be able to enter a variable name even when you have not declared it in the Variables panel. To manually enter the variable name, follow the [handlebarsjs guide here](https://handlebarsjs.com/guide/#what-is-handlebars).

    Below is an example:

    <CodeGroup>
      ```json json
      {
        "array": [
          {
            "product_name": "Aldo Sling Bag",
            "product_price": "3,950.00"
          },
          {
            "product_name": "Clarles & Keith Women Slipper, Biege, 38UK",
            "product_price": "2,549.00"
          },
          {
            "product_name": "RayBan Sunglasses",
            "product_price": "7,899.00"
          }
        ],
        "event": {
          "location": {
            "city": "San Francisco",
            "state": "California"
          },
          "order_id": "11200123",
          "first_name": "Joe"
        },
        "product_page": "https://www.suprsend.com"
      }
      ```
    </CodeGroup>

    - To enter a nested variable: `{{event.location.city}}`
    - To refer to an array element: `{{array.[0].product_name}}`
    - If you have a space in the variable name: `{{event.[first name]}}`

    You will be able to see the sample values in the Preview section. If a variable isn't rendering, check:
    1. The variable is defined in the Variables panel.
    2. The variable name matches the Handlebars syntax exactly.
  </Step>
</Steps>

<Warning>
  At the time of sending communication, if there is a variable present in the template whose value is not rendered due to mismatch or missing, SuprSend will simply discard the template and not send that particular notification to your user.

  Please note that the rest of the templates will be sent. E.g. if there is an error in rendering iOS Push template, but email template is successfully rendered, iOS Push notification will not be triggered, but email notification will be triggered by SuprSend.
</Warning>

## Best practices

<AccordionGroup>
  <Accordion title="Title length">
    Keep under 30 characters. iOS shows titles on a single line on the lock screen; longer text is truncated.
  </Accordion>
  <Accordion title="Body length">
    4 lines are visible in the expanded view. Front-load the key information in the first line.
  </Accordion>
  <Accordion title="Action URL">
    Always set an action URL. Without it, tapping the notification just opens your app's default screen, which is disorienting.
  </Accordion>
  <Accordion title="Rich images">
    Use high-quality images (min 1024x1024 for best rendering). GIFs play in the expanded view and are effective for product showcases.
  </Accordion>
  <Accordion title="Badge count">
    SuprSend increments the app badge count by 1 for each notification. Clear the badge in your app when the user opens it or reads notifications.
  </Accordion>
</AccordionGroup>

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Why aren't images showing in my iOS push notification?">
    Your app needs a **Notification Service Extension** to display rich media. If you're using the SuprSend iOS SDK, this is included. Otherwise, you need to add the extension manually. See [iOS SDK integration](/docs/ios-integration).
  </Accordion>

  <Accordion title="How do I set up deep links for iOS push?">
    Use Universal Links (`https://` URLs with Associated Domains configured) or custom URL schemes (`yourapp://path`). Universal Links are preferred as they work as both web fallback and in-app navigation.
  </Accordion>

  <Accordion title="What happens if a variable is missing at send time?">
    SuprSend discards the iOS Push notification for that user. Other channels in the same template group are still sent if they render successfully.
  </Accordion>
</AccordionGroup>

User represents a person who will receive notifications. Each user is uniquely identified by an immutable `distinct_id`. All channel information (email, phone, push tokens, etc.) and custom properties are attached to the user profile, enabling multi-channel, personalized communication.

### Syncing Users in SuprSend
Users should be synced to SuprSend to send them notification or to reference their profile information in notification templates. Though if you have a usecase where you can't sync users due to PII restrictions, you can also send notifications to users anonymously.
Users can be synced separately using User management methods in SDK or API or they can be identified inline in workflows.

### User types
There are 2 types of users:
1. Recipient: User who will receive the notification.
2. Actor: Who performs the action. Generally used to sending cross-user notifications where user performing the action is different from recipiet and you want to use actor properties in templates, like `@user1 mentioned you in a comment`.

### Creating Users
Once you sync a user in SuprSend, the user payload returned will look like this:
1. Object Payload

```json
{
  "distinct_id": "user_123",
  "properties": {
    "name": "John Doe",
    "email": ["john@example.com"],
    "$preferred_language": "en",
    "$timezone": "America/New_York"
  },
  "$email": ["john@example.com"],
  "$sms": ["+1234567890"]
}
```
Required fields:
- `distinct_id`: Unique identifier for the user. You cannot change a user's id later, so we recommend you use a non-transient `id` like a primary key rather than a phone number or email address.

2. User Creation methods

```python
user = supr_client.users.get_edit_instance("user_123")
user.set("name", "John Doe")
user.add_email("john@example.com")
supr_client.users.async_edit(user)
```

3. **Availabled User Profile Variables:**
  
    SuprSend identifies it's user's profile with the help of the following variables: 
  
    1. `distinct_id` - A unique identifier for each user.

    2. Channel information attached to user profiles:

      - Email ID: `$email`
      - Phone number: `$sms`, `$whatsapp`
      - Push tokens: `$androidpush`, `$iospush`, `$webpush`, 
      - User Identifiers: `$slack`, `$ms_teams`

4. **Notify the User sequentially with** [Smart Delivery](/docs/smart-delivery)

   Rather than sending your notifications to a user on all channels, you can notify the user sequentially on the best channel (which could be different for each user), till the time user interacts with a notification, and do not send subsequent notification.

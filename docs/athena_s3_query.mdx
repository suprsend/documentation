---

Amazon Athena lets you run SQL directly against the Parquet files that the [Amazon S3 v2.0 connector](/docs/amazon_s3_v2) writes to your bucket—no ETL, no separate warehouse. Athena reads the files in place and bills per TB scanned.

This guide assumes the S3 v2.0 connector is already running and writing Parquet files to your bucket. If not, complete the [S3 v2.0 setup](/docs/amazon_s3_v2#setup) first.

---

## Before you start

To use the DDL in this guide, your S3 v2.0 connector must be configured with:

- **Path layout: `per_type`** — the tables below point at one S3 prefix per data point (`<bucket>/<prefix>/workflow_executions/`, `.../requests/`, `.../messages/`), which only exists with the `per_type` layout. This is the default for new connectors.
- **Compression: anything other than `lz4`** — Athena can't read `lz4`-compressed Parquet reliably (a generic Athena limitation, not specific to SuprSend). `snappy` (the default), `gzip`, `zstd`, `brotli`, and `none` all work.

See [Compression and path layout](/docs/amazon_s3_v2#compression-and-path-layout) to view or change these settings.

You'll also need access to the AWS account that owns the bucket (with permission to use Athena and read the bucket), and an S3 location for Athena to store query results. For Athena fundamentals, see the [AWS Athena getting started guide](https://docs.aws.amazon.com/athena/latest/ug/getting-started.html).

<Warning>
**Existing connectors default to `lz4` + `shared`** and need to be reconfigured before this setup will work. Edit your connector and switch compression to a non-`lz4` codec and path layout to `per_type`.

The switch only affects files written **after** the change—files already in your bucket keep their original codec and folder structure. For the historical data you have two options:

- **Scope queries to the post-switch date range** using the `year`/`month`/`day`/`hour` partition filters. Older partitions will simply be empty in the new `per_type` folders.
- **Rewrite or backfill the historical files** into the new layout/codec. Contact support if you need help with this.
</Warning>

## Step 1: Set the Athena query result location

Open the [Athena console](https://console.aws.amazon.com/athena/) and pick the same region as your S3 bucket. The first time you use Athena in a region, you must set a query result location:

1. Go to **Settings** → **Manage**.
2. Set **Location of query result** to an S3 path you control, for example `s3://YOUR_BUCKET_NAME/athena-results/`.
3. Save.

---

## Step 2: Create a database

In the Athena query editor, run:

```sql
CREATE DATABASE IF NOT EXISTS suprsend_db;
```

`suprsend_db` is used throughout the rest of this guide—rename it if you prefer a different database name (remember to update the table-creation statements below to match).

---

## Step 3: Create external tables

Create one external table per data point you're syncing. Each table points at the corresponding folder in your bucket and uses [Athena partition projection](https://docs.aws.amazon.com/athena/latest/ug/partition-projection.html) on `year/month/day/hour`, so you don't need to run `MSCK REPAIR TABLE` or a Glue Crawler—new hourly partitions are picked up automatically.

Replace `s3://suprsend-parqvault-external-test/staging/` in the `LOCATION` and `storage.location.template` values with the actual S3 path the connector is writing to.

## Step 4: Run a query

Filter on the partition columns (`year`, `month`, `day`, `hour`) wherever possible—Athena will skip files outside the range and you'll pay less per query.

```sql
SELECT *
FROM suprsend_db.ss_workflow_executions
WHERE year = '2026';
```

---

## Notes

- Athena charges per TB scanned. Always filter on `year`/`month`/`day`/`hour` and select only the columns you need.
- Because the connector replaces hourly Parquet files when data changes, Athena automatically sees the latest state on the next query—no manual refresh needed.
- If you change the connector's S3 path or prefix later, drop and recreate the tables with the new `LOCATION` and `storage.location.template`.

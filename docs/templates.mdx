## Finding and Filtering Templates

Go to **Templates** in the left sidebar. The listing shows all templates in the workspace:

<Frame caption="Templates listing page">
  <img src="/images/docs/templates-listing.png" />
</Frame>

| Column | Description |
| --- | --- |
| **Template Information** | Display name and slug. Click the clipboard icon to copy the slug. |
| **Status** | `Live` — at least one committed version exists. `Draft` — no version has been committed yet. |
| **Linked Workflow** | Workflow this template is attached to, if any. |
| **Enabled Channels** | Channels with content in this template. Overflow shown as `+N`. |
| **Last Updated** | Timestamp and author of the most recent change. |
| **Last Used** | Timestamp of the last notification sent using this template. |

**Search** by name, slug, or description using the search bar. **Filters and Sort** lets you narrow by channel, status (`Live` / `Draft`), linked workflow slug, or tags, and sort by last updated or last used.

### Approvals tab

When template approvals are enabled in your workspace, team members without publish permissions can make edits and commit — those commits land in the **Approvals** tab instead of going live immediately. A reviewer approves or rejects the commit from this tab before it takes effect. This gives organisations a gating mechanism for content changes in production.

## Creating a Template

Go to **Templates** and click **+ New Template**.

<Frame caption="Create Template dialog">
  <img src="/images/docs/templates-create-dialog.png" />
</Frame>

**Name** — a human-readable display label. Can be changed at any time.

**Slug** — the unique identifier used in workflows and API calls (e.g. `order-shipped`, `password-reset`). Auto-generated from the name. **Cannot be changed after creation** — choose it carefully.

After creation, you land on the channel picker. Select one or more channels to enable: Android Push, Email, In-App Inbox, iOS Push, MS Teams, Slack, SMS, Web Push, WhatsApp. SuprSend creates a `default` variant for each selected channel and opens the editor.

<Frame caption="Select channels for your template">
  <img src="/images/docs/templates-channel-selection.png" />
</Frame>

You can add or remove channels at any time without touching code.

<Tip>
  If you create a template from inside a Workflow node, it is automatically linked to that workflow and its slug is pre-filled. This is the fastest path when building a new notification from scratch.
</Tip>

## Authoring Content

### Static and dynamic content

Template content can be **static** (fixed for all users) or **dynamic** (personalised per recipient). For dynamic content, SuprSend uses:

- **[Handlebars](/docs/handlebars-helpers)** — Email, SMS, WhatsApp, and In-App Inbox
- **JSONNET** — Slack and MS Teams

The most important habit before writing any `{{variable}}` in your template: define it first in the **Variables panel** (`{}` in the left sidebar). This gives you autocomplete as you type, a consistent live preview, and catches missing data before you commit.

<Frame caption="In-App Inbox editor with live notification preview">
  <img src="/images/docs/templates-inbox-editor.png" />
</Frame>

### The Variables panel

The Variables panel has two sections:

- **Input Payload** — define sample values that simulate your trigger payload. Toggle **Enable batching** to simulate batched event content. The panel computes `$batched_events` and `$batched_events_count` automatically.
- **Recipient** — search for a real user by name or email. Their live profile properties load as the variable context, so you can preview exactly what that specific user would receive.

Variables defined here power the live preview, the Test flow, and `{{` autocomplete across all channels.

<Frame caption="Variables panel showing Input Payload, Recipient, and Tenant sections alongside the Android Push editor">
  <img src="/images/docs/templates-android-push-editor.png" />
</Frame>

### Variable sources and syntax

Variables can come from four sources. Reference them differently depending on which editor language your channel uses.

**1. Trigger payload** — data sent when the [workflow](/docs/workflows) is triggered, including data shaped by workflow nodes (transforms, [batch](/docs/batch)/[digest](/docs/digest), [webhook fetch](/docs/fetch)).

| Data shape | Handlebars | JSONNET |
| --- | --- | --- |
| Top-level key | `{{name}}` | `data.name` |
| Nested key | `{{order.address.city}}` | `data.order.address.city` |
| Array item | `{{items.[0].name}}` | `data.items[0].name` |
| URL / string with special characters | `{{{tracking_url}}}` *(triple braces)* | `data.tracking_url` |
| Key with spaces or capitals | `{{[First Name]}}` | `data['First Name']` |
| Batched event count | `{{$batched_events_count}}` | `data['$batched_events_count']` |

**2. Recipient and user properties** — pulled automatically from the user's profile. No need to pass in your payload.

| Handlebars | JSONNET |
| --- | --- |
| `{{$recipient.name}}` | `data['$recipient'].name` |
| `{{$user.name}}` | `data['$user'].name` |
| `{{$actor.name}}` | `data['$actor'].name` |

**3. Tenant properties** — available when a notification is sent in a [tenant](/docs/tenants) context. Used for white-labelled notifications.

| Handlebars | JSONNET |
| --- | --- |
| `{{$brand.brand_name}}` | `data['$brand'].brand_name` |
| `{{$brand.properties.address}}` | `data['$brand'].properties.address` |

**4. Batching data** — when events are batched in a workflow, SuprSend injects `$batched_events` (array of all batched events) and `$batched_events_count` automatically.

For conditionals, loops, date formatting, and helper functions, see [Handlebars Helpers](/docs/handlebars-helpers).

### Sample payload

<CodeGroup>
```json Input Payload
{
  "name": "Alex",
  "order_id": "ORD-9284",
  "items": [
    {
      "name": "Wireless Headphones",
      "tracking_id": "TRK-14677458796",
      "delivery_date": "12 Apr, 2026"
    }
  ],
  "amount": "$129.00",
  "tracking_url": "https://example.com/track/ORD-9284"
}
```
</CodeGroup>

## Variants

Variants let you send different content to different recipients from the same template — without duplicating the template. For the full guide on creating, managing, and targeting variants, see [Template Variants](/docs/template-variants).

### How variant matching works

At send time, SuprSend evaluates variants from **top to bottom** in the Variants panel. The first variant whose conditions all match is delivered. If no variant matches, the `default` variant is sent.

**Order matters.** Put your most specific variants at the top. The `default` variant should always be last — it is the universal fallback.

### What you can target

| Target | How |
| --- | --- |
| **Language / locale** | Set the `Locale` field. SuprSend matches it against the recipient's `$preferred_language` profile property at send time. See [Multi-lingual Templates](/docs/multi-lingual-template). |
| **Tenant** | Set the `Tenant` field. The variant matches only when the notification is triggered for that specific tenant ID. |
| **Any runtime property** | Add **Conditions** — rules that evaluate recipient properties, tenant properties, or workflow payload data against a value using operators: `=`, `!=`, `<`, `>`, `<=`, `>=`, `contains`, `not contains`. |

Multiple conditions on a variant use **AND** logic — all must match. Click **+ OR** to add a condition group; the variant matches if any group passes (OR logic across groups).

### Creating a variant

In edit mode, click **Add Variant** in the top bar. Fill in:

| Field | Required | Description |
| --- | --- | --- |
| **Channels** | Yes | Which channels this variant covers. One variant can span multiple channels. |
| **ID** | Yes | Unique name within the template (e.g. `hindi`, `enterprise-plan`, `experiment-b`). Alphanumeric, `_`, `-`, `.`. Max 128 chars. |
| **Locale** | Yes | Target locale. Defaults to `en`. |
| **Tenant** | No | Restrict to a specific tenant ID. Max 64 chars. |
| **Conditions** | No | Additional matching rules evaluated at send time. |

The `default` variant is created automatically for every channel and **cannot be deleted**. It is always the fallback.

### Managing variants

Right-click a variant in the Variants panel or use its context menu to **Edit**, **Duplicate**, or **Delete** it. Use **Duplicate** as a starting point when creating a new locale or experiment variant that shares structure with an existing one.

<Warning>
  Deleted variants and their content cannot be recovered.
</Warning>

## Committing

Click **Commit** in the top-right corner of the editor when your content is ready.

Committing does two things at once:
1. Snapshots every channel and variant into a new numbered version.
2. Makes that version live — all notifications triggered from this point forward use the new content.

**There is no separate publish step. Commit is publish.**

The previous live version becomes inactive as soon as a new version is committed. All previous versions are retained in history — they can be referenced but not restored without pushing and committing again.

While in edit mode, the live version is completely unaffected. The yellow banner at the top of the editor makes this explicit: *"You're in edit mode. Changes you make here won't affect published content."*

<Frame caption="Edit mode — the yellow banner confirms changes won't affect live content until you commit">
  <img src="/images/docs/templates-whatsapp-editor.png" />
</Frame>

Clicking **Exit** discards all uncommitted changes in the current session and returns the editor to the last committed state. There is no autosave.

## Version History

Every commit is recorded in the **History** panel (clock icon in the left sidebar).

The left pane lists versions newest-first — version number, author, timestamp. The current live version is marked **Live** in green.

Selecting a version shows a diff table on the right: every **Channel + Variant** combination with an **Action** column marking each as `Updated` or `Unchanged` in that commit. This makes it easy to audit exactly what changed in any given commit.

<Frame caption="Version History showing commit diff across channels and variants">
  <img src="/images/docs/templates-version-history.png" />
</Frame>

Click **Preview** (top-right of the history view) to see the full rendered content of any historical version.

## Testing Before You Commit

The **Test** button (top-right corner, available in both view and edit mode) sends a real notification to a real device so you can verify rendering end-to-end before committing. See [Testing the Template](/docs/testing-the-template) for the full guide.

1. Enter a user's `distinct_id` and click **Search** — SuprSend loads their profile and shows available channels.
2. Select the channels to test.
3. Click **Trigger Test using mock data** — the notification sends immediately using values from your Variables panel.
4. Go to [Logs](/docs/logging) to verify delivery status and inspect rendering details.

<Warning>
  Every `{{variable}}` in the template must have a corresponding value in the Variables panel. A variable with no value causes that channel's notification to fail rendering and not send.
</Warning>

## Managing Templates

### Metadata

Every template has a **Name**, **Slug**, **Description**, and **Tags**. Access via the **ⓘ icon** next to the template name in the breadcrumb, or **⋮ → Edit Metadata**.

- **Description** — document what event triggers this template, who owns it, and any business rules. Useful for teammates and AI agents working with the template later.
- **Tags** — group related templates for filtering on the listing page and via the [Templates API](/reference/get-template-list).
- **Slug** — the only immutable field. Cannot be changed after creation.

### Cloning

Click **Clone Template** (duplicate icon in the top bar) to copy a template — all channels, variants, conditions, and content — as a new Draft with a new name and slug.

Cloning works within the same workspace and **across workspaces**. Use cross-workspace cloning to promote a staging template to production without rebuilding it.

### Importing content

In edit mode, the **Import Content** button (arrow icon in the top bar) imports an HTML file directly into the current channel editor. Use this when your design team delivers email HTML from an external tool.

### Archiving

To retire a template without deleting it, archive it from the **⋮ menu**. Archived templates are hidden from the active listing page but can be viewed by selecting the **Archived** tab. 

<Warning>
  Archived templates cannot be recovered.
</Warning>

### Deleting

**⋮ → Delete** permanently removes the template.

<Warning>
  Deletion is permanent and cannot be undone. Before deleting, check the **Linked Workflow** column on the listing page and remove the template from any active workflows to prevent send failures.
</Warning>

## Using Templates in Workflows

Templates are referenced in [workflows](/docs/workflows) by their **slug**.

- **Created from a workflow node** — slug is pre-filled and the template is automatically linked to that workflow.
- **Linked manually on the dashboard** — enter the slug in the workflow's Template node.
- **API-triggered workflows** — pass the slug in your API payload. See [Trigger Workflow](/docs/trigger-workflow).

To copy the slug: click the clipboard icon on the listing page, or open the ⓘ popup in the editor.

## Managing Templates via CLI

All template operations are available from the command line — useful for CI/CD pipelines, scripted environment promotion, and code-first workflows.

```bash
# List templates
suprsend template list

# Pull a template and all its variants to local files
suprsend template pull --slug order-shipped

# Push local changes as a draft
suprsend template push --slug order-shipped

# Commit the draft to live
suprsend template commit order-shipped

# Push and commit in one step
suprsend template push --slug order-shipped --commit --commit-message "Add Hindi variant"
```

See the full [CLI Template Reference](/reference/cli-template-overview) for all commands and flags.

Templates are the content layer of your notifications. In SuprSend, content for all channels (Email, SMS, WhatsApp, Push, Inbox, Slack, MS Teams) is grouped under a single template for simplified management. A template can contain:

- **Static content** — the core message or design that stays the same for every recipient.
- **Dynamic content** — placeholders (`{{first_name}}`, `{{order_id}}`, etc.) replaced at send time with data from your workflow trigger, user profile, or tenant properties.

<Accordion title="Benefits of using templates with SuprSend">
- **Unified content management** — content for all channels is grouped together, editable in one place.
- **WYSIWYG editors** — drag-and-drop and form-based editors let product managers and designers own content without developer involvement.
- **[Multi-lingual support](/docs/multi-lingual-template)** — add content for multiple languages in a single template; SuprSend delivers the recipient's preferred language automatically.
- **White-labeled tenant notifications** — create [variants](/docs/template-variants) per [tenant](/docs/tenants) to dynamically match each tenant's brand identity.
- **Decoupled from code** — design and iterate on templates in the dashboard without deployments.
- **[Version control](/docs/templates#versioning-and-committing)** — every commit creates a new version; compare engagement across versions and roll back when needed.
- **Add or remove channels without code changes** — enable a new channel in the template editor and publish; notifications start flowing through that channel immediately.
</Accordion>

## Create a template

<Steps>
  <Step title="Open the creation modal">
    On the **Templates** listing page, click **+ New Template**.

    <Frame caption="Create Template modal — slug is set at creation and cannot be changed">
      <img src="/images/docs/templates-create-modal.png" />
    </Frame>

    Enter a **Name** (up to 100 characters) and a **Slug**. The slug is auto-derived from the name and is the stable identifier your workflows use to reference this template. It cannot be changed after creation.
  </Step>
  <Step title="Select channels">
    Choose one or more channels to start authoring content for. You can add more channels at any time by clicking the **+** tab in the editor.

    <Frame caption="Select channels at creation">
      <img src="/images/docs/templates-channel-selection.png" />
    </Frame>
  </Step>
  <Step title="Author content">
    You land in the channel editor for your first selected channel. Each channel has a dedicated editor with channel-specific fields and a live device preview on the right.
  </Step>
</Steps>

For detailed guidance on each channel's editor, see the [Channel Editors](#channel-editors) section below.

## Edit mode and view mode

The template editor has two modes:

- **View mode** — shows the live (published) version. Content is read-only. Switch between channels and variants to review published content.
- **Edit mode** — opens when you click **Edit**. A banner at the top confirms _"You're in edit mode. Changes you make here won't affect published content."_ Content auto-saves as you type. Click **Exit** to return to view mode without committing.

<Info>
  Editing always happens on the draft. Live traffic is never affected until you commit.
</Info>

## Versioning and committing

SuprSend creates a new version every time you commit a template. This ensures a full audit trail and lets you compare which content version drives better engagement.

- **Draft** — created automatically when you enter edit mode. All changes are made here.
- **Live** — the most recently committed version. All workflow runs use the live version.
- **Inactive** — earlier published versions. They remain available in the version history for review and rollback.

To commit, click the **Commit** button in the top-right corner of edit mode. You will be prompted for a version name (auto-generated as V1, V2, V3...) and an optional description.

For WhatsApp and SMS (DLT) templates, committing moves the version into **Approval Pending** state rather than going live immediately. See [Template Variants — Approval flow](/docs/template-variants#approval-flow-whatsapp-and-sms).

## Adding variable content

SuprSend supports dynamic templating so you can personalise notifications using data from your workflow, user profile, and tenant settings.

### Templating languages

Templates use two languages depending on the channel:

| Language | Channels | Syntax style |
|---|---|---|
| **Handlebars** | Email, SMS, WhatsApp, Inbox, Android Push, iOS Push, Web Push | `{{variable_name}}` |
| **JSONNET** | Slack, MS Teams | `data.variable_name` |

Handlebars is a simple mustache-based syntax — wrap variable names in double curly braces. JSONNET is a data templating language that extends JSON with variables, conditionals, and loops. See the [Handlebars syntax](#handlebars-syntax) and [JSONNET syntax](#jsonnet-syntax) sections below for details.

### The Variables panel

The left panel of the template editor displays all available data at a glance, organized into three sections:

| Section | What it shows |
|---|---|
| **Input Payload** | Sample data for variables from your workflow trigger. Editable — add or update values to see them rendered in the preview. Toggle **Enable batching** to preview batched/digest content. |
| **Recipient** | Properties from the selected test user's profile (`$recipient`, `$user`, `$actor`). Select a user by entering a name or distinct ID. |
| **Tenant** | Properties from the selected tenant (`$brand`). Choose a tenant from the dropdown to preview tenant-branded content. |

<Frame caption="Variables panel showing Input Payload, Recipient, and Tenant data">
  <img src="/images/docs/templates-editor-sms-panel.png" />
</Frame>

### Variable sources

There are five sources of dynamic data you can use in templates:

**1. Input Payload**

Data from your workflow trigger payload, or data added/modified during the workflow via data transform, batch/digest, webhook/fetch, etc.

| Data Type | Handlebars | JSONNET |
|---|---|---|
| Parent level keys | `{{var1}}` | `data.var1` |
| URLs or values with special characters (`&`, `?`, `=`) | `{{{url}}}` (triple curly braces to avoid HTML-escaping) | `data.url` |
| Nested keys | `{{var1.var2.var3}}` | `data.var1.var2.var3` |
| Array index | `{{var1.[0].name}}` | `data.var1[0].name` |
| Keys with spaces or special characters | `{{[first_name]}}` | `data['first_name']` |
| Batching data | `{{$batched_events_count}}` | `data['$batched_events_count']` |

**2. Recipient properties** (`$recipient` / `$user`)

User profile properties are automatically available. Reference them using `$recipient` or `$user` (both are aliases for the same data — the user who receives the notification).

| Handlebars | JSONNET | Description |
|---|---|---|
| `{{$recipient.name}}` | `data['$recipient'].name` | Recipient's name |
| `{{$recipient.email}}` | `data['$recipient'].email` | Recipient's email |
| `{{$user.name}}` | `data['$user'].name` | Same as `$recipient` — alternate alias |

**3. Actor properties** (`$actor`)

The actor is the person who **performed the action** that triggered the notification — distinct from the recipient. For example, if "Alice commented on Bob's post", Alice is the `$actor` and Bob is the `$recipient`.

| Handlebars | JSONNET |
|---|---|
| `{{$actor.name}}` | `data['$actor'].name` |
| `{{$actor.email}}` | `data['$actor'].email` |

<Info>
  Actor data is only available when `actor` is passed in the workflow trigger. If no actor is provided, `$actor` variables will be empty.
</Info>

**4. Tenant properties** (`$brand`)

Tenant properties let you dynamically display brand-specific details like logo, colours, and address. Use `$brand` to reference tenant data in templates.

<Warning>
  Use `$brand` — not `$tenant`. The `$tenant` namespace is not exposed to templates yet. All tenant data is accessed via `$brand`.
</Warning>

| Handlebars | JSONNET | Description |
|---|---|---|
| `{{$brand.brand_name}}` | `data['$brand'].brand_name` | Tenant display name |
| `{{$brand.logo}}` | `data['$brand'].logo` | Tenant logo URL |
| `{{$brand.primary_color}}` | `data['$brand'].primary_color` | Primary brand colour |
| `{{$brand.secondary_color}}` | `data['$brand'].secondary_color` | Secondary brand colour |
| `{{$brand.properties.address}}` | `data['$brand'].properties.address` | Custom tenant properties |
| `{{$brand.$hosted_preference_url}}` | `data['$brand']['$hosted_preference_url']` | Hosted preference/unsubscribe page URL |
| `{{$brand.$embedded_preference_url}}` | `data['$brand']['$embedded_preference_url']` | Embedded preference page URL |

The email Design Editor also provides a **Tenant** component with pre-designed header, footer, and button that automatically picks up tenant branding. See [Email Template — Tenant branding](/docs/email-template#tenant-branding) for details.

**5. Custom Helpers** (Handlebars only)

Handlebars supports helpers for advanced logic — conditionals, loops, date formatting, default values, math operations, and more. See the full reference at [Handlebars Helpers](/docs/handlebars-helpers).

### Auto-suggestions

When you type `{{` in any Handlebars text field, an auto-suggestion dropdown appears with variables grouped by source:

- **Input Payload** — variables from your sample data
- **Recipient** — `$recipient` / `$user` properties
- **Actor** — `$actor` properties
- **Tenant** — `$brand` properties
- **Preference** — `$hosted_preference_url`, `$embedded_preference_url`
- **Custom Helper** — available Handlebars helpers

Variables that have **missing data** (no value set in the Variables panel) are **highlighted in red** in the editor, making it easy to spot what needs to be filled in before committing.

<Note>
  Auto-suggestions work in all channel editors **except** the Email Design Editor, where you use **Merge Tags** (the button in the text toolbar) to insert variables. See [Email Template — Merge Tags](/docs/email-template#merge-tags).
</Note>

### Handlebars syntax

Handlebars is used in Email, SMS, WhatsApp, Inbox, and all Push channels. Key patterns:

| Pattern | Syntax | Example |
|---|---|---|
| Simple variable | `{{var}}` | `{{order_id}}` |
| Triple braces (no HTML-escaping) | `{{{var}}}` | `{{{tracking_url}}}` |
| Nested access | `{{a.b.c}}` | `{{event.location.city}}` |
| Array index | `{{arr.[0].key}}` | `{{items.[0].name}}` |
| Keys with spaces | `{{[key name]}}` | `{{[first name]}}` |
| Conditional | `{{#if var}}...{{else}}...{{/if}}` | `{{#if discount}}Save {{discount}}%{{/if}}` |
| Loop | `{{#each arr}}...{{/each}}` | `{{#each items}}{{name}}: {{price}}{{/each}}` |
| Default value | `{{default var "fallback"}}` | `{{default name "Customer"}}` |

For the full list of helpers (date formatting, comparisons, math, string operations), see [Handlebars Helpers](/docs/handlebars-helpers).

### JSONNET syntax

JSONNET is used in Slack and MS Teams. It extends JSON with programming constructs. Variables are accessed via the `data` object.

| Pattern | Syntax | Example |
|---|---|---|
| Simple variable | `data.var` | `data.order_id` |
| Special keys (`$` prefix, spaces) | `data['$var']` | `data['$recipient'].name` |
| Nested access | `data.a.b.c` | `data.event.location.city` |
| Array index | `data.arr[0].key` | `data.items[0].name` |
| String concatenation | `"text " + data.var` | `"Order: " + data.order_id` |
| String interpolation | `"%(key)s" % { key: data.var }` | `"Hello %(name)s" % { name: data.user_name }` |
| Array iteration | `item for item in data.arr` | `task.title for task in data.tasks` |
| Conditional | `if "key" in data then A else B` | `if "discount" in data then data.discount else "N/A"` |

For the full JSONNET language reference, see [jsonnet.org/ref/language.html](https://jsonnet.org/ref/language.html). For channel-specific examples, see [Slack Template](/docs/slack-template) and [MS Teams Template](/docs/ms-teams-template).

## Import content

Use **Import** to seed a variant with content from another source — avoiding the need to design from scratch when templates share most of their content.

Click **Import Variant** in the editor to open the import modal. You can import from:

- **Another variant** in the same template — useful when creating a language or tenant variant that's mostly identical to the default.
- **A different template** — pick any template in your workspace and select a specific channel variant to copy.
- **SuprSend sample library** — start from a pre-designed sample template.

The imported content is **copied** into the current variant. Changes to the source after import do not affect the copy. This is a one-time content transfer, not a live link.

<Tip>
  Common use case: create a new language variant, import content from the default English variant, then translate just the text — keeping the layout and design intact.
</Tip>

## Preview and commit

Most channel editors show a live device preview on the right side. Variables in the template are replaced with values from the **Variables panel** for preview.

**For email**, the preview option is available in the bottom-left action bar.

**For Slack and MS Teams JSONNET templates**, click **Load Preview** to render the parsed JSON template.

Once finalized, click **Commit** in the top-right corner to make the draft version live.

## Test a template

You can send test notifications directly from the template editor to see how the message appears on a real device. Click the **Test** button in the top-right corner.

The test panel has two tabs:

<Tabs>
  <Tab title="Selected Variant">
    Test a single variant on a specific channel.

    1. Select the **Channel** to test (e.g., SMS, Email, In-App Inbox).
    2. Enter a **Recipient** — search by email or distinct ID.
    3. Choose a **Notification Category** and **Tenant ID**.
    4. Click **Send Test**.

    <Frame caption="Test a specific variant">
      <img src="/images/docs/templates-test-variant.png" />
    </Frame>
  </Tab>
  <Tab title="Template Group">
    Test across all enabled channels at once.

    1. Enter a **Recipient** — the panel shows all channels associated with that user.
    2. Select the channels you want to test.
    3. Choose a **Notification Category** and **Tenant ID**.
    4. Click **Send Test**.

    <Frame caption="Test the full template group">
      <img src="/images/docs/templates-test-group.png" />
    </Frame>
  </Tab>
</Tabs>

Variable data from the **Variables panel** is used to render the test notification. Make sure to add values for all variables used in the template, otherwise the notification will fail to render.

<Warning>
  Tests are sent using the **live version**. Commit your changes before testing to see the latest content.
</Warning>

## Template slug

The slug serves as the unique identifier for referencing a template in [workflows created through API](/docs/trigger-workflow#triggering-workflow-via-api). To copy the slug, click the clipboard icon next to the template name.

## Edit template metadata

You can edit the **template name, description, and tags** by clicking the edit icon next to the template name (or the info icon).

- **Description** — we recommend adding your template's trigger logic and other relevant notes. Helpful for later reference.
- **Tags** — used for organising templates on the listing page. Tags can be used to [filter](/docs/templates#view-and-filter-your-template-list) templates and also when [fetching templates through API](/reference/get-template-list).

## Clone template

To avoid designing templates from scratch, you can clone an existing template. Click the **clone** icon in the top-right action bar of the template editor to create a copy.

To **promote a template to another workspace** (e.g., staging to production), click the **share** icon. Select the target workspace, channels, and slug — the live version is cloned by default.

## Adding multiple languages

SuprSend allows you to create notifications in multiple languages in the same template. Once languages are added, SuprSend picks the preferred language from the user's profile and sends the message accordingly. For details, see [Multi-lingual Templates](/docs/multi-lingual-template).

## Archive template

You can archive unused templates from the overflow menu (**⋮**) in the top-right corner. Archived templates cannot be recovered.

## View and filter your template list

All active templates are visible on the **Templates** listing page. The page has two tabs:

**All Templates** — shows every active template with columns for Template Information (name + slug), Status (Live / Draft), Linked Workflow, Enabled Channels, Last Updated, and Last Used.

<Frame caption="Template listing — All Templates tab">
  <img src="/images/docs/templates-listing-all.png" />
</Frame>

**Approvals** — shows templates in WhatsApp or SMS (DLT) approval states. Columns include Variants, Linked Workflow, Last Updated, and Sent for Approval status.

<Frame caption="Template listing — Approvals tab">
  <img src="/images/docs/templates-listing-approvals.png" />
</Frame>

Use **Filters and Sort** to narrow templates by channel, tag, status, or templates edited by you.

---
title: "What is SuprSend?"
description: "SuprSend is API-first notification infrastructure for product and GTM teams: one API for email, SMS, WhatsApp, push, inbox, Slack and Teams."
---

Developers integrate SuprSend once in code. Product and marketing teams then run notifications from the dashboard. Because every workflow, template, user and preference is an API object, AI agents can build and send notifications too.

Your code makes one API call or sends one event. SuprSend works out who gets it, when, on which channel, in which language and with whose branding. It sends the message through your providers and logs what happened to it.

Channels include email, SMS, WhatsApp, mobile and web push, an In-App Inbox, Slack and Microsoft Teams. Your team doesn't have to build or maintain its own notification service.

## What teams send with SuprSend

Every workflow belongs to one of three root [notification categories](/docs/notification-category). Each category has its own queue, so a large marketing send doesn't delay a password reset.

| Category | What it covers |
|---|---|
| **System** | Essential messages users can't opt out of, such as one-time passwords, password resets and incident reports |
| **Transactional** | Responses to something a user did, such as payment confirmations, bookings, account updates and activity on their posts |
| **Promotional** | Messages that promote your product or bring users back, such as newsletters, announcements, product updates and deals |

1. **Trigger.** Your backend calls the [workflow API](/docs/trigger-workflow) or sends an [event](/docs/events). A workflow can also start when a user enters or leaves a [list](/docs/lists). A [broadcast](/docs/broadcast) sends one message to a whole list.
2. **Timing.** A [workflow](/docs/workflows) can [delay](/docs/delay) a message, [batch](/docs/batch) many triggers into one, send a daily or weekly [digest](/docs/digest), or [branch](/docs/branch) on your data.
3. **Preferences.** Users choose which categories and channels they want. SuprSend checks this before the workflow runs and again at each send step. See [preference evaluation](/docs/preference-evaluation).
4. **Channels.** Send on one channel, several at once, or one at a time with [Smart Channel Routing](/docs/smart-delivery), which stops as soon as the user engages.
5. **Content.** One [template](/docs/templates) holds the content for every channel. [Translations](/docs/translations) localize it and [variants](/docs/template-variants) change it per customer, language or condition. Content changes don't need a code deploy.
6. **Providers.** Connect your own [providers](/docs/vendors) (SuprSend calls them vendors) for each channel, such as SendGrid, Amazon SES, Twilio, Firebase Cloud Messaging and APNs. Add a [fallback provider](/docs/vendor-fallback) so messages reroute when one fails. You change providers in SuprSend, not in your code.
7. **Logs.** Follow every request, workflow run and message in [logs](/docs/logging). Track delivery and engagement in [analytics](/docs/analytics), or send status events to your systems with [webhooks](/docs/outbound-webhook).

Triggering a workflow is one request:

<CodeGroup>
```bash cURL
curl --request POST \
  --url https://hub.suprsend.com/trigger/ \
  --header "Authorization: Bearer __YOUR_API_KEY__" \
  --header 'Content-Type: application/json' \
  --data '{
    "workflow": "order-shipped-notification",
    "recipients": [{ "distinct_id": "user_1a2b3c" }],
    "data": { "order_id": "ORD-1234" }
  }'
```

```javascript Node.js
const { Suprsend, WorkflowTriggerRequest } = require("@suprsend/node-sdk");
const supr_client = new Suprsend("_workspace_key_", "_workspace_secret_");

const w1 = new WorkflowTriggerRequest({
  workflow: "order-shipped-notification",
  recipients: [{ distinct_id: "user_1a2b3c" }],
  data: { order_id: "ORD-1234" },
});

supr_client.workflows.trigger(w1).then((res) => console.log(res));
```

```python Python
from suprsend import Suprsend, WorkflowTriggerRequest

supr_client = Suprsend("_workspace_key_", "_workspace_secret_")

w1 = WorkflowTriggerRequest(body={
    "workflow": "order-shipped-notification",
    "recipients": [{"distinct_id": "user_1a2b3c"}],
    "data": {"order_id": "ORD-1234"},
})

res = supr_client.workflows.trigger(w1)
```
</CodeGroup>

## Built API-first

The objects you work with in the dashboard are API objects too:

- **Every core object has an API.** Users, objects, tenants, lists, workflows, templates, preferences and translations all have APIs. See the [API reference](/reference/overview) and the [Management API](/docs/management-api-overview).
- **Notifications as code.** Pull and push workflows and templates with the [CLI](/reference/cli-intro), keep them in Git, and [sync them](/reference/cli-sync) from staging to production. [Validate trigger payloads](/docs/validate-workflow-payload) with JSON Schema and [generate types](/docs/type-generation) from them.
- **Agent-ready by design.** The [MCP server](/reference/mcp-overview) exposes the same objects as tools, and agents act with your account's permissions.

Each team can then work the way that suits it:

| Way | Usually used by | What you do there |
|---|---|---|
| **Dashboard** | Product, marketing and support teams | Build workflows and templates visually, send broadcasts, read logs and analytics |
| **API and SDKs** | Developers | Trigger workflows and sync users with the [REST API](/docs/developer/rest-api) or SDKs for [Python, Node.js, Java and Go](/docs/developer/sdk-overview). [Client SDKs](/docs/developer/sdk-overview) for JavaScript, React, React Native, Expo, Flutter, iOS and Android connect your app's users and push, and on supported platforms add the [Inbox](/docs/inbox-overview) and preference center. Manage assets with the [Management API](/docs/management-api-overview). |
| **CLI** | Developers and platform teams | Script changes to workflows, templates, schemas and translations with the [CLI](/reference/cli-intro), and run them in your CI pipeline |
| **AI** | Anyone | Ask an AI client to build, change or debug notifications through the [MCP server](/reference/mcp-overview), or use the [In-Product Agent](/reference/agent) in the dashboard and the [Slack Agent](/reference/slack-agent) |

## What product and marketing teams can do without engineers

Engineering connects SuprSend once: it sends users and events, and adds a provider for each channel. After that, product, marketing and support teams can do this in the dashboard:

- **Change content** in each channel's editor, and preview and test it before it goes live. See [templates](/docs/templates).
- **Send campaigns** to a [list](/docs/lists) as a [broadcast](/docs/broadcast), now or on a schedule.
- **Build audiences** from a database sync, a CSV, Mixpanel, or a SQL [segment](/docs/segment-lists) (beta) that the AI agent can write for you.
- **Let users choose** what they receive with a hosted or embedded [preference center](/docs/user-preferences).
- **See results** by channel, workflow and category in [analytics](/docs/analytics).

## Built for products that serve other businesses

If your customers are companies, each one can get its own notification setup without separate code:

- **[Tenants](/docs/tenants)** hold each customer's branding, preferences and providers. They're available on the Enterprise plan and as an add-on for the Business plan.
- **[Sub-tenants](/docs/sub-tenants)** nest up to 5 levels, so a child account inherits its parent's setup.
- **[Tenant preferences](/docs/tenant-preference)** let a customer's admin set defaults for their own users.
- **[Tenant providers](/docs/tenant-vendor)** send through your customer's own email or SMS accounts.
- **[Objects](/docs/objects)** represent teams, projects or channels that people subscribe to, so you notify the group instead of listing every member.
- **[Slack](/docs/slack)** and **[Microsoft Teams](/docs/microsoft-teams)** messages can go into your customers' own workspaces.

To choose between workspaces, tenants and objects, see [multi-tenant modelling](/docs/guides/multi-tenant-modelling).

## SuprSend for AI agents: MCP server, Agent Skills and Agent SDK

Because SuprSend is API-first, an agent works with the same objects your code does, in three ways:

- **Agents that operate SuprSend.** The hosted [MCP server](/reference/mcp-overview) (beta) gives AI clients such as Claude, ChatGPT, Codex, Gemini and VS Code access to your workspace. They sign in with your SuprSend account and can't do more than your role allows. [Agent Skills](/reference/agent-skills) (beta) give coding agents SuprSend's schemas, CLI flags and examples, so they work from the real spec instead of guessing.
- **Agents that send notifications.** The [Agent SDK](/reference/agent-sdk) (beta, early access) turns your workflows into schema-checked tools that production agents can call when they need to tell a person something.
- **Docs agents can read.** Every page is available as Markdown by adding `.md` to its URL. [llms.txt](https://docs.suprsend.com/llms.txt) lists every page, and [llms-full.txt](https://docs.suprsend.com/llms-full.txt) holds the whole site in one file.

AI features are optional. An admin can turn them all off for the account.

Start with [Build with AI](/reference/build-with-ai).

## Security, reliability and deployment

| Question | Answer |
|---|---|
| Can we test without messaging real users? | Every account has Sandbox, Staging and Production [workspaces](/docs/workspaces), which share no data. [Test Mode](/docs/developer/test-mode) in staging sends only to your testers. |
| How do changes go live? | Workflow and template edits stay drafts until you commit them. Move them between workspaces with the dashboard, the [CLI](/reference/cli-sync) or the Management API. Check the [go-live checklist](/docs/go-live-checklist) before launch. |
| What if our code retries a request? | Pass an [idempotency key](/reference/idempotent-requests). SuprSend skips repeats of the same key for 24 hours. |
| What if a provider goes down? | [Provider fallback](/docs/vendor-fallback) reroutes messages to your next provider. |
| Is our data secure? | SuprSend is SOC 2 Type II and ISO 27001 compliant and supports GDPR, HIPAA and CPRA requirements. Each workspace has a data region, including the EU. See [security](/docs/security). |
| Who can see and change what? | Admins and members have [different permissions](/docs/managing-members). Members can't see user PII in production. [SAML SSO](/docs/authentication-methods) and [audit logs](/docs/audit-logs) are on the Enterprise plan. |
| Can we monitor it with our own tools? | Stream notification metrics to [OpenTelemetry](/docs/opentelemetry), [Datadog](/docs/datadog) or [New Relic](/docs/new-relic) on the Enterprise plan, or export data to [Amazon S3](/docs/amazon_s3_v2). |
| Where can SuprSend run? | SuprSend cloud, your own cloud (BYOC), or fully [self-hosted](/docs/self-hosted/introduction). Self-hosting needs an Enterprise license. |
| What does it cost? | See [plans and pricing](https://www.suprsend.com/pricing). This page notes when a feature needs the Enterprise plan. |
| We already send notifications. Can we move over gradually? | Yes. Start with a few key notifications and add the rest over time. See [migrating your existing notifications](/docs/migrating-your-existing-notifications). |

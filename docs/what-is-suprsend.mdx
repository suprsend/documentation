SuprSend has all the features set which enable you to send notifications in a reliable and scalable manner, as well as take care of end-user experience, thereby eliminating the need to build any notification service in-house.

## Benefits of using SuprSend as your notification stack:

* You do not have to do any vendor integrations for channels in your code. You can easily add/remove/prioritise vendors and channels from your SuprSend account,

* You can design powerful templates for all channels together and manage them from a single place,

* You can leverage powerful features to experiment fast with notifications as well as take care of end user experience without writing a single line of code.

## Introduction to Workflows

Communications are made up of multiple components - trigger, logic, content, variables, target user, channels, vendors, etc. Typical communication solutions have one or more components intertwined with each other. SuprSend solves communications from a different and more powerful approach, which we call **Workflows.**

At SuprSend, all the constituent components are decoupled from each other, making it modular in nature. The components can come from any source. All these components are configured as nodes in Workflows, where the processing happens for delivery and optimisation. This allows Workflows to handle any complexity possible in your communication use cases.

## How do you set up and trigger notifications?

The single end-to-end walkthrough is the **[Quickstart](/docs/getting-started/quickstart)** — it covers signing up, installing the SDKs (backend + frontend), creating a workflow, triggering it (event vs API), wiring preferences, going to production, and everything in between. Read it once, then dip back in via the right-side TOC.

At a high level, there are three ways to integrate, and most teams use a mix:

1. **Vibe-code with MCP (recommended).** Connect SuprSend to your AI coding assistant — Cursor, Claude, Windsurf — via the [SuprSend MCP server](/reference/mcp-overview). Describe what you want in plain English; the agent creates workflows, identifies users, triggers tests, and even integrates the SDK into your codebase.

2. **Backend trigger.** Create a Workflow on the SuprSend dashboard and trigger it from your server using the [direct HTTP API](/docs/trigger-workflow#triggering-workflow-via-api) or one of our backend SDKs (Node, Python, Go, Java).

3. **Frontend events + in-app Inbox.** Send events to SuprSend from your frontend clients (web, Android, iOS) via the Client SDK and trigger workflows on those events. The same client SDKs power the in-app Inbox bell + feed.

All other components (vendors, templates, preferences, optimisation, scaling) are managed on the SuprSend platform. After the [Quickstart](/docs/getting-started/quickstart), the 'Core Concepts' section is the deep dive on every primitive — see [Mandatory concepts](/docs/getting-started/mandatory-concepts) for a 5-minute orientation.

To run SuprSend in your own infrastructure, see the [Self-Hosted documentation](/docs/self-hosted/introduction). Self-hosted deployment is available only for **enterprise customers**.

title: "Testing a Template"
description: "Send a real notification to a device from the editor to verify rendering before publishing."
---

The **Test** button sends a real notification to a real device — not a simulated preview — so you see exactly how the message renders in the actual channel UI before it reaches any of your users.

---

## Before you test

**Variables must have values.** Template variables are rendered using values from the **Variables panel** (Input Payload section) in the [template editor](/docs/templates#the-variables-panel). Every `{{variable}}` used in the template must have a corresponding value defined — a variable with no value causes that channel's notification to fail rendering and not send. Other channels in the same template are unaffected.

**Publish before testing.** The Test flow uses the **live (published) version** of the variant, not the current draft. If you've made edits, publish them first — otherwise you're testing stale content.

> **Test Mode:** If [Test Mode](/docs/developer/test-mode) is enabled in your workspace, test notifications are delivered to your configured test channels rather than real users. This applies to template testing too.

---

## Sending a test

Click **Test** in the top-right corner of the template editor — available in both view and edit mode. A modal opens with two tabs: **Selected Variant** and **Template Group**. Choose based on what you want to verify.

---

### Selected Variant tab

Tests a specific channel and variant in isolation, regardless of whether that variant would be selected by condition matching. Use this when you want to confirm a particular variant's content renders correctly.

<Frame caption="Test a specific variant">
  <img src="/images/docs/templates-test-selected-variant.png" />
</Frame>

| Field | Description |
|---|---|
| **Channel** | The channel to test — Email, SMS, In-App Inbox, etc. |
| **Variant** | The specific variant to test. Defaults to the variant you have open. |
| **Recipient** | The `distinct_id` of the [user](/docs/users) who receives the test notification. The user must exist in SuprSend. After entry, their registered identities for the selected channel appear as checkboxes — deselect any you want to exclude. |
| **Notification category** | Determines which [vendor](/docs/vendors) and delivery settings are used. Defaults to Transactional. For Email and SMS, separate vendor swimlanes exist per [category](/docs/notification-category) — choose the one that matches your intended delivery path. |
| **Tenant ID** | The tenant context for the test. Defaults to `default`. |

Click **Send Test**.

---

### Template Group tab

Tests the entire template group across all channels for a recipient — with SuprSend automatically selecting the variant whose conditions match, exactly as a live workflow run would.

<Frame caption="Test the full template group">
  <img src="/images/docs/templates-test-template-group.png" />
</Frame>

| Field | Description |
|---|---|
| **Recipient** | The `distinct_id` of the [user](/docs/users). All channels associated with that user appear with checkboxes — deselect any you want to exclude. |
| **Notification category** | Determines [vendor](/docs/vendors) and delivery settings. Defaults to Transactional. |
| **Tenant ID** | The [tenant](/docs/tenants) context for the test. Defaults to `default`. |

> **The variant delivered is determined by condition matching** — not necessarily the one you're currently editing. SuprSend evaluates Tenant ID and recipient variables exactly as it would in a real workflow run. If you want to test a specific variant regardless of its conditions, use the **Selected Variant** tab.

Click **Send Test**.

---

## Checking delivery

After sending, go to [Logs](/docs/logging) to verify delivery status and inspect rendering details. If a notification does not arrive, look for a rendering error on the specific channel — this usually means a variable had no value in the mock data.

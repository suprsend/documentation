## Overview

Type generation automatically creates strongly-typed programming language interfaces from your SuprSend [JSON schemas](/docs/validate-workflow-payload). Instead of manually writing type definitions, you define your workflow payload structure once as a JSON schema in SuprSend, and the CLI generates type-safe interfaces for TypeScript, Python, Go, Java, Kotlin, Swift, or Dart.

<Note>
Generated type files are auto-generated and should not be manually edited. Regenerate types when you update schemas in SuprSend.
</Note>

---

## Why Use Type Generation?

Without type generation, you work with plain objects that can lead to runtime errors. Type generation catches these errors during development with compile-time type safety and IDE autocomplete.

```typescript
// ❌ Without types - errors caught at runtime
const data = { invoice_amount: "5000" }; // Oops! Should be number

// ✅ With generated types - errors caught during development
const data: OrderCreatedEventData = { invoice_amount: 5000 };
```

You get early error detection, IDE autocomplete, immediate feedback when schemas change, and self-documenting code.

## Quick Start

Get started with type generation in 4 steps:

<Steps>
  <Step title="1. Install and Authenticate">
    Ensure you have the [SuprSend CLI installed](/reference/cli-installation) and are [authenticated with your workspace](/reference/cli-authentication).
  </Step>
  
  <Step title="2. Create a Schema">
    Define your workflow payload structure as a [JSON schema](/docs/validate-workflow-payload) in SuprSend and ensure it's enabled.
  </Step>
  
  <Step title="3. Generate Types">
    Run the CLI command to generate types for your language:
    
    ```bash
    suprsend generate-types typescript --output-file types.ts
    ```
    
    This processes all enabled schemas in your workspace and generates type definitions.
  </Step>
  
  <Step title="4. Use in Your Code">
    Import and use the generated types in your workflow triggers:
    
    ```typescript
    import { OrderCreatedEventData } from "./types";
    
    const data: OrderCreatedEventData = {
      first_name: "User",
      invoice_amount: 5000,
      invoice_id: "Invoice-1234"
    };
    ```
  </Step>
</Steps>

## Generate Types

### Prerequisites

Before generating types, ensure you have:

1. ✅ [SuprSend CLI installed](/reference/cli-installation)
2. ✅ [Authenticated with your workspace](/reference/cli-authentication)
3. ✅ Created and enabled schemas for your workflows ([see guide](/docs/validate-workflow-payload))

### Command Syntax

```bash
suprsend generate-types <language> --output-file <output-file> [flags]
```

### Supported Languages

| Language | File Extension | Output Type |
|----------|---------------|-------------|
| TypeScript | `.ts` | Interfaces |
| Python | `.py` | Pydantic Models |
| Go | `.go` | Structs |
| Java | `.java` | POJOs |
| Kotlin | `.kt` | Data classes |
| Swift | `.swift` | Structs |
| Dart | `.dart` | Classes |

For complete details on command arguments and flags, see the [CLI Generate Types Reference](/reference/cli-schema-generate-types).

### Basic Examples

<CodeGroup>

```bash TypeScript
suprsend generate-types typescript --output-file types.ts
```

```bash Python
suprsend generate-types python --output-file types.py
```

```bash Go
suprsend generate-types go --output-file types.go
```

```bash Java
suprsend generate-types java --output-file types.java
```

```bash Kotlin
suprsend generate-types kotlin --output-file types.kt
```

```bash Swift
suprsend generate-types swift --output-file types.swift
```

</CodeGroup>

### Advanced Usage

<CodeGroup>

```bash Generate from specific workspace
suprsend generate-types typescript --output-file types.ts --workspace production
```

```bash Custom build flags
suprsend generate-types go --output-file types.go --build-flags "flag1,flag2"
```

```bash Generate from draft schemas
suprsend generate-types typescript --output-file types.ts --mode draft
```

</CodeGroup>

## Use Generated Types

After generating types, import them into your codebase and use them in your workflow triggers. The generated types match your JSON schema structure, ensuring type safety throughout your application.

<CodeGroup>

```typescript TypeScript
// ============================================
// GENERATED TYPE (types.ts)
// ============================================
// This file is generated automatically by SuprSend based on available schema. DO NOT MODIFY IT.
export interface OrderCreatedEventData {
   first_name: string;
   invoice_amount: number;
   invoice_id: string;
}

// ============================================
// USAGE IN YOUR CODE
// ============================================
import { Suprsend, WorkflowTriggerRequest } from "@suprsend/node-sdk";
import { OrderCreatedEventData } from "./types";

const client = new Suprsend("workspace_key", "workspace_secret");

// ✅ Type-safe data creation
const triggerData: OrderCreatedEventData = {
   first_name: "User",
   invoice_amount: 5000,
   invoice_id: "Invoice-1234",
};

const body = {
   workflow: "_workflow_slug_",
   actor: {
       distinct_id: "0fxxx8f74-xxxx-41c5-8752-xxxcb6911fb08",
       name: "actor_1",
   },
   recipients: [
       {
           distinct_id: "0gxxx9f14-xxxx-23c5-1902-xxxcb6912ab09",
           $email: ["abc@example.com"],
           name: "recipient_1",
       },
   ],
   data: triggerData, // ✅ Type-safe
};

const wf = new WorkflowTriggerRequest(body, {
   tenant_id: "tenant_id",
   idempotency_key: "_unique_request_identifier",
});

const response = await client.workflows.trigger(wf);
console.log("response", response);
```

   triggerData := OrderCreatedEventData{
       FirstName:     "User",

       InvoiceID:     "Invoice-1234",
   }

   // Convert struct to map for workflow payload

   jsonData, _ := json.Marshal(triggerData)
   _ = json.Unmarshal(jsonData, &data)

       "actor": map[string]interface{}{
           "distinct_id":  "0fxxx8f74-xxxx-41c5-8752-xxxcb6911fb08",
           "name":         "actor_1",
           "$skip_create": true,
       },
       "recipients": []map[string]interface{}{

               "$email":              []string{"abc@example.com"},
               "name":                "recipient_1",
               "$preferred_language": "en",
               "$timezone":           "America/New_York",
               "$skip_create":        true,

           {
               "object_type":  "teams",
               "id":           "finance",
               "$skip_create": true,
           },
       },

   w1 := &suprsend.WorkflowTriggerRequest{
       Body:           wfReqBody,
       TenantId:       "tenant_id1",

import org.json.JSONObject;
import org.json.JSONArray;
import suprsend.Suprsend;
import suprsend.WorkflowTriggerRequest;
import suprsend.types.OrderCreatedEventData;
import java.util.Arrays;
import java.util.HashMap;
import java.util.Map;
import java.lang.reflect.Field;

public class Workflow {
   
   public static Map<String, Object> toMap(Object obj) {
       Map<String, Object> map = new HashMap<>();
       try {
           for (Field field : obj.getClass().getDeclaredFields()) {
               field.setAccessible(true);
               map.put(field.getName(), field.get(obj));
           }
       } catch (IllegalAccessException e) {
           throw new RuntimeException("Failed to convert object to map", e);
       }
       return map;
   }

   private static void triggerWorkflow() {
       Suprsend suprClient = new Suprsend("workspace_key", "workspace_secret");

       // ✅ Type-safe data creation
       OrderCreatedEventData triggerData = new OrderCreatedEventData();
       triggerData.setFirstName("User");
       triggerData.setInvoiceAmount(5000);
       triggerData.setInvoiceId("Invoice-1234");

       JSONObject data = new JSONObject(toMap(triggerData));

       JSONObject body = new JSONObject()
           .put("workflow", "_workflow_slug_")
           .put("actor", new JSONObject()
               .put("distinct_id", "0fxxx8f74-xxxx-41c5-8752-xxxcb6911fb08")
               .put("name", "actor_1")
               .put("$skip_create", true)
           )
           .put("recipients", new JSONArray()
               .put(new JSONObject()
                   .put("distinct_id", "0gxxx9f14-xxxx-23c5-1902-xxxcb6912ab09")

                   .put("$preferred_language", "en")

                   .put("id", "finance")
                   .put("$skip_create", true)

           )

           body,

## Best Practices

- **Don't edit generated files** — Regenerate when schemas change
- **Commit generated files** — Share type safety across your team
- **Regenerate after updates** — Keep types in sync with schemas
- **Add to CI/CD** — Automate type generation in your pipeline
- **Use with schema validation** — Combine for end-to-end safety
- **Separate by workspace** — Generate different files for staging/production

## Troubleshooting

<AccordionGroup>
  <Accordion title="Types are outdated">
    **Problem:** Generated types don't match your current schemas.

    **Solution:** Regenerate types:
    ```bash
    suprsend generate-types typescript --output-file types.ts
    ```
  </Accordion>

  <Accordion title="Missing fields in generated types">
    **Problem:** Expected fields aren't in the generated types.

    **Solution:** 
    1. Check that the schema is **enabled** in SuprSend
    2. Verify the schema has been **committed** (not just in draft)
    3. Regenerate types after schema changes
  </Accordion>

  <Accordion title="Type errors in IDE but code works">
    **Problem:** TypeScript/Python shows errors, but the code runs fine.

    **Solution:** This usually means:
    - Types are outdated → Regenerate types
    - Schema changed in SuprSend → Regenerate types
    - Using wrong workspace → Check `--workspace` flag
  </Accordion>

  <Accordion title="Command not found or authentication errors">
    **Problem:** CLI command fails or returns authentication errors.

    **Solution:**
    1. Verify the CLI is installed: `suprsend --version`
    2. Check authentication: `suprsend auth status`
    3. Re-authenticate if needed: `suprsend auth login`
  </Accordion>
</AccordionGroup>

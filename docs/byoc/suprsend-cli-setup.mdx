The SuprSend CLI lets you promote [workflows](/docs/workflows), [templates](/docs/templates), and other assets between workspaces from the command line. Use it in CI/CD to automate notification changes and sync assets across self-hosted environments.

---

## Installation

Choose one method:

<CardGroup cols="3">
  <Card title="Homebrew (recommended)" icon="apple-alt" iconType="solid">
    **macOS / Linux** — Easiest install and upgrades via package manager.
  </Card>
  <Card title="Binary release" icon="download" iconType="solid" href="https://github.com/suprsend/cli/releases">
    **Windows / servers / CI** — Pre-compiled binary from GitHub Releases.
  </Card>
  <Card title="Build from source" icon="code" iconType="solid">
    **Contributors** — Build from source with Go 1.20+.
  </Card>
</CardGroup>

### Homebrew

```bash
brew tap suprsend/tap
brew install --cask suprsend
```

### Binary release

Download from [GitHub Releases](https://github.com/suprsend/cli/releases), then:

```bash
# Linux/macOS
chmod +x suprsend
sudo mv suprsend /usr/local/bin/
# Windows: extract suprsend.exe to your PATH
```

### Build from source

```bash
git clone https://github.com/suprsend/cli.git
cd cli/cmd/suprsend
go build -o suprsend
sudo mv suprsend /usr/local/bin/
```

## Authentication

For self-hosted deployments, use **profiles** to persist environment tokens and configuration. Create multiple profiles and switch the active one as needed.

```bash
suprsend profile add --name us-server --service-token "your_token_here" --base-url "base_url" --mgmnt-url "management_url"
suprsend profile use us-server

suprsend profile add --name eu-server --service-token "your_token_here" --base-url "base_url" --mgmnt-url "management_url"
suprsend profile use eu-server
```

You can also authenticate using **environment variables** or **command-line flags** in your session. See [CLI authentication methods](/reference/cli-authentication) for details.

Config is stored at `$HOME/.suprsend.yaml` by default; you can edit it directly.

## Test your setup

After installation, you can use the CLI to **work with assets locally** and **promote changes across environments** (e.g., from staging to production).

List all commands and flags:

```bash
suprsend --help
```

Example: pull workflows from staging and push to production:

```bash
suprsend pull workflow --workspace staging
suprsend push workflow --workspace production
```

For the full list of commands and options, see the [CLI documentation](/reference/cli-intro).

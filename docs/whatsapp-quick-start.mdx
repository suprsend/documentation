WhatsApp has the most setup overhead of any channel because every message template must be **pre-approved by Meta** before it can be sent. Plan for approval lead time when going live.

Adding WhatsApp is three steps:

1. **Configure a WhatsApp vendor** in the dashboard.
2. **Make sure your users have `$whatsapp`** set in their profile.
3. **Add a WhatsApp delivery node** with a Meta-approved template.

## 2. Recipient identity field

The WhatsApp channel identity is `$whatsapp`. Phone numbers must be in E.164 format.

```json
{
  "distinct_id": "user_123",
  "$whatsapp": ["+12135555444"]
}
```

---

## 3. WhatsApp template — and approval

Use the [WhatsApp template editor](/docs/whatsapp-template). Templates have rules:

- Marketing, utility, and authentication categories — Meta enforces different approval criteria for each.
- Variables use Handlebars `{{var}}` syntax but must align with Meta's positional variable format (`{{1}}`, `{{2}}`).
- Buttons (call-to-action, quick reply) must be declared in the template before submission.

Read the full [WhatsApp template guidelines](/docs/whatsapp-template-guidelines) before submitting — Meta rejects templates with promotional language in utility templates, missing examples, or mismatched variables.

---

## WhatsApp gotchas

- **Sandbox limitation:** WhatsApp can only be sent to verified phone numbers during the trial.
- **24-hour session window:** outside Meta's 24-hour customer-care window, you can only send approved template messages — not free-form text.
- **Approval lead time:** Meta typically reviews templates in minutes to hours, but plan for 1–2 days during go-live.
- **Opt-in is required:** users must explicitly opt in to receive WhatsApp. Surface this in your preferences UI.
- **Track engagement:** add the SuprSend webhook URL in your vendor portal for delivery and read receipts.

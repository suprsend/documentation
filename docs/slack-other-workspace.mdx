---
title: Sending a message to another workspace
description: How to send Slack notifications into your customers' Slack workspaces using OAuth V2 and SuprSend.
---

This guide covers sending notifications into Slack workspaces you don't own — your customers' workspaces. This is the right approach for SaaS products where users connect their own Slack workspace to receive product notifications. It requires building an [OAuth V2 flow](https://api.slack.com/authentication/oauth-v2) so each customer can authorize your app.

## How it works

You build an **Add to Slack** button in your product. When a customer clicks it, they're taken to Slack's authorization screen, where they approve your app. Slack then redirects back to your app with a temporary code, which you exchange for a permanent bot token scoped to that customer's workspace. You store that token in the SuprSend user profile for that customer — and from then on, SuprSend can send notifications into their workspace on your behalf.

## Step 1 — Enable the Slack channel in SuprSend

Before any messages can be sent, you need to activate the Slack channel in your SuprSend workspace.

1. Log in to your [SuprSend dashboard](https://app.suprsend.com)
2. Go to **[Vendors → Slack](https://app.suprsend.com/en/staging/vendors/slack)**
3. Toggle the Slack channel to **Enabled** and click **Save**

<Frame>
  ![Enable Slack in SuprSend Vendor Settings](/images/docs/a10a8f8-image.png)
</Frame>

<Callout type="warning">
  Each SuprSend workspace (e.g. staging, production) has its own vendor settings. Enable Slack separately in each environment — notifications will fail silently if the channel is not enabled.
</Callout>

## Step 2 — Set up your Slack app

If you already have a Slack app, you can use it here — you don't need to create a new one. The app's name and icon will appear on Slack's authorization screen, so make sure they're recognizable to your customers.

If you need to create one:

1. Go to [api.slack.com/apps](https://api.slack.com/apps) and click **Create New App**

    <Frame>
      ![Slack Apps page — Create New App](/images/docs/2895991-Screenshot_2022-07-12_at_11.48.16_AM.png)
    </Frame>

2. Select **From scratch** and give it a name your users will recognize

    <Frame>
      ![Name your Slack App](/images/docs/9fa94ad-Screenshot_2022-07-12_at_11.14.51_AM.png)
    </Frame>

3. Select any workspace as your development workspace — this doesn't affect where customers install the app
4. Click **Create App**

## Step 3 — Verify your OAuth scopes

Navigate to **Features → OAuth & Permissions → [Bot Token Scopes](https://api.slack.com/scopes)** and confirm the following scopes are present. Add any that are missing.

| Scope | Required | Purpose |
|-------|----------|---------|
| [`chat:write`](https://api.slack.com/scopes/chat:write) | Yes | Post messages to channels the bot has been invited to |
| [`chat:write.public`](https://api.slack.com/scopes/chat:write.public) | Yes | Post to public channels without the bot needing to join first |
| [`im:write`](https://api.slack.com/scopes/im:write) | Yes | Send direct messages to users |
| [`users:read`](https://api.slack.com/scopes/users:read) | No | Look up a user by their Slack user ID |
| [`users:read.email`](https://api.slack.com/scopes/users:read.email) | No | Look up a user by email. Required for DM by email. |

<Frame>
  ![Adding Bot Token Scopes](/images/docs/75119e0-slack_scope.png)
</Frame>

<Callout type="warning">
  If you added new scopes to an existing app, customers who have already authorized your app will need to re-authorize it before the new scopes take effect in their workspace. Plan scope additions carefully in production.
</Callout>

## Step 4 — Configure your OAuth redirect URL

When a customer completes the authorization flow, Slack redirects them back to a URL you control. You must register this URL before the OAuth flow will work.

1. Go to **Features → OAuth & Permissions**
2. Under **Redirect URLs**, click **Add New Redirect URL**
3. Enter your callback URL, e.g. `https://yourapp.com/auth/slack/callback`
4. Click **Save URLs**

<Callout type="warning">
  The redirect URL in your authorization link must exactly match what you registered here. A mismatch will cause Slack to reject the request.
</Callout>

## Step 5 — Build the authorization flow

This is what your customers will go through when they click **Add to Slack** in your product.

**Construct the authorization URL**

When a customer clicks your button, redirect them to this URL:

```
https://slack.com/oauth/v2/authorize
  ?client_id=YOUR_CLIENT_ID
  &scope=chat:write,chat:write.public,im:write
  &redirect_uri=https://yourapp.com/auth/slack/callback
  &state=YOUR_CSRF_STATE_TOKEN
```

You can find your `client_id` under **[Basic Information](https://api.slack.com/apps)** in your app's settings.

<Callout type="warning">
  Always generate a unique `state` value per authorization request and tie it to the user's session. Verify this value when Slack redirects back to prevent CSRF attacks.
</Callout>

**Handle the callback and exchange the code for a token**

When the customer approves your app, Slack redirects them to your callback URL with a `code` parameter. Exchange it for a permanent bot token using Slack's [`oauth.v2.access`](https://api.slack.com/methods/oauth.v2.access) endpoint.

<CodeGroup>
```javascript Node.js
const response = await fetch("https://slack.com/api/oauth.v2.access", {
  method: "POST",
  headers: { "Content-Type": "application/x-www-form-urlencoded" },
  body: new URLSearchParams({
    client_id: process.env.SLACK_CLIENT_ID,
    client_secret: process.env.SLACK_CLIENT_SECRET,
    code: req.query.code,
    redirect_uri: "https://yourapp.com/auth/slack/callback"
  })
});

const data = await response.json();
const botToken = data.access_token; // Starts with xoxb- — store this per customer
const teamId = data.team.id;        // Slack workspace ID
```

```python Python
import requests, os

response = requests.post("https://slack.com/api/oauth.v2.access", data={
  "client_id":     os.environ["SLACK_CLIENT_ID"],
  "client_secret": os.environ["SLACK_CLIENT_SECRET"],
  "code":          request.args.get("code"),
  "redirect_uri":  "https://yourapp.com/auth/slack/callback"
})

data      = response.json()
bot_token = data["access_token"]  # Store per customer
team_id   = data["team"]["id"]
```
</CodeGroup>

Store the `access_token` and `team.id` securely in your database, associated with the customer. You'll pass this token to SuprSend in the next step.

## Step 6 — Store the target in SuprSend

Initialize the [SuprSend SDK](https://docs.suprsend.com/docs/nodejs-sdk) first if you haven't already:

<CodeGroup>
```javascript Node.js
const { Suprsend, WorkflowTriggerRequest } = require("@suprsend/node-sdk");
const supr_client = new Suprsend("workspace_key", "workspace_secret");
```

```python Python
from suprsend import Suprsend, WorkflowTriggerRequest
import os

supr_client = Suprsend("workspace_key", "workspace_secret")
```
</CodeGroup>

After obtaining the customer's bot token, save their Slack target to their SuprSend user profile using `user.add_slack()`.

**Sending a DM to the user**

<CodeGroup>
```javascript Node.js
const distinct_id = "user_001";
const user = supr_client.user.get_instance(distinct_id);

// By Slack user ID
user.add_slack({
  user_id: "UXXXXXXXXX",
  access_token: botToken  // The token from oauth.v2.access
});

// Or by email (requires users:read.email scope)
user.add_slack({
  email: "user@theirdomain.com",
  access_token: botToken
});

const response = user.save();
response.then((res) => console.log("response", res));
```

```python Python
distinct_id = "user_001"
user = supr_client.user.get_instance(distinct_id)

# By Slack user ID
user.add_slack({
  "user_id": "UXXXXXXXXX",
  "access_token": bot_token
})

# Or by email (requires users:read.email scope)
user.add_slack({
  "email": "user@theirdomain.com",
  "access_token": bot_token
})

print(user.save())
```
</CodeGroup>

**Sending to a channel in the customer's workspace**

During the OAuth flow you can ask the customer to select a channel. After the callback, you'll have that channel's ID.

<CodeGroup>
```javascript Node.js
// Use a distinct_id that ties the channel to the customer
const distinct_id = `channel_${customerId}_general`;
const user = supr_client.user.get_instance(distinct_id);

user.add_slack({
  channel_id: "CXXXXXXXX",
  access_token: botToken
});

const response = user.save();
response.then((res) => console.log("response", res));
```

```python Python
distinct_id = f"channel_{customer_id}_general"
user = supr_client.user.get_instance(distinct_id)

user.add_slack({
  "channel_id": "CXXXXXXXX",
  "access_token": bot_token
})

print(user.save())
```
</CodeGroup>

## Step 7 — Trigger a workflow

With channel data saved, trigger a SuprSend workflow targeting the same `distinct_id`.

<Callout type="info">
  Don't want to pre-store Slack identities? You can pass the identity inline in the `$slack` field of the `recipients` array instead. See [Storing Slack identity: pre-stored vs. inline](/integrations/chat/slack/overview#storing-slack-identity-pre-stored-vs-inline) in the overview.
</Callout>

<CodeGroup>
```javascript Node.js
const body = {
  workflow: "task-assigned",         // workflow slug from the SuprSend dashboard
  recipients: [
    { distinct_id: "user_001" }
  ],
  data: {
    task_name: "Review Q4 report",
    assigned_by: "Jamie"
  }
};

const wf = new WorkflowTriggerRequest(body);
const response = supr_client.workflows.trigger(wf);
response.then((res) => console.log("response", res));
```

```python Python
wf = WorkflowTriggerRequest(
  body={
    "workflow": "task-assigned",     # workflow slug from the SuprSend dashboard
    "recipients": [
      { "distinct_id": "user_001" }
    ],
    "data": {
      "task_name": "Review Q4 report",
      "assigned_by": "Jamie"
    }
  }
)

response = supr_client.workflows.trigger(wf)
print(response)
```
</CodeGroup>

Send formatted messages to Microsoft Teams using Markdown or rich [Adaptive Card](https://adaptivecards.io/) layouts. Each mode uses a different variable syntax.

<Note>
  You need MS Teams connected as a vendor in SuprSend before notifications can be sent. [Set up MS Teams →](/docs/microsoft-teams)
</Note>

The MS Teams editor supports **Markdown** for simple messages and **JSONNET** for Adaptive Card JSON.

### Markdown field

**Required in Markdown mode** · Supports variables

A text editor with Markdown-style formatting. Variables use [Handlebars](/docs/handlebars-helpers) (`{{variable_name}}`). The right panel previews your message in real time.

**Supported formatting:**

| Format | Syntax |
|---|---|
| **Bold** | `**text**` |
| *Italic* | `*text*` |
| `Code` | `` `code` `` |
| Link | `[label](url)` |
| Blockquote | `> text` |

**What to write here:** Use bold for titles, bullet-style lines with links for one-click access. Ideal for DevOps alerts and short operational updates.

> Example deployment alert:

```text
**Deployment Completed**

Service: {{service_name}}
Environment: {{environment}}
Version: {{version}}
Duration: {{duration}}

[View Logs]({{log_url}})
```

Simple and effective when the notification is informational with a single link.

### JSONNET field

**Required in JSONNET mode**

A code editor that outputs [Adaptive Card](https://adaptivecards.io/) JSON. Variables use `data.key` syntax (not Handlebars). Design visually in the [Adaptive Cards Designer](https://adaptivecards.io/designer/) first, then adapt the JSON into JSONNET. Use `FactSet` for key-value data and `Action.OpenUrl` for link buttons. See the full [JSONNET reference](/docs/jsonnet-templates) for syntax, examples, and debugging.

**What to write here:** Start from the Designer with "Microsoft Teams" as host, copy JSON, replace literals with `data.service_name` style keys, and use **Load Preview** in SuprSend to catch syntax errors (shown in red).

> Example: For approval-style alerts, use `FactSet` for structured data and `Action.OpenUrl` for CTA buttons. See the full [Adaptive Card example](/docs/jsonnet-templates#ms-teams-adaptive-card-examples) in the JSONNET reference.

## Personalise with variables

**In Markdown mode** — type `{{` for auto-suggestions. Standard Handlebars syntax:

- `{{order_id}}` — top-level variable
- `{{order.address.city}}` — nested variable
- `{{{tracking_url}}}` — URL (avoid escaping)
- `{{$recipient.name}}` — recipient property

**In JSONNET mode** — variables use `data.key` syntax. See [JSONNET variable reference](/docs/jsonnet-templates#variable-syntax) for the full table.

For conditionals and helpers in Markdown mode, see [Handlebars Helpers](/docs/handlebars-helpers).

<Warning>
  If a variable cannot be rendered at send time (missing or mismatched data), SuprSend skips that notification for the affected user. Other channels in the same template group are still sent.
</Warning>

## Other ways to build this template

### Design Adaptive Cards visually in Microsoft's designer

The [Adaptive Cards Designer](https://adaptivecards.io/designer/) at adaptivecards.io is the official Microsoft tool for building Adaptive Card layouts visually. Drag in TextBlock, Image, FactSet, and ActionSet elements, see a live preview on the right, and the JSON is generated automatically. Choose "Microsoft Teams" as the host app in the designer — this applies the Teams-specific rendering constraints (max card width, supported schema version, Teams-specific `openUrl` behaviour). Copy the JSON, open SuprSend's JSONNET editor, replace static values with `data.key` references, and you have a production-ready Adaptive Card in minutes.

### Use FactSet blocks for structured key-value notifications

Adaptive Cards' `FactSet` element is purpose-built for the most common DevOps/B2B notification pattern: "here is what happened" as a set of labelled values. Deployment completed → `Service: payments-api`, `Environment: production`, `Version: v2.4.1`, `Duration: 42s`. A FactSet renders this as a compact, aligned two-column layout without any custom CSS. It renders correctly in both the Teams desktop app and mobile. Whenever your notification has more than two "here's the data" fields, use a FactSet instead of a text paragraph.

### Test Adaptive Cards in the Teams Developer Portal

Microsoft's [Developer Portal for Teams](https://dev.teams.microsoft.com/) at dev.teams.microsoft.com has a Card Previewer tool that renders your Adaptive Card JSON exactly as it will appear in Teams — including mobile rendering. This is more accurate than the adaptivecards.io designer because it applies Teams-specific styling and schema version constraints. Paste your final JSONNET output (exported as JSON) into the previewer before committing in SuprSend.

### Send to Teams channels via Incoming Webhooks for architecture simplicity

If your use case is internal tooling (CI/CD alerts, monitoring, deployments), consider whether you need SuprSend's full workflow engine or just a direct webhook. MS Teams supports Incoming Webhooks natively — a single URL you post JSON to. For simple alert messages, this can be the right tool. But when you need personalisation per recipient, multi-channel routing, retry logic, preference management, or audit logs, SuprSend's workflow layer is worth the additional setup. Knowing both options helps you make the right architectural choice.

### Use `Action.Execute` for Universal Actions (Teams-only feature)

Teams supports `Action.Execute` in Adaptive Cards (part of the Universal Actions for Adaptive Cards spec, v1.4+). Unlike `Action.OpenUrl` which just opens a link, `Action.Execute` sends an action back to your bot/app and can refresh the card content in-place. This enables approval flows where clicking "Approve" in the notification card updates the card to show "Approved by [user] at [time]" — without opening a browser tab. This is more technically involved (requires a Teams bot integration) but produces the highest-quality interactive experience available in Teams notifications.

## Best practices

- **Use FactSet for key-value data, not paragraphs** — It renders as a clean two-column layout readers can scan quickly.
- **Always test in a real Teams chat before committing** — The Adaptive Cards Designer is an approximation — Teams applies its own renderer.
- **Use v1.6 schema for the widest feature support across Teams desktop and mobile** — Matches the FAQ recommendation for schema version.
- **Keep Adaptive Card payloads under 28 KB** — Teams truncates silently beyond that limit.
- **Use `Action.OpenUrl` for simple link buttons; only use `Action.Execute` if you have a bot to handle responses** — Keeps interactive cards maintainable.

## FAQ

<AccordionGroup>
  <Accordion title="Markdown or JSONNET — which should I use?">
    Start with Markdown for plain-text messages with links. Switch to JSONNET when you need images, buttons, columns, or structured layouts (FactSets, ActionSets).
  </Accordion>

  <Accordion title="What Adaptive Card version should I use?">
    Use version `1.6` for the widest feature support across Teams desktop and mobile.
  </Accordion>

  <Accordion title="What's the message size limit?">
    Teams truncates Adaptive Cards larger than 28 KB. Keep payloads lean, especially when iterating over arrays.
  </Accordion>

  <Accordion title="Why does my card look different in Teams vs the designer?">
    Teams has its own rendering engine. The [Adaptive Cards Designer](https://adaptivecards.io/designer/) is an approximation. Always test in an actual Teams chat before committing.
  </Accordion>

  <Accordion title="What happens if a variable is missing or has the wrong value at send time?">
    SuprSend skips that notification for the affected user. Other channels in the same template group are still sent.
  </Accordion>

  <Accordion title="Can I use this channel alongside other channels in the same workflow?">
    Yes — combine Teams with email, Slack, push, and other channels in the same template group.
  </Accordion>

  <Accordion title="How do I pass variable values when triggering the workflow?">
    Include `data` (workflow) or `properties` (event) so JSONNET `data.*` and Markdown Handlebars paths match your payload. See [JSONNET templates](/docs/jsonnet-templates) and [Adding dynamic content](/docs/templates#the-variables-panel).
  </Accordion>
</AccordionGroup>

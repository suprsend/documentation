SuprSend provides two ways to design MS Teams templates:

- **Markdown editor** — for simple text messages with Handlebars variables.
- **JSONNET editor** — for rich Adaptive Card templates with buttons, images, and complex layouts.

## Markdown editor

Send simple text templates using the Markdown editor. Variables use Handlebars syntax (`{{variable_name}}`).

### Supported Markdown syntax

| Format | Syntax |
|---|---|
| Headings | `# Heading level 1` — see all [heading formats](https://www.markdownguide.org/basic-syntax/#headings) |
| Line break | End a line with two or more spaces, then press return *(only 1 continuous line break is supported)* |
| **Bold** | `**bold text**` or `__bold text__` |
| *Italic* | `_italic text_` or `*italic text*` |
| ***Bold Italic*** | `***bold italic text***` |
| > Blockquotes | `> block quote text` |
| Lists | `1. First item` `2. Second item` — see more [list formats](https://www.markdownguide.org/basic-syntax/#lists-1) |
| `code` | `` `code` `` |
| Links | `[Link text](https://example.com)` |

### Adding dynamic data in Markdown

Use Handlebars syntax (`{{variable_name}}`). For URLs and values with special characters, use triple curly braces (`{{{url}}}`) to avoid HTML-escaping. See the full set of available helpers in the [Handlebars Helpers documentation](/docs/handlebars-helpers).

## Choosing between Markdown and JSONNET

| Scenario | Recommended editor |
|---|---|
| Simple alerts, status updates, plain-text messages | **Markdown** — fastest to set up, uses Handlebars for variables. |
| Notifications with images, buttons, columns, or structured layouts | **JSONNET** — full Adaptive Card support for rich interactive messages. |
| Approval workflows with actionable buttons | **JSONNET** — Adaptive Cards support `Action.Submit` and `Action.OpenUrl` buttons. |

<Info>
  You can switch between Markdown and JSONNET at any time. Content is saved independently for each mode.
</Info>

## JSONNET editor

Switch to the JSONNET editor for rich, interactive templates. Microsoft provides an [Adaptive Card Designer](https://adaptivecards.io/designer/) where you can visually design your template, then copy the JSON payload into the SuprSend JSONNET editor.

SuprSend includes sample templates for quick starts — select one from the right-side options above the editor.

<Warning>
  The `${variable}` syntax from Adaptive Cards is **not supported** in the JSONNET editor. Use `data.variable` syntax instead.
</Warning>

### Adding dynamic data in JSONNET

Add sample data in the **Variables panel**, then reference variables as `data.<variable_name>`.

| Variable Type | JSONNET Syntax |
|---|---|
| Parent level | `data.variable_name` |
| Nested object | `data.location.city` |
| Special characters / spaces in key | `data['$brand'].brand_name` or `data.event['first name']` |
| Array element at index | `data.array[0].product_name` |

**Iterating over arrays:**

```json
{
  "$schema": "http://adaptivecards.io/schemas/adaptive-card.json",
  "body": [
    {
      "text": product.name + " at " + product.price,
      "type": "TextBlock",
      "wrap": true
    }
    for product in data.products
  ],
  "type": "AdaptiveCard",
  "version": "1.6"
}
```

<Info>
  You must add mock data for all variables in your JSONNET template. Missing data causes rendering errors and prevents the preview from loading.
</Info>

## Common scenarios

<AccordionGroup>
  <Accordion title="Deployment status alert (Markdown)">

```text
**Deployment Completed** ✅

Service: {{service_name}}
Environment: {{environment}}
Version: {{version}}
Duration: {{duration}}

[View Logs]({{log_url}})
```

  Simple and effective for DevOps alerts. Markdown is sufficient when the notification is informational with a single link.
  </Accordion>

  <Accordion title="Approval request (Adaptive Card)">

```json
{
  "$schema": "http://adaptivecards.io/schemas/adaptive-card.json",
  "type": "AdaptiveCard",
  "version": "1.6",
  "body": [
    {
      "type": "TextBlock",
      "text": "Expense Report Approval",
      "weight": "Bolder",
      "size": "Medium"
    },
    {
      "type": "FactSet",
      "facts": [
        {"title": "Submitted by", "value": data.requester_name},
        {"title": "Amount", "value": data.amount},
        {"title": "Category", "value": data.category},
        {"title": "Date", "value": data.submitted_date}
      ]
    }
  ],
  "actions": [
    {
      "type": "Action.OpenUrl",
      "title": "Approve",
      "url": data.approve_url
    },
    {
      "type": "Action.OpenUrl",
      "title": "Reject",
      "url": data.reject_url
    }
  ]
}
```

  Adaptive Cards render natively in Teams with structured layouts and actionable buttons. Use `FactSet` for key-value data and `Action.OpenUrl` for CTA buttons.
  </Accordion>
</AccordionGroup>

## Variants

Create different template variants for multi-lingual messaging, tenant-specific content, or A/B testing. Add conditions based on tenant, recipient language, or any data from your workflow trigger. The first variant in order matching all its conditions is sent at runtime. The **default** variant acts as a fallback when no specific variant conditions are met.

For details on creating, managing, and selecting variants, see [Template Variants](/docs/template-variants).

## Preview message

Click **Load Preview** to render the template with sample data from the Variables panel. Verify the parsed JSON is valid before committing.

## Commit and publish

Once finalised, click **Commit** to make the template live. Provide a version name and optional description.

<Warning>
  If a variable in the template cannot be rendered at send time (due to mismatch or missing data), SuprSend discards the Teams notification. Other channels in the same template group are still sent.
</Warning>

## Best practices

- **Markdown for simplicity** — if your message is plain text with links, Markdown is faster to author and easier to maintain. Switch to JSONNET only when you need structured layouts.
- **Adaptive Card version** — use version `1.6` for the widest feature support. Older versions may not render some block types.
- **Message length** — Teams truncates Adaptive Cards larger than 28 KB. Keep your payloads lean, especially when iterating over arrays.
- **FactSet for key-value data** — prefer `FactSet` over manual text formatting for structured data (name/value pairs). It renders cleanly across desktop and mobile.
- **Action buttons** — Teams supports `Action.OpenUrl` (opens a link) and `Action.Submit` (posts data back to your bot). For notification workflows, `Action.OpenUrl` is the most common pattern.
- **Testing** — Teams renders Adaptive Cards differently from the [Adaptive Card Designer](https://adaptivecards.io/designer/). Always test in an actual Teams chat before going live.

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Can I use Handlebars in the JSONNET editor?">
    No. The JSONNET editor uses JSONNET syntax (`data.variable_name`), not Handlebars (`{{variable_name}}`). Handlebars is only for the Markdown editor. Use `data['$brand'].brand_name` for special variables.
  </Accordion>

  <Accordion title="Why does my Adaptive Card look different in Teams vs the designer?">
    Teams has its own rendering engine that may differ from the [Adaptive Card Designer](https://adaptivecards.io/designer/). Some styles, layouts, and features may render differently. Always test in an actual Teams conversation before committing.
  </Accordion>

  <Accordion title="What Adaptive Card version should I use?">
    Use version `1.6` for the widest feature support across Teams desktop and mobile clients. Older versions may not render some block types like `FactSet` or `ActionSet`.
  </Accordion>

  <Accordion title="How do I add buttons to a Teams notification?">
    Use `Action.OpenUrl` for link buttons and `Action.Submit` for form submissions. Add them in the `actions` array of your Adaptive Card JSON. See the [Approval Request example](#common-scenarios) for a working pattern.
  </Accordion>

  <Accordion title="What happens if a variable is missing at send time?">
    SuprSend discards the Teams notification for that user. Other channels in the same template group are still sent if they render successfully.
  </Accordion>
</AccordionGroup>

You can design a simple text template with our default markdown editor. For advanced formatting and interactive options like buttons, images, and avatars, you can use Microsoft's [adaptive card design](https://adaptivecards.io/designer/) in JSONNET editor. Please note that the variable format for both editors will be different. We'll cover more about it in the next sections.

SuprSend provides two ways to design MS Teams templates:

- **Markdown editor** — for simple text messages with `{{variable}}` syntax.
- **JSONNET editor** — for rich Adaptive Card templates with buttons, images, and complex layouts.

## Choosing between Markdown and JSONNET

| Scenario | Recommended editor |
|---|---|
| Simple alerts, status updates, plain-text messages | **Markdown** — fastest to set up, uses `{{variable}}` syntax for variables. |
| Notifications with images, buttons, columns, or structured layouts | **JSONNET** — full Adaptive Card support for rich interactive messages. |
| Approval workflows with actionable buttons | **JSONNET** — Adaptive Cards support `Action.Submit` and `Action.OpenUrl` buttons. |

<Info>
  You can switch between Markdown and JSONNET at any time. Content is saved independently for each mode.
</Info>

## Markdown editor

Send simple text templates using the Markdown editor. Variables use `{{variable_name}}` syntax.

### Supported Markdown syntax

Supported markdown syntax in Teams text messages:

| Format | Syntax |
|---|---|
| Headings | `# Heading level 1`. Refer all [heading formats](https://www.markdownguide.org/basic-syntax/#headings) here |
| Line break | End a line with two or more spaces, and then type return *(only 1 continuous line break is supported)* |
| **Bold** | `**bold text**` or `__bold text__` |
| *Italic* | `_italic text_` or `*italic text*` |
| ***Bold Italic*** | `***bold italic text***` or `___bold italic text___` |
| > Blockquotes | `> block quote text` |
| Lists | `(1) First item (2) Second item`. Refer more [lists format here](https://www.markdownguide.org/basic-syntax/#lists-1) |
| `code` | `` `code` `` |
| Links | `[Duck Duck Go](https://duckduckgo.com)` |

### Adding dynamic data in Markdown editor

To add dynamic data, first add the variable data from your event and workflow request in the **Variables panel**.

<Frame caption="Add variables in the Variables panel">
  <img src="/images/docs/a647239-image.png" />
</Frame>

Enter the variables in JSON format. This JSON should be the same as passed in your workflow or event request (it is a part of the `data` field for workflow and `properties` field for event).

<Frame caption="Sample variable data in the Variables panel">
  <img src="/images/docs/d055e38-image.png" />
</Frame>

Now, you can use your added sample by adding variables in the template. Type `{{` and you'll start getting auto-suggestions of the variables added in your sample data below the text field. You can select the variable from the dropdown or directly type it in.

As a general rule, all the variables have to be entered within double curly brackets: `{{variable_name}}`. For URLs and links, we recommend using triple curly braces `{{{url}}}`. This is to avoid escaping HTML entities. You can also write transformations like date-time formatting, if-else statements inside your templates.

<Frame caption="Auto-suggestions when typing variables in the Markdown editor">
  <img src="/images/docs/8405383-image.png" />
</Frame>

## JSONNET editor

Switch to the JSONNET editor for advanced formatting and interactive options like buttons, images, and avatars. Microsoft provides support for [adaptive card design](https://adaptivecards.io/designer/) to design such templates using a drag-and-drop editor. You can design your template in the adaptive card designer and copy the JSON payload from your designer into the Teams JSONNET editor.

SuprSend includes sample templates for quick starts — select one from the right-side options above the editor to start editing. Copy-paste the mock data values in the **Variables panel** to see the preview.

<Warning>
  The `${variable}` syntax used in Adaptive Card is **not supported** in the JSONNET editor. You'll have to add the variable in JSONNET format as `data.variable`.
</Warning>

### Adding dynamic data in JSONNET editor

To add dynamic data, first add the variable data from your event and workflow request in the **Variables panel**.

Once the variables are declared, you can add them in the template as `data.<variable_name>`.

<Info>
  Note that you will be able to enter a variable name even when you have not declared it in the Variables panel. However, the preview will not load without declaring the variables. Hence it's advised to always declare variables before loading the preview of the template.
</Info>

| Variable Type | JSONNET Syntax |
|---|---|
| Parent level | `data.variable_name` |
| Nested object | `data.location.city` |
| Special characters / spaces in key | `data['$brand'].brand_name` or `data.event['first name']` |
| Array element at index | `data.array[0].product_name` |

Below are some examples of how to enter variables in the JSONNET editor:

<AccordionGroup>
  <Accordion title="Add nested variable">
    To enter a nested variable, enter in the format `data.var1.var2.var3`. E.g. to refer to city in the example above, you need to enter `data.location.city`
  </Accordion>

  <Accordion title="Add variable with space and special characters in variable name">
    If you have any space in the variable name, enclose it in square bracket `data.event['first name']` or `data['$brand'].brand_name`
  </Accordion>

  <Accordion title="Add single array element">
    To refer to an array element, enter in format `data.var[index].var2`. E.g. to refer to `product_name` of the first element of the array `array`, enter `data.array[0].product_name`
  </Accordion>

  <Accordion title="Add list of array items">
    Enter in the below format to add a dynamic list of items. Below is an example code to fetch array items in a text field list:

    <CodeGroup>
      ```json JSONNET
      {
        "$schema": "http://adaptivecards.io/schemas/adaptive-card.json",
        "body": [
          {
            "text": product.name + " at " + product.price,
            "type": "TextBlock",
            "wrap": true
          }
          for product in data.products
        ],
        "type": "AdaptiveCard",
        "version": "1.6"
      }
      ```
    </CodeGroup>

    <Warning>
      You'll need to add mock data for the variables added in your JSONNET template to view the parsed JSON template. JSON template will throw an error in case of missing mock data for a variable.
    </Warning>
  </Accordion>
</AccordionGroup>

You will be able to see if your template is rendering properly with the sample mock data by loading the preview of your draft version. Make sure to see the preview before committing the template to check if the parsed JSON is valid or not.

## Commit and publish

Once finalised, click **Commit** to make the template live. Provide a version name and optional description. Your template is now ready to be triggered.

<Warning>
  At the time of sending communication, if there is a variable present in the template whose value is not rendered due to mismatch or missing, SuprSend will simply discard the template and not send that particular notification to your user.

  Please note that the rest of the templates will still be sent. E.g. if there is an error in rendering Teams template, but email template is successfully rendered, Teams notification will not be triggered, but email notification will be triggered by SuprSend.
</Warning>

## Variants

Create different template variants for multi-lingual messaging, tenant-specific content, or A/B testing. Add conditions based on tenant, recipient language, or any data from your workflow trigger. The first variant in order matching all its conditions is sent at runtime. The **default** variant acts as a fallback when no specific variant conditions are met.

For details on creating, managing, and selecting variants, see [Template Variants](/docs/template-variants).

## Common scenarios

<AccordionGroup>
  <Accordion title="Deployment status alert (Markdown)">

```text
**Deployment Completed** ✅

Service: {{service_name}}
Environment: {{environment}}
Version: {{version}}
Duration: {{duration}}

[View Logs]({{log_url}})
```

  Simple and effective for DevOps alerts. Markdown is sufficient when the notification is informational with a single link.
  </Accordion>

  <Accordion title="Approval request (Adaptive Card)">

```json
{
  "$schema": "http://adaptivecards.io/schemas/adaptive-card.json",
  "type": "AdaptiveCard",
  "version": "1.6",
  "body": [
    {
      "type": "TextBlock",
      "text": "Expense Report Approval",
      "weight": "Bolder",
      "size": "Medium"
    },
    {
      "type": "FactSet",
      "facts": [
        {"title": "Submitted by", "value": data.requester_name},
        {"title": "Amount", "value": data.amount},
        {"title": "Category", "value": data.category},
        {"title": "Date", "value": data.submitted_date}
      ]
    }
  ],
  "actions": [
    {
      "type": "Action.OpenUrl",
      "title": "Approve",
      "url": data.approve_url
    },
    {
      "type": "Action.OpenUrl",
      "title": "Reject",
      "url": data.reject_url
    }
  ]
}
```

  Adaptive Cards render natively in Teams with structured layouts and actionable buttons. Use `FactSet` for key-value data and `Action.OpenUrl` for CTA buttons.
  </Accordion>
</AccordionGroup>

## Best practices

<AccordionGroup>
  <Accordion title="Markdown for simplicity">
    If your message is plain text with links, Markdown is faster to author and easier to maintain. Switch to JSONNET only when you need structured layouts.
  </Accordion>
  <Accordion title="Adaptive Card version">
    Use version `1.6` for the widest feature support. Older versions may not render some block types.
  </Accordion>
  <Accordion title="Message length">
    Teams truncates Adaptive Cards larger than 28 KB. Keep your payloads lean, especially when iterating over arrays.
  </Accordion>
  <Accordion title="FactSet for key-value data">
    Prefer `FactSet` over manual text formatting for structured data (name/value pairs). It renders cleanly across desktop and mobile.
  </Accordion>
  <Accordion title="Action buttons">
    Teams supports `Action.OpenUrl` (opens a link) and `Action.Submit` (posts data back to your bot). For notification workflows, `Action.OpenUrl` is the most common pattern.
  </Accordion>
  <Accordion title="Testing">
    Teams renders Adaptive Cards differently from the [Adaptive Card Designer](https://adaptivecards.io/designer/). Always test in an actual Teams chat before going live.
  </Accordion>
</AccordionGroup>

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Can I use {{variable}} syntax in the JSONNET editor?">
    No. The JSONNET editor uses JSONNET syntax (`data.variable_name`), not `{{variable_name}}`. The `{{...}}` syntax is only for the Markdown editor. Use `data['$brand'].brand_name` for special variables.
  </Accordion>

  <Accordion title="Why does my Adaptive Card look different in Teams vs the designer?">
    Teams has its own rendering engine that may differ from the [Adaptive Card Designer](https://adaptivecards.io/designer/). Some styles, layouts, and features may render differently. Always test in an actual Teams conversation before committing.
  </Accordion>

  <Accordion title="What Adaptive Card version should I use?">
    Use version `1.6` for the widest feature support across Teams desktop and mobile clients. Older versions may not render some block types like `FactSet` or `ActionSet`.
  </Accordion>

  <Accordion title="How do I add buttons to a Teams notification?">
    Use `Action.OpenUrl` for link buttons and `Action.Submit` for form submissions. Add them in the `actions` array of your Adaptive Card JSON. See the [Approval Request example](#common-scenarios) for a working pattern.
  </Accordion>

  <Accordion title="What happens if a variable is missing at send time?">
    SuprSend discards the Teams notification for that user. Other channels in the same template group are still sent if they render successfully.
  </Accordion>
</AccordionGroup>

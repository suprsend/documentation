## Overview

An **Email Template** in SuprSend is a reusable design that combines visual elements, dynamic content, and email settings to create personalized communications. Templates support both drag & drop editing and code-based customization, making them accessible for designers and developers alike.

**Why this matters**: Email templates are the foundation of all email communications in SuprSend. Understanding their structure helps developers create consistent, maintainable email campaigns.

### Key Components

- **Body**: Permanent background and layout structure
- **Blocks**: Content containers that can be conditionally displayed  
- **Content**: Text, images, buttons, and other elements within blocks
- **Settings**: Subject, sender details, email markup, and delivery configuration

**Component Logic**: Each component serves a specific purpose - Body provides structure, Blocks enable conditional logic, Content delivers the message, and Settings control delivery behavior.

## Getting Started with Email Templates

### 1. Design Your Email

Start by creating a new email template and use the intuitive drag & drop editor to build your design.

**Design Philosophy**: The drag & drop approach separates content structure from styling, making templates easier to maintain and modify across different campaigns.

#### Using the Drag & Drop Editor

The editor provides a visual interface where you can:
- Add content blocks by dragging them from the sidebar
- Arrange elements with responsive grid layouts
- Preview desktop and mobile views using the toggle in the bottom-left corner

![Email Editor Interface](/images/docs/ab6f529-Screenshot_2021-10-19_at_4.12.49_PM.png "Email Editor Interface showing drag & drop functionality")

**Editor Logic**: Visual editing reduces the learning curve for designers while maintaining the flexibility of HTML-based templates.

#### Adding and Formatting Content Blocks

1. **Select a block type** from the left sidebar (Text, Image, Button, etc.)
2. **Drag it to your canvas** in the desired location
3. **Customize the content** using the right-side settings panel
4. **Apply styling** including colors, fonts, spacing, and alignment

**Block System Logic**: Modular blocks enable reusable components and consistent styling across templates, while the drag & drop interface prevents layout errors.

#### Responsive Design Tips

- Use the **Desktop/Mobile toggle** to preview how your template appears on different devices
- Test with various content lengths to ensure mobile compatibility
- Keep important elements (like CTAs) above the fold on mobile devices

**Responsive Logic**: Email clients have varying CSS support, so responsive design ensures your template looks professional across all devices and screen sizes.

### 2. Configure Email Settings

Click on **"Other Email Settings"** to configure essential email properties:

![Email Settings Panel](/images/docs/b1145ee-Screenshot_2021-10-20_at_1.27.36_PM.png "Email Settings configuration panel")

| Setting | Description | Example | Why It Matters |
|---------|-------------|---------|----------------|
| **Subject** | Email subject line with variable support | `Welcome {{user.first_name}}!` | Personalization increases open rates |
| **From Name** | Display name for the sender | `SuprSend Team` | Builds brand recognition and trust |
| **From Email** | Sender email address (must be registered domain) | `noreply@yourdomain.com` | Domain authentication prevents spam filtering |
| **Reply To** | Email address for replies (must be registered domain) | `support@yourdomain.com` | Enables customer engagement and support |
| **CC/BCC** | Additional recipients (optional) | `manager@company.com` | Facilitates team collaboration and oversight |
| **Email Markup** | Schema.org markup for Gmail actions | See [Markup & Schema.org](#markup--schemaorg) section | Enables interactive email features in Gmail |
| **Enable Batching** | Batch multiple emails together | Yes/No toggle | Improves delivery performance and reduces costs |
| **Tenant Selection** | Multi-tenant template support | Tenant dropdown | Enables white-labeling for different brands |

**Settings Logic**: Each setting affects deliverability, user experience, or compliance. Proper configuration ensures emails reach inboxes and meet user expectations.

**Note**: File attachments are configured when triggering workflows or events, not in the template itself. See [Workflow API documentation](/docs/trigger-workflow) for attachment details.

## Dynamic Content

### Adding Variables

Variables allow you to personalize content for each recipient. Use Handlebars syntax: `{{variable_name}}`

**Variable Logic**: Dynamic content increases engagement by making each email feel personal and relevant to the recipient.

#### Basic Variable Usage

```handlebars
Hello {{user.first_name}},

Your order #{{order.id}} for {{order.total_amount}} has been confirmed.
```

**Syntax Logic**: Handlebars syntax `{{variable}}` is widely supported, easy to read, and prevents conflicts with HTML syntax.

#### Nested Variables

```handlebars
{{user.profile.company.name}}
{{event.location.city}}
{{order.items.0.product_name}}
```

**Nesting Logic**: Dot notation allows access to deeply nested data structures, enabling complex personalization scenarios.

#### Variables with Spaces

```handlebars
{{user.[first name]}}
{{order.[delivery date]}}
```

**Bracket Logic**: Square brackets handle variable names with spaces or special characters, ensuring compatibility with various data sources.

### Auto-suggestions and Merge Tags

When you type `{` in the editor, SuprSend provides auto-suggestions based on your defined variables:

![Variable Auto-suggestions](/images/docs/24e247d-Screenshot_2021-11-21_at_7.23.25_PM.png "Variable suggestions appear when typing curly braces")

**Auto-suggestion Logic**: Real-time suggestions prevent typos and ensure variable names match your data structure exactly.

Alternatively, use the **Merge Tags** button in the text editor toolbar for a visual selection interface:

![Merge Tags Interface](/images/docs/e5ad9be-Screenshot_2021-11-22_at_12.26.23_PM.png "Merge Tags button provides visual variable selection")

**Merge Tags Logic**: Visual selection reduces errors and makes variable insertion more intuitive for non-technical users.

### Working with Arrays

Arrays require special handling in email templates. Use the **Merge Tags** functionality to add array elements:

**Array Logic**: Arrays enable dynamic lists (products, events, etc.) that automatically expand based on data, making templates truly dynamic.

#### Step 1: Define Array Variables

In your **Variables** section, define arrays with sample data:

```json
{
  "products": [
    {
      "name": "Product 1",
      "price": "$29.99",
      "image": "https://example.com/product1.jpg"
    },
    {
      "name": "Product 2", 
      "price": "$39.99",
      "image": "https://example.com/product2.jpg"
    }
  ]
}
```

**JSON Structure Logic**: Consistent data structure enables predictable template rendering and easier debugging.

#### Step 2: Associate Array with Row

1. Select a **Row** block in your template
2. Click the array button that appears in the bottom-left corner
3. Choose your array from the dropdown

![Array Association](/images/docs/1bfe489-Screenshot_2021-11-22_at_2.33.08_PM.png "Array association button appears when selecting a Row block")

**Row Association Logic**: Rows are the container for repeatable content, allowing the system to automatically duplicate content for each array element.

#### Step 3: Select Array Variables

Once associated, array variables become available in auto-suggestions:

![Array Variables Available](/images/docs/05cb7c2-Screenshot_2021-11-22_at_2.36.16_PM.png "Array variables now appear in suggestions")

**Dynamic Rendering Logic**: The row automatically repeats for each array element when the email is sent, creating dynamic lists without manual template duplication.

## Display Conditions

Display conditions allow you to show or hide content blocks based on user data or preferences.

**Conditional Logic**: Display conditions enable A/B testing, personalization, and targeted messaging without creating multiple templates.

### Adding Display Conditions

1. **Create a separate block** for conditional content
2. **Select the block** and check "Display Conditions" in settings
3. **Define your condition** using the supported operators

![Display Conditions Setup](/images/docs/dcc458e-display_email.png "Display Conditions checkbox in block settings")

**Block Separation Logic**: Separate blocks for conditional content ensure clean template structure and easier maintenance.

### Condition Syntax

Use this format: `(condition <key> <operator> <value>)`

**Syntax Logic**: Lisp-like syntax provides clear, readable conditions that can be easily parsed and validated by the system.

#### Supported Operators

| Operator | Description | Example | Use Case |
|----------|-------------|---------|----------|
| `==` | Equals (loose comparison) | `(condition city "==" "New York")` | String matching with type coercion |
| `===` | Strict equals | `(condition status "===" "active")` | Exact value and type matching |
| `>` | Greater than | `(condition age ">" 18)` | Numeric comparisons |
| `<` | Less than | `(condition score "<" 100)` | Threshold-based logic |
| `>=` | Greater than or equal | `(condition amount ">=" 50)` | Inclusive range checks |
| `<=` | Less than or equal | `(condition quantity "<=" 10)` | Limit validation |
| `!=` | Not equal | `(condition role "!=" "admin")` | Exclusion logic |
| `!==` | Strict not equal | `(condition type "!==" "premium")` | Exact exclusion |

**Operator Logic**: Each operator serves specific comparison needs, from simple equality to complex threshold-based decisions.

#### Complex Conditions

**OR Condition** - Display if any condition is true:
```lisp
(or (condition city "==" "New York") (condition city "==" "Chicago"))
```

**OR Logic**: Useful for showing content to users in multiple locations or with multiple qualifying attributes.

**AND Condition** - Display only if all conditions are true:
```lisp
(and (condition monthly_bill ">=" 100) (condition annual_bill ">=" 1000))
```

**AND Logic**: Ensures all criteria must be met, useful for premium features or high-value customer targeting.

### Example Use Cases

- **User Type**: Show premium features only to paid users
- **Location**: Display region-specific content
- **Behavior**: Show different CTAs based on user engagement level

**Use Case Logic**: Each use case demonstrates how conditional logic can create personalized experiences without template duplication.

## Markup & Schema.org

### What is Email Markup?

Email markup uses [schema.org](https://schema.org/) structured data to add interactive elements directly in Gmail, such as:
- Event confirmations
- Flight reservations  
- Order tracking
- One-click actions

**Markup Logic**: Structured data enables email clients to understand content context and provide interactive features, improving user engagement.

### Setup Requirements

1. **Register with Google** - [Submit your application](https://docs.google.com/forms/d/e/1FAIpQLSfT5F1VJXtBjGw2mLxY2aX557ctPTsCrJpURiKJjYeVrugHBQ/viewform?pli=1)
2. **Follow Google's guidelines** - [Registration requirements](https://developers.google.com/gmail/markup/registering-with-google)
3. **Test with same sender/recipient** - Use identical email addresses during testing

**Registration Logic**: Google's approval process ensures quality and prevents abuse of interactive email features.

### Adding Markup to Templates

1. Go to **Other Email Settings** → **Email Markup**
2. Add your schema.org JSON with Handlebars variables
3. Reference [Google's markup reference](https://developers.google.com/gmail/markup/reference) for examples

**Implementation Logic**: Markup must be valid JSON-LD and follow schema.org standards to be recognized by email clients.

#### Example Schema with Variables

```json
{
  "@context": "https://schema.org",
  "@type": "EventReservation",
  "reservationNumber": "{{booking.confirmation_code}}",
  "reservationStatus": "https://schema.org/Confirmed",
  "event": {
    "@type": "Event",
    "name": "{{event.name}}",
    "startDate": "{{event.start_date}}",
    "location": {
      "@type": "Place",
      "name": "{{event.venue}}"
    }
  }
}
```

**Schema Logic**: The schema defines the data structure that Gmail will recognize, while Handlebars variables enable dynamic content injection.

## Email Preview

### Testing Your Template

1. **Use the Preview panel** to see how your template renders
2. **Test with sample data** to verify variables display correctly
3. **Check responsive views** for desktop and mobile compatibility

**Preview Logic**: Preview functionality allows developers to validate templates before sending, reducing errors and improving user experience.

### Common Preview Issues

If variables aren't rendering properly, check:

1. **Variable declaration** - Ensure variables are defined in the **Variables** section
2. **Syntax accuracy** - Verify Handlebars syntax: `{{variable_name}}`
3. **Data structure** - Confirm nested variables match your data structure

**Validation Logic**: Systematic checking prevents runtime errors and ensures template reliability.

<Warning>
  **Important**: If a template fails to render due to missing or mismatched variables, SuprSend will discard that notification entirely. Other templates in the same workflow will still be sent.
  
  Example: If email template fails but push notification succeeds, only the push will be delivered.
</Warning>

**Failure Logic**: Template failures are isolated to prevent cascading errors, ensuring other communication channels remain functional.

## Publishing and Testing

### Publish Draft

1. **Save your template** as a draft
2. **Click "Publish Draft"** when ready for production
3. **Test with real data** to ensure everything works as expected

**Publishing Logic**: Draft-to-production workflow ensures quality control and prevents accidental deployment of incomplete templates.

### Template Validation

Before publishing, verify:
- All variables have sample data
- Display conditions use valid syntax
- Email markup follows schema.org standards
- Responsive design works on all devices

**Validation Logic**: Comprehensive validation prevents production issues and ensures consistent user experience.

## Troubleshooting

### Common Issues

| Problem | Solution | Root Cause |
|---------|----------|------------|
| **Variables not rendering** | Check variable names and sample data in Variables section | Data mismatch or missing variable definitions |
| **Template not sending** | Verify sender domain is registered with your email vendor | Domain authentication failure |
| **Markup not working** | Ensure Google approval and test with same sender/recipient | Markup validation or approval pending |
| **Mobile display issues** | Use responsive design blocks and test mobile preview | CSS compatibility or responsive design issues |
| **Attachments not working** | Configure attachments in workflow trigger, not template | Attachments are workflow-level, not template-level |
| **Batching not functioning** | Verify batching is enabled in email settings | Batching configuration required in template settings |

**Troubleshooting Logic**: Systematic problem identification and solution mapping enables faster resolution and learning.

### Debugging Checklist

- [ ] Variables declared in Mock Data
- [ ] Handlebars syntax correct (`{{variable}}`)
- [ ] Sender domain registered with email vendor
- [ ] Display conditions use valid operators
- [ ] Email markup follows schema.org format
- [ ] Template previews correctly with sample data
- [ ] Batching enabled if required
- [ ] Tenant selection configured for multi-tenant use

**Checklist Logic**: Sequential validation ensures all critical components are properly configured before deployment.

## FAQs

<Accordion title="Why does my email look different in Gmail/Outlook compared to the preview?" defaultOpen={false}>
  Email clients strip certain HTML tags and CSS for security reasons. Use email-safe HTML and refer to [Campaign Monitor's CSS support guide](https://www.campaignmonitor.com/css/) for client compatibility.
  
  **Technical Reason**: Email clients implement strict security policies that remove potentially dangerous HTML/CSS, causing rendering differences.
</Accordion>

<Accordion title="How do I test email markup before Google approval?" defaultOpen={false}>
  During testing, use the same email address for both sender and recipient (e.g., from support@yourdomain.com to support@yourdomain.com). This allows markup testing while your application is pending.
  
  **Testing Logic**: Same-address testing bypasses Google's approval requirement for development and validation purposes.
</Accordion>

<Accordion title="What happens if a variable is missing when sending?" defaultOpen={false}>
  SuprSend will discard the entire notification if any variable fails to render. Ensure all variables have fallback values or are properly validated before sending.
  
  **Failure Logic**: Template failure isolation prevents partial or corrupted emails from being sent, maintaining quality standards.
</Accordion>

<Accordion title="Can I use custom HTML in the drag & drop editor?" defaultOpen={false}>
  Yes, you can switch to code view for custom HTML, but be aware that email clients may strip certain elements. Test thoroughly across different email clients.
  
  **Flexibility Logic**: Code view provides advanced customization while maintaining the safety of the visual editor for basic operations.
</Accordion>

<Accordion title="How do I add file attachments to emails?" defaultOpen={false}>
  File attachments are configured when triggering workflows or events, not in the template itself. Use the `addAttachment()` method in your workflow trigger API call. See [Workflow API documentation](/docs/trigger-workflow) for details.
  
  **Attachment Logic**: Attachments are dynamic content that varies per email, so they're handled at the workflow level rather than the template level.
</Accordion>

<Accordion title="What is email batching and when should I use it?" defaultOpen={false}>
  Email batching groups multiple emails together for efficient delivery, reducing costs and improving deliverability. Enable it when sending high-volume campaigns or when you want to optimize delivery timing.
  
  **Batching Logic**: Batching improves email infrastructure efficiency by reducing the number of individual API calls and optimizing delivery schedules.
</Accordion>

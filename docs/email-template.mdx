## Overview

The email editor in SuprSend gives you a full visual design environment alongside direct HTML access — whichever way you prefer to work. Every email template has two parts that are always in sync:

- **Design Editor** — drag-and-drop canvas for building HTML emails visually
- **Plain Text** — a plain-text version sent alongside the HTML for email clients that don't render HTML

Both live under the same variant tab. You switch between them using the sub-tabs at the top of the editor.

---

## Getting Started

To add an Email channel to a template, open the template in edit mode and click **+** in the channel tab row. Select **Email** from the channel picker and click **Add Channels**. SuprSend creates a `default` variant for Email and opens the Design Editor.

---

## Email Settings

The **From Name**, **From Email**, and **Subject** fields are displayed in the header row above the canvas. Click the **pencil icon** on the right end of the header row to open the **Email Settings** modal.

### Required fields

| Field | Required | Description |
| --- | --- | --- |
| **Subject** | Yes | The email subject line. Supports Handlebars — e.g. `Your order {{order_id}} has shipped`. |
| **From Name** | No | The display name recipients see in their inbox (e.g. `Acme Support` or `{{$brand.brand_name}}`). |
| **From Email** | No | The sending address (e.g. `no-reply@acme.com`). Must be a verified domain in your vendor settings. |

<Info>
  If **From Name** and **From Email** are left blank, SuprSend falls back to the values configured in your vendor settings. Set them here only when you need to override the vendor default — for example, to send from a tenant-specific address.
</Info>

### Other Settings

Expand the **Other Settings** section in the modal for additional email headers and delivery options:

| Field | Description |
| --- | --- |
| **Preheader Text** | The preview text shown in the inbox below the subject line, before the email is opened. If not set, email clients pull the first line of body text. Use this to complement your subject line and improve open rates. |
| **Cc** | One or more addresses to carbon-copy, comma-separated (e.g. `cc1@example.com, cc2@example.com`). |
| **Bcc** | One or more addresses to blind carbon-copy, comma-separated. |
| **Reply To** | The address replies go to when a recipient clicks Reply. Useful when the From Email is a no-reply address. |
| **Add Multiple Tos** | Send the same email to additional recipients beyond the primary user, comma-separated. |
| **Email Markup JSON** | Structured data added to the email as JSON-LD markup — used for rich inbox features like Google Actions (e.g. one-click RSVP or order tracking directly from Gmail). |

All fields in Other Settings support Handlebars variables. Click **Save** to apply, or **Cancel** to discard.

<Tip>
  Preheader text is one of the highest-leverage fields in email. A subject + preheader pair like `Your order has shipped ✈️` / `Track your package — estimated delivery Friday` gives recipients full context before they open.
</Tip>

## Design Editor

The Design Editor is a drag-and-drop canvas for building HTML emails without writing code. The right panel has five tabs: **Content**, **Blocks**, **Body**, **Images**, and **Uploads**.

### Canvas

The canvas is where your email takes shape. Drag any content block from the **Content** tab on the right and drop it into the canvas. Click any placed block to select it — its settings appear in the right panel. Use the floating toolbar above a selected block to mark it as complete, add tags, duplicate, or delete it.

At the bottom of the canvas:

| Control | Description |
| --- | --- |
| **Undo / Redo** | Step backward or forward through canvas changes. |
| **Preview** (eye icon) | Full-screen preview of the rendered email. |
| **Desktop / Mobile** | Toggle the canvas between desktop and mobile viewport widths. |

### Switching to HTML or copying source

Use the buttons in the top-right of the editor area:

| Button | Description |
| --- | --- |
| **Design** | Visual drag-and-drop canvas (default). |
| **HTML** | Raw HTML code editor — edit the source directly. Changes sync back to the Design view. |
| **Clipboard icon** | Copies the full HTML source to your clipboard. |

## Content Blocks

These are the building blocks you drag onto the canvas from the **Content** tab.

| Block | Description |
| --- | --- |
| **Columns** | Multi-column layout container. Use to build side-by-side content sections. |
| **Button** | CTA button with configurable label, link, colors, and padding. |
| **Divider** | Horizontal rule for visual separation between sections. |
| **Heading** | Styled heading text. Configure font size, weight, color, and alignment. |
| **Paragraph** | Body text block. Supports rich formatting and Handlebars variables. |
| **Image** | Inline image with alt text, link, width, and alignment settings. |
| **Menu** | A row of navigation links — useful for header nav or footer links. |
| **HTML** | Raw HTML block. Write any custom markup directly inside the email canvas. |
| **Table** | Tabular data layout — useful for order line items, pricing tables, or structured data. |
| **Tenant** | Pre-built branded block that auto-populates from your tenant's properties. See [Tenant Block](#tenant-block). |

## Tenant Block

The Tenant block is a special content block for building white-labelled emails. When you drop it onto the canvas, it renders as a branded header using the active tenant's properties — logo, brand colors, and footer bar — pulled automatically at send time from the tenant's configuration.

The block has a **Block Type** dropdown letting you choose between `Header` and other layout variants. The right panel exposes these settings when the block is selected:

| Setting | Description |
| --- | --- |
| **Background Color Code** | Hex code for the block background. Overrides the tenant's primary color if set. |
| **Background Color Picker** | Visual color picker alternative to typing a hex code. |
| **Logo Height** | Height of the tenant logo in pixels (default: 80). |
| **Logo Width** | Width of the tenant logo in pixels (default: 150). |
| **BottomBar Color Code** | Hex code for the colored bar at the bottom of the header block. |

In the canvas, the Tenant block pulls the logo URL from `$brand.logo` and colors from `$brand.primary_color`, `$brand.secondary_color`, and `$brand.tertiary_color`. These resolve at send time from whichever tenant the notification is sent for.

To preview with a real tenant's branding, select a tenant from the **Tenant** dropdown in the Variables panel — the canvas updates live.

<Info>
  You can also reference tenant properties manually anywhere in the email using `{{$brand.brand_name}}`, `{{$brand.properties.address}}`, etc. The Tenant block is a convenience wrapper for the header and footer — it does not limit where tenant data can appear.
</Info>

## Saved Blocks

The **Blocks** tab in the right panel is a library of reusable content blocks saved across your workspace. Use it to maintain consistent components — footers, headers, disclaimer sections — across multiple templates without rebuilding them each time.

Blocks are searchable and organised by name. Click any block to insert it at the bottom of the canvas, or drag it to a specific position. Any block you build can be saved to this library for reuse.

---

## Body Settings

The **Body** tab controls the global visual defaults that apply to the entire email — background, fonts, and layout.

| Setting | Description |
| --- | --- |
| **Text Color** | Default text color for the entire email. Individual blocks can override this. |
| **Background Color** | The outer background behind the email content area. |
| **Content Width** | Width of the email content column in pixels (default: 500px). |
| **Content Alignment** | Left-aligned or center-aligned content column. |
| **Font Family** | Default typeface for the email (e.g. Arial). |
| **Font Weight** | Default font weight — Regular, Bold, etc. |

These are global defaults. Any block-level setting overrides the corresponding body setting for that block only.

## Images

The **Images** tab gives you access to a stock image library and AI image generation — without leaving the editor.

- **Search** millions of free images from Unsplash, Pexels, and Pixabay. All images are licensed under Creative Commons Zero (CC0) — free to use commercially.
- **AI image generation** — describe what you need and the AI generates a custom image for you. Click **See the Magic** to open the generation flow.

Click any image to insert it into a selected Image block on the canvas, or drag it directly onto the canvas.

---

## Uploads

The **Uploads** tab is your workspace image library. Upload your own images by clicking **Upload Image** or dragging files into the drop zone. Uploaded images are stored and searchable by name, available across all templates in the workspace.

Use this for logos, product images, brand assets, and any image that shouldn't come from a public stock source.

## Plain Text

The **Plain Text** sub-tab lets you write or manage a plain-text version of the email. Email clients that cannot render HTML display this version instead. It is also used by some spam filters and accessibility tools.

**How it works:**

- If you leave Plain Text blank, SuprSend **auto-generates** it from your HTML content on every commit. You don't need to maintain it manually.
- If you write your own plain text, it is used as-is and the auto-generation is skipped for that variant.
- Click **Fetch from HTML** at any time to pull the current HTML content into the Plain Text editor as a starting point — useful when you want to manually refine the auto-generated version.

A **Preview** panel on the right shows the plain text exactly as it will be sent.

<Note>
  Plain text auto-generation happens at commit time, not as you type. If you want to see what the auto-generated version will look like before committing, click **Fetch from HTML**.
</Note>

## Dynamic Content and Variables

The email editor fully supports Handlebars for dynamic content. Use `{{variable}}` anywhere in the canvas — inside text blocks, subject lines, button labels, image URLs, or link hrefs.

Define your variables in the **Variables `{}`** panel in the left sidebar before using them in the template. This gives you:
- **Autocomplete** — type `{{` anywhere in a text block to see available variables
- **Live preview** — the canvas substitutes real values so you see the rendered output as you design
- **Consistency** — variable names are shared across all channels in the template

For URLs and strings that contain special characters (`&`, `?`, `=`), use triple braces to prevent HTML-escaping: `{{{tracking_url}}}`.

### Variable sources available in email

| Source | Example syntax | What it pulls |
| --- | --- | --- |
| Trigger payload | `{{order_id}}` | Data sent when the workflow is triggered |
| Nested payload key | `{{order.shipping.city}}` | Nested object properties |
| Array item | `{{items.[0].name}}` | First item in an array |
| Recipient profile | `{{$recipient.first_name}}` | Properties from the user's SuprSend profile |
| Tenant branding | `{{$brand.brand_name}}` | Properties from the linked tenant |
| Tenant custom property | `{{$brand.properties.address}}` | Custom properties set on the tenant |
| Batched event count | `{{$batched_events_count}}` | Number of events batched in this send |

For conditionals, loops, date formatting, and other helpers, see [Handlebars Helpers](/docs/handlebars-helpers).

## Previewing Your Email

The Design Editor canvas updates live as you edit, with variable placeholders replaced by values from the Variables panel.

For a full-screen, client-accurate preview, click the **Preview** (eye icon) in the bottom toolbar. Toggle between **Desktop** and **Mobile** views to check responsive rendering.

To preview with a specific user's data, go to the Variables panel, open the **Recipient** section, and search for a real user by name or email. Their live profile properties load as the variable context.

To preview with a specific tenant's branding, select a tenant from the **Tenant** dropdown in the Variables panel.

## Sending a Test Email

Use the **Test** button in the top-right corner to send a real email to a real inbox before committing.

1. Enter the `distinct_id` or email of the recipient and click **Search**.
2. Select **Email** from the available channels.
3. Click **Trigger Test using mock data**.

The email is sent immediately using the values from your Variables panel. Check [Logs](/docs/logging) to confirm delivery.

<Warning>
  Every `{{variable}}` in the email must have a corresponding value in the Variables panel. Missing values cause the email to fail rendering and not send.
</Warning>

## Committing

When the email content is ready, click **Commit** in the top bar. This publishes the current state — Design Editor content, Plain Text, sender settings, and subject — as a new live version. All emails sent from this template after the commit will use the new content.

The plain text version (if left empty) is auto-generated from the HTML at the moment of commit.

See [Templates → Committing](/docs/templates#committing) for how versioning works across the full template.

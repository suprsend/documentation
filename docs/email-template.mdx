The email editor supports three content modes. Switch between them using the tabs at the top of the editor.

| Mode | Best for |
|---|---|
| **Design Editor** | Drag-and-drop WYSIWYG builder. Responsive by default. No HTML knowledge needed. |
| **HTML Editor** | Full HTML code editor for hand-crafted templates or pasting HTML from external tools. |
| **Plain Text** | Raw text fallback for recipients whose email clients restrict HTML. Better deliverability for transactional messages. |

<Frame caption="Email HTML Editor with code and live preview">
  <img src="/images/docs/templates-editor-email-html.png" />
</Frame>

<Info>
  Whichever mode is active when you click **Commit** is the version that gets published. Design Editor and HTML Editor save independently.
</Info>

## Email settings

Subject, From Name, and From Email are shown inline above the editor. Click the **edit** icon (pencil) to open the full Email Settings panel.

<Frame caption="Inline email settings — click the edit icon to expand">
  <img src="/images/docs/templates-editor-email-settings-edit.png" />
</Frame>

<Frame caption="Email Settings panel">
  <img src="/images/docs/templates-editor-email-settings.png" />
</Frame>

| Field | Description |
|---|---|
| Subject | Single-line text. Supports Handlebars variables. |
| From Name | Display name shown to the recipient. |
| From Email | Sender address. Domain must be registered with your email vendor. |
| Preheader Text | *Optional.* Preview text shown next to the subject in the inbox list. If not set, email clients pull the first text from the body. Recommended: 40–140 characters. |
| CC | *Optional.* Comma-separated email addresses. Supports Handlebars variables. |
| BCC | *Optional.* Comma-separated email addresses. Supports Handlebars variables. |
| Reply To | *Optional.* Reply-to address. Domain must be registered with your vendor. |
| Add Multiple Tos | *Optional.* Additional recipient addresses. Supports Handlebars variables. |

<Info>
  Values for Subject, From Name, and From Email are picked from your vendor settings if left blank. All fields support Handlebars variables for dynamic personalisation.
</Info>

## Design Editor

The drag-and-drop editor lets you build responsive emails visually. The right sidebar has five panels:

| Panel | Purpose |
|---|---|
| **Content** | Drag content blocks (text, buttons, images, etc.) into your layout. |
| **Blocks** | Save and reuse custom block layouts across templates. |
| **Body** | Set global defaults — background colour, content width, fonts, link colour. |
| **Images** | Browse free stock images from Unsplash, Pexels, and Pixabay (Creative Commons Zero). |
| **Uploads** | Upload and manage your own images. |

### Content blocks

Drag blocks from the **Content** panel into a row. Each block has a settings panel when selected.

| Block | What it does | Key settings |
|---|---|---|
| **Columns** | Adds a row with a column layout (1-col, 2-col, 3-col, asymmetric splits). | Column count, width ratios. |
| **Heading** | Large formatted text for titles. | Font size, colour, weight, alignment, padding. |
| **Paragraph** | Body text with rich toolbar (bold, italic, links, lists). | Font, colour, alignment, line height. |
| **Button** | Call-to-action button. | URL, target, background colour, text colour, font, width, border radius, padding. |
| **Image** | Upload, paste URL, or drag from Images/Uploads panel. | Alt text, padding, responsive visibility (Hide on Desktop / Hide on Mobile). |
| **Divider** | Horizontal line separator. | Colour, thickness, width, padding. |
| **Menu** | Navigation menu bar. | Links, alignment, separator. |
| **HTML** | Raw HTML block for custom code or widgets. | HTML source. |
| **Table** | Data table. | Rows, columns, cell content. |
| **Tenant** | Branded header, footer, or button — dynamically renders per tenant. | See [Tenant branding](#tenant-branding) below. |

**Common settings on every block:**

- **Display Conditions** — show/hide the block based on a condition (see [Display conditions](#display-conditions)).
- **Spacing** — alignment, padding (uniform or per-side), border (style, width, colour, radius).
- **Responsive Design** — toggle **Hide on Desktop** or **Hide on Mobile** to show different content per device.

### Saved blocks

Save any row as a reusable block:

1. Select a row and click the **save** icon in the row header.
2. Name the block and save.
3. Reuse it from the **Blocks** panel in any template.

<Note>
  Saved blocks are a **design reference** — a copy is inserted each time. They are not centrally managed. Editing the saved block does not update templates that already use it.
</Note>

### Tenant branding

The **Tenant** block renders a pre-designed branded header, footer, or button that dynamically picks up each tenant's identity (logo, colours, address) from their profile. The branded button uses the tenant's **secondary colour** instead of the primary.

1. Drag the **Tenant** block into your layout.
2. Select a tenant in the **Variables panel** on the left.
3. The preview updates with that tenant's branding. To change tenant properties, click the **edit** (pencil) icon next to the Tenant heading — this opens the tenant profile for editing.

At send time, SuprSend resolves the tenant from `tenant_id` in the workflow trigger. One template serves all tenants — no duplication needed.

<Tip>
  For granular control beyond the Tenant block, use `$brand` variables directly in any block:
  - `{{$brand.logo}}`, `{{$brand.primary_color}}`, `{{$brand.secondary_color}}`
  - `{{$brand.brand_name}}`, `{{$brand.properties.address}}`
  - `{{$brand.$hosted_preference_url}}` — unsubscribe/preference link
</Tip>

Full control over the email markup. Paste HTML from external tools or write from scratch. A live **Preview** panel renders on the right.

<Frame caption="HTML Editor with code and live preview">
  <img src="/images/docs/templates-editor-email-html.png" />
</Frame>

Switch between **Design** and **HTML** using the top-right toggle. Both save independently — whichever editor is open at the time of **Commit** is the version that gets published.

### HTML/CSS stripping by email clients

Email clients strip certain HTML tags and CSS properties for security. Each client has different restrictions:

| Email Client | What gets stripped | Reference |
|---|---|---|
| **Gmail** | `<style>` in `<head>` (partially supported), `position`, `float`, background images in some cases, `<form>` elements | [Gmail CSS support](https://developers.google.com/gmail/design/css) |
| **Outlook** | Most CSS (`float`, `position`, `max-width`), uses Word rendering engine, poor `<div>` support — use `<table>` layouts | [Outlook CSS guide](https://www.campaignmonitor.com/css/email-client/outlook-2021/) |
| **Apple Mail** | Most permissive — supports `<style>`, media queries, web fonts | [Apple Mail CSS](https://www.campaignmonitor.com/css/email-client/apple-mail/) |
| **Yahoo Mail** | Strips `<style>` in `<head>`, rewrites class names | [Yahoo CSS guide](https://www.campaignmonitor.com/css/email-client/yahoo-mail/) |

For a full comparison across all email clients, see [Can I Email](https://www.caniemail.com/) and [Campaign Monitor CSS Support](https://www.campaignmonitor.com/css/).

<Tip>
  **Validate your HTML before committing.** Copy your email HTML and use this prompt with an AI assistant (Claude, ChatGPT, etc.) to check for stripping issues:

  _"Here is my email HTML template. Check it against Gmail, Outlook, Apple Mail, and Yahoo Mail CSS support. List any HTML tags or CSS properties that will be stripped or not rendered correctly in each client, and suggest alternatives."_

  Paste your HTML after the prompt. This catches issues before they reach production.
</Tip>

<Warning>
  Common pitfalls:
  - **Outlook**: Avoid `<div>` based layouts — use `<table>` for structure. `max-width`, `float`, and `position` are ignored.
  - **Gmail**: Inline your CSS. Gmail partially supports `<style>` in `<head>` but inlining is safer.
  - **All clients**: Avoid JavaScript, `<form>` elements, and external fonts (except Apple Mail). Use web-safe font stacks with fallbacks.
</Warning>

## Plain Text editor

Plain text provides a raw text fallback for recipients who block HTML. Uses Handlebars for variables with a live preview on the right.

Plain text emails have **better deliverability and inbox landing rates** — making them ideal for sales outreach, cold emails, and 1:1 communication where you want the message to feel personal rather than designed.

<Frame caption="Plain Text editor with Fetch from HTML">
  <img src="/images/docs/templates-editor-email-plaintext-new.png" />
</Frame>

If left blank, plain text is **auto-generated from HTML on every commit**. Click **Fetch from HTML** to pull the latest HTML content manually. Once you edit the plain text, auto-generation stops and your custom text is preserved.

<Tip>
  **When to use Plain Text over HTML:**
  - Sales and outreach emails — plain text feels personal and avoids spam filters triggered by heavy HTML.
  - OTP and verification codes — minimal formatting, maximum deliverability.
  - Internal alerts — when design doesn't matter and speed of delivery does.
</Tip>

## Variants

Create different template variants for multi-lingual messaging, tenant-specific content, or A/B testing. Add conditions based on tenant, recipient language, or any data from your workflow trigger. The first variant in order matching all its conditions is sent at runtime. The **default** variant acts as a fallback when no specific variant conditions are met.

For details on creating, managing, and selecting variants, see [Template Variants](/docs/template-variants).

## Adding dynamic content

Variables use Handlebars syntax (`{{variable_name}}`). Auto-suggestions appear as you type `{`. For the full variable reference (payload, user, tenant), see [Adding variable content](/docs/templates#adding-variable-content).

### Merge Tags

In the Design Editor, click the **Merge Tags** button in the text toolbar to insert variables from a dropdown. Merge Tags appear only when variables are defined in the Variables panel.

### Repeating content (arrays)

To render a dynamic list (e.g., order line items):

1. Declare an array in the Variables panel (Input Payload).
2. Click a row in the designer — an array association button appears in the bottom-left.
3. Select your array. The row turns green and repeats for each item at send time.

Use this for order summaries, product lists, batched notifications, or any content where the number of items varies.

## Display conditions

Show or hide any row or block based on runtime data.

<Steps>
  <Step title="Select the row or block">
    Click the element you want to conditionally display.
  </Step>
  <Step title="Open Display Conditions">
    Expand **Display Condition** in the settings panel.
  </Step>
  <Step title="Build the condition">
    Set **Property**, **Operator**, and **Value**. Combine with **+ AND** or **+ OR**.
  </Step>
</Steps>

<Frame caption="Display Conditions — Property, Operator, Value with AND/OR">
  <img src="/images/docs/templates-editor-email-display-conditions-modal.png" />
</Frame>

**Example:** Show a block only for tenant "uber" → Property: `$brand.brand_id`, Operator: `==`, Value: `"uber"`.

| Operator | Meaning |
|---|---|
| `==` | Equals (loose) |
| `===` | Equals (strict type) |
| `>` `<` `>=` `<=` | Comparison |
| `!=` `!==` | Not equals |

## Preview and testing

Use the **preview** icon (eye) in the bottom toolbar for a rendered preview. Toggle **Desktop** / **Mobile** to check responsive behaviour.

Variables render using data from the Variables panel. If a variable doesn't render, check that it's defined in the panel and the name matches exactly.

<Warning>
  If a variable cannot be rendered at send time, SuprSend discards that channel's notification. Other channels in the template group are still sent.
</Warning>

## Best practices

<AccordionGroup>
  <Accordion title="Subject line">
    Keep under 50 characters. Most mobile clients truncate beyond this.
  </Accordion>
  <Accordion title="Preheader text">
    Set it explicitly. If blank, email clients pull the first body text, which may not be meaningful.
  </Accordion>
  <Accordion title="Image-to-text ratio">
    Emails that are mostly images often land in spam. Balance text and images, with alt text on every image.
  </Accordion>
  <Accordion title="Responsive testing">
    Preview on both Desktop and Mobile using the bottom toolbar. The Design Editor produces responsive layouts by default; custom HTML may not.
  </Accordion>
  <Accordion title="Preference links">
    Include an unsubscribe link. The Tenant footer includes this via `{{$brand.$hosted_preference_url}}`.
  </Accordion>
  <Accordion title="Triple braces for URLs">
    Use `{{{url}}}` for any value with `&`, `=`, `?`. Double braces HTML-escape these, breaking links.
  </Accordion>
</AccordionGroup>

## Frequently asked questions

<AccordionGroup>
  <Accordion title="How do I add text and change its colour/font?">
    Drag a **Paragraph** or **Heading** block into a row. Click the block to select it — use the rich text toolbar for bold, italic, links, and lists. In the right panel, change **Text Colour**, **Font Family**, **Font Size**, and **Font Weight**. These override the Body-level defaults for that specific block.
  </Accordion>

  <Accordion title="How do I style a button (colour, size, border)?">
    Drag a **Button** block into a row. Select it and configure in the right panel:
    - **Action** — URL and target (same tab / new tab).
    - **Button Options** — background colour, text colour, width (auto / full), font family, weight, size, line height, letter spacing.
    - **Spacing** — alignment, padding, border, border radius for rounded corners.
  </Accordion>

  <Accordion title="How do I add images?">
    Three ways: (1) Drag an **Image** block and upload directly. (2) Paste a public URL in the **Image URL** field. (3) Browse the **Images** panel for free stock photos or the **Uploads** panel for your own images. Set alt text for accessibility.
  </Accordion>

  <Accordion title="How do I add custom HTML?">
    Drag an **HTML** block into a row and paste your code. This is useful for embedding widgets, custom layouts, or code from external tools. The HTML renders within the row container.
  </Accordion>

  <Accordion title="How do I add variables / dynamic content?">
    Type `{{` in any text field — auto-suggestions appear based on the Variables panel data. Or use the **Merge Tags** button in the text toolbar. For URLs with special characters, use triple braces `{{{url}}}` to avoid HTML-escaping. See [Adding variable content](/docs/templates#adding-variable-content) for the full syntax reference.
  </Accordion>

  <Accordion title="How does Tenant branding work?">
    The **Tenant** block auto-renders each tenant's logo, brand colours, and address. It has pre-designed header, footer, and button layouts. The branded button uses the tenant's **secondary colour**. All properties come from the tenant profile (selected in the left panel) — update the tenant profile to change branding. At send time, the tenant is resolved from `tenant_id` in the trigger, so you maintain one template for all tenants. For custom styling, use `{{$brand.primary_color}}`, `{{$brand.logo}}`, etc. directly in any block.
  </Accordion>

  <Accordion title="What are Display Conditions?">
    Display conditions let you show/hide a row or block at send time based on a condition — e.g., show a "Pro" badge only if `plan == "pro"`, or show a tenant-specific banner using `$brand.brand_id == "acme"`. Set conditions via the Display Condition panel on any row or block. You can combine multiple conditions with AND/OR logic.
  </Accordion>

  <Accordion title="How do I repeat content for a list of items (Merge Tags / arrays)?">
    Associate a row with an array variable. The row repeats for each item in the array — useful for order line items, product lists, or batched notification digests. Use `{{$batched_events_count}}` and iterate over `{{#each $batched_events}}` for digest/batched workflows.
  </Accordion>

  <Accordion title="How do I change global styles (background, width, link colour)?">
    Open the **Body** panel (right sidebar). Set defaults for text colour, background, content width, font, and link colour. These apply everywhere unless overridden at the row, column, or block level.
  </Accordion>

  <Accordion title="Can I customise rows and columns individually?">
    Yes. Click a row to set its background colour, background image, and display condition. Click a column to set per-column background, padding, and border. You can add/remove columns, resize by dragging edges, drag content between columns, and duplicate or delete rows.
  </Accordion>

  <Accordion title="Can I reuse a row design across templates?">
    Yes — save any row as a **block** using the save icon in the row header. Saved blocks appear in the **Blocks** panel and can be dragged into any template. Note: saved blocks are copied on insert — they are not centrally managed.
  </Accordion>

  <Accordion title="My rendered email looks different from the editor preview">
    Email clients strip some HTML/CSS for security. Each client (Gmail, Outlook, Apple Mail) has different restrictions. Check [supported CSS by email client](https://www.campaignmonitor.com/css/).
  </Accordion>

  <Accordion title="Design Editor, HTML Editor, or Plain Text — which one gets committed?">
    Whichever editor tab is **open at the time you click Commit** is the version that gets published. All three modes (Design Editor, HTML, Plain Text) save independently. If you're on the Design Editor tab and click Commit, the designer version is published. If you switch to HTML and commit, the HTML version is published. Always verify you're on the right tab before committing.
  </Accordion>

  <Accordion title="What happens to Plain Text if I don't write it?">
    It is auto-generated from HTML on every commit. You can also click **Fetch from HTML** to pull content manually. Once you edit the plain text, auto-generation stops.
  </Accordion>
</AccordionGroup>

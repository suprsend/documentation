## Overview

The email editor gives you a full visual design environment alongside direct HTML and plain text access. Every email template has two parts that are always in sync:

- **Design Editor** — drag-and-drop canvas for building HTML emails visually
- **Plain Text** — a plain-text version sent alongside the HTML for email clients that don't render HTML

Switch between them using the sub-tabs at the top of the editor.

---

## Getting Started

To add an Email channel to a template, open the template in edit mode and click **+** in the channel tab row. Select **Email** and click **Add Channels**. SuprSend creates a `default` variant and opens the Design Editor.

---

## Email Settings

The **Subject**, **From Name**, and **From Email** are displayed in the header row above the canvas. Click the **pencil icon** on the right end of the header row to open the **Email Settings** modal.

### Required fields

| Field | Required | Description |
| --- | --- | --- |
| **Subject** | Yes | The email subject line. Supports Handlebars — e.g. `Your order {{order_id}} has shipped`. |
| **From Name** | No | The display name recipients see in their inbox — e.g. `Acme Support` or `{{$brand.brand_name}}`. |
| **From Email** | No | The sending address — e.g. `no-reply@acme.com`. Must be a verified domain in your vendor settings. |

<Info>
  If **From Name** and **From Email** are left blank, SuprSend falls back to the values configured in your vendor settings. Set them here only when you need to override the vendor default — for example, to send from a tenant-specific address.
</Info>

### Other Settings

Expand **Other Settings** in the modal for additional email headers and delivery options:

| Field | Description |
| --- | --- |
| **Preheader Text** | Preview text shown in the inbox below the subject line before the email is opened. If not set, email clients pull the first line of body text. |
| **Cc** | One or more addresses to carbon-copy, comma-separated. |
| **Bcc** | One or more addresses to blind carbon-copy, comma-separated. |
| **Reply To** | The address replies go to when a recipient clicks Reply. |
| **Add Multiple Tos** | Send the same email to additional recipients beyond the primary user, comma-separated. |
| **Email Markup JSON** | Structured JSON-LD markup for rich inbox features like Google Actions (one-click RSVP, order tracking directly from Gmail). See [Email Markup](#email-markup) below. |

All fields support Handlebars variables. Click **Save** to apply.

<Tip>
  Preheader text is one of the highest-leverage fields in email. A subject + preheader pair like `Your order has shipped` / `Estimated delivery Friday — tap to track` gives recipients full context before they open.
</Tip>

## Design Editor

The Design Editor is a drag-and-drop canvas for building HTML emails without writing code. The right panel has five tabs: **Content**, **Blocks**, **Body**, **Images**, and **Uploads**.

### Canvas

Drag any content block from the **Content** tab on the right and drop it onto the canvas. Click any placed block to select it — its settings appear in the right panel.

**Bottom toolbar:**

| Control | Description |
| --- | --- |
| **Undo / Redo** | Step backward or forward through canvas changes. |
| **Preview** (eye icon) | Full-screen preview of the rendered email. |
| **Desktop / Mobile** | Toggle between desktop and mobile viewport widths. |

**Top-right controls:**

| Button | Description |
| --- | --- |
| **Design** | Visual drag-and-drop canvas (default). |
| **HTML** | Raw HTML code editor — edit the source directly. Changes sync back to the Design view. |
| **Clipboard icon** | Copies the full HTML source to your clipboard. |

## Content Blocks

Drag these from the **Content** tab onto the canvas.

| Block | Description |

| **Columns** | Multi-column layout container for side-by-side content sections. |
| **Button** | CTA button with configurable label, link, colors, and padding. |

## Tenant Block

The Tenant block renders a branded header using the active tenant's properties — logo, brand colors, and footer bar — pulled automatically at send time from the tenant's configuration.

The **Block Type** dropdown lets you choose between `Header` and other layout variants. Settings when selected:

| Setting | Description |
| --- | --- |
| **Background Color Code** | Hex code for the block background. Overrides the tenant's primary color if set. |
| **Background Color Picker** | Visual color picker alternative. |
| **Logo Height** | Height of the tenant logo in pixels (default: 80). |
| **Logo Width** | Width of the tenant logo in pixels (default: 150). |
| **BottomBar Color Code** | Hex code for the colored bar at the bottom of the header block. |

The block pulls `$brand.logo`, `$brand.primary_color`, `$brand.secondary_color`, and `$brand.tertiary_color` at send time. To preview with a real tenant's branding, select a tenant from the **Tenant** dropdown in the Variables panel.

<Info>
  You can also reference tenant properties manually anywhere in the email using `{{$brand.brand_name}}`, `{{$brand.properties.address}}`, etc. The Tenant block is a convenience wrapper — it does not limit where tenant data can appear.
</Info>

## Saved Blocks

The **Blocks** tab is a library of reusable content blocks saved across your workspace. Use it to maintain consistent components — footers, headers, disclaimer sections — across multiple templates without rebuilding them.

Blocks are searchable and organised by name. Click any block to insert it at the bottom of the canvas, or drag it to a specific position. Any block you build can be saved to this library for reuse.

## Plain Text

The **Plain Text** sub-tab lets you write or manage a plain-text version of the email. Email clients that cannot render HTML display this version. A live **Preview** panel on the right shows the plain text exactly as it will be sent.

**How it works:**

- If left blank, SuprSend **auto-generates** plain text from your HTML content at commit time.
- If you write your own plain text, it is used as-is and auto-generation is skipped for that variant.
- Click **Fetch from HTML** at any time to pull the current HTML content into the Plain Text editor as a starting point.

<Note>
  Plain text auto-generation happens at commit time, not as you type. Click **Fetch from HTML** to see what the auto-generated version will look like before committing.
</Note>

## Dynamic Content and Variables

Use `{{variable}}` anywhere in the canvas — inside text blocks, subject lines, button labels, image URLs, or link hrefs.

Define variables in the **Variables `{}`** panel in the left sidebar before using them. This gives you autocomplete (type `{{` in any text block), live preview substitution, and consistency across all channels in the template.

For URLs and strings containing special characters (`&`, `?`, `=`), use triple braces to prevent HTML-escaping: `{{{tracking_url}}}`.

### Variable sources

| Source | Example | Description |
| --- | --- | --- |
| Trigger payload | `{{order_id}}` | Data sent when the workflow triggers |
| Nested key | `{{order.shipping.city}}` | Nested object property |
| Array item | `{{items.[0].name}}` | First item in an array |
| Recipient profile | `{{$recipient.first_name}}` | Properties from the user's SuprSend profile |
| Tenant branding | `{{$brand.brand_name}}` | Properties from the linked tenant |
| Tenant custom property | `{{$brand.properties.address}}` | Custom properties set on the tenant |
| Batched event count | `{{$batched_events_count}}` | Number of events batched in this send |

### Merge Tags

The text editor toolbar has a **Merge Tags** button for inserting variables without typing. Click any text block to select it — Merge Tags appears in the toolbar and shows all variables declared in the Variables panel as a point-and-click menu.

<Note>
  The Merge Tags button only appears when variables are declared in the Variables panel. If you don't see it, add your variables to the Input Payload first.
</Note>

### Adding array variables (dynamic lists)

To loop over an array and repeat a row for each item — for example, a list of order line items — use the Merge Tags row association feature:

1. **Select a Row** on the canvas. A small array-association button appears in the bottom-left corner of the selected row.
2. Click it to see all arrays declared in your Variables panel. **Select the array** whose items should populate this row.
3. The selected row turns **green** to indicate the association.
4. Inside that row, use Merge Tags or type `{{` to insert array item variables — e.g. `{{product_name}}`, `{{product_price}}`. The row will repeat for every item in the array at send time.

<Warning>
  Array element variables only appear in autocomplete suggestions after you associate the row with an array. If you don't see them, make sure the row is selected and associated first.
</Warning>

For conditionals, loops, date formatting, and other helpers, see [Handlebars Helpers](/docs/handlebars-helpers).

## Display Conditions

Display conditions let you show or hide a content block based on the value of a variable — for example, showing a branding watermark only to free-plan users, or a discount banner only to users in a specific region.

Display conditions are applied at the **block level**. Create a separate block for any content you want to conditionally show or hide.

**To add a display condition:**

1. Select the block on the canvas.
2. Click the **Display Conditions** checkbox in the block's quick settings toolbar or in the right panel settings.
3. Enter a condition expression and click **Create new condition**. Give it a name and description.
4. Once created, the same condition can be reused across multiple blocks.

**Condition syntax:**

```
(condition <key> "<operator>" <value>)
```

For example: `(condition plan "===" "pro")`

**Supported operators:**

| Operator | Returns true when |
| --- | --- |
| `==` | LHS equals RHS (loose equality) |
| `===` | LHS value and type both match RHS |
| `>` | LHS is greater than RHS |
| `<` | LHS is less than RHS |
| `>=` | LHS is greater than or equal to RHS |
| `<=` | LHS is less than or equal to RHS |
| `!=` | LHS does not equal RHS |
| `!==` | LHS value or type does not match RHS |

**Combining conditions:**

Use `or` to show the block when any condition is true:
```
(or (condition city "==" "New York") (condition city "==" "Chicago"))
```

Use `and` to show the block only when all conditions are true:
```
(and (condition monthly_bill ">=" 100) (condition annual_bill ">=" 1000))
```

## Email Markup

The **Email Markup JSON** field in Email Settings accepts [schema.org JSON-LD](https://developers.google.com/gmail/markup/reference) markup — used to add rich inbox actions directly in Gmail (one-click RSVP, order tracking, event highlights, etc.).

**Before using Email Markup:**

You must [register with Google](https://docs.google.com/forms/d/e/1FAIpQLSfT5F1VJXtBjGw2mLxY2aX557ctPTsCrJpURiKJjYeVrugHBQ/viewform) before sending Email Markup to recipients. Review the [Google Registration Guidelines](https://developers.google.com/gmail/markup/registering-with-google) to ensure your application is successful.

**Testing before registration:** Google allows markup testing when the sender email and recipient email are the same account — e.g. sending from `support@yourcompany.com` to `support@yourcompany.com`.

Supports Handlebars variables in the markup JSON.

## Live Preview

The canvas updates live as you edit, with variable placeholders replaced by values from the Variables panel. For a full-screen preview, click the **eye icon** in the bottom toolbar. Toggle **Desktop** and **Mobile** to check responsive rendering.

To preview with a specific user's data, open the **Recipient** section in the Variables panel and search for a real user. To preview with a specific tenant's branding, select a tenant from the **Tenant** dropdown.

---

## Sending a Test Email

Click **Test** in the top-right corner to send a real email to a real inbox. See [Testing the Template](/docs/testing-the-template) for the full testing flow.

<Warning>
  Every `{{variable}}` in the email must have a corresponding value in the Variables panel. If a variable is missing at send time, **the email is not sent** — but other channels in the same workflow (e.g. SMS, push) are unaffected and will still be delivered.
</Warning>

---

## Committing

Click **Commit** in the top bar to publish the current state as a new live version. This includes the Design Editor content, Plain Text, sender settings, and subject. The plain text version is auto-generated from HTML at commit time if left empty.

## Frequently Asked Questions

<Accordion title="My rendered email looks different from the editor preview in Gmail or Outlook.">
  Email clients strip certain HTML and CSS tags while rendering to prevent security risks. Use alternative tags where needed. Check supported CSS by client at [campaignmonitor.com/css](https://www.campaignmonitor.com/css/).
</Accordion>

<Accordion title="When should I use double braces vs triple braces for variables?">
  Use `{{variable}}` for most cases — double braces HTML-escape values by default, which prevents injection. Use `{{{variable}}}` only when the value contains special characters like `&`, `?`, or `=` that would be incorrectly escaped (e.g. tracking URLs).
</Accordion>

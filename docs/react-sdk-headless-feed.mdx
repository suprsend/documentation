If the drop-in [`Inbox`](/docs/react-in-app-feed) and [`NotificationFeed`](/docs/react-full-screen-or-sidesheet-notifications-feed) components don't fit your design, you can build your own UI from scratch using the headless hooks. These hooks give you direct access to the feed data and actions — you control the rendering.

<Note>
  If you don't need any built-in UI components, you can use the lighter [`@suprsend/react-core`](https://github.com/suprsend/suprsend-react-core) package instead of `@suprsend/react`. The hooks and providers are identical in both.
</Note>

## Prerequisites

Make sure you have [installed the SDK and set up `SuprSendProvider`](/docs/react-installation).

## Installation

<CodeGroup>
```bash npm
npm install @suprsend/react-core
```

```bash yarn
yarn add @suprsend/react-core
```
</CodeGroup>

## Integration

### SuprSendFeedProvider

Wrap your feed UI in `SuprSendFeedProvider` (inside `SuprSendProvider`). This provider creates the feed client, opens a real-time WebSocket connection, and cleans up on unmount.

```jsx
import { SuprSendProvider, SuprSendFeedProvider } from "@suprsend/react-core";

function App() {
  return (
    <SuprSendProvider
      publicApiKey="YOUR_PUBLIC_API_KEY"
      distinctId="YOUR_DISTINCT_ID"
      userToken="SIGNED_USER_TOKEN"
    >
      <SuprSendFeedProvider>
        <MyFeedComponent />
      </SuprSendFeedProvider>
    </SuprSendProvider>
  );
}
```

```typescript
interface SuprSendFeedProviderProps {
  tenantId?: string;
  pageSize?: number;
  stores?: IStore[] | null;
  host?: { socketHost?: string; apiHost?: string };
}
```

### useFeedClient

Returns the feed client instance. Use it to call actions like mark as read, mark as seen, archive, and fetch the next page.

```jsx
import { useFeedClient } from "@suprsend/react-core";

function MyComponent() {
  const feedClient = useFeedClient();

  return (
    <button onClick={() => feedClient.markAsSeen(notificationId)}>
      Mark Seen
    </button>
  );
}
```

**Available methods on `feedClient`:**

| Method | Description |
|--------|-------------|
| `markAsSeen(id)` | Mark a notification as seen. |
| `markAsRead(id)` | Mark a notification as read. |
| `markAsUnread(id)` | Mark a notification as unread. |
| `markAsArchived(id)` | Archive a notification. |
| `markAsInteracted(id)` | Mark a notification as interacted. |
| `markAllAsSeen()` | Mark all notifications as seen. |
| `markAllAsRead()` | Mark all notifications as read. |
| `fetchNextPage()` | Fetch the next page of notifications (infinite scroll). |

### useFeedData

Returns a reactive state object with the notification list and metadata. The state updates automatically when notifications change. See [Feed](/docs/feed-data) for the full notification JSON structure.

```jsx
import { useFeedData } from "@suprsend/react-core";

function MyComponent() {
  const feedData = useFeedData();
  const notifications = feedData.notifications;

  return (
    <div>
      {notifications.map((n) => (
        <p key={n.n_id}>{n.message.header}</p>
      ))}
    </div>
  );
}
```

**Fields on `feedData`:**

| Field | Type | Description |
|-------|------|-------------|
| `notifications` | `IRemoteNotification[]` | Array of notification objects. |
| `apiStatus` | `string` | `"LOADING"`, `"SUCCESS"`, `"FETCHING_MORE"`, or `"ERROR"`. |
| `pageInfo` | `object` | Pagination info including `hasMore`. |
| `unreadCount` | `number` | Number of unread notifications. |
| `unseenCount` | `number` | Number of unseen notifications. |

## Complete example

```jsx
import {
  SuprSendProvider,
  SuprSendFeedProvider,
  useFeedData,
  useFeedClient,
} from "@suprsend/react-core";

function App() {
  return (
    <SuprSendProvider
      publicApiKey="YOUR_PUBLIC_API_KEY"
      distinctId="YOUR_DISTINCT_ID"
      userToken="SIGNED_USER_TOKEN"
    >
      <SuprSendFeedProvider>
        <MyFeedComponent />
      </SuprSendFeedProvider>
    </SuprSendProvider>
  );
}

function MyFeedComponent() {
  const feedData = useFeedData();
  const feedClient = useFeedClient();

  if (!feedData) return null;
  if (feedData.apiStatus === "LOADING") return <p>Loading...</p>;
  if (feedData.apiStatus === "SUCCESS" && !feedData?.notifications?.length) {
    return <p>No notifications yet</p>;
  }

  return (
    <div>
      {feedData.notifications.map((notification) => (
        <div
          key={notification.n_id}
          onClick={() => feedClient.markAsRead(notification.n_id)}
          style={{
            padding: 12,
            borderBottom: "1px solid #eee",
            cursor: "pointer",
          }}
        >
          <strong>{notification.message.header}</strong>
          <p>{notification.message.text}</p>
        </div>
      ))}

      {feedData.pageInfo?.hasMore && (
        <button onClick={() => feedClient.fetchNextPage()}>Load more</button>
      )}
    </div>
  );
}
```

## Using built-in components in headless

If you want to use your own layout but reuse specific SDK components, switch from `@suprsend/react-core` to `@suprsend/react`. The integration steps remain the same — only the import path changes.

### NotificationCard

Renders a single notification with all built-in features (actions, markdown body, avatars, timestamps).

```jsx
import { NotificationCard } from "@suprsend/react";

<NotificationCard notificationData={notification} />
```

```typescript
interface NotificationCardProps {
  notificationData: IRemoteNotification;
  notificationClickHandler?: (notificationData: IRemoteNotification) => void;
  notificationComponent?: React.FC<CustomNotificationCard>;
  hideAvatar?: boolean;
  themeType?: ThemeType;
  primaryActionClickHandler?: (notification: IRemoteNotification) => void;
  secondaryActionClickHandler?: (notification: IRemoteNotification) => void;
  theme?: INotificationCardTheme;
}
```

### BodyMarkdown

Renders the notification body with markdown support. Useful when you want a custom card layout but need markdown rendering.

```jsx
import { BodyMarkdown } from "@suprsend/react";

<BodyMarkdown body={notification.message.text} />
```

## Overview

Web push notifications are browser-native alerts delivered to a user's device even when they are not actively on your website. They appear as system-level notifications — the same UI as OS notifications — and are supported across Chrome, Firefox, Edge, and Safari on desktop and Android.

The Web Push editor in SuprSend is a structured form with a live preview panel that renders the notification exactly as it appears on the user's operating system.

---

## Getting Started

To add Web Push to a template, open the template in edit mode, click **+** in the channel tab row, select **Web Push**, and click **Add Channels**. SuprSend creates a `default` variant and opens the Web Push editor.

To send web push notifications, you need a Web Push vendor configured in your workspace. See [Web Push Vendor Integration](/docs/web-push-vendor-integration).

## Fields

### Title *(required)*

The headline of the notification — displayed in bold at the top of the notification card. Keep it short and specific. Most operating systems truncate titles beyond ~50 characters.

Supports Handlebars variables and emoji.

### Body *(required)*

The main message body displayed below the title. This is where you provide context — what happened and what the user should do.

Supports Handlebars variables and emoji.

<Tip>
  Web push notifications get one shot at attention. Lead with the most important information in the title. Use the body for the "why" or the call to action — e.g. Title: `Your order has shipped` / Body: `Estimated delivery: Friday, Apr 4. Tap to track.`
</Tip>

### Banner Image URL

An optional image displayed inside the notification card below the body text. Adds visual context — useful for product images, promotional banners, or brand imagery.

- **Recommended size:** 720 × 480px
- Provide a direct image URL. Supports Handlebars — e.g. `{{product.image_url}}`.
- Click the upload icon next to the field to upload an image directly from your device.

<Info>
  Banner image support varies by browser and OS. Chrome on Windows and Android display it reliably. Safari and some Linux environments may not render the banner image.
</Info>

### Action URL

The URL that opens when the user clicks the notification. This is the primary call to action for the notification.

If left blank, clicking the notification opens your website's base URL as configured in your Web Push vendor settings.

### Chrome Action Buttons

Optional CTA buttons rendered inside the notification on Chrome. Each button has:

| Field | Description |
| --- | --- |
| **Button Title** | The label displayed on the button. Keep it under 20 characters — longer labels are truncated on most OS. |
| **URL** | The destination URL when the button is clicked. |

Click **+ Add Button** to add a button. You can add multiple buttons, though most browsers display a maximum of two action buttons regardless of how many are configured.

<Info>
  Chrome Action Buttons are supported on Chrome desktop and Android. They are not rendered in Firefox or Safari — users on those browsers see only the title, body, and image.
</Info>

## Live Preview

The right panel shows a live preview of the notification as it appears on the user's OS. Toggle between **Windows** and **MacOS** to check how the notification renders on each platform.

The preview updates in real time as you edit fields. Variables are replaced with values from the Variables panel — search for a real user in the **Recipient** section to preview with their actual data.

---

## Variables

All text fields — Title, Body, Banner Image URL, and Action URL — support Handlebars syntax.

Define variables in the **Variables `{}`** panel before using them to get autocomplete and live preview substitution.

| Source | Example | Description |
| --- | --- | --- |
| Trigger payload | `{{order_id}}` | Data sent when the workflow triggers |
| Nested key | `{{order.status}}` | Nested object from the payload |
| Recipient profile | `{{$recipient.first_name}}` | Properties from the user's SuprSend profile |
| Tenant | `{{$brand.brand_name}}` | Tenant branding properties |

For conditionals, loops, and helpers, see [Handlebars Helpers](/docs/handlebars-helpers).

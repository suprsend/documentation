Send browser push notifications with a title, body, optional images, action URL, and Chrome action buttons — with a live preview (toggle Windows and macOS). Content is personalised with [Handlebars](/docs/handlebars-helpers) variables (`{{variable_name}}`).

<Note>
  You need a Web Push vendor connected and the SuprSend SDK integrated on your site before notifications can be sent. [Set up Web Push →](/docs/web-push-quick-start)
</Note>

The Web Push editor is a form with title, body, icons, images, action URL, and buttons — with a live preview on the right.

## Fields

### Title

**Required** · Supports variables

Single-line heading in the browser notification.

**What to write here:** State the main reason for the alert — Windows truncates aggressively; macOS is more generous. Stay under about 40 characters for predictable display on Windows.

Supports Handlebars: `{{variable_name}}`

> Example: `Back in stock: {{product_name}}` · `New article: {{article_title}}` · `Price dropped on {{product_name}}`

### Large Icon

**Optional** (organisation default)

Shown to the right of the notification text. Defaults to your organisation logo (set in Organisation Settings). Cannot be changed per template.

**What to write here:** You cannot override per template — update **Organisation Settings** if the logo is wrong. See **How do I change the large icon?** in the FAQ.

### Body

**Required** · Supports variables

Main message copy — aim for 2–3 lines. One sentence with a clear call to action works well.

**What to write here:** Write as if images and action buttons might not appear (Firefox and Safari show limited chrome) — the title and body must carry the full message.

> Example: `The item you were watching is available again.` · `{{article_excerpt}}` · `Now {{new_price}} (was {{old_price}})`

### Banner Image URL

**Optional** · Supports variables

2:1 aspect ratio (recommended 720×480), under 200 KB for fast rendering. Formats: PNG, JPG, JPEG.

**What to write here:** Host on a CDN; large or slow URLs may render blank. Chromium browsers show the banner; Firefox and Safari often do not — do not rely on it for the core message.

> Example: `{{product_image_url}}` · `{{cover_image_url}}`

### Action URL

**Required for click behaviour** · Supports variables

URL opened when the user clicks the notification body.

**What to write here:** Always set a URL — without it, clicking may do nothing. Add UTM parameters for analytics (see Best practices).

> Example: `https://yourapp.com/product/{{product_id}}?utm_source=web_push&utm_campaign={{campaign_name}}`

### Chrome Action Buttons

**Optional** · Supports variables

Up to 2 buttons with action-oriented labels (2–3 words: "View Order", "Shop Now"). Supports Handlebars. Only visible on Chromium browsers (Chrome, Edge, Brave) — on Firefox and Safari, only the title, body, and click action are shown.

**What to write here:** Treat buttons as an enhancement — duplicate the critical action in the body or title when possible.

> Example: `Buy Now` → `https://yourapp.com/cart/add/{{product_id}}` · `View Deal` / `Add to Cart` pairs for promotions

## Personalise with variables

You can add variables in the template to personalise it per recipient. SuprSend replaces variables with actual data at send time.

<Steps>
  <Step title="Add variables in the Variables panel">
    Add sample data in the **Variables panel** (Input Payload section) on the left side of the editor. This powers auto-suggestions and the live preview. For the full guide, see [Adding dynamic content](/docs/templates#the-variables-panel).
  </Step>

  <Step title="Use variables in the template">
    Type `{{` in any field — matching variables appear as auto-suggestions. You can also type variable names manually following [Handlebars syntax](https://handlebarsjs.com/guide/#what-is-handlebars).

    **Examples using this sample data:**

    <CodeGroup>
      ```json json
      {
        "event": {
          "order_id": "11200123",
          "first_name": "Nikita"
        },
        "product_name": "RayBan Sunglasses",
        "product_image_url": "https://yourapp.com/images/product.jpg"
      }
      ```
    </CodeGroup>

    - **Nested variable:** `{{event.order_id}}` → renders as `11200123`
    - **Variable with space in name:** `{{event.[first name]}}`

    The preview section shows sample values rendered in real-time. If a variable isn't rendering, check:
    1. The variable is defined in the Variables panel.
    2. The variable name matches the Handlebars syntax exactly.
  </Step>
</Steps>

<Warning>
  If a variable cannot be rendered at send time (missing or mismatched data), SuprSend skips that notification for the affected user. Other channels in the same template group are still sent.
</Warning>

## Other ways to build this template

### Test across browsers before committing

Web push renders differently across Chrome (and Chromium browsers), Firefox, and Safari. A banner image and action buttons visible in Chrome are invisible in Firefox and Safari. Before committing, open SuprSend's test flow in each of the three browsers on your machine — Chrome, Firefox, and Safari on macOS — and trigger a test notification from the editor. Verify the notification text and click action work everywhere, even if the image and buttons only show in Chrome. Write your title and body so they tell the full story without the image.

### Host banner images on a CDN with cache-control headers

Web push downloads the banner image URL at notification delivery time in the browser. If your image URL is slow to load, the notification can appear without the image. Host all banner images on a CDN (Cloudflare, AWS CloudFront, Fastly) with `Cache-Control: public, max-age=31536000` so the browser can cache it. Keep images under 100 KB — even though the field documents 200 KB as the limit, smaller images load faster and are more likely to appear in the notification before the user dismisses it.

### Use notification click analytics to measure template effectiveness

The Action URL you set in Web Push is the best signal you have about whether your notification copy worked. Set up UTM parameters on every action URL: `https://yourapp.com/product/{{product_id}}?utm_source=web_push&utm_campaign={{campaign_name}}&utm_content={{template_version}}`. In Google Analytics or your analytics tool, create a segment for `utm_source=web_push` and track conversion rate from notification click to goal completion. This tells you which title/body combinations actually drive action — more useful than open rates alone.

### Implement a permission prompt strategy before collecting subscribers

Web push has an opt-in rate problem: browsers show the permission prompt immediately on first visit, most users dismiss it, and you can never ask again (unless the user manually resets). Instead of triggering the browser's native prompt immediately, build a "soft ask" in your product — a banner, modal, or tooltip that explains why push is valuable and has a "Yes, notify me" button. Only trigger the real browser prompt after the user clicks that button. This pattern typically triples opt-in rates compared to asking on first load. SuprSend's Web Push SDK exposes the `requestPermission()` call you trigger manually.

### Design your large icon for dark mode

The large icon in Web Push (your org logo) shows on both dark and light system themes in Windows and macOS. A logo with a dark background looks bad in dark mode notification drawers. Export two versions of your logo: one on white, one on transparent background. In your Organisation Settings in SuprSend, use the transparent-background version — it renders cleanly on both light and dark system themes.

## Best practices

- **Write title and body as if image and buttons don't exist** — They're invisible in Firefox and Safari — the copy must stand alone.
- **Keep banner images under 100 KB** — They're downloaded at delivery time; slower loads mean users dismiss before the image appears.
- **Add UTM parameters to every action URL** — The most reliable way to measure whether the notification drove action.
- **Build a permission soft-ask before the browser prompt** — Triples opt-in rates compared to prompting on first load — wire `requestPermission()` to your UI.
- **Export your org logo with a transparent background for Organisation Settings** — It renders cleanly on light and dark system themes.

## FAQ

<AccordionGroup>
  <Accordion title="Which browsers support which features?">
    | Feature | Chrome | Firefox | Safari (macOS) | Edge |
    |---|---|---|---|---|
    | Title + Body | Yes | Yes | Yes | Yes |
    | Banner Image | Yes | Yes | No | Yes |
    | Action Buttons | Yes (up to 2) | No | No | Yes (up to 2) |
    | Large Icon | Yes | Yes | No | Yes |

    Action buttons are labelled "Chrome Action Buttons" in the editor because they only render on Chromium browsers. Design your notification so the core message is in the title + body, with buttons as an enhancement.
  </Accordion>

  <Accordion title="How do I change the large icon?">
    The large icon defaults to your organisation logo set in **Organisation Settings** on the SuprSend dashboard. It cannot be changed per template — update it in your org settings if you need a different icon.
  </Accordion>

  <Accordion title="How often should I send web push notifications?">
    Web push has higher opt-out rates than other channels. Send only high-value, time-sensitive notifications to maintain subscriber trust. Over-sending is the fastest way to lose subscribers.
  </Accordion>

  <Accordion title="What happens if a variable is missing or has the wrong value at send time?">
    SuprSend skips the Web Push notification for that user. Other channels in the same template group are still sent if they render successfully.
  </Accordion>

  <Accordion title="Can I use this channel alongside other channels in the same workflow?">
    Yes — Web Push is one channel in a template group; other channels send independently.
  </Accordion>

  <Accordion title="How do I pass variable values when triggering the workflow?">
    Include properties in your trigger payload so Handlebars paths match. Use the **Variables panel** for sample data. See [Adding dynamic content](/docs/templates#the-variables-panel).
  </Accordion>
</AccordionGroup>

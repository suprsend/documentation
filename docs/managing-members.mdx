## Overview
Access the [team page](https://app.suprsend.com/en/account-settings/team) via **Account Settings** → **Team**. You can search members, change their roles, invite new members, and remove members. All actions are logged in audit logs.

## Accessing Teams

Navigate to the [team](https://app.suprsend.com/en/account-settings/team) page to manage your team members.

<Frame caption="Team page showing all account members">
  ![](/images/team.png)
</Frame>

You can search by name or email address, with results updating as you type. You can also filter the list by role (Admin or Member) and by status (Active or Deactivated). Filters can be combined to narrow down the results.

### Inviting a new user

Admins can invite new team members to join the account:

<Steps>
  <Step title="Open the invite modal">
    Click the **Invite member** button located at the top right of the team page.

<Frame caption="Invite member button">
  ![](/images/invite-member.png)
</Frame>
  </Step>
  <Step title="Fill in member details">
    Provide:
    - **Email Address** (required)
    - **Name** (required)
    - **Role** (required): Member or Admin (default: Member)
  </Step>
  <Step title="Send the invite">
    Click **Send Invite** to send the invitation email to the user.
  </Step>
</Steps>

The user receives an email invitation. Invited members appear with "Invited" status until they accept.

**Managing pending invitations**: For invited members, click the three dots icon to:
- **Resend invite**: Sends a new invitation email (logs `account.member_invite_resent`)
- **Delete invite**: Cancels the pending invitation (logs `account.member_invite_cancelled`)

<Frame caption="Managing pending invitations">
  ![](/images/invited.png)
</Frame>

**Invite validity**: Invitations remain valid for one day. Resend if expired.

**Error handling**: If inviting a user already in another account, you may see:
- **"[email] is already a member in another team. Reach out to support to add user to this account."** - User is in a different account/team.
- **"[email] is already a part of your organization"** - User is already in your account.

**Resolution**: The user must leave their current account, or contact SuprSend support for assistance.

### Removing a member

Remove a team member's account access when they leave your organization:

<Steps>
  <Step title="Locate the member">
    Find the member in the team list using search or filters.
  </Step>
  <Step title="Open the action menu">
    Click the three dots icon on the right side of the member's row.

<Frame caption="Remove member action menu">
  ![](/images/remove-member.png)
</Frame>
  </Step>
  <Step title="Remove the user">
    Click **Remove User** from the dropdown menu.
  </Step>
  <Step title="Confirm removal">
    Confirm the action. The member's status changes to "Deactivated" and their row appears in a light gray/disabled state.
  </Step>
</Steps>

<Warning>
  **Important**: After removing a team member:
  - Delete or rotate API keys and service tokens the member had access to
  - Review shared credentials and audit logs
  
  This is critical for maintaining account security.
</Warning>

The `account.member_deactivated` action is logged when a member is removed.

### Reactivating removed member

Restore access for a previously removed team member by sending a new invitation:

<Steps>
  <Step title="Find the deactivated member">
    Filter by "Deactivated" status or search by name/email. Deactivated members appear in a light gray/disabled state.
  </Step>
  <Step title="Open the action menu">
    Click the three dots icon on the right side of the deactivated member's row.

<Frame caption="Reactivate member action menu">
  ![](/images/reactivate-member.png)
</Frame>
  </Step>
  <Step title="Invite the user">
    Click **Invite user** from the dropdown menu to send a rejoin invitation.
  </Step>
  <Step title="User accepts invitation">
    After accepting, their status changes to "Active" and they regain access with their previous role.
  </Step>
</Steps>

<Note>
  **Role changes for deactivated members**: You cannot change a deactivated member's role. The role can only be changed after reactivation when their status is "Active".
</Note>

### Changing member role

Admins can change a team member's role, which affects their permissions and access level.

<Steps>
  <Step title="Locate the member">
    Find the member in the team list.
  </Step>
  <Step title="Open role dropdown">
    Click the role dropdown (Member/Admin) in the member's row.
  </Step>
  <Step title="Select new role">
    Choose Member or Admin from the dropdown.
  </Step>
  <Step title="Confirm change">
    - **Member to Admin**: Applied immediately (no confirmation).
    - **Admin to Member**: Confirmation dialog appears. Click **Confirm** to proceed.
  </Step>
</Steps>

<Frame caption="Confirmation dialog when revoking admin access">
  ![](/images/revoke-admin.png)
</Frame>

The `account.member_role_changed` action is logged when a role change is applied.

#### Permissions

Permissions for Admin and Member roles:

| Action | Admin | Member |
|--------|-------|--------|
| Full platform access | ✓ | ✓ |
| View team members | ✓ | ✓ |
| Search and filter team members | ✓ | ✓ |
| Change user roles | ✓ | ✗ |
| Invite new members | ✓ | ✗ |
| Remove/deactivate members | ✓ | ✗ |
| Reactivate members | ✓ | ✗ |
| Access all account settings | ✓ | ✓ |
| Manage API keys and service tokens | ✓ | ✓ |
| View and manage workflows, templates, and configurations | ✓ | ✓ |
| Access audit logs | ✓ | ✓ |
| Full access to all workspaces (staging and production) | ✓ | ✓ |
| View unmasked PII information | ✓ | ✗ |
| Expand logs to see full details | ✓ | ✗ |
| View workflow trigger payload | ✓ | ✗ |
| Add users in production workspace | ✓ | ✗ |
| Edit users in production workspace | ✓ | ✗ |

#### Member restrictions

Members have full platform access but are restricted from:

- **PII Information Masking**: User PII (email addresses, phone numbers, etc.) is masked in user profiles. Only admins can view unmasked PII information.
- **Log Restrictions**: Members cannot expand logs to see detailed execution information and error messages.
- **Workflow Trigger Payload**: Members cannot view the full payload passed when a workflow is triggered.
- **Production Workspace User Management**: Members cannot add or edit users in the production workspace.
- **User Preferences Management**: Members cannot edit user preferences.

<Info>
**Enterprise only.** This guide is for SuprSend **enterprise customers** with access to Self-Hosted deployment.
</Info>

Follow this guide to set up SuprSend in your own infrastructure. You'll install dependencies in order, then deploy the SuprSend Helm chart and verify the deployment.

<Tip>
For production deployments, we recommend using managed services for databases and queues to ensure high availability and performance.
</Tip>

---

## Deployment overview

Deploy in this order: install each dependency, then the SuprSend chart. After install, run through the verification checklist.

<CardGroup cols="2">
  <Card title="Installation order" icon="layer-group" iconType="solid">
    **1** → PostgreSQL · **2** → Redis · **3** → OpenSearch · **4** → Temporal · **5** → SuprSend Helm chart
  </Card>
  <Card title="After install — verify" icon="circle-check" iconType="solid">
    DB connections → Temporal workers → Health checks → Test notification → Backups & monitoring
  </Card>
</CardGroup>

**Installation flow**

| Component | What to do |
|-----------|------------|
| **PostgreSQL** | Primary data store. [Setup guide →](/docs/self-hosted/setup-dependencies/postgres) |
| **Redis** (×2) | Cache + workflow state. [Setup guide →](/docs/self-hosted/setup-dependencies/redis) |
| **OpenSearch** | Inbox / search. [Setup guide →](/docs/self-hosted/setup-dependencies/opensearch) |
| **Temporal** | Workflow engine. [Setup guide →](/docs/self-hosted/setup-dependencies/temporal) |
| **SuprSend** | [Helm chart](https://self-hosted.suprsend.com/install/suprsend) — then dashboard & test |

**Post-install checks**

1. Verify DB connections (Postgres, Redis, OpenSearch)
2. Confirm Temporal workers are running
3. Run SuprSend health checks
4. Send a test workflow notification
5. Set up backups and monitoring

Details for each step are in the sections below.

---

## Step-by-step: Install dependencies

<Steps>
  <Step title="PostgreSQL" stepNumber="1">
    Primary data store for SuprSend. Use a managed PostgreSQL service in production, or deploy with Helm for dev/test.  
    **[→ PostgreSQL setup guide](/docs/self-hosted/setup-dependencies/postgres)**
  </Step>
  <Step title="Redis (two instances)" stepNumber="2">
    **Shared Redis** — caching across services. **Workflow state Redis** — execution state. Keep them separate so delays in one don't affect delivery.  
    **[→ Redis setup guide](/docs/self-hosted/setup-dependencies/redis)**
  </Step>
  <Step title="OpenSearch" stepNumber="3">
    Data store for Inbox notifications. Prefer managed (AWS OpenSearch, GCP Elastic, Azure Elastic) in production; for air-gapped setups, use the OpenSearch Operator in Kubernetes.  
    **[→ OpenSearch setup guide](/docs/self-hosted/setup-dependencies/opensearch)**
  </Step>
  <Step title="Temporal" stepNumber="4">
    Workflow execution engine and state management.  
    **[→ Temporal setup guide](/docs/self-hosted/setup-dependencies/temporal)**
  </Step>
  <Step title="SuprSend application" stepNumber="5">
    Install via the [SuprSend Helm chart](https://self-hosted.suprsend.com/install/suprsend). Then access the dashboard and start testing.
  </Step>
</Steps>

## Post-deployment checklist

<Steps>
  <Step title="Access dashboard and create admin" stepNumber="1">
    Open `https://your-domain.com/dashboard` and set up your first admin user.
  </Step>
  <Step title="Configure channels and webhooks" stepNumber="2">
    Add email, SMS, and push providers; set webhook endpoints in vendors for real-time logs in the dashboard.
  </Step>
  <Step title="Send a test notification" stepNumber="3">
    Create a workflow and trigger a test from the dashboard or API to verify the flow.
  </Step>
</Steps>

**Verify these are working:**

| Check | Description |
|-------|-------------|
| Dashboard | Accessible via HTTPS |
| API | Endpoints responding |
| Databases | Postgres, Redis, OpenSearch connections OK |
| Temporal | Workflows executing |
| Channels | Email (and SMS if configured) sending |

Once everything is green, use the same [workflows](/docs/workflows), [templates](/docs/templates), and [APIs](/reference/overview) as in the main docs.

In-App Inbox notification template lets you add a header, body, buttons, avatar, card click action, and advanced configurations like pinning, expiry, tags, importance, and extra data to customise the view and behaviour of each Inbox notification.

## Designing the Template

Designing templates in SuprSend is intuitive with WYSIWYG editors for all channels. We use [Handlebars](https://handlebarsjs.com/guide/#what-is-handlebars) as the templating language. Add variables in the template as `{{var}}`. We also support [Handlebars helpers](/docs/handlebars-helpers) for complex use cases like if-else conditions, default values when a variable is absent, or handling arrays.

To create a template, go to [SuprSend dashboard → Templates](https://app.suprsend.com/en/staging/templates/) and enable the Inbox channel.

The channel tab menu (**⋮** next to the tab name) has one option: **Disable Channel** — this removes the channel from the template without deleting the variant content.

### Form fields

| Field | Type | Description |
| --- | --- | --- |
| **Header** | Single line text | Heading of the message shown in bold at the top. Use it to summarise the notification — e.g. `New comment received`, `Your story has 30 views`. |
| **Text** *(required)* | Multi-line text | Body of the message. Supports Markdown syntax for links, blockquotes, bold, and more. See [supported Markdown](#supported-markdown-syntax-in-text-field). |
| **Avatar** | Public image URL (`.jpeg`, `.png`) | Image displayed alongside the notification. Use for actor photos (like LinkedIn) or static icons based on message type (like HubSpot). |
| **Subtext** | Single line text | Footer line of the notification card. Clickable — use for metadata like comment counts and likes (LinkedIn) or task card numbers (Jira). |
| **Action URL** | `http` / `https` URL | URL the user is redirected to on card click. Check **Open in new tab** to open in a new tab. |
| **Action Buttons** | Text–URL pair | Up to **2 buttons** in the notification card. Use for redirect links or inline actions like opening a modal or triggering an internal function (e.g. an `Approve` button). Refer to [custom click handlers](https://github.com/suprsend/suprsend-react-inbox/blob/main/docs/customization.md#action-button-custom-click-handlers) to customise button click behaviour. Check **Open in new tab** to open the link in a new tab. |

### Supported Markdown syntax in text field

We support [headings](https://www.markdownguide.org/basic-syntax/#headings), [bold](https://www.markdownguide.org/basic-syntax/#bold), [italic](https://www.markdownguide.org/basic-syntax/#italic), [blockquotes](https://www.markdownguide.org/basic-syntax/#blockquotes-1), [nested blockquotes](https://www.markdownguide.org/basic-syntax/#nested-blockquotes), [links](https://www.markdownguide.org/basic-syntax/#links), and [code](https://www.markdownguide.org/basic-syntax/#code).

| Syntax | Output |
| --- | --- |
| `# Heading` | Heading |
| `**text**` | **Bold** |
| `*text*` | *Italic* |
| `[label](url)` | Hyperlink |
| `> text` | Blockquote |
| `` `code` `` | Inline code |

Markdown and Handlebars variables can be combined — e.g. `**{{$recipient.first_name}}**, your order has shipped.`

## Advanced Configuration

Expand the **Advanced Configuration** section for controls that affect notification behaviour and organisation in the Inbox feed.

### Tags

Tags are labels attached to a notification that your Inbox UI uses to organise notifications into tabs or filter views. For example, a SaaS product might tag notifications as `billing`, `product`, or `team` to power separate Inbox tabs.

Search for existing tags or type to create a new one. Multiple tags can be applied to a single notification.

<Note>
  **Tags in Inbox template vs Tags in Workflow**: Tags added in the Inbox template are used to filter notifications in Inbox tabs. Tags in a workflow are only used to group or filter workflows on the workflow listing page — they do not affect Inbox filtering. To filter notifications in tabs, add tags in the Inbox template and reference them in your Inbox configuration using `tags: "your_tag"` in the query.
</Note>

See [Multi Tabs](/docs/multi-tabs) for how to build tab-based Inbox UIs using tags.

### Pinned Notification

Toggle **Pinned Notification** on to pin this notification to the top of the user's Inbox feed with a `pinned` tag, regardless of recency. Use for critical alerts where you need the user to take action — finish compliance, renew a plan, or respond to a limited-time offer.

<Frame>
  <img src="/images/docs/7ee3c01-image.png" />
</Frame>

<Tip>
  Always combine pinning with an expiry. Without expiry, the notification stays pinned in the user's Inbox until they manually archive it.
</Tip>

### Expiry

Toggle **Expiry** on to set a time-to-live for the notification. After the expiry time passes, the notification is automatically archived from the user's feed. Use for time-sensitive content like flash sale alerts, event reminders, or feedback requests that become irrelevant after a certain point.

<Frame>
  <img src="/images/docs/c66d113-image.png" />
</Frame>

You can also [show an expiry timer](#show-expiry-timer) on the notification to drive action urgency.

#### Fixed expiry

A fixed expiry can be set as a relative time — `**d **h **m **s` (e.g. `2d 4h` for 2 days and 4 hours) — or as an absolute timestamp — e.g. `2024-04-01 2:00 pm`. Absolute timestamps entered in the form are interpreted in your local timezone.

<Frame>
  <img src="/images/docs/2c401ff-image.png" />
</Frame>

#### Dynamic expiry

Dynamic expiry is computed at send time using data from your event payload or user properties. Add it as a Handlebars variable — e.g. `{{expiry_time}}`.

<Frame>
  <img src="/images/docs/316b734-image.png" />
</Frame>

The variable value must resolve to one of:

- An **ISO-8601 timestamp** — e.g. `2024-03-02T20:34:07Z` — must be a datetime in the future.
- A **relative duration** — either:
  - An integer like `50`, interpreted as seconds.
  - An interval string in `**d **h **m **s` format — e.g. `3d 12h`.

#### Show expiry timer

Enable **Show expiry timer** to display a countdown on the notification card. The timer renders on a grey background when more than 1 hour remains, and turns red when under 1 hour — drawing the user's attention as expiry approaches.

<Frame caption="Expiry timer with different time remaining">
  <img src="/images/docs/2c44f10-image.png" />
</Frame>

### Importance

Controls the visual prominence of the notification in the Inbox feed. Set to **Default** for standard styling. Higher importance levels may affect visual weight and ordering depending on your Inbox SDK configuration.

### Extra Data

A freeform JSON object sent with the notification payload — not displayed to the user, but available to your frontend via the Inbox SDK. Use it to pass structured metadata your application logic needs when the user interacts with the notification — for example, an `order_id` or `entity_type` so your app can navigate to the right screen on click, without encoding that logic in the URL.

```json
{"key": "value"}
```

## Adding Dynamic Content

There will always be cases where you need to personalise a notification for each user. Add variables in the template — they are replaced with live data at send time. Pass these values when triggering the workflow from one of our [backend or frontend SDKs](/docs/trigger-workflow).

<Steps>
  <Step title="Declare variables in the Variables panel">
    Open the **Variables `{}`** panel in the left sidebar and define your variables with sample values. This gives you autocomplete as you type `{{` in any field and powers the live preview.

    See [Templates → Adding variable content](/docs/templates#authoring-content) for how the Variables panel works.
  </Step>

  <Step title="Use variables in the template fields">
    All text fields — Header, Text, Subtext, Avatar URL, Action URL, and Button labels — support Handlebars syntax. As a general rule, variables are entered within double curly brackets: `{{variable_name}}`.

    If you declared the variable in the Variables panel, it will appear as an autocomplete suggestion when you type `{`.

    <CodeGroup>
      ```json Sample payload
      {
        "array": [
          {
            "product_name": "Aldo Sling Bag",
            "product_price": "3,950.00"
          },
          {
            "product_name": "Clarles & Keith Women Slipper, Biege, 38UK",
            "product_price": "2,549.00"
          },
          {
            "product_name": "RayBan Sunglasses",
            "product_price": "7,899.00"
          }
        ],
        "event": {
          "location": {
            "city": "Bangalore",
            "state": "KA"
          },
          "order_id": "11200123",
          "first_name": "Nikita"
        },
        "product_page": "https://www.suprsend.com"
      }
      ```
    </CodeGroup>

    Common variable patterns:

    - **Nested variable** — `{{var1.var2.var3}}`. E.g. to reference `city` above: `{{event.location.city}}`
    - **Array element** — `{{var1.[index].var2}}`. E.g. to reference the first product name: `{{array.[0].product_name}}`
    - **Key with spaces** — wrap in square brackets: `{{event.[first name]}}`

    <Frame>
      <img src="/images/docs/da63a3b-Screenshot_2022-06-20_at_8.48.24_AM.png" />
    </Frame>

    For the full syntax reference, see [Handlebars Helpers](/docs/handlebars-helpers).

    <Warning>
      If a variable is present in the template but its value is missing or mismatched at send time, SuprSend will not send that channel's notification. Other channels in the same template that render successfully will still be sent.
    </Warning>
  </Step>
</Steps>

The right panel shows a live preview of the Inbox UI — a floating notification centre with **All**, **Mentions**, and **Replies** tabs, exactly as it appears in your product. The notification card updates in real time as you fill in fields.

To preview with a specific user's data, search for a user in the **Recipient** section of the Variables panel. Their live profile properties load as the variable context.

## Best Practices

Here's a breakdown of how to use each advanced field effectively:

- **Tags** act as filters to create Inbox tabs — a useful way to organise notifications. LinkedIn separates mentions and reactions into distinct tabs. A typical SaaS app might use `All`, `Product releases`, and `Upcoming events`. Learn how to implement tabs [here](/docs/multi-tabs).

- **Expiry** — it's good practice to add an expiry of 15 days or more to all notifications, except long-lived ones users may want to reference later (product updates, blog posts). Set shorter expiry for time-bound content like webinars and event registrations. Use the [expiry timer](#show-expiry-timer) to prompt urgency — the colour change from grey to red as expiry approaches is an effective way to drive action.

- **Pinning** is for notifications that must stay visible until the user acts — compliance actions, critical system updates, or urgent app version requirements. Always combine pinning with an expiry, otherwise the notification remains pinned until the user manually archives it.

<Note>
  Avoid adding expiry to long-lived notifications that users might want to reference later, like product updates or blog posts.
</Note>

## Overview

The In-App Inbox editor lets you design notifications that appear inside your 
product's notification centre — powered by SuprSend's [Inbox SDK](/docs/inbox-overview). 
Unlike email or push, inbox notifications are persistent: they live in the user's 
feed until they are read, dismissed, or expired.

The editor is a structured form with a live preview of the Inbox UI on the right 
that updates in real time as you fill in fields.

## Getting Started

To add In-App Inbox to a template, open the template in edit mode, click **+** 
in the channel tab row, select **In-App Inbox**, and click **Add Channels**. 
SuprSend creates a `default` variant and opens the inbox editor.

The channel tab menu (**⋮** next to the tab name) has one option: 
**Disable Channel** — this removes the channel from the active workflow without 
deleting the variant content.

## Content Fields

### Header

An optional title displayed at the top of the notification card in bold. Use it 
to give the notification a clear subject at a glance — similar to an email 
subject line. For example: `New comment received`, `Your story has 30 views`.

Supports Handlebars variables and emoji.

### Text *(required)*

The main body of the notification. This is the only required field.

Supports **HTML and Markdown** — use `**bold**`, `*italic*`, `` `code` ``, 
`[link text](url)`, blockquotes, and standard Markdown syntax. The rendered 
output is shown live in the preview panel.

Supports Handlebars variables and emoji.

### Avatar

An optional image displayed alongside the notification — typically a user photo, 
product image, or brand icon.

| Field | Description |
| --- | --- |
| **Image URL** | URL of the avatar image. Supports static URLs or dynamic variables e.g. `{{$actor.avatar}}`. Accepts `.jpeg` and `.png` formats. |
| **Click Action URL** | URL to open when the user clicks the avatar image specifically. |

### Subtext

A secondary line of smaller text displayed below the main body. Use it for 
metadata — timestamps, category labels, or contextual details. It is clickable, 
so it can serve as a subtle secondary action — for example, showing comment 
counts like LinkedIn, or task card numbers like Jira.

| Field | Description |
| --- | --- |
| **Subtext** | The secondary text content. Supports Handlebars. |
| **Click Action URL** | URL to open when the user clicks the subtext. |

### Action URL

The URL that opens when the user clicks anywhere on the notification card 
(excluding avatar and subtext click areas, if those have their own URLs set).

| Field | Description |
| --- | --- |
| **Launch URL** | Destination URL for the card click action. Accepts `http` / `https` URLs. |
| **Open in new tab** | When checked, the URL opens in a new browser tab. |

### Action Buttons

Add up to **2 CTA buttons** rendered inside the notification card. Each button has:

| Field | Description |
| --- | --- |
| **Button Title** | The label displayed on the button. |
| **Button Link** | The URL the button navigates to on click. |
| **Open in new tab** | Opens the link in a new tab when checked. |

Click **+ Add Button** to add a button. Remove with the **✕** icon. The maximum 
is 2 buttons per notification.

Buttons can also trigger inline actions (like opening a modal or calling an 
internal function) using a 
[custom click handler](https://github.com/suprsend/suprsend-react-inbox/blob/main/docs/customization.md#action-button-custom-click-handlers).

<Tip>
  Use action buttons for clear, specific calls to action — "View Order", 
  "Approve", "Dismiss". Avoid adding buttons when the card click action already 
  covers the primary intent.
</Tip>

## Advanced Configuration

Expand the **Advanced Configuration** section for controls that affect 
notification behaviour and organisation in the Inbox feed.

### Tags

Tags are labels attached to the notification that your Inbox UI can use to 
organise notifications into tabs or filter views. For example, a SaaS product 
might tag notifications as `billing`, `product`, or `team` to power separate 
tabs in the Inbox.

Search for existing tags or type to create a new one. Multiple tags can be 
applied to a single notification.

<Note>
  **Inbox template tags vs workflow tags:** Tags added in the Inbox template are 
  used to filter notifications in Inbox tabs — reference them in your Inbox 
  configuration using `tags: "your_tag"` in the query. Tags added in a workflow 
  are only used to group or filter workflows on the workflow listing page and 
  **do not** affect Inbox filtering. To filter notifications in tabs, you must 
  add tags here in the Inbox template.
</Note>

See [Multi Tabs](/docs/multi-tabs) for how to build tab-based Inbox UIs 
using tags.

### Pinned Notification

Toggle **Pinned Notification** on to pin this notification to the top of the 
user's Inbox feed regardless of recency. Use for high-priority notifications 
that require user action — compliance tasks, plan renewals, critical system 
updates.

<Tip>
  Always combine pinning with an expiry, otherwise the notification stays pinned 
  indefinitely until the user archives it manually.
</Tip>

### Expiry

Toggle **Expiry** on to set a time-to-live for the notification. After the 
expiry time passes, the notification is automatically removed from the user's 
feed. Useful for time-sensitive content like flash sale alerts or event reminders.

As a general rule, set an expiry of 15 days or more on all standard notifications 
to keep user inboxes clean. Avoid expiry on long-lived notifications users may 
want to reference later, like product updates or blog posts.

There are two expiry modes:

#### Fixed Expiry

A relative time — e.g. `2d 4h 30m 0s` — or an absolute timestamp — e.g. 
`2024-04-01 2:00 pm`. Absolute timestamps are interpreted in your local timezone.

#### Dynamic Expiry

Expiry computed from your event or user properties. Pass a Handlebars variable 
— e.g. `{{expiry_time}}` — whose value resolves to one of:

- An **ISO-8601 timestamp** in the future — e.g. `2024-03-02T20:34:07Z`
- An **integer** — treated as a duration in seconds — e.g. `50`
- An **interval string** — e.g. `2d 4h 30m 0s` where d = days, h = hours, 
  m = minutes, s = seconds

#### Show Expiry Timer

Enable **Show Expiry Timer** to display a countdown on the notification card. 
The timer renders with a grey background when more than 1 hour remains, and 
turns red when under 1 hour — drawing attention as the deadline approaches. 
Use this to drive action urgency on time-sensitive notifications.

### Importance

Controls the visual weight of the notification in the Inbox feed.

| Value | Behaviour |
| --- | --- |
| **Default** | Standard notification styling. |
| Other levels | Higher importance levels may affect visual prominence depending on your Inbox component configuration. |

### Extra Data

A freeform JSON object attached to the notification payload — not displayed to 
the user, but available to your frontend via the Inbox SDK. Use it to pass 
structured metadata your application logic needs when the user interacts with 
the notification.
```json
{"key": "value"}
```

For example, pass an `order_id` or `entity_type` so your app can navigate to 
the right screen on notification click, without encoding that logic in the URL.

## Live Preview

The right panel shows a live preview of the Inbox UI — a floating notification 
centre with **All**, **Mentions**, and **Replies** tabs, exactly as it appears 
in your product. The notification card updates in real time as you fill in fields.

To preview with a specific user's data, search for a user in the **Recipient** 
section of the Variables panel.

## Variables

All text fields support Handlebars syntax. Define variables in the 
**Variables `{}`** panel before using them to get autocomplete and ensure the 
preview renders correctly.

| Source | Example | Description |
| --- | --- | --- |
| Trigger payload | `{{order_id}}` | Data sent when the workflow triggers |
| Recipient profile | `{{$recipient.first_name}}` | Properties from the user's SuprSend profile |
| Actor profile | `{{$actor.name}}` | Properties from the actor (e.g. the user who triggered the action) |
| Tenant | `{{$brand.brand_name}}` | Tenant branding properties |

For conditionals, loops, and helpers, see 
[Handlebars Helpers](/docs/handlebars-helpers).

<Warning>
  If a variable is missing at send time, **the Inbox notification is not sent** 
  — but other channels in the same workflow (e.g. email, push) are unaffected 
  and will still be delivered.
</Warning>

## Markdown Support

The **Text** field renders both HTML and Markdown. Supported Markdown formatting:

| Syntax | Output |
| --- | --- |
| `**text**` | **Bold** |
| `*text*` | *Italic* |
| `` `code` `` | Inline code |
| `[label](url)` | Hyperlink |
| `> text` | Blockquote |
| `# Heading` | Heading |

Markdown and Handlebars variables can be combined — e.g. 
`**{{$recipient.first_name}}**, your order has shipped.`

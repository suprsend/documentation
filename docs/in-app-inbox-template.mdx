Build notification cards that appear inside your product's [notification center](/docs/inbox-overview). Each card supports a header, body (with Markdown), avatar, action buttons, click URL, and advanced options like pinning, expiry, and tags for tab filtering. Content is personalised with [Handlebars](/docs/handlebars-helpers) variables (`{{variable_name}}`).

<Note>
  You need the SuprSend Inbox SDK installed in your product before in-app notifications are visible to users. [Set up the Inbox SDK →](/docs/inbox-quick-start)
</Note>

## Fields

### Header

**Required** · Supports variables

Heading shown in bold at the top of the card.

**What to write here:** One scannable sentence — the action and object (`New comment received`, `Your story has got 30 views`).

Supports Handlebars: `{{variable_name}}`

> Example: `{{actor_name}} commented on your post` · `Order #{{order_id}} shipped` · `New feature: {{feature_name}}`

### Body (Text)

**Required** · Supports variables

Body of the message. Supports [Markdown syntax](https://www.markdownguide.org/basic-syntax/) — headings, **bold**, *italic*, blockquotes, [links](https://www.markdownguide.org/basic-syntax/#links), and `code`.

**What to write here:** Use bold for key facts on transactional cards; blockquotes for excerpts on social notifications.

> Example: `"{{comment_excerpt}}"` · `Your package is on the way! Expected delivery: **{{delivery_date}}**` · `{{requester_name}} submitted a {{amount}} expense report for {{category}}.` · `{{feature_description}}`

### Avatar

**Optional** · Supports variables

Public image URL (`.jpeg`, `.png`).

**What to write here:** Actor profile photo for social notifications (`{{actor_avatar_url}}`), or a static product logo URL for announcements.

### Subtext

**Optional** · Supports variables

Clickable footer line for secondary info — comment count, task ID, or timestamps.

**What to write here:** Relative time (`{{time_ago}}`) or IDs users might copy.

### Action URL

**Optional** · Supports variables

URL the user opens when they click the card (not a button). Toggle **Open in new tab** if needed.

**What to write here:** Deep link into the relevant screen — include comment anchors when useful.

> Example: `https://yourapp.com/posts/{{post_id}}#comment-{{comment_id}}` · `https://yourapp.com/orders/{{order_id}}` · `https://yourapp.com/changelog/{{release_id}}`

### Action Buttons

**Optional**

Up to 2 buttons with text + URL. Use for CTAs like "View", "Approve", or inline actions. See [custom click handlers](https://github.com/suprsend/suprsend-react-inbox/blob/main/docs/customization.md#action-button-custom-click-handlers) for advanced button behaviour.

**What to write here:** Label with verbs — `View Report`, `Approve`, `Track Order` — not bare nouns.

> Example: `Track Order` → `https://yourapp.com/track/{{order_id}}` · `Approve` / `Reject` for expense flows with approve and reject URLs.

## Personalise with variables

You can add variables in the template to personalise it per recipient. SuprSend replaces variables with actual data at send time. Pass these values while triggering the communication from one of the frontend or backend SDKs.

We use [Handlebars](https://handlebarsjs.com/guide/#what-is-handlebars) as the templating language. You can add variables as `{{variable_name}}`. We also support [Handlebars helpers](/docs/handlebars-helpers) for complex use cases like if-else conditions, default values, and array iteration.

<Steps>
  <Step title="Add variables in the Variables panel">
    Add sample data in the **Variables panel** (Input Payload section) on the left side of the editor. This defines the structure of your variables, enables auto-suggestions while designing, and powers the live preview. For the full guide on setting up variables, see [Adding dynamic content](/docs/templates#the-variables-panel).
  </Step>

  <Step title="Use variables in the template fields">
    Type `{{` in any text field — auto-suggestions appear based on the data in the Variables panel. You can also manually type variable names following Handlebars syntax.

    **Examples using this sample data:**

    <CodeGroup>
      ```json json
      {
        "array": [
          {
            "product_name": "Aldo Sling Bag",
            "product_price": "3,950.00"
          },
          {
            "product_name": "Clarles & Keith Women Slipper",
            "product_price": "2,549.00"
          }
        ],
        "event": {
          "location": {
            "city": "Bangalore",
            "state": "KA"
          },
          "order_id": "11200123",
          "first_name": "Nikita"
        },
        "product_page": "https://www.suprsend.com"
      }
      ```
    </CodeGroup>

    - **Nested variable:** `{{event.location.city}}` → renders as `Bangalore`
    - **Array element:** `{{array.[0].product_name}}` → renders as `Aldo Sling Bag`
    - **Variable with space in name:** `{{event.[first name]}}`

    The preview section shows sample values rendered in real-time. If a variable doesn't render, check:
    1. The variable is defined in the Variables panel.
    2. The variable name matches the Handlebars syntax exactly.
  </Step>
</Steps>

<Warning>
  If a variable in the template cannot be rendered at send time (due to mismatch or missing data), SuprSend skips that notification for the affected user. Other channels in the same template group are still sent.
</Warning>

### Tags

**Optional** · Supports variables (where applicable)

Tags filter and organise notifications inside [multiple tabs](/docs/multi-tabs). You can filter tabs by tag, [notification category](/docs/notification-category), or read status — For example, show all `unread` notifications with the `mentions` tag in a "Mentions" tab. Use them to separate updates from mentions, product releases from events.

<Note>
  **Tags in Inbox template vs Tags in Workflow:** Template tags filter notifications in inbox tabs. Workflow tags only group workflows on the listing page and do not affect inbox filtering. To filter inbox tabs, add tags in the template and reference them in your [inbox tab configuration](/docs/multi-tabs).
</Note>

<Frame caption="Inbox with tabs - All, mentions and replies">
  <img src="/images/docs/1c56c00-image.png" />
</Frame>

**What to write here:** Define a small taxonomy (`mentions`, `product-updates`) and use it consistently so tabs stay useful.

### Pin notification

**Optional**

Pinned notifications display with a `pinned` badge and stay at the top of the notification list until the user reads or archives them. Reserve for notifications requiring immediate action — compliance tasks, plan renewals, or limited-time offers. Always combine with an expiry so stale pins don't persist indefinitely.

<Frame>
  <img src="/images/docs/7ee3c01-image.png" />
</Frame>

**What to write here:** Turn on Pin for approvals and deadlines — always pair with **Expiry**.

### Expiry (relative)

**Optional**

Set a duration relative to when the notification is sent — e.g., `2 days 6 hours`.

<Frame caption="Relative expiry with days, hours, minutes, seconds">
  <img src="/images/docs/templates-editor-inbox-expiry-relative.png" />
</Frame>

**What to write here:** Use ~7 days for transactional updates so the inbox stays tidy; shorter windows for flash sales or reminders.

### Expiry (absolute)

**Optional**

Set a fixed date and time. The timestamp uses your local timezone.

<Frame caption="Absolute expiry with date and time picker">
  <img src="/images/docs/templates-editor-inbox-expiry-absolute.png" />
</Frame>

**What to write here:** Use when the notification stops being relevant at a specific calendar moment.

### Expiry (dynamic)

**Optional** · Supports Handlebars

For expiry computed from your event or user data, use a Handlebars variable — e.g., `{{expiry_time}}`. The value can be:

- An ISO-8601 timestamp (e.g., `2024-03-02T20:34:07Z`) — must be in the future.
- A relative duration: an integer (seconds) or an interval string like `2d 6h 30m 0s`.

**What to write here:** Pass the exact moment the content becomes irrelevant — event start time, offer end — so the card archives automatically.

### Show expiry timer

**Optional**

Enable this to display a countdown timer on the notification card. The timer shows in grey when more than 1 hour remains and turns red below 1 hour to drive urgency.

<Frame caption="Expiry timer with different time remaining">
  <img src="/images/docs/2c44f10-image.png" />
</Frame>

**What to write here:** Use for time-bound offers and event reminders where countdown visibility helps conversion.

### Extra Data

**Optional**

A JSON field for passing custom key-value pairs alongside the notification. Use this for app-level metadata that your frontend can process — e.g., deep link parameters, feature flags, or tracking IDs.

## Preview and test

Preview and test before you rely on this template in production.

The right panel shows a live preview of the inbox notification card, updated in real time as you edit. Variables render using data from the **Variables panel** — select a recipient or tenant to preview with real data.

Click **Test** in the top-right corner to send a real notification to a real user's inbox. This uses the **live version** — commit your changes before testing. See [Testing a Template](/docs/templates#test) for the full guide.

## Publish

Click **Commit** in the top bar to publish the current draft as a new live version. Add an optional description for versioning. Once committed, all notifications triggered after this point use the new content.

Committing snapshots everything: field content, advanced configurations (tags, pinning, expiry), and variable references.

## Other ways to build this template

If a blank editor is slow, start from an artifact you already have. Keep it to these three high-impact paths.

### Workflow payload -> inbox card (fastest)

- **Start with:** a real workflow trigger payload from staging.
- **Do:** paste it into the Variables panel, then map keys directly to Header, Body, Avatar, Action URL, and Buttons.
- **Best for:** teams that already trigger workflows and want minimal guesswork.

### Frontend route list -> deep-link-first templates

- **Start with:** your route table or mobile deep-link config.
- **Do:** define Action URL/Button destinations first, then write copy that matches each destination.
- **Best for:** reducing broken links and wrong-screen navigation from notifications.

### Support ticket or incident -> action-required card

- **Start with:** a recurring support issue or incident playbook.
- **Do:** convert it into one card with two buttons (for example `Acknowledge` and `View Runbook`), plus Pin and short Expiry.
- **Best for:** ops and admin dashboards where users must act quickly.

## Best practices

- **Header = one scannable sentence:** Not a paragraph. A complete thought in about eight words or less.
- **Label action buttons with verbs:** `View Report` not `Report`, `Approve` not `Action`.
- **Always pair Pin with Expiry:** A pinned notification without expiry stays at the top of your inbox forever.
- **Set expiry dynamically to the exact moment the notification stops being relevant:** Use `{{expiry_time}}` from your backend when you have a real timestamp.

## FAQ

<AccordionGroup>
  <Accordion title="How do I design a social activity notification (comment, like, mention)?">
    Use **Avatar** for the actor's profile photo, **Header** for the action summary (e.g., `{{actor_name}} commented on your post`), **Text** for the excerpt, and **Subtext** for relative timestamps. Tag with `mentions` to route into a dedicated Mentions tab.

  | Field | Value |
  |---|---|
  | Header | `{{actor_name}} commented on your post` |
  | Text | `"{{comment_excerpt}}"` |
  | Avatar | `{{actor_avatar_url}}` |
  | Subtext | `{{time_ago}}` |
  | Action URL | `https://yourapp.com/posts/{{post_id}}#comment-{{comment_id}}` |
  | Tags | `mentions` |
  </Accordion>

  <Accordion title="How do I design a transactional notification (order, payment, delivery)?">
    Use **bold markdown** in the text to highlight key details. Set a 7-day expiry so delivered-order notifications don't clutter the inbox. Add a tracking button via Action Buttons.

  | Field | Value |
  |---|---|
  | Header | `Order #{{order_id}} shipped` |
  | Text | `Your package is on the way! Expected delivery: **{{delivery_date}}**` |
  | Action URL | `https://yourapp.com/orders/{{order_id}}` |
  | Button 1 | `Track Order` → `https://yourapp.com/track/{{order_id}}` |
  | Expiry | Relative: 7 days |
  </Accordion>

  <Accordion title="How do I design an approval / action-required notification?">
    Use **Pin** so the notification stays at the top. Set a short expiry (e.g., 3 days) so stale approvals auto-archive. Use [custom click handlers](https://github.com/suprsend/suprsend-react-inbox/blob/main/docs/customization.md#action-button-custom-click-handlers) for in-line Approve/Reject without leaving the page.

  | Field | Value |
  |---|---|
  | Header | `Expense report needs approval` |
  | Text | `{{requester_name}} submitted a {{amount}} expense report for {{category}}.` |
  | Button 1 | `Approve` → `https://yourapp.com/expenses/{{expense_id}}/approve` |
  | Button 2 | `Reject` → `https://yourapp.com/expenses/{{expense_id}}/reject` |
  | Pin | Enabled |
  | Pin | Enabled |
  | Expiry | Relative: 3 days |
  </Accordion>

  <Accordion title="How do I design a product announcement notification?">
    Use a static product logo as the **Avatar** and a `product-updates` tag to route into a dedicated tab. Avoid setting expiry — users may want to reference announcements later.

  | Field | Value |
  |---|---|
  | Header | `New feature: {{feature_name}}` |
  | Text | `{{feature_description}}` |
  | Avatar | (static product logo URL) |
  | Action URL | `https://yourapp.com/changelog/{{release_id}}` |
  | Tags | `product-updates` |
  </Accordion>

  <Accordion title="When should I use Pin vs Expiry?">
    - **Pin** — for notifications that must stay at the top until the user acts (compliance, critical alerts). Always combine with an expiry so they don't stay pinned forever.
    - **Expiry** — for time-sensitive content (flash sales, event reminders). Use relative expiry for consistent durations, absolute for fixed deadlines, and dynamic for computed values from your payload.
  </Accordion>

  <Accordion title="How do Tags work for Inbox tabs?">
    Tags added in the template filter notifications into [Inbox tabs](/docs/multi-tabs). For example, tag with `mentions` to show in a "Mentions" tab, or `product-updates` for a "Product" tab. Tags in the template are different from workflow tags — workflow tags only group workflows on the listing page.
  </Accordion>

  <Accordion title="How do I add dynamic expiry from my payload?">
    Use a Handlebars variable like `{{expiry_time}}` in the Dynamic Expiry field. The value can be an ISO-8601 timestamp (e.g., `2024-03-02T20:34:07Z`) or a relative duration (integer for seconds, or `2d 6h 30m 0s` format).
  </Accordion>

  <Accordion title="What happens if a variable is missing or has the wrong value at send time?">
    SuprSend skips the In-App notification for that user. Other channels in the same template group are still sent.
  </Accordion>

  <Accordion title="Can I use this channel alongside other channels in the same workflow?">
    Yes — add In-App Inbox with email, push, Slack, and others in the same template group.
  </Accordion>

  <Accordion title="How do I pass variable values when triggering the workflow?">
    Include properties in your trigger payload or event so Handlebars paths match. Use the **Variables panel** for sample data. See [Adding dynamic content](/docs/templates#the-variables-panel).
  </Accordion>
</AccordionGroup>

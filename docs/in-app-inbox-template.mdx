## Overview

The In-App Inbox editor lets you design notifications that appear inside your product's notification centre — powered by SuprSend's [Inbox SDK](/docs/inbox-overview). Unlike email or push, inbox notifications are persistent: they live in the user's feed until they are read, dismissed, or expired.

The editor is a structured form — no drag-and-drop canvas. Every field maps directly to a property on the rendered notification card. A live preview of the Inbox UI updates on the right as you fill in fields.

---

## Getting Started

To add In-App Inbox to a template, open the template in edit mode, click **+** in the channel tab row, select **In-App Inbox**, and click **Add Channels**. SuprSend creates a `default` variant and opens the inbox editor.

The channel tab menu (**⋮** next to the tab name) has one option: **Disable Channel** — this removes the channel from the template without deleting the variant content.

## Content Fields

### Header

An optional title displayed at the top of the notification card in bold. Use it to give the notification a clear subject at a glance — similar to an email subject line.

Supports Handlebars variables and emoji.

### Text *(required)*

The main body of the notification. This is the only required field.

Supports **Markdown** — use `**bold**`, `*italic*`, `` `code` ``, `[link text](url)`, and other standard Markdown syntax. The rendered output is shown live in the preview panel.

Supports Handlebars variables and emoji.

### Avatar

An optional image displayed alongside the notification — typically a user photo, product image, or brand icon.

| Field | Description |
| --- | --- |
| **Image URL** | URL of the avatar image. Can be a static URL or a dynamic variable e.g. `{{$actor.avatar}}`. |
| **Click Action URL** | URL to open when the user clicks the avatar image specifically. |

### Subtext

A secondary line of smaller text displayed below the main body. Use it for metadata — timestamps, category labels, or contextual details that are useful but don't belong in the primary message.

| Field | Description |
| --- | --- |
| **Subtext** | The secondary text content. Supports Handlebars. |
| **Click Action URL** | URL to open when the user clicks the subtext. |

### Action URL

The URL that opens when the user clicks anywhere on the notification card (excluding avatar and subtext click areas, if those have their own URLs set).

| Field | Description |
| --- | --- |
| **Launch URL** | Destination URL for the card click action. |
| **Open in new tab** | When checked, the URL opens in a new browser tab instead of the current one. |

### Action Buttons

Add up to multiple CTA buttons rendered inside the notification card. Each button has:

| Field | Description |
| --- | --- |
| **Button Title** | The label displayed on the button. |
| **Button Link** | The URL the button navigates to on click. |
| **Open in new tab** | Opens the link in a new tab when checked. |

Click **+ Add Button** to add another button. Remove a button with the **✕** icon on the right.

<Tip>
  Use action buttons for clear, specific calls to action — "View Order", "Approve", "Dismiss". Avoid adding buttons when the card click action already covers the primary intent.
</Tip>

## Advanced Configuration

Expand the **Advanced Configuration** section for controls that affect notification behaviour and organisation in the Inbox feed.

### Tags

Tags are labels attached to the notification that your Inbox UI can use to organise notifications into tabs or filter views. For example, a SaaS product might tag notifications as `billing`, `product`, or `team` to power separate tabs in the Inbox.

Search for existing tags or type to create a new one. Multiple tags can be applied to a single notification.

See [Multi Tabs](/docs/multi-tabs) for how to build tab-based Inbox UIs using tags.

### Pinned Notification

Toggle **Pinned Notification** on to pin this notification to the top of the user's Inbox feed regardless of recency. Use sparingly — for high-priority, time-sensitive notifications that must not be missed.

### Expiry

Toggle **Expiry** on to set a time-to-live for the notification. After the expiry time passes, the notification is automatically removed from the user's feed. Useful for time-sensitive content like flash sale alerts or event reminders that become irrelevant after a certain point.

### Importance

Controls the visual weight and urgency of the notification in the Inbox feed. Options:

| Value | Behaviour |
| --- | --- |
| **Default** | Standard notification styling. |
| Other levels | Higher importance levels may affect visual prominence depending on your Inbox component configuration. |

### Extra Data

A freeform JSON object attached to the notification payload — not displayed to the user, but available to your frontend via the Inbox SDK. Use it to pass structured metadata that your application logic needs when the user interacts with the notification.

```json
{"key": "value"}
```

For example, pass an `order_id` or `entity_type` so your app can navigate to the right screen when the notification is clicked, without encoding that logic in the URL.

## Live Preview

The right panel shows a live preview of the Inbox UI — a floating notification centre with **All**, **Mentions**, and **Replies** tabs, exactly as it appears in your product. The notification card updates in real time as you fill in fields.

To preview with a specific user's data, search for a user in the **Recipient** section of the Variables panel. Their profile properties load as the variable context, and the preview renders with their actual values.

## Variables

The Inbox editor supports full Handlebars syntax in all text fields (Header, Text, Subtext, Avatar URL, Button labels, and URLs).

Define variables in the **Variables `{}`** panel before using them — this gives you autocomplete as you type `{{` in any field and ensures the preview renders correctly.

| Source | Example | Description |
| --- | --- | --- |
| Trigger payload | `{{order_id}}` | Data sent when the workflow triggers |
| Recipient profile | `{{$recipient.first_name}}` | Properties from the user's SuprSend profile |
| Actor profile | `{{$actor.name}}` | Properties from the actor (e.g. the user who took an action) |
| Tenant | `{{$brand.brand_name}}` | Tenant branding properties |

For conditionals, loops, and helpers, see [Handlebars Helpers](/docs/handlebars-helpers).

## Markdown Support

The **Text** field renders Markdown. Supported formatting:

| Syntax | Output |
| --- | --- |
| `**text**` | **Bold** |
| `*text*` | *Italic* |
| `` `code` `` | Inline code |
| `[label](url)` | Hyperlink |
| `> text` | Blockquote |
| `` ```code block``` `` | Code block |

Markdown and Handlebars variables can be combined — e.g. `**{{$recipient.first_name}}**, your order has shipped.`

---

## Disabling the Channel

To remove the In-App Inbox channel from a template without losing its content, click **⋮** next to the channel tab and select **Disable Channel**. The channel stops sending but its configuration is preserved. Re-enable it by adding the channel back via the **+** tab.

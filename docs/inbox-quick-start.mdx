<Note>
  In-app Inbox needs **frontend work** to render the bell + feed. The full SDK install + wiring walkthrough lives in the [Quickstart](/docs/getting-started/quickstart) (Phase B5 for SDK install, Phase E6 for the Inbox component, Phase E7 for identify/reset wiring). This page covers what's special about the Inbox **channel** itself — useful when you're building the workflow + template that powers the feed.
</Note>

Inbox is unique among SuprSend channels in three ways:

1. **No vendor configuration needed** — SuprSend hosts the feed natively.
2. **No recipient identity field** — every user is auto-attached to Inbox the moment they're identified.
3. **Frontend SDK required** — to actually display the messages in your product, you need to install the Inbox SDK ([React](/docs/react-inbox-integration), [JS](/docs/web-components-integration), [React Native](/docs/inbox-react-native), [Flutter](/docs/inbox-flutter)).

## Sending an Inbox message

Add an Inbox delivery node to your workflow with an [Inbox template](/docs/in-app-inbox-template). The template defines the message body, action buttons, deeplink, and any custom data exposed to your frontend.

Trigger as you would for any other channel — but you don't need to pass `$email`, `$sms`, etc. Just `distinct_id`:

```json
"recipients": [
  { "distinct_id": "user_123" }
]
```

## Authentication — HMAC

For production Inbox, your frontend must present an HMAC-signed subscriber ID so only the correct user can read their feed. Your backend mints the HMAC using the **Inbox secret** from the [Inbox vendor configuration page](https://app.suprsend.com/en/sandbox/vendors/inbox/suprsend-inbox?brand_id=default).

Full guide: [HMAC authentication](/docs/hmac-authentication). The Inbox secret is **per-environment** — re-mint when promoting to Production.

## Inbox features worth knowing

- [Multi-tab inbox](/docs/multi-tabs) — separate categories (mentions, alerts, comments) into tabs.
- [Embedded preference centre](/docs/embedded-preference-centre) — a drop-in UI for users to manage opt-in/out.
- [Customizable React components](/docs/react-customising-feed) — restyle the feed, header, and notification cards.
- [Headless React](/docs/react-headless) — bring your own UI; we handle the realtime + state.
- [Toast notifications](/docs/react-toast-notifications) — show transient toasts in addition to the persistent feed.
- [Live Inbox Playground](https://inbox-playground.suprsend.com/) — interactive demo of every layout (bell, sidesheet, fullscreen).

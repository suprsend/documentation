<Steps>
  <Step title="Create your account">
    [Sign up](https://auth.suprsend.com/sign-up) on SuprSend to create your account. If you already have a company account, ask your admin to invite you to the team.
  </Step>

  <Step title="Explore the playground">
    See a live demo of Inbox implementation in our [playground](https://inbox-playground.suprsend.com/). You'll also get sample code for all types of Inbox views in the [GitHub repo](https://github.com/suprsend/suprsend-inbox-example) linked in the playground.
  </Step>

  <Step title="Choose your workspace">
    Your SuprSend account includes three default workspaces. Switch between them from the top navigation bar.

    <CardGroup cols={3}>
      <Card title="Sandbox" icon="flask">
        **Demo workspace** with pre-configured vendors for quick exploration and POC. Includes sample workflow and user with your registered email. Available for a trial period.
      </Card>
      <Card title="Staging" icon="code-branch">
        **Development workspace** for testing notification flows before production. Enable [Test Mode](/docs/developer/test-mode) to safely test without delivering to real users.
      </Card>
      <Card title="Production" icon="rocket">
        **Live workspace** for syncing your actual product users and running production workflows. We don't recommend making changes directly here.
      </Card>
    </CardGroup>
  </Step>

  <Step title="Create a workflow">
    Workflows house the automation logic of your notifications. Each workflow starts with a trigger, processes the defined logic, and sends messages to end users.

    <Frame caption="Create a new workflow from the dashboard">
      <img src="/images/docs/d78be2d-image.png" />
    </Frame>

    To design a workflow, you need:

    **1. A Trigger** - Initiates the workflow
    - [Direct workflow API](/docs/trigger-workflow#triggering-workflow-via-api) - Include recipient channel information, preferences, and actor details directly in the trigger
    - [Event-based trigger](/docs/trigger-workflow#event-based-trigger) - Trigger from your frontend or backend (recipient must be pre-created)

    **2. A Delivery Node** - Sends notifications to users
    - [Multi-channel](/docs/delivery-multi-channel) - Send across multiple channels
    - [Smart channel routing](/docs/smart-delivery) - Notify users sequentially (recommended)
    - **Template** - Contains notification content with static and dynamic content using handlebars `{{var}}`

    <Tip>
      Add trigger data in the **mock** to get variable auto-suggestions during template editing. Ensure to publish the template before using it in a workflow.
    </Tip>

    <Frame caption="Design your inbox template">
      <img src="https://files.readme.io/e5b9db7-template_edit.gif" />
    </Frame>

    [Learn more about designing In-app Inbox templates](/docs/in-app-inbox-template)

    **3. Functional Nodes (Optional)** - Add logic like delay, batch, or conditional branches. [Check out all workflow nodes](/docs/delay)
  </Step>

  <Step title="Trigger the workflow">
    You can trigger a test workflow directly from the dashboard by clicking the **`Test`** button, or **"Commit"** changes to trigger it from your code. We follow Git-like versioning for workflow changes.

    <Tip>
      In Sandbox, a sample user with your registered email ID is pre-created for testing. You can add more users or edit existing profiles from the subscriber page.
    </Tip>

    **Get your API credentials:**

    <Frame caption="Find your API keys in Settings">
      <img src="/images/reference/f14274c-API_key_page.png" />
    </Frame>

    Get your workspace key, secret, or API Key from [Settings → API Keys](https://app.suprsend.com/en/sandbox/developers/api-keys). Inbox channel is automatically updated in user profile on user creation, so you won't need to pass Inbox channel in your trigger call.

    **Sample API trigger:**

      ```go go
      package main

      import (
        "log"
        suprsend "github.com/suprsend/suprsend-go"
      )

      // Initialize SDK
      func main() {
        suprClient, err := suprsend.NewClient("_workspace_key_", "_workspace_secret_")
        if err != nil {
          log.Println(err)
        }
        _ = suprClient
        triggerWorkflowAPI(suprClient)
      }

      func triggerWorkflowAPI(suprClient *suprsend.Client) {

        // Create WorkflowRequest body
        wfReqBody := map[string]interface{}{
          "workflow": "_workflow_slug_",
          "recipients": []map[string]interface{}{
            {
              "distinct_id":  "0gxxx9f14-xxxx-23c5-1902-xxxcb6912ab09",
              "name":"recipient_1",
            },
          },
          // # data can be any json / serializable python-dictionary
          "data": map[string]interface{}{
            "first_name":    "User",
            "invoice_amount": "$5000",
            "invoice_id":"Invoice-1234",
            "spend_amount":  "$10",
          },
        }

        w1 := &suprsend.WorkflowTriggerRequest{
          Body: wfReqBody,
          IdempotencyKey: "_unique_identifier_of_the_request_",
        }
        // Call Workflows.Trigger to send request to Suprsend
        resp, err := suprClient.Workflows.Trigger(w1)
        if err != nil {
          log.Fatalln(err)
        }
        log.Println(resp)
      }
      ```

      ```java java
      package test;

      import java.io.IOException;
      import java.io.UnsupportedEncodingException;
      import java.util.Arrays;

      import org.json.JSONArray;
      import org.json.JSONObject;

      import suprsend.Suprsend;
      import suprsend.SuprsendException;
      import suprsend.WorkflowTriggerRequest;

      public class Workflow {

        public static void main(String[] args) throws Exception {
          WorkflowTrigger();
        }

        private static void WorkflowTrigger() throws SuprsendException, UnsupportedEncodingException {
          Suprsend suprClient = Helper.getClientInstance();
          // payload
          JSONObject body = getWorkflowBody();
          String idempotencyKey = "_unique_request_identifier";
          WorkflowTriggerRequest wf = new WorkflowTriggerRequest(body, idempotencyKey, tenantId);
          //
          JSONObject resp = suprClient.workflows.trigger(wf);
          System.out.println(resp);
        }

        private static JSONObject getWorkflowBody() {
          JSONObject body = new JSONObject()
            .put("workflow", "__workflow_slug__")
            .put("recipients", new JSONArray()
                 .put(new JSONObject()
                      .put("distinct_id", "0gxxx9f14-xxxx-23c5-1902-xxxcb6912ab09")
                      .put("name", "recipient_1")
                     ))
            .put("data", new JSONObject()
                 .put("first_name", "User")
                 .put("invoice_amount", "$5000")
                 .put("invoice_id", "Invoice-1234")
                );

          return body;
        }
      }
      ```

  <Step title="Check notification logs">
    View the status of any sent notification under the Logs tab. Logs are organized in three sections:

    <Frame caption="Monitor your notification delivery">
      <img src="/images/docs/af79354-logs.png" />
    </Frame>

    - **Requests** - Captures all API/SDK requests sent to SuprSend from your backend or frontend. View input payload and request response.
    - **Executions** - Workflow executions are logged here. Click on a log entry to open the step-by-step workflow debugger.
    - **Messages** - All delivery nodes (including webhooks) are tracked here along with their message status (delivered, seen, clicked).
  </Step>

  <Step title="Push to production">
    In SuprSend, each environment is isolated—workflows, users, and vendors are configured separately in testing and production workspaces. You'll also need to change the Inbox secret in your server-side code to generate `subscriber_id` for your production users.

    Follow this [go live checklist](/docs/go-live-checklist) to set up production once you're done testing.

Adding SMS is three steps:

1. **Configure an SMS vendor** in the dashboard.
2. **Make sure your users have `$sms`** set in their profile.
3. **Add an SMS delivery node** to your workflow with an SMS template.

## 2. Recipient identity field

The SMS channel identity is `$sms`. Phone numbers must be in E.164 format (`+<country code><number>`).

```json
{
  "distinct_id": "user_123",
  "$sms": ["+12135555444"]
}
```

Or inline at trigger time:

```json
"recipients": [
  {
    "distinct_id": "user_123",
    "$sms": ["+12135555444"]
  }
]
```

## 3. SMS template

Use the [SMS template editor](/docs/sms-template). Plain text + Handlebars variables. Watch the character count — multi-segment SMS costs more.

---

## SMS gotchas

- **Sandbox limitation:** SMS can only be sent to verified phone numbers during the trial.
- **DLT compliance (India):** Indian SMS sends require pre-registered DLT templates. See [DLT guidelines](/docs/dlt-guidelines).
- **Always-on segments:** keep messages under 160 characters (GSM-7) or 70 characters (UCS-2 / emoji) to avoid silent multi-segment billing.
- **Opt-out keywords:** US carriers require honoring STOP / UNSUBSCRIBE — handle inbound webhooks from your vendor.
- **Track delivery:** add the SuprSend webhook URL in your vendor portal so delivery and failure events show up in [Logs](/docs/logging).
- **Common errors:** [Twilio errors](/docs/twilio-sms-errors) · [Gupshup errors](/docs/gupshup-sms-errors) · [MessageBird errors](/docs/messagebird-sms-errors).

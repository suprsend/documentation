---
title: "Multi-lingual Templates"
description: "Deliver notifications in each recipient's preferred language from a single template."
---

SuprSend allows you to create notifications in multiple languages within a single template. At send time, SuprSend picks the right language based on the recipient's profile and sends the message accordingly.

English is the default fallback language. Users with no language preference set — or whose preferred language has no content in the template — receive the notification in English.

## How it works

Multi-lingual delivery is powered by [template variants](/docs/template-variants). Each language is a separate variant with a **locale** condition. When a notification is triggered:

1. SuprSend checks the recipient's `preferred_language` from their [user profile](/docs/users).
2. If a variant exists for that language, it is used.
3. If no matching language variant exists, SuprSend falls back to the **default** variant (English).

<Info>
  Language (`locale`) is a **soft condition** — it has automatic fallback behaviour. If a specific language variant doesn't exist, SuprSend falls back gracefully to the default. This is different from hard conditions (like payload-based conditions) which have no fallback.
</Info>

## Setting a user's preferred language

Set the `preferred_language` property on the user profile using any of the backend SDKs:

- [Python SDK](/docs/python-create-user-profile#set-preferred-language)
- [Node.js SDK](/docs/node-create-user-profile#set-preferred-language)
- [Java SDK](/docs/java-create-user-profile)
- [Go SDK](/docs/go-create-user-profile)
- [REST API](/reference/edit-user-profile)

The language value should be a standard locale code (e.g., `en`, `es`, `fr`, `hi`, `de`, `pt-BR`).

## Creating language variants

<Steps>
  <Step title="Open the Variants panel">
    In the template editor, click the **Variants** tab (share icon) in the left panel. Click the **+** button and select **New Variant**.
  </Step>

  <Step title="Set the locale">
    In the Create Variant modal:
    - **Channels** — select the channels this variant applies to.
    - **ID** — give it a descriptive ID (e.g., `default-es`, `default-fr`).
    - **Locale** — select the language (e.g., Spanish, French, Hindi).
    - **Tenant** — leave empty unless this is a tenant-specific language variant.
    - **Conditions** — locale is automatically used as the matching condition. You can add additional conditions if needed.
  </Step>

  <Step title="Author content in the target language">
    The variant opens in the editor. Author the content in the selected language. Use [Import content](/docs/templates#import-content) to copy the default English variant as a starting point, then translate the text while keeping the layout intact.
  </Step>

  <Step title="Commit">
    Click **Commit** to make the variant live. The commit modal shows all variants being committed — you can deselect any you're not ready to publish.
  </Step>
</Steps>

<Tip>
  When creating language variants, use **Import content** to copy from the default English variant first. This preserves the layout, images, and structure — you only need to translate the text.
</Tip>

## Combining language with tenant

For tenants that need both brand customisation and localisation, create variants with combined conditions — e.g., a variant with locale `es` + tenant `acme` for Acme's Spanish-speaking customers.

The [fallback hierarchy](/docs/template-variants#variant-evaluation-at-send-time) works as:
1. Tenant + language (most specific) → e.g., Acme + Spanish
2. Tenant + default language → e.g., Acme + English
3. Default tenant + language → e.g., Default + Spanish
4. Default tenant + default language → the **default** variant

Place more specific variants (tenant + language) above general ones (language only) in the variant order.

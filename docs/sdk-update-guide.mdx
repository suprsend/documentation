## Before You Start

Updating SDKs can be tricky, especially with breaking changes. We've seen teams get caught off-guard by the JavaScript SDK v2.0 release.

**First:** Check your current versions on our [SDK Versioning](/docs/sdk-versioning) page.

## Check for Breaking Changes

**Don't skip this step.** Check our [SDK Changelog](/docs/sdk-changelog) for:

- **⚠️ Breaking changes** - these will break your code
- **✨ New features** - might be worth the update  
- **🔒 Security fixes** - update these ASAP

> **JavaScript SDK v2.0** completely changed authentication - no more workspace key/secret, now it's API keys and JWT tokens. Check our [migration guide](/docs/migration-guide-from-v1).

## Update Commands

### Package Managers
```bash
# Python
pip install suprsend-py-sdk --upgrade

# Node.js
npm install @suprsend/node-sdk@latest

# Go
go get -u github.com/suprsend/suprsend-go

# JavaScript
npm install @suprsend/web-sdk@latest

# React
npm install @suprsend/react@latest

# React Native
npm install @suprsend/react-native-sdk@latest

# Flutter
flutter pub upgrade suprsend_flutter
```

### Dependency Files
For Java, Android, and iOS, update the version in your dependency files:

**Java (pom.xml or build.gradle):**
```xml
<dependency>
  <groupId>com.suprsend</groupId>
  <artifactId>suprsend-java-sdk</artifactId>
  <version>0.5.0</version>
</dependency>
```

**Android (build.gradle):**
```gradle
implementation 'com.suprsend:rn:0.1.10'
```

**iOS (Package.swift or Xcode):**
Update to `SuprSend: 1.0.0` in Swift Package Manager.

## Test It Out

Now the fun part - testing. Don't just run your tests and call it a day.

- **Run your test suite** - look for warnings and deprecated method calls
- **Try the new features** - test out anything cool from the changelog
- **Check your logs** - look for deprecation warnings or new error messages

The JavaScript SDK v2.0 will definitely throw warnings if you're still using the old auth methods.

## Deploy Strategy

### Staging First
Deploy to staging and actually use it. Send some test notifications, check the delivery status, make sure everything works as expected.

If you're updating the JavaScript SDK, test it in a real browser - the authentication changes can be subtle.

### Production
Pick a good time (not Friday at 5 PM) and deploy. Keep an eye on your monitoring dashboards for the first hour or so.

**Pro tip:** Have a rollback plan ready. If something goes wrong, you want to be able to revert quickly.

## When Things Break

Breaking changes happen. The JavaScript SDK v2.0 completely changed how authentication works - no more workspace key/secret, now it's API keys and JWT tokens.

**What to do:**
1. Read the [migration guide](/docs/migration-guide-from-v1)
2. Update your code
3. Test thoroughly
4. For critical apps: gradual rollout

## Security Updates

If there's a security fix, update it. Like, now. Don't wait for the next sprint.

Test it quickly but thoroughly, then deploy. Security patches are usually small and focused, so they're less likely to break things.

## Pro Tips

- **Pin your versions** - Don't use `@latest` in production. Pin to specific versions like `"@suprsend/node-sdk": "1.13.0"`
- **One at a time** - Update one SDK at a time. If you update everything at once and something breaks, you won't know which one caused it
- **Keep staging in sync** - Your staging environment should always match production

## Common Gotchas

**Build failures after update:**
- Check the changelog for breaking changes
- Make sure all your dependencies are compatible
- Sometimes you need to update related packages too

**Runtime errors:**
- Double-check your API usage against the new version
- The migration guides usually have the answers
- Test with some sample data to make sure it works

**Performance issues:**
- Keep an eye on your resource usage
- Check if any methods got deprecated
- Sometimes configuration changes are needed

**JavaScript SDK v2.0 specific:**
- The authentication completely changed - no more workspace key/secret
- You'll need to generate API keys and JWT tokens
- Check our [migration guide](/docs/migration-guide-from-v1) for the full details

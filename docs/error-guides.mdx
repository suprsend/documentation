## Overview

Errors appear in different **log types** depending on when they occur. See [Logging](/docs/logging) for log structure. Workflow Execution Logs = before message is handed to vendor. Message Logs = after SuprSend attempts delivery via vendor. Use **idempotency key** to trace across log types.

<CardGroup cols={2}>
  <Card title="Request Logs" icon="code" iconType="solid" href="/docs/api-request-errors">
    **Before workflow starts** — API structure, validation, auth, trigger condition mismatches
  </Card>
  <Card title="Workflow Execution Logs" icon="sitemap" iconType="solid">
    **During workflow** — Variable/data errors, template rendering, node processing, channel computation
  </Card>
  <Card title="Broadcast Execution Logs" icon="tower-broadcast" iconType="solid">
    **Broadcast** — Template fetch, user profile fetch, pre-trigger processing
  </Card>
  <Card title="Message Logs" icon="envelope" iconType="solid">
    **After trigger** — Delivery attempt errors, vendor errors, message preparation
  </Card>
</CardGroup>

## Errors

<span id="error-1"></span>

### """jq-expression (for pivot_expr): '.&lt;name>' evaluated to..."""

**Cause:** jq expression returned empty or wrong type.

**Fix:** Fix the jq path or expression so it returns a non-empty value. Use correct variable names (e.g. $recipient, data). See [Trigger workflow](/docs/trigger-workflow).

<span id="error-2"></span>

### """&lt;channel>: template rendering failed. error: ""&lt;nam..."""

```
<channel>: template rendering failed. error: ""<name>"" not defined in [object object] - <id> :<id>
```

**Cause:** Template or variable error during render.

**Fix:** Fix the template: ensure variables exist in workflow/event data, fix Handlebars/JSONNet syntax, or add defaults. See [Templates](/docs/templates).

<span id="error-3"></span>

### """post ""&lt;url> "": context deadline exceeded (client.tim..."""

```
post ""<url> "": context deadline exceeded (client.timeout exceeded while awaiting headers)
```

**Cause:** Request or render timed out.

**Fix:** Simplify template/expression or retry. For external URLs, check endpoint availability.

<span id="error-4"></span>

### """jq-expression for dynamic duration key '.&lt;name>' resul..."""

**Cause:** jq expression failed.

**Fix:** Fix the expression: path, type, or format. See workflow override docs.

<span id="error-5"></span>

### """error evaluating jq-expression (.&lt;name>). unexpected t..."""

**Cause:** jq expression failed.

**Fix:** Fix the expression: path, type, or format. See workflow override docs.

<span id="error-7"></span>

### """error evaluating jq-expression (.&lt;name>). function not..."""

**Cause:** jq expression uses undefined function or variable.

**Fix:** Use valid jq syntax and variable names (e.g. data.key, $recipient.distinct_id).

<span id="error-8"></span>

### """request: post &lt;url> status: &lt;id>, message: &#123;""..."""

```
request: post <url> status: <id>, message: {""error"":""invalid request body""}
```

**Cause:** Vendor or HTTP call failed.

**Fix:** Check status/message in the error; fix request body, URL, or auth. See [Message Logs](/docs/logging).

<span id="error-9"></span>

### """handlebars helper 'compare' doesn't know the operator &lt..."""

**Cause:** Handlebars helper error.

**Fix:** Use correct helper name and arguments (e.g. datetime-format, compare). See [Handlebars helpers](/docs/handlebars-helpers).

### """timed out while rendering jsonnet snippet after 500ms"""

**Fix:** Simplify template/expression or retry. For external URLs, check endpoint availability.

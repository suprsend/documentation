## Overview

The Android Push editor lets you design push notifications delivered to Android devices via FCM (Firebase Cloud Messaging). The editor is a structured form with a live Android lock screen preview that updates as you type.

---

## Getting Started

To add Android Push to a template, open the template in edit mode, click **+** in the channel tab row, select **Android Push**, and click **Add Channels**.

To send Android push notifications, you need an FCM vendor configured in your workspace. See [Android Push Vendor Integration](/docs/android-push-vendor-integration).

Your app must also integrate the SuprSend Android SDK to receive and register device tokens. See [Android SDK](/docs/android-sdk).

## Fields

### Title *(required)*

The headline of the notification displayed in bold. Appears in the notification shade, lock screen, and heads-up notification banner. Keep it concise — most launchers truncate beyond ~50 characters.

Supports Handlebars variables and emoji.

### Message *(required)*

The main body text displayed below the title. This is the primary content the recipient reads.

Supports Handlebars variables and emoji.

### Subtext

An optional third line of text displayed below the message body. Useful for secondary context — a category label, sender name, or timestamp. Rendered in a lighter style.

Supports Handlebars variables.

### Banner Image

An optional large image displayed inside the expanded notification. Visible when the user pulls down the notification in the shade.

Provide a direct image URL or upload an image using the upload icon next to the field. Supports Handlebars — e.g. `{{product.image_url}}`.

### Action URL

The deep link or URL that opens when the user taps the notification body. Use a deep link scheme (e.g. `myapp://orders/{{order_id}}`) to navigate directly to the relevant screen in your app.

### Action Buttons

Optional CTA buttons rendered in the expanded notification view. Each button has:

| Field | Description |
| --- | --- |
| **Button Title** | The label displayed on the button. |
| **URL** | The deep link or URL the button navigates to on tap. |

Click **+ Add Button** to add a button. Remove with the **✕** icon. Android supports up to 3 action buttons.

## Advanced Configuration

Expand **Advanced Configuration** for delivery behaviour and system-level settings.

| Field | Description |
| --- | --- |
| **Silent** | When enabled, the notification is delivered without playing a sound, vibrating, or appearing as a heads-up banner. The notification still appears in the shade. Use for low-priority background updates. |
| **Sticky Notifications** | When enabled, the notification cannot be dismissed by swiping. It persists in the notification shade until the user takes an action or the app clears it. Use for ongoing alerts like active calls or timers. |
| **Timeout (in seconds)** | How long the notification lives on the device before being automatically dismissed. Set to `0` for no timeout. |
| **Notification Group** | Groups multiple notifications from your app together under a summary in the shade. Provide a group key string — notifications with the same key are bundled together. |
| **App Icon** | The small icon shown in the status bar and notification shade. Provide the drawable resource identifier name (e.g. `ic_notification`). Must be a monochrome PNG added to your app's drawable resources. |
| **Sound** | Custom notification sound. Provide the sound file name (without extension) from your app's `res/raw` directory (e.g. `alert_tone`). If blank, the system default sound plays. |
| **Custom key-value pairs** | Arbitrary metadata delivered with the notification payload to your app. Click **+ Add key-value pair** to add entries. Your app can read these in the notification handler to drive custom behaviour — e.g. navigation, badge updates, or analytics. |

<Info>
  On Android O (API 26) and above, notification sound is a property of the **notification channel**, not the individual notification. The sound you set here applies only when the user receives a notification in a given channel for the first time, or after reinstalling the app. Changing the sound in the template does not affect existing notification channels on devices that have already received a notification in that channel.
</Info>

## Live Preview

The right panel shows a live Android lock screen preview — the notification card rendered exactly as it appears on a device, including the title, message, subtext, and action buttons. Updates in real time as you type.

To preview with a specific user's data, search for a user in the **Recipient** section of the Variables panel.

## Variables

All text fields — Title, Message, Subtext, Banner Image, Action URL, and Button URLs — support Handlebars syntax.

| Source | Example | Description |
| --- | --- | --- |
| Trigger payload | `{{order_id}}` | Data sent when the workflow triggers |
| Recipient profile | `{{$recipient.first_name}}` | Properties from the user's SuprSend profile |
| Tenant | `{{$brand.brand_name}}` | Tenant branding properties |

For conditionals and helpers, see [Handlebars Helpers](/docs/handlebars-helpers).

<Warning>
  Every variable in the template must have a corresponding value in the trigger payload or Variables panel. Missing values cause the notification to fail rendering and not be delivered.
</Warning>

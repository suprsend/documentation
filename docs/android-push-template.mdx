Design Android push notifications with a live device preview. Content is personalised with [Handlebars](/docs/handlebars-helpers) variables (`{{variable_name}}`).

<Note>
  You need an Android Push vendor connected and the SuprSend SDK integrated in your app before notifications can be sent. [Set up Android Push →](/docs/firebase-fcm-androidpush)
</Note>

The Android Push editor is a form with title, message, images, action URL, and buttons — with a live device preview on the right.

## Fields

### Title

**Required** · Supports variables

Single-line heading shown in the notification shade.

**What to write here:** Lead with the reason for the alert — Android truncates to one line. The product recommends staying under about 40 characters.

Supports Handlebars: `{{variable_name}}`

> Example: `Order #{{order_id}} shipped` · `Flash sale ends tonight`

### Small Icon

**Optional** (defaults apply)

Icon in the status bar and notification header. Defaults to the SuprSend bell icon. See **How do I add a custom app icon?** in the FAQ to use your app icon.

**What to write here:** Use your app notification icon asset — Android uses alpha only for small icons (monochrome in the status bar).

### Large Icon

**Optional**

Appears left of the text on Android 4.0–6.0, right on Android 7.0+. Defaults to your organisation logo (set in Organisation Settings).

**What to write here:** Leave default for brand consistency, or override per template if your use case needs a different avatar (e.g. sender photo).

### Message

**Required** · Supports variables

Multi-line body text.

**What to write here:** Put the key fact in the first two lines — expanded view shows roughly six lines. Supports Handlebars variables.

> Example: `Your package is on the way! Expected delivery: {{delivery_date}}`

### Subtext

**Optional**

Appears next to your brand name at the top of the notification.

**What to write here:** Use for secondary context (app section, category, or short metadata).

### Banner Image

**Optional**

Supported formats: PNG, JPG, JPEG. Recommended: 2:1 aspect ratio, under 700 KB. Static uploads are auto-scaled and optimised by SuprSend.

**What to write here:** Use a sharp, lightweight image — SuprSend also optimises by network. See **How does SuprSend optimise push notification images?** in the FAQ.

> Example: `{{product_image_url}}` for a product shot on a shipping update.

### Action URL

**Required for a tap target** · Supports variables

URL opened when the user taps the notification body. Supports deep links (see **How do deep links work in push notifications?** in the FAQ) and Handlebars variables.

**What to write here:** Prefer `https://` App Links when your app supports them — they work as web fallback and deep links.

> Example: `https://yourapp.com/track/{{order_id}}`

### Action Buttons

**Optional**

Up to 3 buttons with label + URL. Use 1–2 buttons with concise labels (2–3 words): "Track Order", "View Details". Supports Handlebars in both fields. Button colour is set in Organisation Settings.

**What to write here:** Pair primary and secondary actions — avoid more than three buttons.

> Example: `Shop Now` → `https://yourapp.com/sale` · `View Wishlist` → `yourapp://wishlist`

## Advanced options

### Silent

**Optional** · Boolean

When on, users do not see the notification; the payload still reaches your app for background work.

**What to write here:** Use for background sync, prefetch, or silent data refresh — combine with **Custom Key-Value Pairs** to pass structured data.

> Example: set **Silent** ON with key-value pairs `sync_type` = `catalog_update`, `version` = `{{catalog_version}}`.

### Timeout

**Optional** · Numeric

Auto-dismiss after N seconds if the user has not interacted.

**What to write here:** Use for time-sensitive prompts (e.g. 2FA) — often paired with **Sticky Notifications** for urgent alerts.

### Sticky Notifications

**Optional** · Boolean

Prevents swipe-dismiss; the notification only clears when tapped.

**What to write here:** Use sparingly — users who cannot dismiss a notification may block your channel entirely.

### Notification Group

**Optional** · Text

Group name so related notifications stack in the shade (e.g. multiple messages in one thread).

**What to write here:** Use a stable pattern per thread, e.g. `order_{{order_id}}` or `comments_{{post_id}}`.

### App Icon (name)

**Optional** · Text

Icon name **without extension** referencing the drawable in your app. See **How do I add a custom app icon?** in the FAQ for drawable paths and densities.

### Sound

**Optional** · Text

Sound file name (see **How do I add a custom notification sound?** in the FAQ for `res/raw` placement and Android 8+ channel behaviour).

### Custom Key-Value Pairs

**Optional** · Key-value pairs (strings)

Send custom data to the app. Both key and value are strings. Combine with silent notifications for background updates.

**What to write here:** Pass deep-link metadata, feature flags, or IDs your client code reads when the notification opens or in a silent handler.

<Note>
  **SDK version requirements:**
  - App icon: Android native and React Native SDK version 0.1.8+
  - Custom sound: Android native and React Native SDK version 2.2.0+
</Note>

## Personalise with variables

You'll often want to add dynamic content to personalise notifications per recipient. Add variables in the template — SuprSend replaces them at send time. Pass values from your frontend or backend SDKs when you trigger the workflow.

<Steps>
  <Step title="Add variables in the Variables panel">
    Add sample data in the **Variables panel** (Input Payload section) on the left side of the editor. If you have declared the variables and added sample data, they will come as auto-suggestions when you type a curly bracket `{`. This removes the chances of error like variable mismatch at the time of template rendering. To see how to declare variables, refer to [this section in the Templates documentation](/docs/templates#the-variables-panel).
  </Step>

  <Step title="Use variables in the template">
    We support `handlebars` to add variables in the template. As a general rule, all the variables have to be entered within double curly brackets: `{{variable_name}}`

    You can enter a variable name even when you have not declared it in the Variables panel. To manually enter the variable name, follow the [handlebars guide here](https://handlebarsjs.com/guide/#what-is-handlebars).

    Below are some examples:

    <CodeGroup>
      ```json json
      {
        "array": [
          {
            "product_name": "Aldo Sling Bag",
            "product_price": "3,950.00"
          },
          {
            "product_name": "Clarles & Keith Women Slipper, Biege, 38UK",
            "product_price": "2,549.00"
          },
          {
            "product_name": "RayBan Sunglasses",
            "product_price": "7,899.00"
          }
        ],
        "event": {
          "location": {
            "city": "Bangalore",
            "state": "KA"
          },
          "order_id": "11200123",
          "first_name": "Nikita"
        },
        "product_page": "https://www.suprsend.com"
      }
      ```
    </CodeGroup>

    - To enter a nested variable: `{{event.location.city}}`
    - To refer to an array element: `{{array.[0].product_name}}`
    - If you have a space in the variable name: `{{event.[first name]}}`

    You will be able to see the sample values in the Preview section. If a variable isn't rendering, check:
    1. The variable is defined in the Variables panel.
    2. The variable name matches the Handlebars syntax exactly.
  </Step>
</Steps>

<Warning>
  At send time, if a variable in the template cannot be rendered due to mismatch or missing data, SuprSend skips that notification for the affected user.

  Other channels in the same template group are still sent. For example, if Android Push fails to render but email succeeds, only Android Push is skipped for that user.
</Warning>

## Preview and test

Preview and test before you rely on this template in production.

The right panel shows a live Android device preview, updated in real time as you edit. Variables render using data from the **Variables panel**.

Click **Test** in the top-right corner to send a real push notification to a real device. This uses the **live version** — commit your changes before testing. See [Testing a Template](/docs/templates#test) for the full guide.

## Publish

Click **Commit** in the top bar to publish the current draft as a new live version. Add an optional description for versioning. Once committed, all notifications triggered after this point use the new content.

## Other ways to build this template

### Use Android Studio's notification preview tools

Android Studio (free, from Google) has a live notification preview pane under Layout Inspector. Create a simple test project, add a local notification trigger with the same title/body/icon you plan to use in SuprSend, run it on an emulator, and see exactly how it looks across different Android versions (13, 12, 11, 10) and manufacturers (Samsung, Pixel, OnePlus — each renders the notification shade differently). This is the most accurate preview method — infinitely more reliable than guessing from SuprSend's editor preview.

### Design your small icon correctly from the start

Android's small icon rules are strict: transparent background, white/light fill only (Android ignores colour channels), 24dp recommended size, vector drawable preferred. The easiest path: go to [Android Asset Studio — Notification Icon Generator](https://romannurik.github.io/AndroidAssetStudio/icons-notification.html), upload your logo SVG, and download the generated PNG set at all densities (mdpi through xxxhdpi). This tool does the alpha-channel conversion automatically. Drop the generated files into the correct `res/drawable-*` directories and reference them in your template.

### Test silent notifications with adb before going live

Silent push notifications (where Silent = ON) are invisible to users but trigger background app logic. Before deploying a silent push workflow in production, test the full payload flow locally: use `adb` (Android Debug Bridge) to send a test FCM payload directly to a connected device or emulator: `adb shell am broadcast -a com.google.android.c2dm.intent.RECEIVE -p your.package.name`. This lets you verify your app correctly processes the `data` payload and handles the background task — without needing to trigger a real workflow.

### Use custom key-value pairs for deep personalisation beyond text

The Custom Key-Value Pairs field is massively underused. Beyond simple string values, you can pass serialised JSON as a string value and parse it in your app. For example, pass `{"product_id": "123", "category": "shoes", "discount": 0.2}` as the value of a `payload` key. Your app deserialises it and uses those values to set the deep-link destination, populate a pre-filled cart, or trigger specific app logic — all from a single notification. Combined with Handlebars variables, you can generate these payloads dynamically per user.

### Group related notifications with Notification Group

If your app sends multiple notifications in quick succession (e.g. 5 new comments on a post, or 3 order status updates), use the Notification Group field with a consistent group name like `order_{{order_id}}` or `comments_{{post_id}}`. Android stacks grouped notifications in the shade under a single expandable row. Users see "3 new comments" instead of 3 separate notifications. This dramatically reduces notification fatigue and banner blindness for high-frequency use cases.

### Simulate different network conditions for banner image loading

SuprSend optimises banner images based on the user's network (wifi, 4G, 3G, 2G). To test this behaviour before going live: in Android Studio's emulator, go to Extended Controls → Cellular → Network Type. Set it to GPRS (2G equivalent) and trigger a test notification with your banner image URL. Verify the notification still delivers promptly and the image loads at the compressed size. This catches cases where oversized source images create delivery delays on slow connections.

## Best practices

- **Keep titles under 50 characters** — Android truncates in the notification shade — front-load the important words.
- **Small icon must have transparent background** — Android ignores colour channels and uses alpha only — solid squares usually mean missing alpha.
- **Silent + key-value pairs is the background sync pattern** — Use it for data updates without alerting users.
- **Sound is set at category level on Android 8+** — Changing sound in the template only affects new users and new categories — see FAQ for details.
- **Use Sticky sparingly** — Users who cannot dismiss a notification often block your app's notifications entirely.
- **Use Timeout for time-sensitive alerts** — Auto-dismiss after the relevant window so stale prompts do not linger.

## FAQ

<AccordionGroup>
  <Accordion title="How do deep links work in push notifications?">
    The **Action URL** and **Action Button URLs** support three URL types:

    | URL type | Format | Behaviour |
    |---|---|---|
    | Web URL | `https://yourapp.com/orders/123` | Opens in the browser (or your app if [App Links](https://developer.android.com/training/app-links) are configured) |
    | Custom scheme | `yourapp://orders/123` | Opens the matching activity in your app directly |
    | App Link | `https://yourapp.com/orders/123` (verified) | Opens your app directly without a browser redirect |

    If your app supports App Links, prefer `https://` URLs — they work as both web fallback and deep links.
  </Accordion>

  <Accordion title="How do I add a custom app icon?">
    Add a small icon named `ic_suprsend_app_icon` in the drawable folders of your app. Android only uses the alpha channel — the icon displays as monochrome in the status bar. You can use a vector drawable (`androidApp/src/main/res/drawable/`) or PNG icons at each density:

    | Density | Size |
    |---|---|
    | MDPI | 24x24 |
    | HDPI | 36x36 |
    | XHDPI | 48x48 |
    | XXHDPI | 72x72 |
    | XXXHDPI | 96x96 |

    Use [Android Asset Studio](https://romannurik.github.io/AndroidAssetStudio/icons-notification.html) for quick icon generation. If you see the default bell icon, ensure all density sizes are present. If you see a solid square, the image lacks alpha transparency.

    **SDK requirement:** Android native and React Native SDK version 0.1.8+.
  </Accordion>

  <Accordion title="How do I add a custom notification sound?">
    Add the sound file to `projectroot/app/res/raw` (lowercase filename, underscores instead of spaces, e.g. `notification_music.mp3`).

    **Important:** On Android 8.0+ (~95% of users), sound is set at the [notification channel](https://developer.android.com/develop/ui/views/notifications/channels) level when the [category](/docs/notification-category) is first created. Changing the sound in the template only takes effect for:
    - a new notification category
    - a user installing the app for the first time
    - a user who uninstalled and reinstalled the app

    **SDK requirement:** Android native and React Native SDK version 2.2.0+.
  </Accordion>

  <Accordion title="How does SuprSend optimise push notification images?">
    For static images uploaded in the Banner Image field, SuprSend applies two optimisations:
    - **Screen width** — large images are resized to fit the user's mobile screen width.
    - **Network-aware** — image quality is adjusted based on the user's connection (WiFi, 4G, 3G, 2G) to improve delivery speed on slow networks.
  </Accordion>

  <Accordion title="What are silent notifications used for?">
    Silent notifications deliver a payload to the app without displaying anything to the user. Use them for background data sync, content pre-fetching, or triggering app-level logic. Combine with **Custom Key-Value Pairs** to pass structured data.
  </Accordion>

  <Accordion title="Why does my small icon show as a solid square?">
    Small icons must use transparency — Android draws only the alpha channel. A square usually means the asset is opaque or missing alpha. Regenerate with [Android Asset Studio](https://romannurik.github.io/AndroidAssetStudio/icons-notification.html) or fix your source image.
  </Accordion>

  <Accordion title="Why doesn't the new sound play for existing users?">
    On Android 8.0+, notification sound is tied to the channel created when the category was first registered. Existing users keep the original channel settings until they reinstall, you create a new category, or they clear app data. See **How do I add a custom notification sound?** above.
  </Accordion>

  <Accordion title="What's the difference between Silent and regular push?">
    **Silent** — no visible notification; your app receives the payload for background logic. **Regular** — shows in the system tray with title, message, and optional image/buttons. Use silent for sync; use regular when the user should see the alert.
  </Accordion>

  <Accordion title="What happens if a variable is missing or has the wrong value at send time?">
    SuprSend skips the Android Push notification for that user. Other channels in the same template group (email, SMS, etc.) are still sent if they render successfully.
  </Accordion>

  <Accordion title="Can I use this channel alongside other channels in the same workflow?">
    Yes — Android Push is one channel in a template group; email, SMS, and others still send if their templates render.
  </Accordion>

  <Accordion title="How do I pass variable values when triggering the workflow?">
    Include properties in your trigger payload or event so Handlebars paths match. Use the **Variables panel** for sample data. See [Adding dynamic content](/docs/templates#the-variables-panel) and your SDK documentation.
  </Accordion>
</AccordionGroup>

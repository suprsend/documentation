Android Push in SuprSend lets you design and send rich push notifications to your Android users — with titles, images, action buttons, deep links, and dynamic variables. A live device preview updates as you build, so you see exactly what recipients will see before you send.

This guide covers every field in the editor, how variables work, advanced delivery options, and how to handle Android-specific quirks like icon alpha, notification channels, and silent delivery.

<Note>
  You need an Android Push vendor connected and the SuprSend SDK integrated in your app before notifications can be sent. [Set up Android Push →](/docs/firebase-fcm-androidpush)
</Note>

---

## How the Android Push editor works

The editor is a structured form — title, message, images, action URL, and buttons — with a live Android device preview on the right that updates as you type.

Keep in mind that Android notification rendering varies by OS version and OEM (Samsung, Pixel, OnePlus all differ). The editor preview is a good baseline, but for critical templates, test on a real device or emulator — see [Best practices](#best-practices).

## Fields

### Title

**Required** · Supports variables

Single-line heading shown in the notification shade. Android truncates to one line, so lead with the reason for the alert. Stay under ~40 characters where possible.

Supports Handlebars: `{{variable_name}}`

> Example: `Order #{{order_id}} shipped` · `Flash sale ends tonight`

### Message

**Required** · Supports variables

Multi-line body text. The expanded notification view shows roughly six lines — put the key fact in the first two lines.

> Example: `Your package is on the way! Expected delivery: {{delivery_date}}`

### Subtext

**Optional**

Appears next to your brand name at the top of the notification. Use for secondary context — app section, category, or short metadata.

### Small Icon

**Optional** (defaults apply)

Icon shown in the status bar and notification header. Defaults to the SuprSend bell icon.

**Important:** Android uses only the alpha channel for small icons — they render as monochrome in the status bar. A solid square means your asset is missing alpha transparency. See [How do I add a custom app icon?](#how-do-i-add-a-custom-app-icon) in the FAQ.

### Large Icon

**Optional**

Appears left of the text on Android 4.0–6.0, and right on Android 7.0+. Defaults to your organisation logo (set in Organisation Settings). Override per template when your use case needs a different avatar — for example, a sender photo in a messaging notification.

### Banner Image

**Optional**

A rich image shown in the expanded notification. Recommended: 2:1 aspect ratio, PNG or JPG, under 700 KB. SuprSend auto-scales and optimises static uploads by screen width and network class (WiFi, 4G, 3G, 2G).

> Example: `{{product_image_url}}` for a product shot on a shipping update.

### Action URL

**Required for a tap target** · Supports variables

URL opened when the user taps the notification body. Supports deep links and Handlebars variables.

Prefer `https://` App Links when your app supports them — they work as both a web fallback and a direct deep link. See [How do deep links work in push notifications?](#how-do-deep-links-work-in-push-notifications) in the FAQ.

> Example: `https://yourapp.com/track/{{order_id}}`

### Action Buttons

**Optional**

Up to 3 buttons, each with a label and a URL. Use 1–2 buttons with concise action labels (2–3 words). Supports Handlebars in both label and URL fields. Button colour is set in Organisation Settings.

> Example: `Track Order` → `https://yourapp.com/orders/{{order_id}}` · `View Details` → `yourapp://orders/{{order_id}}`

## Advanced options

These fields control delivery behaviour and are optional for most templates.

### Silent

**Boolean**

When enabled, the notification is not shown to the user — the payload is delivered to your app silently for background work. Use for background sync, content prefetch, or silent data refresh. Combine with **Custom Key-Value Pairs** to pass structured data to your app.

> Example: Silent ON with key-value pairs `sync_type` = `catalog_update`, `version` = `{{catalog_version}}`.

### Timeout

**Numeric (seconds)**

Auto-dismisses the notification after N seconds if the user has not interacted. Use for time-sensitive prompts like 2FA codes — often paired with Sticky Notifications for urgent alerts.

### Sticky Notifications

**Boolean**

Prevents swipe-dismiss. The notification only clears when tapped. Use sparingly — users who cannot dismiss a notification may block your app's notification channel entirely.

### Notification Group

**Text**

Groups related notifications so they stack as one expandable row in the shade, instead of spamming separate entries. Use a stable pattern per thread.

> Example: `order_{{order_id}}` · `comments_{{post_id}}`

### App Icon (name)

**Text**

Icon name without file extension, referencing a drawable in your app. See [How do I add a custom app icon?](#how-do-i-add-a-custom-app-icon) in the FAQ for drawable paths and density requirements.

### Sound

**Text**

Sound file name referencing a file in `res/raw`. See [How do I add a custom notification sound?](#how-do-i-add-a-custom-notification-sound) in the FAQ — on Android 8+, sound is tied to the notification channel, not the template.

### Custom Key-Value Pairs

**Key-value pairs (strings)**

Send custom data to your app alongside the notification. Both key and value are strings. Combine with silent notifications for background updates, or use to pass deep-link metadata, feature flags, or IDs your client code reads when the notification opens.

<Note>
  **SDK version requirements:**
  - App icon (custom): Android native and React Native SDK version 0.1.8+
  - Custom sound: Android native and React Native SDK version 2.2.0+
</Note>

## Personalise with variables

You'll often want to add dynamic content to personalise notifications per recipient. Add variables in the template — SuprSend replaces them at send time. Pass values from your frontend or backend SDKs when you trigger the workflow.

<Steps>
  <Step title="Add variables in the Variables panel">
    Add sample data in the **Variables panel** (Input Payload section) on the left side of the editor. If you have declared the variables and added sample data, they will come as auto-suggestions when you type a curly bracket `{`. This removes the chances of error like variable mismatch at the time of template rendering. To see how to declare variables, refer to [this section in the Templates documentation](/docs/templates#the-variables-panel).
  </Step>

  <Step title="Use variables in the template">
    We support `handlebars` to add variables in the template. As a general rule, all the variables have to be entered within double curly brackets: `{{variable_name}}`

    You can enter a variable name even when you have not declared it in the Variables panel. To manually enter the variable name, follow the [handlebars guide here](https://handlebarsjs.com/guide/#what-is-handlebars).

    Below are some examples:

    <CodeGroup>
      ```json json
      {
        "array": [
          {
            "product_name": "Aldo Sling Bag",
            "product_price": "3,950.00"
          },
          {
            "product_name": "Clarles & Keith Women Slipper, Biege, 38UK",
            "product_price": "2,549.00"
          },
          {
            "product_name": "RayBan Sunglasses",
            "product_price": "7,899.00"
          }
        ],
        "event": {
          "location": {
            "city": "Bangalore",
            "state": "KA"
          },
          "order_id": "11200123",
          "first_name": "Nikita"
        },
        "product_page": "https://www.suprsend.com"
      }
      ```
    </CodeGroup>

    - To enter a nested variable: `{{event.location.city}}`
    - To refer to an array element: `{{array.[0].product_name}}`
    - If you have a space in the variable name: `{{event.[first name]}}`

    You will be able to see the sample values in the Preview section. If a variable isn't rendering, check:
    1. The variable is defined in the Variables panel.
    2. The variable name matches the Handlebars syntax exactly.
  </Step>
</Steps>

<Warning>
  At send time, if a variable in the template cannot be rendered due to mismatch or missing data, SuprSend skips that notification for the affected user.

  Other channels in the same template group are still sent. For example, if Android Push fails to render but email succeeds, only Android Push is skipped for that user.
</Warning>

## Best practices

- **Cross-platform copy:** Keep title under ~40 characters and body under ~80 so collapsed views work on Android and iOS.
- **Action URL on every push:** Default tap should open a deep link — a push with nowhere to go is broken.
- **OTP and verification:** Never put the actual code in title or body (lock screen risk). Use neutral copy like "Your code is ready" and open the app for the code.
- **Images:** Use banner (2:1) for promo, events, or cart — not for transactional receipts or OTP. Large icon = product or avatar, not your logo (the app icon already represents the brand).
- **Buttons:** Add 1–2 action buttons only when there are two real choices (`Track` / `Cancel`); use 2–3 word labels. Skip duplicate actions that match the default tap.
- **Emoji:** At most one, at the start of the title — skip on failure and security alerts.
- **Promo timing:** Avoid promotional push outside quiet hours (e.g. ~8:00 AM–8:30 PM) unless the send is tied to a specific appointment time.

## FAQ

<AccordionGroup>
  <Accordion title="How do deep links work in push notifications?">
    The **Action URL** and **Action Button URLs** support three URL types:

    | URL type | Format | Behaviour |
    |---|---|---|
    | Web URL | `https://yourapp.com/orders/123` | Opens in the browser (or your app if [App Links](https://developer.android.com/training/app-links) are configured) |
    | Custom scheme | `yourapp://orders/123` | Opens the matching activity in your app directly |
    | App Link | `https://yourapp.com/orders/123` (verified) | Opens your app directly without a browser redirect |

    If your app supports App Links, prefer `https://` URLs — they work as both web fallback and deep links.
  </Accordion>

  <Accordion title="How do I add a custom app icon?">
    Add a small icon named `ic_suprsend_app_icon` in the drawable folders of your app. Android only uses the alpha channel — the icon displays as monochrome in the status bar. You can use a vector drawable (`androidApp/src/main/res/drawable/`) or PNG icons at each density:

    | Density | Size |
    |---|---|
    | MDPI | 24x24 |
    | HDPI | 36x36 |
    | XHDPI | 48x48 |
    | XXHDPI | 72x72 |
    | XXXHDPI | 96x96 |

    Use [Android Asset Studio](https://romannurik.github.io/AndroidAssetStudio/icons-notification.html) for quick icon generation. If you see the default bell icon, ensure all density sizes are present. If you see a solid square, the image lacks alpha transparency.

    **SDK requirement:** Android native and React Native SDK version 0.1.8+.
  </Accordion>

  <Accordion title="How do I add a custom notification sound?">
    Add the sound file to `projectroot/app/res/raw` (lowercase filename, underscores instead of spaces, e.g. `notification_music.mp3`).

    **Important:** On Android 8.0+ (~95% of users), sound is set at the [notification channel](https://developer.android.com/develop/ui/views/notifications/channels) level when the [category](/docs/notification-category) is first created. Changing the sound in the template only takes effect for:
    - a new notification category
    - a user installing the app for the first time
    - a user who uninstalled and reinstalled the app

    **SDK requirement:** Android native and React Native SDK version 2.2.0+.
  </Accordion>

  <Accordion title="How does SuprSend optimise push notification images?">
    For static images uploaded in the Banner Image field, SuprSend applies two optimisations:
    - **Screen width** — large images are resized to fit the user's mobile screen width.
    - **Network-aware** — image quality is adjusted based on the user's connection (WiFi, 4G, 3G, 2G) to improve delivery speed on slow networks.
  </Accordion>

  <Accordion title="What are silent notifications used for?">
    Silent notifications deliver a payload to the app without displaying anything to the user. Use them for background data sync, content pre-fetching, or triggering app-level logic. Combine with **Custom Key-Value Pairs** to pass structured data.
  </Accordion>

  <Accordion title="Why does my small icon show as a solid square?">
    Small icons must use transparency — Android draws only the alpha channel. A square usually means the asset is opaque or missing alpha. Regenerate with [Android Asset Studio](https://romannurik.github.io/AndroidAssetStudio/icons-notification.html) or fix your source image.
  </Accordion>

  <Accordion title="Why doesn't the new sound play for existing users?">
    On Android 8.0+, notification sound is tied to the channel created when the category was first registered. Existing users keep the original channel settings until they reinstall, you create a new category, or they clear app data. See **How do I add a custom notification sound?** above.
  </Accordion>

  <Accordion title="What's the difference between Silent and regular push?">
    **Silent** — no visible notification; your app receives the payload for background logic. **Regular** — shows in the system tray with title, message, and optional image/buttons. Use silent for sync; use regular when the user should see the alert.
  </Accordion>

  <Accordion title="What happens if a variable is missing or has the wrong value at send time?">
    SuprSend skips the Android Push notification for that user. Other channels in the same template group (email, SMS, etc.) are still sent if they render successfully.
  </Accordion>

  <Accordion title="Can I use this channel alongside other channels in the same workflow?">
    Yes — Android Push is one channel in a template group; email, SMS, and others still send if their templates render.
  </Accordion>

  <Accordion title="How do I pass variable values when triggering the workflow?">
    Include properties in your trigger payload or event so Handlebars paths match. Use the **Variables panel** for sample data. See [Adding dynamic content](/docs/templates#the-variables-panel) and your SDK documentation.
  </Accordion>
</AccordionGroup>

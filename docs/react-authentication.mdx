title: "Authentication"

---

React applications use **JWT-based authentication** to securely identify users. Your backend generates a signed token for each user, which the React SDK uses to establish a trusted session.

## Quick setup

Pass the `userToken` to the `SuprSendProvider` component alongside the user's `distinctId`:

```jsx
import { SuprSendProvider } from "@suprsend/react";

function App() {
  return (
    <SuprSendProvider
      publicApiKey="YOUR_PUBLIC_API_KEY"
      distinctId="USER_DISTINCT_ID"
      userToken="SIGNED_USER_TOKEN"
    >
      <YourApp />
    </SuprSendProvider>
  );
}
```

| Prop | Description |
|------|-------------|
| `publicApiKey` | Your workspace public API key from [Settings → API Keys](https://app.suprsend.com/en/sandbox/developers/api-keys). |
| `distinctId` | A unique identifier for the current user (e.g., user ID, email). |
| `userToken` | A JWT token generated on your backend using your workspace secret. |

## How it works

1. When the user logs in, your **backend** generates a JWT token using the SuprSend workspace secret.
2. Your frontend passes this token to `SuprSendProvider`.
3. The SDK authenticates the user and opens a real-time WebSocket connection for live notification delivery.

<Info>
  The `userToken` should be generated server-side and never expose your workspace secret to the client.
</Info>

## Learn more

For detailed instructions on generating signing keys, creating JWT tokens on your backend (Node.js, Python, etc.), and handling token refresh, see the [complete authentication guide](/docs/client-authentication). You can manage your API keys from the [SuprSend Dashboard](https://app.suprsend.com/en/sandbox/developers/api-keys).

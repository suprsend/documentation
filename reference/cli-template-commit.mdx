Commit a template from draft to live in a workspace. Pass the template slug as a positional argument or via `--slug`. Once committed, the template changes become visible to users — all notifications triggered after the commit will use the new content across all channel variants.

This is the CLI equivalent of clicking **Commit** in the template editor on the dashboard.

## Syntax

```bash
suprsend template commit [<slug>] [flags]
```

The template slug can be passed as a positional argument or via the `-g, --slug` flag.

## Flags

| Flag | Description | Default |
|------|-------------|---------|
| `-h,`<br />`--help` | Show help for the command | – |
| `-g,`<br />`--slug string` | Template slug. Alternative to passing the slug as a positional argument. | – |
| `--commit-message`<br />`string` | Message describing the changes in this commit | – |
| `-n,`<br />`--dry-run` | Print what would be committed without making any changes | – |
| `-F,`<br />`--force` | Force commit by skipping variants with errors | – |

## Example

```bash
# Commit a template (positional slug)
suprsend template commit order-shipped

# Commit using the flag form
suprsend template commit --slug order-shipped

# Commit with a message
suprsend template commit order-shipped --commit-message "Fix Hindi variant subject line"

# Dry run: see what would be committed without making changes
suprsend template commit order-shipped --dry-run

# Commit in production
suprsend template commit order-shipped --workspace production

# Commit in production, skipping variants with errors
suprsend template commit order-shipped --workspace production --force
```

## End-to-End Example

```bash
# 1. Pull the current live version to local files
suprsend template pull order-shipped

# 2. Edit the local template file
#    (update variant content, conditions, mock data, etc.)

# 3. Push the edited file as a draft
suprsend template push order-shipped

# 4. Commit the draft to make it live
suprsend template commit order-shipped --commit-message "Add Hindi variant"
```

Or collapse push and commit into one step:

```bash
suprsend template push order-shipped --commit --commit-message "Add Hindi variant"
```

<Warning>
  Using `--force` skips validation on variants that have errors and commits the rest. Variants with errors remain in draft. Use with caution in production environments.
</Warning>

## SDK & React Setup

### Integrate SuprSend SDK in a React app

```
Integrate SuprSend React SDK into this application.

Requirements:
- Install @suprsend/react
- Wrap the app with SuprSendProvider
- Configure with SUPRSEND_WORKSPACE_KEY and SUPRSEND_PUBLIC_KEY environment variables
- Set distinctId for user identification
- Pass userToken to SuprSendProvider for enhanced security
- Store all keys in environment variables, never hardcode them
```

### Add React Popover Inbox and Toast Notifications

```
Add a real-time in-app notification system using SuprSend React SDK.

Requirements:
- Implement Inbox component with bell icon and unread badge in the header
- Add toast notifications in bottom-right corner when new notifications arrive
- Toast notifications should have a progress bar animation
- Ensure toast notifications don't block UI interactions (use pointer-events CSS)
- Badge count should persist until user opens inbox popover
- Use SuprSend's useFeedClient hook to listen for 'feed.new_notification' events
- Display toasts using ToastNotificationCard component from @suprsend/react
- Integrate with react-hot-toast for toast management
```

### Add Notification Preference Centre

```
Build a notification preferences management page using SuprSend React SDK.

Requirements:
- Display all notification categories with toggle switches for opt-in/opt-out
- Show channel-level preferences (email, inbox) for each category
- Set default preferences to opt-in for both email and inbox channels when user first signs up
- Use SuprSend's useSuprSendClient hook to access preferences API
- Implement getPreferences, updateCategoryPreference, and updateChannelPreferenceInCategory methods
- Use PreferenceOptions.OPT_IN and PreferenceOptions.OPT_OUT constants
- Add UI for category and channel-level preferences with real-time updates
```

## Workflow Creation

### Create a workflow from scratch

```
Create a SuprSend workflow JSON file for [describe your use case].

Requirements:
- Save the file to suprsend/workflow/ directory
- Include a unique slug field that matches the filename
- Conform to https://schema.suprsend.com/workflow/v1/schema.json
- Use correct node_type values for every node
- After generating, push with: suprsend workflow push --commit=true
```

### Cart abandonment workflow

```
Create a SuprSend cart abandonment workflow JSON with slug "cart-abandonment".
Save to suprsend/workflow/cart-abandonment.json.

Requirements:
- Trigger: cart_abandoned event
- Use branch_waituntil node: hold for 1 hour, exit early if cart_completed event arrives
  matching on cart_id
- If timeout expires (cart still active): send email and mobile push simultaneously
  using send_multi_channel with channels: [email, androidpush, iospush]
- Template: "cart-abandonment-reminder"
- After generating, run: suprsend workflow push --slug cart-abandonment --commit=true
```

### Payment reminder with smart routing

```
Create a SuprSend payment reminder workflow JSON with slug "payment-reminder".
Save to suprsend/workflow/payment-reminder.json.

Requirements:
- Trigger: payment_due event
- Use send_smart_channel_routing node
- Try email first, wait 2 hours for engagement, then try SMS if no engagement
- Template: "payment-reminder"
- After generating, run: suprsend workflow push --slug payment-reminder --commit=true
```

### Document access request notification

```
Create a SuprSend document access request workflow JSON with slug "document-access-request".
Save to suprsend/workflow/document-access-request.json.

Requirements:
- Trigger: document_access_requested event
- Immediately send email to document owner via send_email node
- Add branch_waituntil node: wait 24 hours for a response event
- If no response (timeout branch): send Slack notification via send_slack node
- After generating, run: suprsend workflow push --slug document-access-request --commit=true
```

## CLI Operations

### Pull, edit, and push a workflow

```
Using the SuprSend CLI:
1. Verify the active profile with: suprsend profile list
2. Pull all workflows from the workspace into suprsend/workflow/
3. In [workflow-name].json, update [describe the change]
4. Push and commit with: suprsend workflow push --commit=true --commit-message "[your message]"
```

### Sync staging to production

```
Using the SuprSend CLI, sync all workflows from my staging workspace to production.
Show me the sync command with the correct --source and --target workspace flags.
```

### Generate TypeScript types from schemas

```
Using the SuprSend CLI:
1. Pull all event schemas from the workspace
2. Generate TypeScript type definitions from them
3. Show me where the generated files are saved and how to import them
```

### Set up a CI/CD pipeline

```
Set up a GitHub Actions workflow for SuprSend notification deployments.

Requirements:
- On pull request: pull workflows from staging and validate schemas
- On merge to main: push all workflows to production with --commit=true
- Use SUPRSEND_SERVICE_TOKEN as a GitHub Actions secret
- Output a summary of what was pushed
```

## Debugging with MCP

### Debug why a user isn't receiving notifications

```
Using the SuprSend MCP server, help me debug why user [user_id or email] is not receiving
notifications.

Steps to take:
1. Get the user's profile and all registered channel addresses
2. Check their notification preferences across all categories
3. Verify the relevant workflow is enabled
4. Check if the user's channel preferences have any restrictions
5. Summarise what's wrong and suggest the fix
```

### Inspect a workflow end-to-end

```
Using the SuprSend MCP server, list all workflows in my workspace and show me the full
details of the [workflow-name] workflow — its nodes, trigger config, and current status.
```

### Bootstrap test data

```
Using the SuprSend MCP server:
1. Create a test user with distinctId "test-user-001", email "test@example.com"
2. Create a test tenant with tenantId "acme-corp"
3. Trigger the [workflow-name] workflow for this user under the acme-corp tenant
4. Confirm the workflow was triggered successfully
```

### Check and update user preferences

```
Using the SuprSend MCP server:
1. Get all notification preferences for user [user_id]
2. Enable email notifications for the [category-name] category
3. Confirm the update was applied
```

## Self-evaluation prompt

After your agent completes a SuprSend task, run this to improve future outputs:

```
Retrospect on what you just built. What information was missing or unclear that caused
you to make mistakes or ask follow-up questions? What would have helped you complete
this in one shot? Focus specifically on gaps in the SuprSend skills or documentation.
```

Share the output with the SuprSend team — it directly informs what gets added to the skills next.

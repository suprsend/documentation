Windsurf is now part of Devin. The config paths below match [Devin's MCP docs](https://docs.devin.ai/desktop/cascade/mcp).

## Set up the connection

<Steps>
  <Step title="Add the SuprSend MCP server">
    Add this to `~/.config/devin/mcp_config.json` on macOS and Linux, or `%APPDATA%\devin\mcp_config.json` on Windows. Create the file if it doesn't exist.

    ```json
    {
      "mcpServers": {
        "suprsend": {
          "serverUrl": "https://mcp.suprsend.com/mcp"
        }
      }
    }
    ```

    This is the US endpoint. Use the endpoint for your workspace's data region:

    | Region | Endpoint |
    |---|---|
    | US | `https://mcp.suprsend.com/mcp` |
    | EU | `https://mcp.eu.suprsend.com/mcp` |
    | India | `https://mcp.in.suprsend.com/mcp` |
  </Step>

  <Step title="Sign in with your SuprSend account">
    Restart Windsurf. On the first tool call, Windsurf opens your browser. Sign in with your SuprSend account. The agent gets the same permissions your role has in the SuprSend dashboard.
  </Step>

  <Step title="Verify the connection">
    In Cascade, ask:

    ```
    List my SuprSend workspaces.
    ```

    Windsurf answers with your SuprSend workspaces.
  </Step>
</Steps>

## Pin a workspace and restrict tools

By default, Windsurf can use every workspace and tool your role allows. To keep it on one workspace, or to give it only the tools a job needs, change `serverUrl` in your config:

- **Pin a workspace** by adding its slug to the path. The agent then can't switch to another workspace:

  ```
  https://mcp.suprsend.com/mcp/staging
  ```

- **Restrict tools** with `?tools=`, a comma-separated list of tool names or groups:

  ```
  https://mcp.suprsend.com/mcp/staging?tools=users.*,data.*
  ```

See [Scope the connection](/reference/mcp-overview#scope-the-connection) for every URL pattern, and the [tool list](/reference/mcp-tool-list) for every tool.

## Troubleshooting

<AccordionGroup>
  <Accordion title="Server shows disconnected or refuses the connection">
    Check the workspace slug in the URL. It must match a workspace in your SuprSend account exactly, for example `staging`, not the workspace's display name. A slug that doesn't exist fails with `403 workspace_forbidden`. To see your slugs, remove the slug, reconnect, and ask: "List my SuprSend workspaces."
  </Accordion>
</AccordionGroup>

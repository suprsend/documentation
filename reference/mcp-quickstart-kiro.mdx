These steps use the Kiro CLI.

## Set up the connection

<Steps>
  <Step title="Create the MCP config file">
    Kiro reads MCP servers from `~/.kiro/settings/mcp.json`. If the file doesn't exist yet, create it:

    ```bash
    touch ~/.kiro/settings/mcp.json
    ```
  </Step>

  <Step title="Add the SuprSend MCP server">
    Open the file:

    ```bash
    open ~/.kiro/settings/mcp.json
    ```

    Add:

    ```json ~/.kiro/settings/mcp.json
    {
      "mcpServers": {
        "suprsend": {
          "url": "https://mcp.suprsend.com/mcp"
        }
      }
    }
    ```

    Save the file.
  </Step>

  <Step title="Sign in with your SuprSend account">
    Start `kiro-cli` and run:

    ```
    /mcp auth suprsend
    ```

    Kiro prints a sign-in URL in the chat. Copy it into your browser and sign in with your SuprSend account. Your role decides the tools: admins get every tool, and members get read-only tools except the two that show sent message content, `messages_get_content` and `messages_preview_content`.
  </Step>

  <Step title="Restart Kiro and verify">
    Quit `kiro-cli` and start it again so it loads the SuprSend tools. Then ask:

    ```
    List my SuprSend workspaces.
    ```

    Kiro answers with your SuprSend workspaces.
  </Step>
</Steps>

## Pin a workspace and restrict tools

By default, Kiro can use every workspace and tool your role allows. To keep it on one workspace, or to give it only the tools a job needs, change `url` in your config:

- **Pin a workspace** by adding its slug to the path. The agent then can't switch to another workspace:

  ```
  https://mcp.suprsend.com/mcp/staging
  ```

- **Restrict tools** with `?tools=`, a comma-separated list of tool names or groups:

  ```
  https://mcp.suprsend.com/mcp/staging?tools=users_*,data_*
  ```

Don't add send tools to Kiro's `autoApprove` list, so Kiro asks before each one.

See [Scope the connection](/reference/mcp-overview#scope-the-connection) for every URL pattern, and the [tool list](/reference/mcp-tool-list) for every tool.

## Troubleshooting

<AccordionGroup>
  <Accordion title="Server shows disconnected or refuses the connection">
    Check the workspace slug in the URL. It must match a workspace in your SuprSend account exactly, for example `staging`, not the workspace's display name. A slug that doesn't exist fails with `403 workspace_forbidden`. To see your slugs, remove the slug, reconnect, and ask: "List my SuprSend workspaces."
  </Accordion>
  <Accordion title="SuprSend tools don't show up after sign-in">
    Quit `kiro-cli` and start it again. Kiro loads the tools only after a restart.
  </Accordion>
</AccordionGroup>

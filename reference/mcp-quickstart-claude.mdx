  **Beta — launched 2026-10-08.** The hosted SuprSend MCP server is in Beta. The endpoint, auth flow, and tool list may still change before general availability.
</Note>

<Note>
  **Not sure which client you're using?** Claude Code runs in your terminal or IDE and is invoked with the `claude` command. Claude Desktop is the standalone chat app from [claude.ai/download](https://claude.ai/download); Claude.ai is the web client at [claude.ai](https://claude.ai). Setup differs for each — pick the matching tab below.
</Note>

<Tip>
  Prefer a one-command install? The **SuprSend Claude plugin** wires the hosted server into Claude Code, Claude Desktop, Claude.ai, mobile, and Cowork — run `/plugin marketplace add suprsend/claude-plugin` then `/plugin install suprsend@suprsend`. See the [Agent plugin](/reference/agent-plugin) page.
</Tip>

<Tabs>

<Tab title="Claude Code">

<Steps>
  <Step title="Install Claude Code">
    Claude Code is distributed as an npm package and requires [Node.js](https://nodejs.org/) 18+.

    ```bash
    npm install -g @anthropic-ai/claude-code
    ```

    Run `claude` once and complete the one-time browser login it prompts.
  </Step>

  <Step title="Add the SuprSend MCP server">
    From your **regular terminal** (not inside a running `claude` session):

    ```bash
    claude mcp add --transport http suprsend https://mcp.suprsend.com/mcp
    ```

    This writes the server to `~/.claude.json` with `type: "http"` (an alias of `streamable-http`). Short form: `-t http` works the same as `--transport http`.

    **Pin a workspace** by appending its slug to the URL path:

    ```bash
    claude mcp add --transport http suprsend https://mcp.suprsend.com/mcp/staging
    ```

    **Scope to specific tool groups** with `?tools=`:

    ```bash
    claude mcp add --transport http suprsend-read https://mcp.suprsend.com/mcp?tools=users.*,data.*
    ```
  </Step>

  <Step title="Sign in with your SuprSend account">
    The first time Claude Code connects, it opens a browser window for a WorkOS sign-in. Sign in with the SuprSend account that has access to the workspace you pinned (or any workspace, if you didn't pin one). After sign-in, your SuprSend role decides which tools you see — members get read tools, admins get every tool.
  </Step>

  <Step title="Verify the connection">
    ```bash
    claude mcp list
    ```

    You should see `suprsend` listed as connected. Then start a Claude Code session:

    ```bash
    cd ~/any-project
    claude
    ```

    Inside the session, type `/mcp` to see the tool count. Try a read-only prompt to confirm the loop works:

    ```
    Search the SuprSend docs for how preference categories work.
    ```

    Claude asks for permission before the first tool call — approve it, and you're done.
  </Step>
</Steps>

</Tab>

<Tab title="Claude Desktop / Claude.ai">

<Steps>
  <Step title="Open the connectors settings">
    In Claude Desktop or at [claude.ai](https://claude.ai), go to **Settings → Connectors**. For the generic flow, see Anthropic's [Connect to Remote MCP Servers](https://modelcontextprotocol.io/docs/develop/connect-remote-servers) walkthrough.
  </Step>

  <Step title="Add a custom connector">
    1. Click **Add** → **Add custom connector**.
    2. Paste the URL: `https://mcp.suprsend.com/mcp`.
    3. To pin a workspace, use `https://mcp.suprsend.com/mcp/<workspace>` instead.
    4. Save.
  </Step>

  <Step title="Sign in with your SuprSend account">
    Claude prompts a browser sign-in on the first tool call. Sign in with your SuprSend account. Your role (admin or member) decides which tools you see.
  </Step>

  <Step title="Verify the connection">
    In a new conversation, click the **tools icon** in the input area — SuprSend's tools should appear. Try:

    ```
    Search the SuprSend docs for how preference categories work.
    ```

    Approve the first tool call, and you're set.
  </Step>
</Steps>

## Restricting which tools Claude can access

The SuprSend MCP server limits tools in two ways:

- **By URL** — append `?tools=` to the endpoint to restrict which tool groups the client sees. For example:

  ```
  https://mcp.suprsend.com/mcp?tools=users.*,data.*
  ```

  Scope can only reduce access, never widen it.

- **By role** — your SuprSend role decides what the agent can do. Members see only read tools; admins see every tool, including the ones that send real notifications (`workflows.trigger`, `broadcasts.trigger`, `workflows.test_run`, `events.track`, `templates.send_test`).

See the [tool list](/reference/mcp-tool-list) for every tool and its read/write label.

## Troubleshooting

<AccordionGroup>
  <Accordion title="OAuth sign-in loop">
    If the browser keeps redirecting without completing sign-in, close every Claude window, clear your SuprSend session at [app.suprsend.com](https://app.suprsend.com), and reconnect. For Claude Code, run `claude mcp remove suprsend` and re-add the server.
  </Accordion>

  <Accordion title="Server shows disconnected">
    Check that the SuprSend account you signed in with has access to the workspace in the URL. If you pinned `/mcp/staging` but your account is only on `production`, the server rejects the connection. Re-add with a workspace you can access, or drop the slug to let the server pick one.
  </Accordion>

  <Accordion title="Tools icon missing after restart on Claude Desktop">
    Fully quit the app (⌘Q on macOS, Quit from the tray on Windows) and reopen it. Custom connectors only reload on a full restart; closing the window isn't enough.
  </Accordion>
</AccordionGroup>

Sync notification assets from one workspace to another. Pulls assets from the source workspace and pushes them to the destination. Supports syncing all asset types or a specific type (workflow, template, schema, event, category, translation). Source and destination workspaces must be different.

<Warning>
  `sync` pushes **and commits** every synced asset, so the changes go live in the destination immediately. There's no draft-only sync: `--mode` only picks which version to read from the source. Sync also pushes any asset already in its local directory, not only what it pulled, so use a fresh `--dir` to push only what's in the source.
</Warning>

In a non-interactive shell, such as CI or an AI agent, sync starts without asking for confirmation. See [CI/CD with the SuprSend CLI](/reference/cli-ci-cd).

## Syntax

```bash
suprsend sync [flags]
```

## Flags

| Flag | Description | Default |
|------|-------------|---------|
| `-a, --assets string` | Asset types to sync: `all`, `workflow`, `template`, `schema`, `event`, `category`, or `translation` | `all` |
| `-S, --from string` | Source workspace to pull assets from | `staging` |
| `-m, --mode string` | Version of the source assets to pull: draft or live. The destination is always committed live. | `live` |
| `-t, --to string` | Destination workspace to push assets to | `production` |
| `-d, --dir string` | Local directory for intermediate file storage during sync | `./suprsend` |
| `--commit-message string` | Commit message applied to every committed resource in this sync run | – |
| `-n, --dry-run` | Pull the source into local files, then only print what would be pushed. Makes no changes to the destination, but overwrites local files in the sync directory. | `false` |
| `-F, --force` | Skip confirmation prompt | `false` |
| `-h, --help` | Show help for the command | – |

## Example

```bash
# Sync all assets from staging to production
suprsend sync

# Sync all assets between custom workspaces
suprsend sync --from dev-staging --to dev-production

# Sync workflows from staging to production
suprsend sync --assets workflow

# Sync staging's draft schemas to production, where they're committed live
suprsend sync --assets schema --mode draft

# Preview a sync: pull staging into local files and list what would be pushed
suprsend sync --from staging --to production --dry-run

# Sync through a fresh directory so only assets that exist in staging are pushed
suprsend sync --from staging --to production --dir ./sync-tmp
```

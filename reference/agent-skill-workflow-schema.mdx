## Overview

The `suprsend-workflow-schema` skill gives your agent the full SuprSend workflow JSON schema. Workflows are defined as JSON conforming to `https://schema.suprsend.com/workflow/v1/schema.json`. Every workflow requires a trigger (event or API) and at least one delivery node. Between trigger and delivery, you can add function, branch, and data nodes to build sophisticated notification journeys.

With this skill installed, your agent can generate complete, valid workflow JSON from a plain-English description — correct `node_type` values, proper field names, and working branch conditions.

---

## Installation

```bash
npx skills add https://github.com/suprsend/skills --skill suprsend-workflow-schema
```

## What your agent can do

- Generate valid end-to-end workflow JSON from a plain-English prompt
- Use correct `node_type` values for every node type without looking them up
- Configure multi-channel, smart routing, and fallback delivery patterns
- Build branch conditions and wait-until logic
- Invoke external APIs and transform data mid-workflow
- Push the generated workflow to SuprSend using the CLI

## Node reference

### Delivery nodes

Send notifications to users. Every workflow must end with at least one delivery node.

| Node | `node_type` | Description |
|---|---|---|
| Email | `send_email` | Send via email |
| SMS | `send_sms` | Send via SMS |
| WhatsApp | `send_whatsapp` | Send via WhatsApp |
| In-App Inbox | `send_inbox` | Send to in-app notification inbox |
| Mobile Push | `send_mobile_push` | Send mobile push notification |
| Web Push | `send_webpush` | Send web push notification |
| Slack | `send_slack` | Send to Slack |
| MS Teams | `send_ms_teams` | Send to Microsoft Teams |
| Multi-Channel | `send_multi_channel` | Send across multiple channels simultaneously |
| Smart Channel Routing | `send_smart_channel_routing` | Send sequentially across channels with delays until user engages |
| HTTP API | `httpapi_webhook` | Notify an external endpoint (GET/POST/PUT/PATCH/DELETE) |

### Function nodes

Control timing and aggregation of notifications.

| Node | `node_type` | Description |
|---|---|---|
| Delay | `delay` | Pause for a fixed, dynamic, or relative duration |
| Batch | `batch` | Aggregate multiple triggers into one notification |
| Digest | `digest` | Send a batched summary on a recurring schedule |
| Time Window | `timewindow` | Deliver only within specified days and time ranges |

### Branch nodes

Route notifications through different paths based on conditions.

| Node | `node_type` | Description |
|---|---|---|
| Branch | `branch` | If/else routing based on conditions |
| Wait Until | `branch_waituntil` | Pause until a condition is met or a timeout expires |

### Data nodes

Fetch, transform, or update data during workflow execution.

| Node | `node_type` | Description |
|---|---|---|
| Fetch | `httpapi_fetch` | GET data from an external API |
| Data Transform | `transform` | Generate or modify variables using Handlebars or JSONNET |
| Invoke Workflow | `invokeworkflow` | Trigger another SuprSend workflow as a step |
| Update User Profile | `userupdate` | Modify recipient or actor profile properties |

### List & Object nodes

Manage user list memberships and object subscriptions.

| Node | `node_type` | Description |
|---|---|---|
| Add User to List | `subscriberlistoperation_adduser` | Add recipient/actor to a subscriber list |
| Remove User from List | `subscriberlistoperation_removeuser` | Remove recipient/actor from a list |
| Subscribe to Object | `objectoperation_addsubscription` | Add user to an object subscription |
| Unsubscribe from Object | `objectoperation_removesubscription` | Remove user from an object subscription |

## Example prompts

**Cart abandonment:**
> "Create a cart abandonment workflow. Wait 1 hour, then check if the cart is still active. If yes, send email and push simultaneously. If not opened within 24 hours, send a WhatsApp follow-up."

**Document access request:**
> "Build a document access request workflow. Notify the document owner via email immediately. If no response in 24 hours, send a Slack message as a fallback."

**Payment reminder with smart routing:**
> "Create a payment reminder workflow using smart channel routing — try email first, wait 2 hours, then try SMS if there's no engagement."

**Notify and check status:**
> "Send a notification and check back after 30 minutes via a fetch node to see if the user has completed the action. If not, send a reminder."

## Known limitations

<Warning>
  Agents may struggle with complex `expression_v1` event conditions inside branch nodes. Review generated branch conditions before pushing to production. This is being actively improved.
</Warning>

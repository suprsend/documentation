These flags apply to **any SuprSend CLI command**.  
They control things like authentication, logging, and output formatting.  

You can set them in three ways:
* Pass directly in the command  
* Use environment variables (where supported)  
* Store defaults in a config file  

## Flags Overview

| Flag | Description | Default | Env Var |
|------|-------------|---------|---------|
| `--config string` | Path to config file | `$HOME/.suprsend.yaml` | – |
| `-h, --help` | Show help for any command | – | – |
| `-n, --no-color` | Disable color output | Enabled | `NO_COLOR` |
| `-o, --output string` | Output format (`pretty`, `yaml`, `json`) | `pretty` | – |
| `-s, --service-token string` | Service token for authentication | – | `SUPRSEND_SERVICE_TOKEN` |
| `-v, --verbosity string` | Log level (`debug`, `info`, `warn`, `error`, `fatal`, `panic`) | `info` | – |
| `-w, --workspace string` | Workspace to use | `staging` | – |

## Flag Details

### `--config`

Specify a custom config file:

```bash
suprsend --config /path/to/config.yaml workflow list
```

Default: `$HOME/.suprsend.yaml`
Useful for **team or project-specific setups**.

### `-h, --help`

Show help information for the CLI or any command:

```bash
suprsend --help
suprsend workflow --help
suprsend workflow list --help
```

### `-n, --no-color`

Disable colorized CLI output:

```bash
suprsend --no-color workflow list
```

Or set globally:

```bash
export NO_COLOR=1
```

### `-o, --output`

Choose the output format:

```bash
suprsend workflow list --output json
suprsend workflow list --output yaml
```

Default: `pretty`
Use `json` or `yaml` for **automation or scripting**.

### `-s, --service-token`

Provide a service token inline:

```bash
suprsend workflow list --service-token "your_token_here"
```

<Note>
⚡ Instead of inline tokens, prefer [Authentication](/reference/cli-authentication) or [Profiles](/reference/cli-profiles).
</Note>

### `-v, --verbosity`

Control the logging level:

```bash
suprsend workflow list --verbosity debug
```

Default: `info`
Use `debug` when troubleshooting.

### `-w, --workspace`

Select which workspace to target:

```bash
suprsend --workspace production workflow list
```

Default: `staging`
Helps when working across **staging and production environments**.

## Environment Variables

Some flags can be set globally with environment variables:

```bash
export SUPRSEND_SERVICE_TOKEN="your_service_token_here"
export NO_COLOR=1
```

## Configuration File

You can store defaults in a YAML config file (default: `$HOME/.suprsend.yaml`):

```yaml
service-token: "your_service_token_here"
output: "json"
verbosity: "warn"
workspace: "production"
```

<Note>
👉 Use [Profiles](/reference/cli-profile-overview) if you manage multiple environments.
</Note>

## Advanced Configuration

### Custom Config File Location
```bash
suprsend --config /path/to/custom.yaml workflow list
```

### Environment-Specific Settings
```bash
# Development
export SUPRSEND_SERVICE_TOKEN="dev_token"
export SUPRSEND_BASE_URL="https://dev.suprsend.com/"

# Production
export SUPRSEND_SERVICE_TOKEN="prod_token"
export SUPRSEND_BASE_URL="https://hub.suprsend.com/"
```

### Debug Mode

Enable debug logging for troubleshooting:

```bash
export DEBUG=true
suprsend workflow list
```

Or use the verbosity flag:

```bash
suprsend workflow list --verbosity debug
```

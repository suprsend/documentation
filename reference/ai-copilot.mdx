The SuprSend AI Copilot is a conversational assistant embedded directly in your dashboard. It has full access to your workspace and can take real actions on your behalf — reading data, creating records, updating preferences, managing subscriptions — all in plain English.

No API calls. No tab-switching. No copy-pasting IDs into a terminal.

<Note>
  The Copilot uses the same tool layer as the [MCP server](/reference/mcp-overview). Everything you can do here is also available programmatically via MCP for IDE or agent-driven workflows.
</Note>

## Users

Manage everything about a user — their profile, channel addresses, notification preferences, and what lists or objects they're subscribed to.

**What you can do:**

- Fetch a user's full profile, channels, and properties
- Create a new user or update an existing one
- Get a user's notification preferences across categories and channels
- Update a user's preference for a specific notification category
- Set global channel-level restrictions (e.g., block all SMS)
- See all lists a user belongs to
- See all objects a user is subscribed to

<AccordionGroup>
  <Accordion title="Example prompts">
    ```
    Get the profile for user priya_42.
    ```

    ```
    Create a user with ID user_9821. Set their email to priya@example.com and phone to +919876543210.
    ```

    ```
    Update user bob_99 — add their Slack user ID as U012AB3CD.
    ```

    ```
    What notification categories has user alice_77 opted out of?
    ```

    ```
    Show me all channel preferences for user john_doe — I want to debug why he's not getting emails.
    ```

    ```
    Turn off WhatsApp notifications globally for user mark_55.
    ```

    ```
    Update user priya_42's preference for the "Order Updates" category — opt her in for email, opt her out for SMS.
    ```

    ```
    Which lists is user alice_77 subscribed to?
    ```

    ```
    Show me all the objects user john_doe is subscribed to.
    ```
  </Accordion>
</AccordionGroup>

## Objects

Objects represent non-user entities in your product — teams, accounts, projects, devices — that can receive notifications. The Copilot gives you full read and write access.

**What you can do:**

- Fetch an object's profile, channels, and subscriber count
- Create a new object or update an existing one
- View an object's notification preferences across categories and channels
- Update an object's preference for a specific notification category
- Update an object's global channel-level restrictions
- Add a user as a subscriber to an object

<AccordionGroup>
  <Accordion title="Example prompts">
    ```
    Get the details for the object with type "teams" and ID "team_finance".
    ```

    ```
    How many subscribers does the object "account_enterprise_01" have?
    ```

    ```
    Create an object of type "projects" with ID "proj_launch_2025". Set its Slack channel to C012AB3CD.
    ```

    ```
    Update the object "team_design" — add an email address notifications@design.example.com.
    ```

    ```
    Opt out the object "team_growth" from the "Product Announcements" notification category.
    ```

    ```
    Block push notifications globally for the object "device_kiosk_lobby".
    ```

    ```
    Add user priya_42 as a subscriber to the object "team_finance".
    ```
  </Accordion>
</AccordionGroup>

## Notification Preferences

Manage notification preference categories at the workspace level — the building blocks that power per-user and per-tenant preference control.

**What you can do:**

- Fetch all preference categories defined in the workspace
- Create or update a preference category
- Commit a preference category draft to make it live

<AccordionGroup>
  <Accordion title="Example prompts">
    ```
    Show me all notification preference categories in my workspace.
    ```

    ```
    Create a new preference category called "Security Alerts" with email and push channels, mandatory opt-in.
    ```

    ```
    Update the "Marketing Emails" preference category — change its display name to "Promotions & Offers".
    ```

    ```
    Commit the preference category "Weekly Digest" so it goes live.
    ```
  </Accordion>
</AccordionGroup>

<Info>
  Preference categories define the options users and tenants see when managing their notification settings. Changes here propagate to the preference centre for all users.
</Info>

## Best practices

<AccordionGroup>
  <Accordion title="Tips for effective prompts">
    - **Specify IDs explicitly.** The Copilot operates on your live workspace data. Provide exact user IDs, tenant IDs, object IDs, or workflow slugs — e.g., `Get the profile for user priya_42` instead of `Get the user who signed up last week`.
    - **Chain actions in one prompt.** The Copilot can handle multi-step requests in a single turn — e.g., `Get the preferences for user priya_42, then opt her out of the "Promotional" category for email`.
    - **Use follow-ups to iterate.** Context carries across a conversation. Ask a question, then refine or act on the result in follow-up messages.
    - **Check before you change.** For tenant-level or global preference changes, fetch the current state first before making updates.
  </Accordion>
</AccordionGroup>

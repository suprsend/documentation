# SuprSend CLI Reference

The SuprSend CLI is a powerful command-line interface that enables developers to interact with SuprSend's notification infrastructure directly from their terminal. This tool is essential for managing workflows, schemas, and other resources in your SuprSend workspace, making it easier to integrate notification management into your development workflow and CI/CD pipelines.

## Why Use the SuprSend CLI?

The SuprSend CLI provides several key benefits:

- **Local Development**: Work with your notification templates and workflows locally before deploying
- **Version Control**: Track changes to your notification configurations in Git
- **CI/CD Integration**: Automate deployment of notification changes across environments
- **Team Collaboration**: Share and review notification configurations through code reviews
- **Environment Management**: Easily manage different configurations for staging and production
- **Type Safety**: Generate type definitions from your JSON schemas for better development experience
- **User Management**: Manage users and their properties directly from the CLI
- **Object Management**: Handle object operations and subscriptions
- **MCP Integration**: Connect with other tools through Model Context Protocol

## Setup

### Installation

#### Homebrew (macOS)

```bash
brew tap suprsend/tap
brew install suprsend
```

#### Binary Releases

Download pre-compiled binaries for your platform from the [GitHub Releases page](https://github.com/suprsend/cli/releases).

#### Building from Source

```bash
git clone https://github.com/suprsend/cli.git
cd cli/cmd/suprsend
go build -o suprsend
sudo mv suprsend /usr/local/bin/
```

**Note**: Building from source requires Deno to be installed for the type-morph binary. Run `make build` in the root directory after installing Deno.

### Shell Completion

The SuprSend CLI supports autocompletion for multiple shells. To enable it:

```bash
# Bash
suprsend completion bash > ~/.bash_completion.d/suprsend

# Zsh
suprsend completion zsh > ~/.zsh/completions/_suprsend

# Fish
suprsend completion fish > ~/.config/fish/completions/suprsend.fish

# PowerShell
suprsend completion powershell > suprsend_completion.ps1
```

## Authentication

The SuprSend CLI requires authentication to access your workspace resources. There are several ways to provide your credentials:

### Service Token

A service token is required for all CLI operations. You can obtain one from your SuprSend dashboard.

### Authentication Methods

#### 1. Environment Variables

Set the `SUPRSEND_SERVICE_TOKEN` environment variable:

```bash
export SUPRSEND_SERVICE_TOKEN="your_service_token_here"
```

#### 2. Command Line Flags

Pass the token directly with each command:

```bash
suprsend workflow list --service-token "your_token"
```

#### 3. Configuration File (Recommended)

Create a configuration file at `$HOME/.suprsend.yaml`:

```yaml
profiles:
  default:
    service_token: "your_service_token_here"
    base_url: "https://hub.suprsend.com/"
    mgmnt_url: "https://api.suprsend.com/"
  production:
    service_token: "production_token_here"
    base_url: "https://hub.suprsend.com/"
    mgmnt_url: "https://api.suprsend.com/"
  active_profile: "default"
```

#### 4. Profiles

Profiles allow you to manage multiple authentication configurations:

```bash
# Add a new profile
suprsend profile add --name production --service-token "token123"

# List profiles
suprsend profile list

# Switch to a profile
suprsend profile use --name production

# Modify a profile
suprsend profile modify --name production --service-token "new_token"

# Remove a profile
suprsend profile remove --name old_profile
```

## Global Flags

The following flags are available for all SuprSend CLI commands:

```
      --config string          config file (default: $HOME/.suprsend.yaml)
  -h, --help                   help for suprsend
  -n, --no-color               Disable color output (default: $NO_COLOR)
  -o, --output string          Output Type (pretty, yaml, json) (default "pretty")
  -s, --service-token string   Service token (default: $SUPRSEND_SERVICE_TOKEN)
  -v, --verbosity string       Log level (debug, info, warn, error, fatal, panic) (default "info")
  -w, --workspace string       Workspace to use (default "staging")
```

## Commands

### suprsend sync

Syncs assets between different workspaces.

**Global Flags:**
- `--workspace` - Target workspace (default: staging)

**Local Flags:**
```
  -a, --assets string          Assets to sync (all, workflows, schemas) (default "all")
  -f, --from string            Source workspace (required) (default "staging")
  -m, --mode string            Mode to sync assets (draft, live) (default "live")
  -t, --to string              Destination workspace (required) (default "production")
```

**Examples:**

```bash
# Sync all assets from staging to production
suprsend sync --from staging --to production

# Sync only workflows
suprsend sync --from staging --to production --assets workflows

# Sync schemas in draft mode
suprsend sync --from staging --to production --assets schemas --mode draft
```

### suprsend workflow

Manages workflows in your SuprSend workspace.

**Global Flags:**
- `--workspace` - Target workspace (default: staging)

#### suprsend workflow list

Lists workflows in a workspace.

**Local Flags:**
```
  -l, --limit int              Limit the number of workflows to list (default 20)
  -f, --offset int             Offset the number of workflows to list (default 0)
  -m, --mode string            Mode of workflows to list (default "live")
  -o, --output string          Output Type (pretty, yaml, json) (default "pretty")
```

**Examples:**

```bash
# List all live workflows
suprsend workflow list

# List first 10 workflows in production
suprsend workflow list --workspace production --limit 10

# List draft workflows
suprsend workflow list --mode draft
```

#### suprsend workflow pull

Pulls workflows from a workspace to your local directory.

**Local Flags:**
```
  -m, --mode string            Mode of workflows to pull from (default "live")
  -d, --output-dir string      Output directory for workflows
```

**Examples:**

```bash
# Pull all live workflows
suprsend workflow pull

# Pull workflows to a specific directory
suprsend workflow pull --output-dir ./my-workflows

# Pull draft workflows
suprsend workflow pull --mode draft
```

#### suprsend workflow push

Pushes workflows from local directory to SuprSend.

**Local Flags:**
```
  -d, --output-dir string      Output directory containing workflow files
```

**Examples:**

```bash
# Push workflows from current directory
suprsend workflow push

# Push workflows from a specific directory
suprsend workflow push --output-dir ./my-workflows
```

#### suprsend workflow enable <workflow_key>

Enables a workflow in the specified workspace.

**Examples:**

```bash
# Enable a workflow
suprsend workflow enable my-workflow-key

# Enable in production
suprsend workflow enable my-workflow-key --workspace production
```

#### suprsend workflow disable <workflow_key>

Disables a workflow in the specified workspace.

**Examples:**

```bash
# Disable a workflow
suprsend workflow disable my-workflow-key

# Disable in production
suprsend workflow disable my-workflow-key --workspace production
```

**Local Flags:**
```
  -l, --limit int              Limit the number of schemas to list (default 20)
  -f, --offset int             Offset the number of schemas to list (default 0)
  -m, --mode string            Mode of schemas to list (default "live")
  -o, --output string          Output Type (pretty, yaml, json) (default "pretty")
```

**Examples:**

```bash

suprsend schema list

suprsend schema list --workspace production --limit 10

suprsend schema list --mode draft
```

#### suprsend schema pull

Pulls schemas from a workspace to your local directory.

**Local Flags:**
```
  -m, --mode string            Mode of schemas to pull (default "live")
  -d, --output-dir string      Output directory for schemas
```

**Examples:**

```bash
# Pull all live schemas
suprsend schema pull

# Pull schemas to a specific directory
suprsend schema pull --output-dir ./my-schemas

# Pull draft schemas
suprsend schema pull --mode draft
```

#### suprsend schema push <schema_key>

Pushes a schema directory to SuprSend.

**Examples:**

```bash
# Push a schema
suprsend schema push my-schema-key

# Push to a specific workspace
suprsend schema push my-schema-key --workspace production
```

#### suprsend schema commit

Commits all schema changes in the development workspace.

**Local Flags:**
```
  -m, --commit-message string  Commit message to use for all changes
  --force                      Removes the confirmation prompt
```

**Examples:**

```bash
# Commit schema changes
suprsend schema commit --commit-message "Update user notification schema"

# Force commit without confirmation
suprsend schema commit --commit-message "Emergency fix" --force
```

#### suprsend schema reset

Resets all schema changes in the development workspace.

**Local Flags:**
```
  --force                      Removes the confirmation prompt
```

**Examples:**

```bash
# Reset all schema changes
suprsend schema reset

# Force reset without confirmation
suprsend schema reset --force
```

### suprsend profile

Manages profiles and stores credentials for different SuprSend environments.

#### suprsend profile add

Adds a new profile to store credentials.

**Local Flags:**
```
  --name string                Name of the profile (required)
  --base-url string            Base URL for SuprSend API
  --mgmnt-url string           Management URL for SuprSend API
  --service-token string       Service token (required)
  --config string              Config file path
```

**Examples:**

```bash
# Add a profile with all parameters
suprsend profile add --name production --service-token "token123" --base-url "https://hub.suprsend.com/" --mgmnt-url "https://api.suprsend.com/"

# Add a profile interactively
suprsend profile add
```

#### suprsend profile list

Lists all available profiles.

**Local Flags:**
```
  -o, --output string          Output Type (pretty, yaml, json) (default "pretty")
```

**Examples:**

```bash
# List all profiles
suprsend profile list

# List profiles in JSON format
suprsend profile list --output json
```

#### suprsend profile modify

Modifies an existing profile.

**Local Flags:**
```
  --name string                Name of the profile to modify (required)
  --base-url string            New base URL
  --mgmnt-url string           New management URL

```

**Examples:**

```bash
# Modify a profile's service token
suprsend profile modify --name production --service-token "new_token_456"

# Modify a profile's URLs
suprsend profile modify --name staging --base-url "https://staging.suprsend.com/" --mgmnt-url "https://staging-api.suprsend.com/"
```

#### suprsend profile remove

Removes a profile.

**Local Flags:**
```
  --name string                Name of the profile to remove (required)
  --config string              Config file path
```

**Examples:**

```bash
# Remove a profile

```

#### suprsend profile use

Sets a profile as the active profile.

**Local Flags:**
```
  --name string                Name of the profile to use (required)
```

**Examples:**

### suprsend user

Manages users in your SuprSend workspace.

**Global Flags:**
- `--workspace` - Target workspace (default: staging)

#### suprsend user get <distinct_id>

Gets user details by distinct ID.

**Local Flags:**
```
  --workspace string           Workspace name (required)
  -o, --output string          Output Type (pretty, yaml, json) (default "pretty")
```

**Examples:**

```bash
# Get user details
suprsend user get user123 --workspace staging

```

### suprsend generate-types <filename>

Generates type definitions from JSON schemas in your workspace.

**Global Flags:**
- `--workspace` - Target workspace (default: staging)

**Local Flags:**
```
  -m, --mode string            Mode of schema to fetch (default "live")
  --build-flags string         Flags to generate types in a certain way
```

**Supported Languages:**
- `.ts` - TypeScript
- `.go` - Go
- `.py` - Python
- `.kt` - Kotlin
- `.swift` - Swift
- `.java` - Java
- `.dart` - Dart

**Examples:**

```bash
# Generate TypeScript types
suprsend generate-types types.ts

# Generate Go types
suprsend generate-types types.go

# Generate types from a specific workspace
suprsend generate-types types.ts --workspace production

# Generate types with build flags
suprsend generate-types types.ts --build-flags "strict"
```

### suprsend start-mcp-server

Starts an MCP (Model Context Protocol) server for SuprSend.

**Local Flags:**
```
  -t, --transport string       The transport to use for the MCP server. Can be stdio/sse/http (default "stdio")
  -T, --tools string           The types of tools to use. Can be either 'all' or comma separated list of tool names (default "all")
```

#### suprsend start-mcp-server list-tools

Lists all the tools supported by the MCP server.

**Local Flags:**
```
  -o, --output string          Output Type (pretty, yaml, json) (default "pretty")
```

**Available MCP Tools:**
- **User Tools**: User management operations
- **Tenant Tools**: Tenant-related operations
- **Object Tools**: Object management and subscriptions
- **Documentation Tools**: Documentation generation

**Examples:**

```bash
# Start MCP server with stdio transport
suprsend start-mcp-server

# Start MCP server with HTTP transport
suprsend start-mcp-server --transport http

# Start MCP server with specific tools
suprsend start-mcp-server --tools "user,tenant"

# List available tools
suprsend start-mcp-server list-tools
```

## Common Workflows

### Basic Development Workflow

```bash
# 1. Set up authentication
suprsend profile add --name production --service-token "your_token"

# 2. Pull workflows from staging
suprsend workflow pull --workspace staging --output-dir ./workflows

# 3. Make changes to workflow files locally

# 4. Push workflows to production
suprsend workflow push --output-dir ./workflows --workspace production

# 5. Sync all assets from staging to production
suprsend sync --from staging --to production
```

### Schema Management

```bash
# 1. Pull schemas from staging
suprsend schema pull --workspace staging --output-dir ./schemas

# 2. Generate TypeScript types
suprsend generate-types ./src/types.ts

# 3. Push schema changes
suprsend schema push user-schema --workspace staging

# 4. Commit changes
suprsend schema commit --commit-message "Update user schema"
```

### User Management

```bash
# 1. Get user details
suprsend user get user123 --workspace staging

# 2. Use MCP server for advanced user operations
suprsend start-mcp-server --tools "user"
```

### CI/CD Integration

```bash
# 1. Pull all resources
suprsend workflow pull --workspace staging
suprsend schema pull --workspace staging

# 2. Make changes and test locally

# 3. Push to staging
suprsend workflow push --workspace staging
suprsend schema push my-schema --workspace staging

# 4. Sync to production
suprsend sync --from staging --to production
```

## Troubleshooting

### Common Issues

1. **Authentication Error**: Ensure your service token is valid and properly configured
2. **Workspace Not Found**: Verify the workspace name and your access permissions
3. **Permission Denied**: Check that your service token has the necessary permissions
4. **Network Issues**: Verify your internet connection and firewall settings
5. **Missing Dependencies**: Ensure Deno is installed for building from source
6. **Output Format Issues**: Check that the specified output format is supported

### Debug Mode

Enable debug logging to get more detailed information:

```bash
suprsend --verbosity debug workflow list
```

Or set the DEBUG environment variable:

```bash
export DEBUG=true
suprsend workflow list
```

### Getting Help

Use the help command to get information about any command:

```bash
suprsend --help
suprsend workflow --help
suprsend workflow list --help
```

## Best Practices

1. **Use Profiles**: Set up profiles for different environments to avoid passing tokens manually
2. **Version Control**: Commit your workflow and schema files to version control
3. **Testing**: Always test changes in staging before pushing to production
4. **Backup**: Keep backups of your production configurations
5. **Documentation**: Document any custom workflows or schemas you create
6. **MCP Integration**: Use MCP server for advanced operations and tool integration
7. **Output Formats**: Use JSON output for programmatic consumption, pretty for human reading

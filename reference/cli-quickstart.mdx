## Overview

This quickstart guide shows you how to set up and use the SuprSend CLI to manage your notification workflows. After completing this guide, you will have a fully functional CLI environment ready to manage workflows across different environments.

**Prerequisites**: You'll need a [SuprSend account](https://app.suprsend.com) to get started.

---

## Step 1: Install the CLI

Install the SuprSend CLI using your preferred package manager:

<Steps>
  <Step title="Choose your installation method">

<CodeGroup>

```bash Homebrew (macOS/Linux)
brew tap suprsend/tap
brew install suprsend
```

```bash npm (Node.js)
npm install -g @suprsend/cli
```

```bash curl (Universal)
curl -fsSL https://cli.suprsend.com/install.sh | sh
```

```bash Binary (Windows)
# Download from: https://github.com/suprsend/cli/releases
# Extract and add to your PATH
```

</CodeGroup>

Verify the installation:

```bash
suprsend version
```

You should see output like `v1.0.0`. If you see a version number, the installation was successful! ✅

  </Step>
</Steps>

---

## Step 2: Authentication

Before you can use the CLI, you need a service token from your SuprSend workspace.

<Steps>
  <Step title="Navigate to Service Tokens">
    Go to the [SuprSend Dashboard](https://app.suprsend.com) and sign in
  </Step>
  <Step title="Create New Token">
    Navigate to **Account Settings** → **Service Tokens** and click **"Create New Token"**
  </Step>
  <Step title="Name and Copy Token">
    Name it "CLI Development" and **copy the token immediately** - you won't see it again!
    
    <Note>
    **Best Practice**: Use descriptive names for your service tokens to easily identify their purpose later.
    </Note>
  </Step>
  <Step title="Choose Authentication Method">
    The CLI supports three authentication methods, each optimized for different use cases:

    <CodeGroup>

    ```bash Profile (Recommended)
    # Best for: Local development, multiple workspaces, and persistent authentication
    suprsend profile add --name "my-workspace" --service-token "your_service_token_here"
    suprsend profile use --name "my-workspace"
    ```

    ```bash Environment Variable
    # Best for: CI/CD pipelines, scripts, and temporary sessions
    export SUPRSEND_SERVICE_TOKEN="your_service_token_here"
    ```

    ```bash Command Flag
    # Best for: One-off commands and testing
    suprsend workflow list --service-token "your_service_token_here"
    ```

    </CodeGroup>
  </Step>
</Steps>

## Step 3: Boost your CLI experience (Optional) ⚡

Supercharge your development workflow with these productivity features:

#### 🚀 Enable Autocompletion

Autocompletion helps avoid typos and speeds up command entry with <kbd>tab</kbd> completion.

```bash
# For current session (bash/zsh)
source <(suprsend completion bash)
source <(suprsend completion zsh)

# For persistent setup
suprsend completion bash >> ~/.bashrc
suprsend completion zsh >> ~/.zshrc
```

Learn more about [autocompletion setup](/reference/cli-autocompletion).

---

#### 🎨 No color flag

By default, suprsend output is colored for readability. You can disable colors when piping results to scripts, log files, or CI systems where ANSI codes may cause issues.

```bash
# Disable colors for a single command
suprsend --no-color workflow list
suprsend -n workflow list

# Set globally
export NO_COLOR=1
```

## Step 4: Discover and manage workflows

Let's see what workflows are available in your staging environment:

```bash
suprsend --workspace staging workflow list
```

**No workflows found?** 🚀 Let's create your first one! 

<Steps>
  <Step title="Open the Dashboard">
    Click here to open the [SuprSend Dashboard](https://app.suprsend.com/en/staging/workflows)
  </Step>
  <Step title="Create New Workflow">
    Click the **"+"** button to create a new workflow
  </Step>
  <Step title="Follow the Guide">
    Use our [workflow design guide](/docs/design-workflow) to build your workflow
  </Step>
  <Step title="Return Here">
    Come back and run `suprsend --workspace staging workflow list` to see your new workflow!
  </Step>
</Steps>

Now let's pull the workflows to work with them locally:

```bash
suprsend --workspace staging workflow pull
```

You should see workflow files (`.yaml` files) in the `suprsend/workflow/` directory. 📁

---

## Step 5: Control workflow states

Learn to enable and disable workflows:

```bash
# Disable a workflow
suprsend --workspace staging workflow disable welcome-email

# Enable a workflow  
suprsend --workspace staging workflow enable welcome-email
```

<Warning>
**Note**: Replace `welcome-email` with an actual workflow slug from your list. Learn more about [workflow state management](/reference/cli-workflow-enable).
</Warning>

---

## Step 6: Push changes to production

If you've made changes to workflow files locally, push them directly to production:

```bash
# Push all workflows to production
suprsend --workspace production workflow push --commit=true --commit-message "Update workflows"

# Or push a specific workflow to production
suprsend --workspace production workflow push --slug welcome-email --commit=true --commit-message "Update workflow"
```

<Info>
**Important**: Always use `--commit=true` when pushing workflows to make them live. Without commit, workflows remain in draft mode. Learn more about [workflow push operation](/reference/cli-workflow-push).
</Info>

<Tip>
**Pro Tip**: Use `suprsend sync` to clone and validate assets between workspaces. Perfect for promoting tested workflows from staging to production! Learn more about [sync operations](/reference/cli-sync).
</Tip>

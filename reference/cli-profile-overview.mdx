<Info>
Profiles are only required for **self-hosted and BYOC (Bring Your Own Cloud) deployments** where you need to connect to different servers with custom API endpoints. If you are using SuprSend's SaaS platform, you don't need profiles — use [environment variables or command-line flags](/reference/cli-authentication) instead.
</Info>

Profiles allow you to store connection details for multiple servers and switch between them without repeatedly entering credentials. This is useful when you manage multiple self-hosted or BYOC environments (e.g., staging and production servers with different base URLs).

## Commands

| Command | Description |
|---------|-------------|
| [`profile list`](/reference/cli-profile-list) | List all configured profiles |
| [`profile add`](/reference/cli-profile-add) | Add a new profile configuration |
| [`profile modify`](/reference/cli-profile-modify) | Modify an existing profile |
| [`profile remove`](/reference/cli-profile-remove) | Remove a profile configuration |
| [`profile use`](/reference/cli-profile-use) | Switch to a specific profile |
---

## Inherited Global Flags

This command also supports [Global Flags](/reference/cli-global-flags), such as:

* `--config` – Config file (default: `$HOME/.suprsend.yaml`)
* `-n`, `--no-color` – Disable color output
* `-v`, `--verbosity` – Log level (debug, info, warn, error, fatal, panic) (default "info")

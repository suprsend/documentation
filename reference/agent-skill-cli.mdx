The `suprsend-cli` skill gives your agent the complete SuprSend CLI reference so it can run commands correctly on the first try — no guessing at flag names or subcommand structure.

---

## Installation

```bash
npx skills add https://github.com/suprsend/skills --skill suprsend-cli
```

Or install all SuprSend skills at once:

```bash
npx skills add suprsend/skills
```

---

## Advantages

- **Full workflow lifecycle**: Pull workflows from your workspace, edit locally, and push back — with `--commit=true` and `--commit-message` for version tracking.
- **Multi-asset management**: Manage not just workflows but also [schemas](https://docs.suprsend.com/reference/cli-schema-overview.md), [events](https://docs.suprsend.com/reference/cli-event-overview.md), [preference categories](https://docs.suprsend.com/reference/cli-category-overview.md), and [translations](https://docs.suprsend.com/reference/cli-translation-overview.md) — all from the terminal.
- **Cross-workspace sync**: [Sync](https://docs.suprsend.com/reference/cli-sync.md) notification assets between staging and production workspaces in a single command.
- **Type generation in 7 languages**: [Generate](https://docs.suprsend.com/docs/type-generation.md) TypeScript, Python, Go, Java, Ruby, Swift, or Kotlin type definitions from your event schemas for type-safe integrations.
- **CI/CD pipeline setup**: Configure GitHub Actions, GitLab CI, or other pipelines to pull, validate, and push notification changes automatically on merge.
- **MCP server management**: Start and configure the [SuprSend MCP server](https://docs.suprsend.com/reference/mcp-overview.md) directly from the terminal with `suprsend start-mcp-server`.

## Before using the CLI

**Authentication** — All CLI commands require a service token. See [Service Tokens](https://docs.suprsend.com/docs/developer/service-tokens.md) to generate one, then set it as an environment variable:

```bash
export SUPRSEND_SERVICE_TOKEN="your_service_token_here"
```

**Active profile** — Always verify you're on the right workspace before pushing:

```bash
suprsend profile list
suprsend profile use --name <profile-name>
```

<Note>
  `--workspace` switches between workspaces within an account. The `profile` command is for self-hosted or BYOC deployments. See [Setting Up CLI Access](https://docs.suprsend.com/docs/self-hosted/cli-profiles.md) for self-hosted setup.
</Note>

## Pushing workflows

```bash
# Push all workflows from the default directory (suprsend/workflow/)
suprsend workflow push

# Push from a custom directory
suprsend workflow push --dir /path/to/workflows/

# Push a single workflow by slug
suprsend workflow push --slug cart-abandonment

# Push and make live immediately
suprsend workflow push --slug cart-abandonment --commit=true --commit-message "Add cart abandonment"
```

See [Push Workflows](https://docs.suprsend.com/reference/cli-workflow-overview.md) for the full flag reference.

## Gotchas

These are the mistakes agents make most often with the CLI. They're documented here so both you and your agent know what to watch for.

| What goes wrong | Why it happens | How to fix it |
|---|---|---|
| `workflow push myfile.json` silently pushes 0 | The command expects a directory or `--slug`, not a file path | Use `suprsend workflow push --slug cart-abandonment` or `--dir suprsend/workflow/` |
| Workflow is pushed but no notifications fire | Pushed workflows are **drafts by default** | Add `--commit=true` to your push command |
| "Successfully pushed: 0" with no error | Wrong active profile or workspace | Run `suprsend profile list` and switch with `suprsend profile use --name <n>` |
| `suprsend/workflow/` directory not found | Default push directory doesn't exist yet | Create `suprsend/workflow/` and place your JSON files inside |
| Workflow JSON can't be targeted by slug | Missing `slug` field in the JSON | Always include `"slug": "your-slug"` in generated workflow files |
| Validation error on push | Referenced schema or category doesn't exist in the target workspace | Push [schemas](/reference/cli-schema-overview) and [categories](/reference/cli-category-overview) before pushing workflows |

<Note>
  **Beta — launched 2026-10-08.** The hosted SuprSend MCP server is in Beta. The endpoint, auth flow, and tool list may still change before general availability.
</Note>

The hosted SuprSend MCP server exposes **95 tools across 18 groups** — users, lists, broadcasts, workflows, templates, preferences, delivery analytics, and more. This page is the full list.

- **Members** of a SuprSend account see only the read tools.
- **Admins** see every tool, including the ones that send real notifications.
- **Role comes from the auth exchange**, not from the workspace URL.

Tools that send real notifications are flagged below. Hosts see this through the `openWorldHint` annotation.

## Scoping tool access

Add `?tools=` to the server URL to limit which groups a client sees. Use a comma-separated list of tool names or group patterns:

```
https://mcp.suprsend.com/mcp?tools=users.*,data.*
```

```
https://mcp.suprsend.com/mcp/staging?tools=data.*
```

A pattern that matches no tool is an error. URL scope can only reduce access, never widen it.

| Pattern | What it allows |
|---|---|
| `users.*` | All user tools |
| `users.get` | Only the `users.get` tool |
| `tenants.*,workflows.*` | All tenant and workflow tools |
| `data.*` | Only the delivery-analytics tools |

## Workspaces

| Read tools | Write and send tools (admins only) |
|---|---|
| `list` | — |

## Users

| Read tools | Write and send tools (admins only) |
|---|---|
| `get`, `find` (by exact email, phone, or distinct ID), `get_preferences`, `list_subscriptions`, `list_tenant_profiles` | `upsert`, `update`, `set_preferences`, `reset_preferences` |

## Objects

| Read tools | Write and send tools (admins only) |
|---|---|
| `get`, `list_subscribers`, `list_subscriptions` (parent objects) | `upsert`, `update`, `add_subscribers`, `remove_subscribers` |

## Tenants

| Read tools | Write and send tools (admins only) |
|---|---|
| `get`, `get_preferences` | `upsert`, `set_category_preference` |

## Vendors

| Read tools | Write and send tools (admins only) |
|---|---|
| `list_types`, `list` (no secrets), `get_routing` (primary vendor and fallbacks per channel) | `upsert` (add a vendor or replace its config), `set_routing` (primary, fallbacks, own or inherited routing) |

## Lists

| Read tools | Write and send tools (admins only) |
|---|---|
| `list`, `list_subscribers`, `preview_query`, `get_sync`, `list_sync_runs` | `add_users`, `remove_users`, `start_replace`, `finish_replace`, `cancel_replace`, `upsert` (static or dynamic, with the query), `set_sync_enabled` |

## Broadcasts

| Read tools | Write and send tools (admins only) |
|---|---|
| `get` (the status and user counts of one broadcast, by idempotency key or broadcast ID) | **`trigger`** (one template to every user of a list; supports `dry_run` which checks that the list and template exist and returns the list size), `cancel` (broadcasts that have not finished) |

<Warning>
  `broadcasts.trigger` sends real notifications. Use `dry_run: true` to confirm the list and template before sending to real recipients.
</Warning>

## Workflows

| Read tools | Write and send tools (admins only) |
|---|---|
| `list`, `get`, `validate` | `save_draft`, `publish`, **`trigger`**, **`test_run`**, `set_enabled` (turn off or on), `cancel_run` (pending runs) |

<Warning>
  `workflows.trigger` and `workflows.test_run` send real notifications. `workflows.trigger` supports `dry_run: true`, which validates the payload against the schema and sends nothing.
</Warning>

## Events

| Read tools | Write and send tools (admins only) |
|---|---|
| `get` | `create`, `link_schema`, **`track`** |

<Warning>
  `events.track` can start workflows that send real notifications. It supports `dry_run: true`, which validates the payload and sends nothing.
</Warning>

## Schemas

| Read tools | Write and send tools (admins only) |
|---|---|
| `list`, `get` | `save_draft`, `publish` |

## Templates

| Read tools | Write and send tools (admins only) |
|---|---|
| `list`, `get`, `get_variant`, `list_versions`, `get_mock_data`, `validate` | `upsert`, `upsert_variant`, `set_mock_data`, `publish`, **`send_test`** |

<Warning>
  `templates.send_test` sends a real test notification to the configured test recipient.
</Warning>

## Translations

| Read tools | Write and send tools (admins only) |
|---|---|
| `list`, `get`, `list_versions`, `get_version` | `save` (one file in the draft), `delete`, `publish` (all changed files), `rollback` (an archived version) |

## Preferences

| Read tools | Write and send tools (admins only) |
|---|---|
| `list_categories`, `list_category_translations`, `get_category_translation` | `save_categories`, `publish_categories`, `save_category_translation`, `delete_category_translation` |

## Messages

| Read tools | Write and send tools (admins only) |
|---|---|
| `get_content` (admins only: the text of one sent message, with link queries and codes masked) | — |

In hosts that support MCP Apps, `messages.get_content` renders a message preview — email, Inbox, SMS, push — with images and links off and OTPs masked. Slack messages render as JSON with a link to Slack's Block Kit Builder.

## Data

| Read tools | Write and send tools (admins only) |
|---|---|
| `query` (read-only SQL on delivery analytics, logs, executions, and configuration), `validate` (checks SQL without running it), `retention`, `user_properties_schema` | — |

In hosts that support MCP Apps, `data.query` results render as a chart (metric, line, bar, stacked bar, or pie) or a table with a Refresh button.

## Assets

| Read tools | Write and send tools (admins only) |
|---|---|
| — | `upload` (hosts an image or a PDF on the SuprSend CDN from a URL, small base64, or a file attached in ChatGPT), `create_upload` (a single-use upload URL and a `curl` command, for agents with a shell) |

## Expressions

| Read tools | Write and send tools (admins only) |
|---|---|
| `evaluate` (Handlebars with SuprSend helpers and translations, JSONNET on SuprSend's runtime, jq as in workflow nodes) | — |

## Docs

| Read tools | Write and send tools (admins only) |
|---|---|
| `search` (the SuprSend documentation), `get_skill` (the SuprSend skills for clients without the MCP Skills extension: workflow JSON, template content, semantic layer SQL, docs support) | — |

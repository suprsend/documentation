The SuprSend MCP server exposes **94 tools in 18 groups**. Tools are named `<group>.<action>`. This page lists every one, with an example prompt that makes the agent call it.

The **Access** column says what a tool does to your account:

- **Read** looks things up and changes nothing.
- **Write** changes data in your workspace. Drafts stay drafts until you publish them.
- **Sends** delivers real notifications to real recipients.

The agent gets the tools your SuprSend role allows. Tools your role can't use don't appear in your client. Your AI client asks for your approval before a write or send tool runs.

## Scoping tool access

Add `?tools=` to the server URL to limit which tools a client sees. Use a comma-separated list of tool names or group patterns:

```
https://mcp.suprsend.com/mcp?tools=users.*,data.*
```

```
https://mcp.suprsend.com/mcp/staging?tools=data.*
```

A pattern that matches no tool is an error. URL scope can only reduce access, never widen it. A group pattern includes the group's write and send tools: for read-only access, list the read tools by name. See [Scope the connection](/reference/mcp-overview#scope-the-connection).

| Pattern | What it allows |
|---|---|
| `users.*` | All user tools |
| `users.get` | Only the `users.get` tool |
| `tenants.*,workflows.*` | All tenant and workflow tools |
| `data.*` | Only the delivery-analytics tools |

| Tool | What it does | Example prompt | Access |
|---|---|---|---|
| `workspaces.list` | Lists the workspaces this connection can use, such as staging and production. On a pinned URL it returns only that workspace. | "Which SuprSend workspaces can you see?" | Read |

## Users

| Tool | What it does | Example prompt | Access |
|---|---|---|---|
| `users.find` | Finds users by exact email, phone number or distinct_id, and filters by active channel, locale or tenant. | "Find the user with the email emily.carter@routewise-demo.com." | Read |
| `users.get` | Gets a user's full profile: channel addresses, locale, timezone and custom properties. With a tenant, also the user's profile in that tenant. | "Show me the profile of usr_8f3k2m." | Read |
| `users.get_preferences` | Gets a user's opt-in or opt-out for each category and channel, and the channels they blocked everywhere. | "Is usr_8f3k2m opted out of quote reminders?" | Read |
| `users.list_subscriptions` | Lists the subscriber lists or the objects, such as teams, that a user belongs to. | "Which lists is usr_8f3k2m on?" | Read |
| `users.list_tenant_profiles` | Lists a user's profile in each tenant. A tenant profile overrides the global profile when a workflow runs for that tenant. | "Does usr_8f3k2m have a different profile in any tenant?" | Read |
| `users.upsert` | Creates a user, or merges properties and adds channel addresses to an existing one. Nothing is removed. | "Create a user usr_4k2p9q with the email james.miller@routewise-demo.com." | Write |
| `users.update` | Changes a user with operations in order: set, set once, add to a number, unset, append, remove, and add or remove a channel. | "Remove the old phone number from usr_8f3k2m." | Write |
| `users.set_preferences` | Opts a user in or out of categories, and blocks or unblocks channels across all categories. Reports any change SuprSend didn't apply. | "Turn off SMS for usr_8f3k2m in the quote reminders category." | Write |
| `users.reset_preferences` | Resets 1 to 100 users' preferences to the category or tenant defaults, removing every choice they made. | "Reset usr_8f3k2m's preferences to the defaults." | Write |

## Objects

| Tool | What it does | Example prompt | Access |
|---|---|---|---|
| `objects.get` | Gets an object, such as a team or project, with its channels, properties and number of subscribers. | "Show me the object team/dispatch-east." | Read |
| `objects.list_subscribers` | Lists the users and child objects subscribed to an object. A notification sent to the object reaches them. | "Who is subscribed to team/dispatch-east?" | Read |
| `objects.list_subscriptions` | Lists the parent objects an object belongs to, for example the organization of a team. | "Which organization does team/dispatch-east belong to?" | Read |
| `objects.upsert` | Creates an object, or merges properties and adds channel values to an existing one. | "Create a team object dispatch-west named West Coast Dispatch." | Write |
| `objects.update` | Changes an object with operations, such as setting or deleting properties and removing channel values. | "Remove the Slack webhook from team/dispatch-east." | Write |
| `objects.add_subscribers` | Adds up to 100 users or child objects as subscribers of an object. | "Add usr_8f3k2m and usr_4k2p9q to team/dispatch-east." | Write |
| `objects.remove_subscribers` | Removes users or child objects from an object's subscribers. Profiles don't change. | "Remove usr_4k2p9q from team/dispatch-east." | Write |

| `lists.add_users` | Adds up to 10,000 existing users to a static list per call. | "Add these 50 users to the beta-testers list." | Write |

| `lists.cancel_replace` | Drops the replacement draft. The live list doesn't change. | "Cancel the replace of beta-testers." | Write |
| `lists.set_sync_enabled` | Turns a dynamic list's scheduled sync on or off. Members stay as they are when it's off. | "Pause the sync of active-shippers." | Write |

## Broadcasts

<Warning>
  `broadcasts.trigger` sends real notifications to every user on the list. Ask for a dry run first: it checks the list and template and returns the list size.
</Warning>

| Tool | What it does | Example prompt | Access |
|---|---|---|---|
| `broadcasts.get` | Gets a broadcast's status, with the users processed, completed, skipped and failed. | "Did the port-closure broadcast finish?" | Read |
| `broadcasts.trigger` | Sends one published template to every user of a list, now or on a schedule. With `dry_run`, checks the list and template and sends nothing. | "Dry-run the port-closure notice to freightco-us-shippers, then send it at 9 AM tomorrow." | Sends |
| `broadcasts.cancel` | Cancels broadcasts that haven't finished, including scheduled ones. Messages already sent stay. | "Cancel the scheduled port-closure broadcast." | Write |

## Workflows

<Warning>
  `workflows.trigger` and `workflows.test_run` send real notifications. `workflows.trigger` with `dry_run` checks the data against the payload schema and sends nothing.
</Warning>

| Tool | What it does | Example prompt | Access |
|---|---|---|---|
| `workflows.list` | Finds workflows by name, slug or description, with their status, trigger type and category. | "Which workflows send quote reminders?" | Read |
| `workflows.get` | Gets a workflow's trigger, payload schema, category, steps and templates. | "Explain what quote-expiring-reminder does." | Read |
| `workflows.validate` | Checks a whole workflow definition without saving it. | "Check this workflow JSON before you save it." | Read |
| `workflows.save_draft` | Saves a whole workflow definition as the draft, or creates the workflow. The live workflow doesn't change. | "Add a WhatsApp fallback to quote-expiring-reminder if the email isn't opened in an hour." | Write |
| `workflows.publish` | Makes a workflow's draft live. New triggers use it at once. | "Publish quote-expiring-reminder." | Write |
| `workflows.test_run` | Runs the draft or live version once for test recipients. Sends real notifications. | "Run the draft of quote-expiring-reminder for usr_8f3k2m." | Sends |
| `workflows.trigger` | Starts the live version of an API-triggered workflow for 1 to 100 recipients. With `dry_run`, checks the data and sends nothing. | "Send the quote reminder for QT-20931 to usr_8f3k2m." | Sends |
| `workflows.set_enabled` | Turns a workflow off so it starts no new runs, or on again. The emergency stop. | "Turn off quote-expiring-reminder now." | Write |
| `workflows.cancel_run` | Cancels runs that haven't finished, such as runs waiting in a delay or digest. | "Cancel the pending reminder for usr_8f3k2m, they already accepted the quote." | Write |

## Events

<Warning>
  `events.track` starts every live workflow that listens for the event, and those can send real notifications. With `dry_run`, it checks the properties and sends nothing.
</Warning>

| Tool | What it does | Example prompt | Access |
|---|---|---|---|
| `events.get` | Gets an event's description, payload schema, the workflows it starts, and when it last arrived. | "Which workflows start on QUOTE_REQUESTED?" | Read |
| `events.create` | Creates an event definition so workflows can start on it, or updates its description. | "Create an event SHIPMENT_DELAYED." | Write |
| `events.link_schema` | Links a trigger schema to an event, or removes it. | "Link the shipment-delayed schema to SHIPMENT_DELAYED." | Write |
| `events.track` | Sends an event for a user, which starts every live workflow that listens for it. | "Track SHIPMENT_DELAYED for usr_8f3k2m with shipment SH-4471." | Sends |

## Data

<Note>
  In clients that support MCP Apps, `data.query` results show as a chart (metric, line, bar, stacked bar or pie) or a table, with a Refresh button.
</Note>

| Tool | What it does | Example prompt | Access |
|---|---|---|---|
| `data.query` | Runs a read-only SQL query over delivery, engagement, logs, workflow runs and configuration. Up to 10 queries a minute for your organization. | "Show the email delivery rate by tenant for the last 7 days as a line chart." | Read |
| `data.validate` | Checks SQL for `data.query` without running it. | "Check this query before you run it." | Read |
| `data.retention` | Gives how many days of activity data the workspace keeps, and the earliest date. | "How far back does our delivery data go?" | Read |
| `data.user_properties_schema` | Gives the custom user properties defined in the workspace, with their types. | "Which custom properties do our users have?" | Read |

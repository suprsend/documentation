## Prerequisites

Before you start, ensure you have:

* [SuprSend CLI installed](/reference/cli-installation)  
* A **service token** from your SuprSend dashboard  
* Access to your SuprSend workspace  

<Warning>
**Security reminder:**  
Keep your service tokens secure. Never commit them to version control or share them publicly.
</Warning>

## Get Your Service Token

1. Log in to your SuprSend dashboard  
2. Go to **Account Settings → Service Tokens**  
3. Create a new service token or copy an existing one  

## Authentication Methods

The CLI resolves authentication using this priority order:

| Priority | Method                | Best For                |
|----------|-----------------------|-------------------------|
| 1        | Environment Variable  | Development, CI/CD      |
| 2        | Command-Line Flag     | One-off commands        |
| 3        | Active Profile        | Multiple environments   |

## Method 1: Environment Variable (Recommended for Dev & CI/CD)

```bash
export SUPRSEND_SERVICE_TOKEN="your_service_token_here"
export SUPRSEND_BASE_URL="https://hub.suprsend.com/"
export SUPRSEND_MGMNT_URL="https://api.suprsend.com/"
```

<Note>
**Advantages:**
- Works across all commands automatically
- Easy to integrate into scripts and pipelines
- Can override profile settings
</Note>

## Method 2: Command-Line Flag

```bash
suprsend workflow list --service-token "your_service_token_here"
```

<Note>
**Good for quick tests** ⚠️ Not recommended long-term — token appears in shell history
</Note>

## Method 3: Profiles (Recommended for Multiple Environments)

Profiles let you manage **production, staging, and dev tokens** separately.

```bash
suprsend profile add --name production --service-token "your_token_here"
suprsend profile use production
```

<Note>
👉 See the full [Profiles guide](/reference/cli-profiles) for details on managing multiple environments.
</Note>

## Verify Authentication

Run the following command to confirm setup:

```bash
suprsend version
```

If successful, you'll see the CLI version.
If authentication fails, you'll get an error message.

## Security Best Practices

* Use **environment variables** in production and CI/CD
* Rotate tokens regularly from your dashboard
* Use **profiles** for multiple environments
* Never commit tokens to version control
